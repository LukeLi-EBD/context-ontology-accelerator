### 2.4 与 `metric_observation` 的关系

```
期次事实表（独立）
  -> metric_definition.fact_function（SQL 聚合函数，按显式观察窗）
  -> platform.metric_observation（一行/实体/窗口）
  -> MetricService.compute（只读 observation，按 v3 formula/agg/window 出数）
```

- period 口径：只汇总 `due_date ∈ [start, end]` 的期次；同一保单取 `status_as_of` 最新快照。
- instant 口径：要求 `start == end`，聚合函数内再次断言 `p_start = p_end`，只取 `status_as_of = 观察日` 的期次。
- 计算器未改：Python 仍只做通用 SQL 聚合 + AST 白名单求值，无逐指标公式；v3 的 `formula / numerator_agg / denominator_agg / window_kind` 一字未改。

## 4. 可算性验证

### 4.1 链路命令

```
platform metrics facts-load --kind insurance_payment \
  --file /app/tests/fixtures/metrics/s14h04/insurance_payment_records.csv \
  --data-source fixture --fixture true --apply          # rowsAfter=11

platform metrics facts-load --kind loan_installment \
  --file /app/tests/fixtures/metrics/s14h04/loan_installment_plans.csv \
  --data-source fixture --fixture true --apply          # rowsAfter=10

platform metrics project --metric FIN-INS-021 \
  --window-start 2024-01-01 --window-end 2024-12-31 \
  --data-source fixture --fixture true --apply          # rowsProjected=2

platform metrics project --metric FIN-BANK-001 \
  --window-start 2024-12-31 --window-end 2024-12-31 \
  --data-source fixture --fixture true --apply          # rowsProjected=4
```

### 4.2 手算对照

| 指标 | 窗口 | 分子 | 分母 | 公式（v3） | 人工算式 | compute |
|---|---|---|---|---|---|---|
| FIN-INS-021 | 2024-01-01..2024-12-31（366 天） | 4 | 8 | `numerator / denominator * 100` | LIFE-A 2/5，LIFE-B 2/3 → `(2+2)/(5+3)*100 = 50.0` | **50.0 %** |
| FIN-BANK-001 | 2024-12-31 时点 | 90 | — | `numerator` | A=0、B=max(45,20)=45、C=90、D=0 → `max(0,45,90,0) = 90` | **90 天** |

逐实体明细（直接查聚合函数）：

| 指标 | 实体 | 值 |
|---|---|---|
| FIN-INS-021 | `H04-LIFE-A` | 2 / 5（P3 未缴、P4 lapsed；P5 最新快照 surrendered；第 12 期与 2023 年窗外行排除） |
| FIN-INS-021 | `H04-LIFE-B` | 2 / 3（Q2 未缴） |
| FIN-BANK-001 | `H04-AGREE-A` | 0 |
| FIN-BANK-001 | `H04-AGREE-B` | 45 |
| FIN-BANK-001 | `H04-AGREE-C` | 90 |
| FIN-BANK-001 | `H04-AGREE-D` | 0 |
| FIN-BANK-001 | `H04-AGREE-E` | 仅 2024-09-30 的 120 天快照，未混入 2024-12-31 |

口径语义验证：

- “不许把时点值当期间值”：021 的 period 只按 `due_date` 入窗；P5 的两条快照按 `status_as_of` 取最新，而非简单计数；BANK-001 的 instant 只取 `status_as_of = 2024-12-31`，2024-09-30 的 120 天未进入。
- 窗口不足：021 用 31 天窗 → `E_METRIC_WINDOW_INSUFFICIENT`，observation 行数不变。
- 时点指标传期间窗：BANK-001 用 2024-12-30..2024-12-31 → `E_METRIC_WINDOW_INSUFFICIENT`。
- 无实体源：FIN-BANK-025 → `E_METRIC_FACT_SOURCE_MISSING`。
- 证据/公式守卫：`E_METRIC_NOT_PUBLISHABLE` / `E_METRIC_FORMULA_DISABLED` 未放宽。
