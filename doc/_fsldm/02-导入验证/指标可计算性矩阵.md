## 3. S14-H-04 实体落地与平台复核（2026-11-06）

### 3.1 实体表与 `metric_observation` 的关系

两条口径补的是**独立事实表**，不是 `metric_observation` 的维度：

- `platform.ins_payment_record`：一行 = 一张保单一个期次在一个状态观察日的缴费/保单状态；期间归属看 `due_date`，状态取 `status_as_of` 最新一条。
- `platform.loan_installment_plan`：一行 = 一笔协议一个期数在一个状态观察日的应还/实还/逾期天数；时点口径只取 `status_as_of = 观察日`。
- 投影不是计算器的一部分：`metric_definition.fact_function` 指向聚合函数，按显式观察窗把期次事实聚成 `metric_observation` 一行/实体；计算器仍只读 `metric_observation`，仍按 `definition_version=v3.0` 的 `formula / numerator_agg / denominator_agg / window_kind` 出数。
- 因此“时点值当期间值”在链路层就被挡住：period 口径只按 `due_date ∈ [start,end]` 汇总；instant 口径要求 `start == end`，聚合函数内也加了同样约束。

## 4. 六条 SQL（实际执行）

### 4.1 FIN-BANK-001 DPD

```sql
SELECT loan_id, due_date, snapshot_date,
       CASE WHEN paid_amount >= balance THEN 0
            ELSE CAST(julianday(snapshot_date) - julianday(due_date) AS INTEGER) END AS dpd
  FROM loans
 ORDER BY loan_id;
```

合成结果：20 行；`L001=90`、`L002=91`、`L003=0`、`L004=0`；`DPD>90` 4 行。

### 4.2 FIN-BANK-025 单一客户贷款集中度

```sql
SELECT customer_id,
       MAX(bal) AS max_balance,
       MAX(bal) / (SELECT capital_net FROM capital) AS ratio
  FROM (SELECT customer_id, SUM(balance) AS bal FROM loans GROUP BY customer_id)
 GROUP BY customer_id
 ORDER BY max_balance DESC;
```

合成结果：6 行；最大 `C001=0.12`；`>10%` 仅 `C001`。

### 4.3 FIN-BANK-030 大额风险暴露认定

```sql
SELECT l.customer_id,
       SUM(l.exposure) AS exposure,
       (SELECT tier1_net FROM capital) AS tier1,
       SUM(l.exposure) / (SELECT tier1_net FROM capital) AS ratio,
       CASE WHEN SUM(l.exposure) > 0.025 * (SELECT tier1_net FROM capital)
            THEN 1 ELSE 0 END AS is_large
  FROM loans l
 GROUP BY l.customer_id
 ORDER BY ratio DESC;
```

合成结果：6 行；`C001=0.375`、`C002=0.0375` 超门槛；认定 2 户。

### 4.4 FIN-INS-001 原保险保费收入

```sql
SELECT product_type, SUM(premium) AS premium_income
  FROM policies
 WHERE is_investment_link = 0
   AND issue_date >= '2025-01-01' AND issue_date < '2026-01-01'

```

合成结果：3 个险种；短期健康 300、车险 500、长期寿险 400；合计 1,200；投连险 700 被排除。

### 4.5 FIN-INS-021 13个月继续率

```sql
SELECT SUM(CASE WHEN month13_paid = 1 AND status = '有效' THEN 1 ELSE 0 END) AS kept,
       COUNT(*) AS due
  FROM policies
 WHERE month13_due = 1 AND product_type = '长期寿险';
```

合成结果：`kept=3`、`due=4`、比率 `0.75`。

**卡点说明**：`month13_due`/`month13_paid` 是探针自造字段。S14-H-04 已补 `platform.ins_payment_record` 及其本体类 `fsldm:InsurancePaymentRecord`，平台侧不再依赖探针字段；探针值仅保留作表达力对照。

### 4.6 CUST-004 RFM 五分位

```sql
WITH rfm AS (
    SELECT customer_id,
           CAST(julianday('2025-12-31') - julianday(MAX(txn_date)) AS INTEGER) AS r,
           COUNT(*) AS f,
           SUM(amount) AS m
      FROM transactions
     GROUP BY customer_id
),
scored AS (
    SELECT customer_id, r, f, m,
           NTILE(5) OVER (ORDER BY r DESC) AS r_score,
           NTILE(5) OVER (ORDER BY f ASC)  AS f_score,
           NTILE(5) OVER (ORDER BY m ASC)  AS m_score
      FROM rfm
)
SELECT customer_id, r, f, m, r_score, f_score, m_score,
       CAST(r_score AS TEXT) || CAST(f_score AS TEXT) || CAST(m_score AS TEXT) AS rfm_code
  FROM scored
 ORDER BY customer_id;
```

合成结果：6 行；示例 `C001: r=30, f=3, m=1000, code=354`；`C002: r=11, f=2, m=900, code=443`。

**卡点说明**：6 个客户分 5 档，NTILE 出现 2 个客户同档；真实业务需固定边界与并列值规则，不能直接以样本分位替代阈值分档。
