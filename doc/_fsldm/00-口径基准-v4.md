# 00-口径基准 v4

> **数据声明：本基准只登记口径，不含业务数值；所有验证与探针数值均为合成数据、非业务结论。**
> 状态：文档与种子（未灌库）。基线：`00-口径基准-v3.md`（79 条）。本文件不替代 v3，仅在其上补齐每条指标的五件套并登记标注。
> 边界：不改 v3、不改 `05-*`、不改 `_design`、不写 `a_progress.md`、不跑 Docker、不写数据库、不 git commit。

## 1. 本版做了什么

v3 的 79 条中有 73 条缺少可直接用于建模的定义文本（只有名称、证据档位与是否可发布）。v4 为**每一条**补齐：

- `definition`：一句话业务定义（人话，不是指标名复述）
- `formula`：分子/分母表达式；比率写 `numerator / denominator * 100`，可加性写 sum，时长写 max
- `denominator`：分母口径、单位、去重对象
- `observationPeriod`：时点 vs 期间与窗口长度
- `granularity` + `unit`：机构/产品/客户/协议维度与单位

并为每条新增两级标注：`provenanceLabel ∈ {原文, 行业通行, 推测}` 与 `inference ∈ {true, false}`。

## 2. 标注规则（固定，不许自创）

| provenanceLabel | 含义 | display_name 后缀 | inference | evidence_basis 约束 |
| --- | --- | --- | --- | --- |
| 原文 | 研究稿可定位监管原文/条款（未与 PDF 逐字核验） | 无后缀 | false | 必须是 `regulatory` |
| 行业通行 | 有成文且被普遍使用的行业公式，但非监管原文 | `〔行业〕` | true | 必须是 `industry` |
| 推测 | 无原文也无成文行业公式，由本轮按实务常识补写 | `〔推测〕` | true | 只能是 `none` 或 `industry`，绝不允许 `regulatory` |

存储名（`metric_id`）与规范 `name_zh` 主体不改，只有 `display_name` 末尾追加固定后缀。

## 6. 可算性预测（补定义不等于可算）

“可算”按平台现状定义：需要 ①口径四元组（formula / 分母 / 窗口 / 聚合）②对应事实源 ③`publishable=true`。补定义只解决 ①，不新建事实表，因此：

| 分层 | 条数 | 指标 | 结论 |
| --- | --- | --- | --- |
| A 已可算且可发布 | 4 | FIN-BANK-001 / 025 / 030、FIN-INS-021 | 保持可算，口径未被改动 |
| B 规则型（非比率/非时长，平台 `metric_kind` 不直接支持） | 11 | FIN-BANK-003/004/005/007/009/010/011/012/024/034、CUST-004 | 仍不可算为数值指标；需分类输出与规则引擎支持 |
| C 口径齐但缺事实表/字段 | 61 | 其余（含全部 industry/no-source 比率与金额类） | 仍不可算；补实体后可进入建模，其中 `publishable=false` 的仍不得对外出数 |
| D 缺外部数据 | 3 | FIN-INS-029、FIN-INS-030、CUST-011 | 仍不可算；需偿付能力报表 / 客户品类总消费外部数据 |

合计 4 + 11 + 61 + 3 = 79。**预计新增可算 0 条，可算总数仍为 4 条**（与 `02-导入验证/指标可计算性矩阵.md` 的 6/6 结构性、4/6 可发布一致）。即使 C 类全部补齐事实，`publishable=false` 的 42 条仍被证据门禁挡住。
