## 0. 结论

1. 术语层做成 **类级 SKOS 注释层 + 可核查词条记录**：新增独立模块 `fsldm-terms.ttl`，与 T-Box 同图合并发布；不建立独立 term 图，不改类/属性语义。
2. 第一批覆盖 **28 个类**，来源是 36 条"可用"指标牵涉的核心实体（客户、账户、协议、产品、担保、保单、理赔、保障、事件）。
3. 54 条候选别名全部归档：**A 档 6 词、B 档 12 词、C 档 36 条否决**；**13 个类没有任何别名**（原因见 3.4）。
4. 12 个类写出完整词条（prefLabel / altLabel / definition / 出处）；A 档全部有 chunk 级出处，B 档全部有两轮 LLM 判定与 confidence。
5. LLM 两轮跑通：主轮 26 类 122s，补充轮 2 个类 + 语料候选词补判；两轮结论冲突项（"押品"）按保守原则否决。

## 1. 为什么需要术语层

### 1.1 实测：当前字面匹配的失败面

在 `fsldm-merged.ttl` 全量 `rdfs:label` + `skos:prefLabel` + `skos:altLabel` 字面中做子串匹配（只读脚本，等价于 `context.py` 的种子查询口径）：

| 业务问法 | 命中数 | 结论 |
|---|---:|---|
| 客户 | 0 | 类叫"当事人"，业务第一高频词完全落空 |
| 逾期贷款 | 0 | 监管用语，本体只有属性/概念，不含该字面 |
| 不良率 | 0 | 只有"不良贷款（后三类）"概念（L455），无"不良率" |
| 集团客户 / 关联客户 | 0 / 0 | `PartyGroup` / `PartyRelationship` 存在但接不上 |
| 风险暴露 | 0 | 大额风险暴露指标无法锚定 |
| 信用评级 | 0 | `PartyRiskGrade` 存在但无业务词 |
| 险种 | 0 | `InsuranceProduct` 存在但无业务词 |
| 赔案 | 0 | `Claim` / `ClaimEvent` 存在但无业务词 |
| 报案 | 0 | 同上 |
| 押品 / 担保合同 | 0 / 0 | `CollateralItem` / `RiskMitigantAgreement` 接不上 |
| 退保 / 继续率 / AUM | 0 / 0 / 0 | 保险与客户经营高频词全落空 |
| 保单 | 3 | 同时命中 `agmt:Policy`（L1568）与 `ins:InsuranceAgreement`（L3285），无 canonical |

### 1.2 五个具体失败场景

1. **"这家客户在你们这有几个账户？"**
   问句里"客户"在 `rdfs:label` 中 0 命中。`ContextResolver._seeds` 只对 `rdfs:label` 做整句子串 `CONTAINS`（`_impl/src/platform_core/context.py#L346`，过滤条件在 `#L354`），种子为空 → 图侧 `facts=[]`，只剩文档块，答案没有主体锚点。

2. **"单一集团客户授信集中度是多少？"（FIN-BANK-028）**
   本体有 `party:PartyGroup`、`party:PartyRelationship`、`agmt:CreditAgreement`，但"集团客户 / 关联客户"均 0 命中；"授信额度"只命中指标概念（L556），不是类。指标口径与图实体之间没有桥，只能退化为纯文档检索。

3. **"今年报案立案率、案均已决金额多少？"（FIN-INS-018 / 015）**
   "报案""赔案"0 命中；`agmt:Claim`、`evt:ClaimEvent` 存在但无别名。监管口径（保监发〔2015〕27号 LP-Ⅱ-1、LP-Ⅲ-1）用的是"报案立案率""案均赔款"，与本体词面完全不重合。

4. **"不良率 / NPL ratio 是多少？"（FIN-BANK-004）**
   0 命中。"不良贷款（后三类）"只是 `codes.ttl` 里的**分类值概念**（L455），不是类；"不良率"是指标名。用户既找不到类，也找不到指标概念，查询扩展开不了。

5. **"查一下这张保单的保障项"**
   "保单"同时命中 `agmt:Policy` 与 `ins:InsuranceAgreement`（两个类语义重叠），种子会同时召回两个类，facts 重复且可能冲突；"保障项"只命中 `ins:Coverage`，但"保险责任"这类更常用的说法 0 命中。

> 现有文档检索（`adapters/search_pg.py#L46-L57`：`plainto_tsquery('simple')` + `word_similarity`）与向量检索都只作用于 chunk，不负责"业务词 → 本体实体"的对齐。术语层补的就是这一层，不改检索算法本身。

## 2. 术语层的结构决策

### 2.1 放在哪一层：T-Box 注释层（独立文件，同图发布）

**决策**：新建 `_fsldm/fsldm-terms.ttl`，只包含 `owl:Class` 的 SKOS 注释 + `term:*` 词条记录；发布时与 `fsldm-merged.ttl` 合并进同一个 T-Box 图。**不建独立 term 图**。

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| A. 类上直接挂 SKOS（本方案） | 种子查询一次 join 即可用；类与词条同版本、不会漂移；SHACL 直接校验类节点 | 类实例同时是 `skos:Concept`（OWL 2 punning），会多出 `?c a skos:Concept` 推理 | **采用**。punning 合法，且由一致性门禁兜底 |
| B. 独立 term 图 + `skos:exactMatch` | SKOS 语义纯正、词条可独立生命周期 | 检索要两跳、两层图对不上会静默漂移；多一套发布/回滚 | 不采用 |

理由补充：
- 现有检索路径是 `rdfs:label` 单跳；A 方案让"换谓词"就能生效，B 方案要改两处。
- 项目已有 `codes.ttl` 承载**取值词表**的 SKOS；类术语必须和类同图，否则"类改名、词条没改"无法被门禁发现。
- 单机优先、依赖最小化：不引入新的词表服务/图。

### 2.2 用哪些谓词

| 谓词 | 用途 | 约束 |
|---|---|---|
| `skos:prefLabel` | 每类每语言**恰好 1 个**首选词；`@zh` 必须等于 `rdfs:label@zh` | 由 SHACL 强制 |
| `skos:altLabel` | 同义业务别名，可多个；**必须带语言标签** | 同语言全局唯一；不得等于任何类的 prefLabel |
| `skos:definition` | 一句话定义，20–220 字 | 不得复述 label；只允许基于本体注释/FS-LDM 原义改写 |
| `skos:scopeNote` | 可选，写消歧提示（如"不用于指标口径"） | 不参与检索扩展 |
| `term:termBatch` | 标记属于第几批（本批=1） | 门禁只校验声明了批次的类 |
| `term:termStatus` | `evidenced` / `inferred` | 与别名一一对应 |
| `term:termConfidence` | `high` / `medium` | 仅 `inferred` 必填 |
| `term:termSource` | 可核查定位串 | `evidenced` 必填 |

**不使用** `skos:broader` / `skos:narrower` 于类层：类上下位已经由 `rdfs:subClassOf` 表达，再用 SKOS 层级会形成两套可能冲突的层次。SKOS 层级只保留在 `codes.ttl` 的 ConceptScheme 内（现状不变）。

### 2.3 与 `rdfs:label` 的关系：共存，不替代

- `rdfs:label@zh` 继续作为既有查询与展示的兼容字段，本轮**不改一个字的 label**。
- `skos:prefLabel@zh` 与 `rdfs:label@zh` **强制相等**（SHACL-SPARQL 校验）；`@en` 由 `fsldm:fsldmEntity` 做 Title Case 归一（如 `PARTY` → `Party`），可追溯到本体字段。
- 术语层不替代 label，避免一次性改动打破现有 1,227 份文档与既有验收。

### 2.4 一义多词 / 一词多义

- **一义多词**：允许，多个 `skos:altLabel`。例：`agmt:IndividualInsurancePolicy` 同时有"个人保单""个险保单"。
- **一词多义**：**禁止**作为 altLabel。同一语言下，一个词面只能属于一个类；若两个类语义重叠（`agmt:Policy` vs `ins:InsuranceAgreement`），必须先定 canonical（记入待确认 T6），非 canonical 类不得写该词。
- **跨类同义但语义重叠**：不硬造两个 altLabel，而是由 `term:canonicalFor` 指向 canonical 类，检索扩展只取 canonical，避免种子重复。

### 2.5 同义词方向

altLabel **单向**：从类指向词，不建反向三元组（SKOS 本身也不要求）。
类间上下位**只走** `rdfs:subClassOf`；`codes.ttl` 的 `skos:broader/narrower` 不动。
"集团客户""客户""押品"这类**上位/角色/分类词**不写 altLabel（见附录 A），保留给后续"检索扩展词表（非本体）"，因为它们的语义是 narrowed/broader，而不是同义。

### 2.6 缩写 / 中英混写 / 单位归一

| 情形 | 规则 | 例 |
|---|---|---|
| 中英对照 | `prefLabel@zh` 用监管原文用语；`prefLabel@en` 用 FS-LDM 实体名（Title Case） | 当事人 / Party |
| 缩写 | 只有在**类级同义**时才进 altLabel；比率/指标缩写留给指标概念 | `NPL` 属"不良贷款率"指标概念，不属任何类 |
| 中英混写 | 统一拆成 `@zh` 与 `@en` 两个 altLabel，不写"账户 Account"混合串 | `Account`@en |
| 单位 | **不写进任何 label**；单位属于 `codes.ttl` 的 `unitOfMeasure` 概念（`code:Day` / `code:Percent`） | 逾期天数不写"（天）" |
| 旧字形 | 有原文出处的变体才收（"帐户"有 FS-LDM 原文）；无出处的口语变体不收 | 帐户（A 档）/ 账户账号（C 档） |

### 2.7 既存 146 条大写 altLabel 的处理

现状：`fsldm-merged.ttl` 有 **146 条 `skos:altLabel`，全部是大写 ASCII 实体名**（`ACCOUNT`、`PARTY`…），其中 2 条值重复（`ACCOUNT GROUP`、`INSURABLE INTEREST`）。这些不是"业务别名"，而是机器码被放进了 `altLabel` 位置。

**决策**：本轮**冻结不动**，但新写入的 altLabel 一律要求**语言标签**（`@zh`/`@en`），SHACL 只校验带语言标签的 altLabel；这样旧数据不会被新门禁误伤。迁移到 `skos:notation` 的方案放到 T7（需人工确认，因为会改变下游对 `altLabel` 的依赖）。

### 2.8 词条取证结构

类上保留 SKOS 谓词供检索/SKOS 消费；每个别名再用一个可核查的 `term:TermEntry` 记录出处，两者由 SHACL 做**集合相等**校验，防止"类上有词、记录里没出处"。

```turtle
term:Account_alias_zhanghu a term:TermEntry ;
    term:forClass agmt:Account ;
    term:label "帐户"@zh ;
    term:status term:evidenced ;
    term:evidenceType term:CorpusChunk ;
    term:source "453_FSLDM课堂练习.pdf#p20/seq19; document_id=08b15dc6c1fc…" .
```

## 3. 范围决策：第一批 28 个类

### 3.1 为什么是这批

`00-口径基准-v1.md` 共 79 条指标，**36 条"可用"**（L195）：银行 7、保险 20、客户经营 9。把这 36 条的公式拆成实体后，只牵涉以下 8 组核心实体；每一组都能在现有 156 类中找到准确落点，因此第一批按"实体组"取 28 类，而不是按"看起来重要"取。

| 实体组 | 对应可用指标（节选） | 落地类 |
|---|---|---|
| 客户主体与分组 | 集中度、关联度、大额风险暴露、客户留存/AUM | Party / Individual / Organization / Household / PartyGroup / PartyRelationship / PartyRiskGrade |
| 协议与账户 | 逾期天数、贷款余额、授信、集中度 | Agreement / Account / CreditAgreement |
| 保单 | 签单保费、续期保费、继续率、退保率、保单件均 | Policy / IndividualInsurancePolicy / GroupInsurancePolicy / CommercialInsurancePolicy / InsuranceAgreement |
| 产品 | 产品持有数、险种、费用率 | Product / InsuranceProduct |
| 度量 | 余额、额度、逾期、拨备、资本净额 | Metric |
| 担保 | 担保覆盖、押品 | Asset / CollateralItem / CollateralAgreement / RiskMitigantAgreement |
| 理赔与保障 | 赔付率、未决赔款准备金、案均、报案立案率 | Claim / ClaimCoverage / Coverage |
| 事件 | 还款、缴费、退保、报案/立案/结案 | FinancialEvent / AccountEvent / ClaimEvent |

### 3.2 必须说清的一件事：余额 / 额度 / 逾期 / 还款不是类

在 156 个 `owl:Class` 中**不存在**"余额""额度""逾期""还款"类。它们分别落在：

- 余额/额度/逾期余额/拨备余额 → `fsldm:Metric` + `codes.ttl` 的 MetricType 概念（如 `code:MetricLoanBalance`、`code:MetricCreditLimit`）；
- 逾期天数 → `Metric`（`code:MetricDaysPastDue`）+ 账户属性；
- 还款/缴费 → `evt:FinancialEvent` / `evt:AccountEvent`；
- 不良率/AUM/继续率/退保率 → 指标概念（`codes.ttl`），不是类。

因此第一批**只做类级词条**；指标概念级词条（MetricType + 单位 + 口径）放第二批，理由是概念级需要同时给"单位、时点、口径"三个约束，混进类表会让 SHACL 无法区分。

### 3.4 13 个无别名类：为什么留空

| 类 | 原因 |
|---|---|
| `party:Organization`、`party:Household` | 候选词（组织机构/非自然人/住户/家庭户/居民家庭）全部是上位、行政统计口径或一词多义，无严格同义词 |
| `party:PartyRiskGrade` | "评级"是过程/体系，"等级"是结果；LLM 判多义，且"信用评级"是另一概念 |
| `fsldm:Agreement` | "合同/合约"是法律子类或衍生品专用词，不是同义 |
| `fsldm:Product`、`ins:InsuranceProduct` | "交易品种"是交易标的，"险种"是产品分类，均为上下位 |
| `fsldm:Metric` | "指标"在业务里默认指 KPI/考核目标，多义 |
| `fsldm:Asset` | 无候选，且与抵押物、财务项边界未定（见待确认） |
| `agmt:Claim`、`evt:ClaimEvent` | "赔案"是案件记录、"索赔"是行为，"理赔"是处理过程；三者都不同义 |
| `agmt:ClaimCoverage`、`evt:FinancialEvent`、`evt:AccountEvent` | 无可靠候选；避免为凑数编词 |

结论：**宁可 13 个类留空，也不写一条无出处/不同义的别名**。

## 4. 样例词条（12 个类，完整 TTL 片段）

### 4.1 归档规则（写进门禁）

对每个候选词按以下顺序归档：

1. 先在语料里找原词（`D:\FS-LDM` 抽取文本 / 平台库 chunk / 本体自身 label 与属性名）。找到 → **A 档**，`termStatus=evidenced`，必须写 `termSource`（文件名 + 页码/seq 或 `document_id` + 定位）。

## 5. 落地与门禁

### 5.1 SHACL 形状

| 形状 ID | 约束 | 严重级别 | 说明 |
|---|---|---|---|
| `term:PrefLabelShape` | `skos:prefLabel@zh` 恰好 1；`@en` 恰好 1 | Violation | 只 target `sh:targetSubjectsOf term:termBatch` |
| `term:PrefLabelEqualsLabelShape` | `STR(prefLabel@zh) = STR(rdfs:label@zh)` | Violation | SPARQL 约束，防止两层词不一致 |
| `term:AltLabelProvenanceShape` | 每个 `skos:altLabel`（带语言标签）必须有同值的 `term:TermEntry`，且 `term:source` 非空 | Violation | 旧的无语言标签大写 altLabel 不在此形状范围 |
| `term:TermEntryShape` | `forClass`/`label`/`status` 各 1；`evidenced` 必须有 source；`inferred` 必须有 high/medium confidence | Violation | 词条结构合法性 |
| `term:DefinitionShape` | `skos:definition@zh` 恰好 1，长度 20–220 | Violation | 定义必须可读且不灌水 |
| `term:AltLabelUniqueShape` | 同语言同词面不得被 2 个类同时使用；altLabel 不得等于任何类的 prefLabel | Violation | 防跨类重复、防与 canonical 类名冲突 |
| `term:LegacyAltLabelShape` | 无语言标签且全大写的 altLabel → Warning | Warning | 提醒旧 146 条待迁移，不阻塞 |
| `term:ScopeShape` | `term:termBatch` 只允许 1（本批） | Warning | 防止误把第二批词条混入门禁 |

### 5.2 与 `validation.py` / shapes 注册表接线

- 形状放 `_impl/data/shapes/fsldm/terms.ttl`。`ShapesRegistry.shapes(namespace)` 会扫描 `shapes/<segment>/*.ttl`（`validation.py#L51-L57`），`namespace_segment("https://w3id.org/fsldm/")` 得到 `fsldm`，因此**无需改注册表、无需改 manifest**，新增文件即被发现。
- `validation.py#L149-L181` 的 `validate(data_nt, graph_iri, namespace)` 用 pySHACL，已开启 `allow_warnings`/`allow_infos`，所以 Warning 档不会让导入失败。
- G-01 本体导入门禁传 `namespace=fsldm` 时自动执行术语形状；A-Box 校验（无 namespace）不受影响。
- **分期**：T1/T2 期把 `term:PrefLabelShape` 等设为 Warning；T3 期 28 类全部达标后再升 Violation，避免一次性把现有 156 类全部卡死。
- 只读验证命令（设计，不执行）：`platform ontology import --file fsldm-terms.ttl --namespace fsldm`，看 `shacl.conforms` 与 `violations[]`。

### 5.3 检索侧怎么用

**图侧（主要收益）**
- 现在：`_seeds` 把**整句 query**对 `rdfs:label` 做 `CONTAINS`（L354），"集团客户授信集中度"这种长句永远匹配不到。
- 改为三步，不改接口契约：
  1. 用 T-Box 构建内存词表 `{label -> class}`（`prefLabel@zh/en` + `altLabel@zh/en` + legacy `rdfs:label`）；
  2. 对 query 做**最长匹配**切词，命中词映射到 canonical 类，得到 hints；
  3. 无命中才回退到原 `CONTAINS`。
- canonical 去重：`agmt:Policy` 与 `ins:InsuranceAgreement` 只保留一个（待 T6 确认），避免种子重复。

**文档侧（辅助收益）**
- `search_pg.py` 的词法检索（L46-L57）用 `plainto_tsquery('simple', q)` + `word_similarity(q, text)`；"simple" 分词对中文等于整串，所以"不良率"根本切不开。
- 方案：识别到术语后，用 canonical prefLabel + altLabel + `prefLabel@en` 生成**多条词法查询**，每条走原 SQL，结果与原始查询一起进 `SearchService` 的固定 RRF（`k=60`，`search.py#L1-L4`），不新增融合算法。
- **向量侧本轮不动**：不把扩展词重新向量化（会改变向量语义，违反既有约束）。若后续要做，必须单开切片并重新评估。

**对现有命中率的影响**
- 只增加召回入口，不改排序公式；原查询始终保留一路，理论上 recall 单调不降。
- 风险是**误扩展**（如"客户"被扩到 `Party` 却应落到个人/机构）。对策：上位/角色词不进 altLabel（已在附录 A 否决），并且扩展默认 **off**，由评估决定是否打开。

### 5.4 评估方法（不改生产指针）

1. **Golden set**：36 条可用指标 × 3 种问法（监管全称 / 业务简称 / 英文缩写或中英混写）= **108 条**。
2. **指标**：
   - `graphSeedHit@1`：期望类是否出现在 `_seeds` 结果首位；
   - `docRecall@5`：含定义句的文档是否进前 5；
   - `MRR@5`；
   - `expansionFP`：扩展出的 canonical 类不在期望集合的比例（目标 ≤2%）。
3. **流程**：离线脚本对同一语料跑两遍（baseline = 现状；candidate = 词表扩展），同一 `SearchService`/`ContextResolver` 实例，不切换 embedding 指针、不重建分区。
4. **准入**：`graphSeedHit@1` 不低于基线；`docRecall@5` 提升 ≥5pp；`expansionFP ≤2%`；现有 acceptance 全绿、purity 保持 0/0。
