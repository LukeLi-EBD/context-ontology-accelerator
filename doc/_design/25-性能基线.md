## 5. 瓶颈假设（只记录，不改代码）

1. **`/context/resolve` 被 embedding 支配**：响应 `steps` 显示 `search.hybrid=2829 ms`，总耗时 2858 ms（graph.seed/facts≈1 ms）；embedding 容器 CPU 249%（4 核配额下约 2.5 核）。c1→c4 吞吐 0.35→1.29 rps（≈3.7×，近线性），说明瓶颈是 TEI 单请求推理而非平台 API。假设：查询向量化单次约 2.8 s，加并发可线性收益直到 4 核配额。
2. **只读 API 与 SPARQL 余量充足**：c4 p99 ≤ 20.06 ms，错误率 0；API 容器 CPU 峰值仅 93%，Oxigraph 峰值 38%。
3. **`metrics load --dry-run` ≈0.93–1.1 s 主要是进程启动 + schema migrate**：日志先打印 `migration applied`；并发 4 时单次略升至 1.09 s，但吞吐 3.4 rps，说明瓶颈在每次 CLI 的固定启动开销，不在 CSV 解析（10 行）。
4. **推理作业 2.87 s**：owl 阶段 1.84 s 为主；对 2961 triples 的 EL 物化属正常量级。未做缓存/并行优化。
5. **内存不是约束**：容器合计峰值 4.49 GiB，仅为 11.68 GiB 上限的 38%；宿主余量 11 GiB 左右。
