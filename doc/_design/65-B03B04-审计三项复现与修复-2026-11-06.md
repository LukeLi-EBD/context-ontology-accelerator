## 1. 实体页超时（B-03）

### 复现（改前）

真实 IRI：`urn:platform:synthetic/investment_InvestmentObjective-00175`

```
GET /ui/api/entity?iri=urn:platform:synthetic/investment_InvestmentObjective-00175
run=1 timeout  (客户端 30s 未返回；审计报告为 15s)
run=2 timeout
run=3 timeout
```

直连 Oxigraph 执行同形状 SPARQL：`>25s` 未返回，即服务端本身挂起，不是前端或网关超时。

### 根因

`entity_view._triples_query` 使用：

```sparql
VALUES ?g { <...> } GRAPH ?g { { BIND(<iri> AS ?s) ?s ?p ?o } UNION { ?s ?p <iri> } }
```

与已修复的 `webui.neighbors` 504（`a4d493e` / `6ca8561`，E-01）为**同一根因**：Oxigraph 对「变量图 + UNION」挂起。该形状此前只从 `webui.neighbors` 移除，`entity_view` 漏改。

### 修法

改为两条普通一跳查询，不再生成 UNION：

```sparql
# 出边
SELECT ?g ?s ?p ?o WHERE { VALUES ?g { ... } GRAPH ?g { BIND(<iri> AS ?s) ?s ?p ?o } } LIMIT 200
# 入边
SELECT ?g ?s ?p ?o WHERE { VALUES ?g { ... } GRAPH ?g { BIND(<iri> AS ?o) ?s ?p ?o } } LIMIT 200
```

`entity_detail` 分别执行后合并，并按 `(graph,s,p,o)` 去重（自环会同时命中两侧）。推理图沿用同样的两条查询。

### 修后实测（重建镜像后）

```
run=1 status=200 ms=135
run=2 status=200 ms=32
run=3 status=200 ms=29
```

响应体正常包含 `classes[].chain`、`properties[]`、`neighbors.nodes/edges`；`label=InvestmentObjective-00175`。页面 `/ui/entity.html?iri=...` 由该端点供数，修后返回正常。

## 2. 健康看板查错图（B-04）

### 复现（改前）

```
GET /health/dashboard
tbox=ont-11f92ebb3326
coverage.instances.total=0
coverage.instances.graphs=[urn:platform:graph:abox:main]
coverage.classes total=159 withInstances=0 ratio=0.0
coverage.properties total=139 withValues=0 ratio=0.0
```

直接计数：`abox:main` = 0 三元组；`abox:synthetic` = 304,919 三元组（60,525 个带类型实例）。

### 图名来源

**不是硬编码**：

```
healthboard._abox_graphs(runtime)
  -> runtime.reasoning.status()["aboxGraphs"]
  -> config.reasoning.abox_graphs
  -> /data/platform.yaml: [urn:platform:graph:abox:main]
```

即来自运行时配置。配置指向受治理的事实图 `abox:main`（本环境为空），而演示/覆盖数据在独立的 `abox:synthetic`。

### 修法

新增 `_view_graphs(runtime)`：在 `_abox_graphs` 基础上，若 `urn:platform:graph:abox:synthetic` 实际存在（`ASK` 命中）则纳入**只读健康看板**；`reasoning.abox_graphs` 保持不动，避免把 30 万条演示三元组送进 materialize。`entity_view._graphs` 同样在存在时纳入该图，使真实 IRI 可解析。

### 修后实测

```
tbox=ont-11f92ebb3326 graph=urn:platform:graph:tbox:ont-11f92ebb3326
coverage.instances.total=60525
coverage.instances.graphs=[urn:platform:graph:abox:main, urn:platform:graph:abox:synthetic]
coverage.classes total=159 withInstances=156 ratio=0.9811
coverage.properties total=139 withValues=129 ratio=0.9281
```

156/158 个 synthetic 类在 T-Box 中有定义（覆盖统计与口径一致，未放宽）。

## 3. `orphanInstances` SPARQL 400（B-04）

### 复现（改前）

`GET /health/dashboard` 返回：

```
orphanInstances.error = "error at 1:318: expected one of ... "
```

直接执行 healthboard 生成的原文，Oxigraph 返回 HTTP 400（同一 1:318 位置）。

### 根因

查询由 Python f-string 拼接，闭合 `FILTER NOT EXISTS` 组需要两个字面量 `}`，但源码写作 `}}`；f-string 中 `}}` 只产生一个 `}`，导致内层 `GRAPH ?g2` 关闭后 `FILTER NOT EXISTS {` 未关闭，语法树在位置 318 处报错。与 Oxigraph 版本无关。

### 修法

将该处 `}}` 改为 `}}}}`（产出两个字面量 `}`）。生成的查询随即为合法 SPARQL，语义与其他查询保持一致，未改动任何过滤条件。

### 修后实测

```
orphanInstances.count = 0
orphanInstances.error = ""
```

在 `abox:synthetic` 上直接执行修正后的查询：0.9s 返回 `0`，印证该图中所有带类型实例都有边。

### 6.5 `reasoning.abox_graphs = abox:main` 的写路径影响（只核对，未改）

没有任何写路径会向 `abox:main` 写入三元组；所有使用点都是**读/导出**。但会影响写路径的**产物与门禁**：

| 位置 | 行为 | 影响 |
| --- | --- | --- |
| `reasoning.py:191-192` → `materialize` | 导出 `abox_graphs` 作为推理输入，写入 `urn:platform:inferred:<version>` | A-Box 为空时产出的推理图为空/严重缺失，30 万真实事实不参与推理 |
| `ontology_pg.py:2567-2573` `_gate_consistency` | publish 前导出 `abox_graphs` 做一致性校验 | 空 A-Box 使一致性门禁“空过”，无法发现真实数据冲突 |
| `ontology_pg.py:891-903` `_import_impact` | 统计变更影响的三元组/实体 | `affectedEntities/affectedTriples` 报 0，发布证据失真（只读） |
| `assembly.py:155` / `api.py:3229,3336` | 把配置/请求覆盖值注入适配器 | 覆盖只影响上述读与派生写，不直接改写 A-Box |

接真实数据前必须把 `reasoning.abox_graphs` 指向真实的 A-Box 图。风险：若直接指向 `abox:synthetic`，物化将导出 304,919 三元组并交给 ROBOT 推理，在 8 核机上可能长时间运行或内存吃紧；需先评估物化预算，或仅让读侧展示接入而保持推理输入为空。本次修复只改读侧（实体页/看板），未动该配置。
