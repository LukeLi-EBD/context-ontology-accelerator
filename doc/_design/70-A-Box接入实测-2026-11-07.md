## 9. 离线窗口形态（本次落地）

### 9.1 在线是否还会触发全量：**不会**

落地前：治理发布（governed / implicit publish）和回滚都会同步调用 `self._materializer()`，也就是一次全量推理
（[ontology_pg.py](file:///D:/agentABC/wt/abox-materialize/platform/src/platform_core/adapters/ontology_pg.py#L3585-L3593)、回滚 §3810）。
即“发布即自动全量推理”是**存在**的。

落地后：`ReasoningService` 增加发布钩子，默认 `materialize_online=false` 时直接返回 deferred，不推理
（[reasoning.py](file:///D:/agentABC/wt/abox-materialize/platform/src/platform_core/reasoning.py#L147-L163)），
`assembly.py` 把该钩子交给治理门禁（[assembly.py](file:///D:/agentABC/wt/abox-materialize/platform/src/platform_core/assembly.py#L151-L160)）。
发布证据会记录：

```json
"materialization": {"jobId": null, "inferred": 0, "skipped": true, "deferred": "offline_only"}
```

运行期实测（真实 assemble 后调用钩子）：

```json
{"materializeOnline": false,
 "publishHook": {"jobId": null, "inferred": 0, "skipped": true,
                 "deferred": "offline_only", "reason": "reasoning.materialize_online=false"}}
```

唯一仍会跑全量的是**显式**动作 `POST /reasoning/materialize`（以及 smoke 脚本里的直接调用）——这正是离线窗口入口。
若某个环境确实要恢复“发布即推理”，显式设置 `reasoning.materialize_online: true` 即可（默认 false）。

### 9.2 离线窗口标准操作

**前置条件（全部满足才开跑）**

1. 灌数/验收线空闲：8082 无重采任务，8080 无批量导入（推理峰值叠加会触发 swap）。
2. 内存余量：`docker run --rm alpine free -m` 的 `available` ≥ 5 GiB；不足时先停 embedding 或改期。
3. T-Box 已发布：`GET /reasoning/status` 的 `pointer` 非空、`ontologyVersion` 为目标版本。
4. A-Box 可读：`aboxGraphs` 中每个图都能导出（不可读会进 `aboxGraphsUnavailable`）。
5. reasoner 健康：`GET /reasoning/status` 的 `available=true`。

## 13. 为什么当前机器不建议在线全量；提到 16 GiB 后的判据

**当前机器**：Docker VM 11.68 GiB，与 8080、8082 及两个 embedding（合计约 4.6 GiB）共驻；推理窗口内可用 2.0–2.4 GiB，
而本栈峰值合计约 4.5 GiB（API 2.14 + reasoner 1.43 + oxigraph 0.93），实测 swap 已用 2.7 GiB。功能上跑通了（212.6 s < 10 min），
但内存判据不通过，因此不在线自动跑。

**判据（VM/机器 ≥ 16 GiB 且单栈运行）**：

- 峰值预算：API 2.14 + reasoner 1.43 + oxigraph 0.93 + PG 0.17 ≈ 4.5 GiB；
- 常驻基线（单栈：api/pg/oxigraph/embedding/fuseki）≈ 3.5–4.0 GiB；
- 合计 ≈ 8–8.5 GiB < 16 GiB，仍有 ≥ 7 GiB 余量 → 可放开在线全量（或保持离线窗口，二者都安全）。
- 仍建议：推理窗口内不并发 embedding 全量重算；保留 `materialize_online=false` 作为默认，需要时才 `true`。
