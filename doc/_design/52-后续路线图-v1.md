## 3 HermiT / 推理扩展专章

> 本章为**观察项**（H-01），不占本轮 P0/P1；结论只用于回答"要不要把 DL 推理做成独立扩展"。

### 3.1 三个推理器的定位与代价

| 维度 | HermiT | ELK | Konclude |
| --- | --- | --- | --- |
| 表达力 | OWL 2 DL（含并/补/逆属性/属性链） | OWL 2 EL（交、存在；一般不支持逆/并/补） | OWL 2 DL |
| 完备性 | DL 完备（tableau） | EL 完备，EL 外无结论 | DL 完备，部分场景优于 HermiT |
| 实例规模 | 万级个体、分钟级；ABox 大时内存与时间陡增（`05` §2.2） | 百万级三元组秒级（`05` §2.2） | 强于 HermiT，C++ |
| 单次代价 | 2–4 GB JVM、冷启动 5–20s（`05` §2.6，估算） | 1–2 GB、冷启动 3–10s | 未实测 |
| 许可/部署 | LGPL（经 ROBOT 调用）；独立 JVM | Apache-2.0；独立 JVM | 开源但具体许可**待核实**（`05` §2.2） |
| 我们用它做什么 | **仅 DL 一致性 + 分类** | **EL 物化主选** | 不装配（`23` §1：`E_PROVIDER_NOT_IMPLEMENTED`） |

**结论**：ELK 与 HermiT 是"快 + 准"的分工，不是二选一；不能用 EL 结果冒充 DL 结论（`05` §2.3）。

### 3.2 我们已经有什么（不是从零开始）

### 3.3 缺什么

| 缺口 | 现状 | 后果 |
| --- | --- | --- |
| 独立按需容器 | 与 ELK 共用同一 `reasoner` 容器与镜像；无 `reasoner-hermit` profile | 无法只起 HermiT、无法单独限内存、无法避免 ELK 作业互相挤占 |
| 超时护栏 | adapter 固定 300s + 容器 504；无 per-call 预算、无分级 | 大 ABox 下最长阻塞 5 分钟；发布门禁可能被拖住 |
| 内存护栏 | 仅容器 4g；无 `-Xmx` 分级、无 OOM 归因 | HermiT OOM 与"不一致"难区分，可能误判 |
| 回退策略 | 超时只报 `DeadlineExceeded`；**不自动回退 ELK** | DL 门禁不可用时只能阻断，无"可用性降级"路径 |
| 结果可比对 | 双跑只在测试期一次性跑；`result_summary` 无 `equiv` 字段 | 无法在发布门禁上持续断言"两个推理器结论一致" |
| 规模护栏 | 未按 T-Box 三元组/ABox 个体数分级 | 不知道多大本体不该用 HermiT（60,420 个体属中高负载，**推断**，需实测） |

### 3.4 扩展设计：`reasoner-hermit`

| 项 | 设计 |
| --- | --- |
| 新 profile | `reasoning-dl`，服务名 `reasoner-hermit`；`restart: "no"`；按需 `docker compose --profile reasoning-dl run --rm reasoner-hermit` |
| 镜像 | 复用 reasoner 镜像，入口固定 `robot reason --reasoner HermiT`；不新建算法实现 |
| 资源 | `mem_limit: 3g`、`JAVA_OPTS=-Xmx2g`；与 `reasoner`(4g) 分开，互不挤占 |
| 超时 | 新配置 `reasoning.hermit.timeout_ms`，默认 **120,000ms**（低于现状 300s）；单次调用预算 |
| 回退 | `reasoning.hermit.fallback=elk|none`，默认 `elk`；仅当本体**不含 DL-only 构造**时允许回退，回退置 `degraded=true`、`reasonCode=E_REASONER_FALLBACK_ELK` |
| 失败关闭 | 若本体含 `inverseOf`/`unionOf`/`complementOf`/`propertyChain`，回退一律拒绝，返回 `E_REASONER_DL_REQUIRED`（**fail closed**，不静默降级） |
| 双跑一致性断言 | 发布门禁可选 `--dl-double-run`：同输入分别跑 ELK 与 HermiT，`result_summary.dl_dual={hermit,elk,equiv}`；`equiv=no` 阻断，`partial` 记录不阻断 |
| 结果可比对 | 归一化 `consistent` 布尔 + `unsatisfiable` 集合 + 错误码映射；差异写 `platform.reasoning_job.result_summary`，可导出 |
| 规模护栏 | `reasoning.hermit.max_tbox_triples`（默认 10,000）、`max_abox_individuals`（默认 20,000）；超限直接 `E_REASONER_SCALE_GUARD`，提示改用 ELK 或减小 ABox |
| 工作量 | 8–12h（compose+配置+护栏+单测）；含双跑持久化与门禁断言 12–16h |

**验收判据**（扩展落地时）：
1. 只起 `reasoner-hermit` 时 `/healthz=200`，`engine=hermit` 一致性可跑；ELK 容器不启动也不影响。
2. 超时用例（构造大 ABox）在 120s 返回 `E_REASONER_TIMEOUT`，且当本体为 EL 子集时回退 ELK 成功、`degraded=true`。
3. DL-only 本体（含 `inverseOf`）不触发回退，返回 `E_REASONER_DL_REQUIRED`，门禁拒绝。
4. 双跑 3 组固定用例（一致/不一致/不可满足）`equiv` 全为 `yes`；不一致用例两引擎状态一致。
5. 峰值内存 ≤3 GiB、OOM 与不一致可通过 `reasonCode` 区分。

### 3.5 什么条件下才值得切默认

**全部满足才切默认；否则保持 ELK 默认、HermiT 按需。**

| 条件 | 阈值 | 现状 |
| --- | --- | --- |
| 本体确有 DL-only 构造 | `inverseOf`/`unionOf`/`complementOf`/`propertyChain` 至少 1 处，且影响业务判定 | 未见证据（当前 1.2.1 以 EL 可覆盖为主） |
| EL 侧出现实质漏判 | 发布门禁 ≥1 次"EL 判一致但 DL 不一致"或不可满足类漏报 | 未见证据 |
| 性能可承受 | 目标本体（3,625 T-Box + 60,420 ABox）p95 ≤60s、峰值 ≤3 GiB | **未实测**；60,420 个体对 HermiT 属中高负载（推断） |
| 回退可标记 | 失败可回退且 `degraded`/`reasonCode` 可查 | 当前无自动回退 |
| 双跑有持续记录 | 连续 ≥3 次 `equiv=yes` | 当前仅测试期 2/2 |

## 8 D1「画布多跳」重新评估

### 8.1 它是什么，与现有"一跳邻居"差在哪

**画布多跳** = 在图上做**路径探索**：给定实体 A 与 B，沿关系走 1–3 跳，返回**途经的节点与边**（类/属性/方向），回答"它们为什么有关"。它不等于"把邻居画成一张图"。

| 维度 | 现状（一跳） | 提案（多跳） |
| --- | --- | --- |
| 入口 | `/ui/api/neighbors`、`/ui/api/entity`、`/browse/triples` | `/browse/path?from=&to=&maxHops=3` |
| 深度 | 1 跳 | 1–3 跳 |
| 输出 | 邻居节点/边列表（边上限 200，`truncated`） | 路径序列 `{nodes[], edges[], length}` |
| 回答的问题 | "它连着谁" | "为什么 A 与 B 有关" / "影响经过哪些类" |
| 交互 | 列表浏览 | 表格优先，简单 SVG 辅助 |

**现状证据**：

| 事实 | 证据 |
| --- | --- |
| 实体页只展开 1 跳，邻居边上限 200 并标 `truncated` | `49` §2；`api.py` L3394 `/ui/api/neighbors`、L3401 `/ui/api/entity` |
| `/browse/triples` 只能按主谓宾筛三元组，无深度/路径参数 | `api.py` L2272；`46` L486 |
| 无 `/browse/path` 或等价路径端点 | 代码检索**未见实现**（`api.py` 无 path/maxHops 路由） |
| `33` 的 UI 缺口只提"可答性 tab 缺失"（G6），未提多跳/画布 | `33` L111 |
| `36` 的 Ontology Hub 是"类/属性可视化编辑 + SHACL Studio + 本体对齐 + 健康看板 + 版本 diff"，未提多跳路径 | `36` L122（**未见实现**） |
| 原评估把"力导向画布 + 多跳路径探索"判为架构冲突，理由是"无 path/多跳读接口，先做画布只会得到节点堆叠 + 假交互" | `39` §5 HX-U1、§1.5.6 D1 |

### 8.2 两阶段结论

**D1-1 轻量版（先做，P1）**

| 项 | 内容 |
| --- | --- |
| 是什么 | `GET /browse/path?from=<IRI>&to=<IRI>&maxHops=3`；返回 `paths[]`（节点、边、长度、是否截断）；前端表格 + ≤12 节点简单 SVG |
| 解决什么问题 | 解释两个实体的关系链、血缘/影响链；把"一跳邻居"升级为"可解释路径"，不引入画布 |
| 实现要点 | 有界 BFS 1–3 跳，谓词取 T-Box 白名单；图集合限定 `urn:platform:`；结果上限 20 条；单查询 500ms；优先 BFS 而非无界 property path（避免谓词爆炸，R-07）；`S1` §3.2 已实测 `/`、`+`、`^` 可用 |
| 成本 | **3–5h**（端口 + simple 实现 + 端点 + 单测 + 表格/SVG + 空态） |
| 验收判据 | 3 组固定实体对（合成 ABox）各返回 ≥1 条路径；`maxHops=3` 生效（4 跳对返回空且有原因）；环去重；p95 ≤300ms；0 写操作；越权图 403；无路径返回结构化空态 |
| 做不做 | **做**：成本低、无架构冲突、直接服务"可解释"；列为下一周 P1（若与 P0 冲突可降 P2） |

**D1-2 全画布版（后置待排，本轮不做）**

| 项 | 内容 |
| --- | --- |
| 是什么 | 力导向布局、拖拽、缩放、增量展开、节点详情侧栏、图例与筛选；由 full 实现返回布局/视图所需结构 |
| 解决什么问题 | 空间导航：在大图中"逛"实体与关系 |
| 成本 | **16–24h**（full 实现 + 布局/交互/状态/性能/可访问性），且需前端组件化 |
| 验收判据（排期后） | 单页 ≤300 节点布局 <2s、拖拽 ≥30fps、增量展开不丢状态、空态与截断可辨；与 simple 同一接口切换后调用方零改动 |
| 做不做 | **后置待排**：无真实使用场景；节点上限未知；与 D7"原生 HTML 无构建链"冲突；先做画布会重演"节点堆叠 + 假交互" |

### 8.3 同一接口、两个实现、配置切换

D1 的两个阶段不是两套 API，而是**同一端口 + 两个实现 + 配置切换**，详见 [`53-D1-画布多跳双实现`](53-D1-画布多跳双实现.md)。

| 项 | 内容 |
| --- | --- |
| 端口 | `ports.py` 定义 `CanvasPort`：起点、跳数/展开深度、节点/边上限、类型与来源标注、返回子图/路径 |
| 实现 | `simple`（D1-1，受控跳数与节点上限、单点邻域展开、走现有 Oxigraph 查询路径）与 `full`（D1-2，更广展开 + 布局/视图结构）方法签名一致 |
| 配置 | `canvas.provider ∈ {off, simple, full}`；未实现值 `E_PROVIDER_NOT_IMPLEMENTED`、非法值 `E_PROVIDER_INVALID`（沿用 Q8 分码） |
| 切换 | 只改配置即可在 `simple`/`full` 之间切换，调用方与前端不改；`off` 时接口返回不可用，其余功能不受影响 |
| 现状 | `simple` 随 D1-1 落地；`full` 在 D1-2 前保持"认识但未装配" |

### 8.4 建议

1. **D1-1 列入"下一周可交付"P1**（R-05，3–5h）；若与 O-01/M-02/R-01 冲突，降 P2 但仍在本月内。
2. **D1-2 从"明确不做"改为"后置待排"**，触发条件：出现真实血缘解释需求 **且** 用户明确要求可视化 **且** 单页节点规模上限已确认（三条同时成立）。
3. 轻量版上线后，用真实查询日志判断是否值得排 D1-2：若"路径查询"周请求 ≥50 次且平均路径长度 ≥2.5，再排全画布。
4. **C2 成本/预算护栏不参与**上述任何阶段，维持"暂不做（用户裁决）"。
