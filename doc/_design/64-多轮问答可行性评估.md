## 0 一句话结论

现状 `/answer` 是**完全无状态的单轮链路**：输入只有一段 query，输出是确定性模板 + 四层覆盖度 + 引用 + 可选 PROV 记录；**答案文本不是 LLM 生成的**，因此"多轮"不是加一个聊天壳就能成立，必须补齐**会话状态、追问重写、槽位边界、引用跨轮治理**四件事。技术上可做，档 A 成本可控；档 B 的主要成本不在检索，而在**评测集与一致性治理**。

### 1.3 检索实际怎么走

- `/answer` 的 `strategy` 默认是 **`lexical`**（`api.py` L1861、L1884），不是 hybrid；`_qa_retrieve` 把 `strategy` 原样传给 `context.resolve`（L927）。
- `context.resolve` 默认 `taskType=answer`、`strategy` 由请求带入、`topK` 由 `/answer` 带入、`tokenBudget` **硬编码 512**（L924），不是 `ContextConfig.default_token_budget=2048`。
- 词扩展只在 `context.term_expand=True`（默认 true，`config.py` L211）时生效；扩展串只进 lexical 路（`search.py` L464–481）。
- 检索失败只降级：`context` 异常或 search 异常 → `status=degraded`，不会让 `/answer` 返回 500（`api.py` L958–961）。

### 1.4 引用怎么生成

| citation kind | 生成点 | 指向 |
| --- | --- | --- |
| `ontology-version` | `_qa_answer` L1015–1025 | 当前/指定的 T-Box `versionId` + graph IRI |
| `rdfs-term` / `skos-term` | L1026–1038 | 覆盖度 layers 的 matched 项，带 span |
| `metric-definition` | L1039–1058 | `metricId@definitionVersion` + 公式/窗口/publishable/unit |
| `formula` | L1059–1069 | 公式表达式 |
| `rule-set` | L1070–1080 | `outputMode=rule_set` 的规则数 |
| `fact-projection` / `fact-table` / `fact-table-field` | L1081–1113 | 事实投影函数、表、字段 |
| `fact-observation` | L1114–1135 | 观察集 + `source_ref` |
| `value-source` | L1209–1219 | `metrics.compute` 返回的 `sourceRef` |
| `chunk` | L1136–1137（来自 retrieve） | `doc:{documentId}#{chunkId}`，并生成 `source_ref` |

**关键事实**：citation 没有 `turnId` / `conversationId` 命名空间，也没有跨轮快照；`source_ref_registry` 是全局注册表，只记录"曾经发出过"，不记录"属于哪一轮"。同一 `metricId@version` 的 citation 在不同轮会得到**相同 id**，无法区分来源轮次（`source_ref.py` L269–312）。

### 1.5 拒答怎么判定

- **definition 类**：`coverage.answerable = base.answerable || selected_rows`（L698）。若 T-Box 词面覆盖不足且没有指标候选 → `refused=true`，`reasonCode` 取 `base.reasonCode`（默认 `E_ANSWER_NOT_COVERED`）。
- **value 类**：必须有 selected 指标；`facts_status in (missing, unavailable)` → `E_ANSWER_FACTS_MISSING`；无指标 → `E_ANSWER_METRIC_NOT_FOUND`（L700–707）。
- 另有 `E_ANSWER_RULE_SET_NEEDS_FACTS`、`E_ANSWER_VALUE_DEGRADED`（L1178–1250）。
- 拒答文本固定："证据不足，拒绝作答。缺口：…"，缺口来自 `coverage.missing` 的前 4 条（L1253–1257）。
- 拒答一定写 PROV refusal（L1375–1383）；但**没有"澄清"概念**——只要没覆盖/没指标就是拒答，不会反问用户"你指的是哪个指标/哪个实体"。

### 1.6 现状能力边界（与多轮直接相关）

| 事实 | 证据 | 对多轮的含义 |
| --- | --- | --- |
| 无任何会话/轮次/历史代码 | `platform/src/platform_core` 检索未见 `conversation` / `session` / `turn` 业务实现；只有无关的 PROV `decision_history` | 会话状态必须新增 |
| 答案文本不是 LLM 生成 | `api.py` L1252–1289 全为模板；LLM 仅用于抽取（`extraction.py` L301 `_llm_batch`） | 重写若要上 LLM，是本项目**首次把 LLM 放进问答主链路**，需额外护栏 |
| 每次请求自包含 | `_qa_answer` 的入参只有 query/metricId/version/topK/strategy/requestId（L966–974） | 指代（"它的口径呢"）必然覆盖不足或误配 |
| 术语匹配有两条路径 | 可答性用 `_qa_graph_entries`（`api.py` L229–263）；上下文扩展用 `TermLexicon`（`termlex.py` L155） | 重写后的 query 必须同时喂给两条路径，否则会出现"可答但检索不到"或反之 |
| 版本可选但不固定 | `_qa_answerable` / `context.resolve` 都支持传入 `ontologyVersion`（L601、L150），但默认取当前版本 | 跨轮必须把版本钉住，否则第 2 轮可能换版本 |
| 引用 id 全局可重复 | `source_ref.register_ref`（L269）无轮次字段 | 跨轮引用需要轮次命名空间或快照 |

### 2.2 追问重写到哪一步插入（新增）

| 项 | 设计 | 落点 |
| --- | --- | --- |
| 插入位置 | **在调用 `_qa_answer` 之前**：新入口 `POST /conversation/{id}/ask` 先做 `rewrite(raw_query, slots, last_turn)`，得到 `resolved_query` 与 `resolved_slots`，再原样调用现有 `_qa_answer`。`_qa_answerable` 与 `_qa_retrieve` **不改语义**，仍只接收一段完整 query | `api.py` 新增 wrapper；`_qa_answer` L966 保持不变 |

| 可观测 | 响应同时返回 `rawQuery`、`resolvedQuery`、`rewriteMethod`、`slotsUsed`、`rewriteConfidence`；PROV 记录重写 activity | `api.py` 响应；`prov.py` 扩展 |

### 2.3 槽位继承边界（新增 + 改造）

| 槽位 | 默认是否继承 | 边界 |
| --- | --- | --- |
| `metricId` / selected metric | **是**，仅当本轮没有任何 ≥0.85 的新指标候选，且 query 无新指标名 | 新指标名命中 → 以新指标为准，不继承；两个指标冲突 → 澄清，不猜 |
| `ontologyVersion` | **是**，会话级钉住 | 本轮显式传新版本才允许切换；否则一律用会话版本，避免第 N 轮换库 |
| `intent`（value/definition） | **是**，仅当本轮无新的数值/定义信号 | 本轮出现相反信号 → 重算，不继承 |
| 实体 / `entityHints` | **是**，仅当 query 含指代且上一轮答案有唯一实体 | 上一轮有多个实体或本轮出现新实体 → 澄清 |
| 时间窗口 / topK / strategy | 可继承 topK/strategy；时间窗口**默认不继承** | 时间窗口若由"今年/上月"等相对词产生，必须按本轮锚定日期重算，不能复制旧窗口 |
| 上一轮拒答状态 | **不继承为"可答"** | 上一轮拒答，下一轮仍独立走覆盖度；不能因为"上一轮拒了"就直接拒，也不能因为"上一轮答了"就直接答 |

**改造点**：`_qa_answer` 的 `metric_id` 与 `ontology_version` 入参（L966–974）保持；新增 wrapper 负责把继承结果映射成这两个参数。`_qa_intent`（L215）与 `_qa_metric_candidates`（L273）**不改**，只作为"本轮是否出现新槽位"的判定器复用。

### 2.4 引用如何跨轮失效（改造）

| 引用类型 | 失效条件 | 防法 |
| --- | --- | --- |
| `chunk`（`src://doc/...`） | 文档被删除 / 重建 / chunk 序号变化 | 每轮复用前调 `source_ref.resolve`（L509）；`rowCount=0` 时按 `E_SOURCE_REF_STALE` 标 stale，不静默沿用 |
| `metric-definition` / `formula` / `rule-set` | `metric_definition.definition_version` 已变（当前无独立 supersede 状态列，**推断**以版本号比较为准） | citation 里带 `definitionVersion`；跨轮复用时与当前值比对，不一致标 `superseded`，旧轮答案保留但标明"口径已更新" |
| `ontology-version` / `rdfs-term` / `skos-term` | 会话钉住版本之外的新版本发布 | 会话钉版本；跨版本时旧引用标 `pinnedTo=<version>`，不冒充当前版本 |
| `fact-observation` / `value-source`（`src://obs-set/...`） | 观察值被重算、窗口漂移、实体键变化 | 复用时 `source_ref.resolve`；`E_SOURCE_REF_STALE` 不静默；数值回答重算而不是沿用旧值 |
| citation ID 冲突 | 同 id 跨轮重复 | 响应增加 `turnId`，citation 增加 `turnId`；会话级 citation ledger 记录 `citationId -> turnId`，前端可按轮展开 |

**落点**：`_qa_answer` 的 citation 装配（L1006–1137）增加 `turnId` 字段；新 `citation_ledger` 逻辑放 `conversation.py`；`source_ref.resolve` 不改（已有 stale/not-found 语义，L509–557）。**不改 `source_ref` 的 canonical form**，只在响应层加轮次。

### 2.5 澄清与拒答如何协同（改造）

| 概念 | 触发 | 响应 | 不能做什么 |
| --- | --- | --- | --- |
| 拒答（refusal） | 证据缺口：T-Box 未覆盖 / 指标不存在 / 事实缺失 | 现有 `refused=true` + `reasonCode` + `missing` 层；PROV refusal | 不能用澄清替代拒答，掩盖"没有证据" |
| 澄清（clarify） | **问题缺口**：指代不唯一、槽位冲突、指标候选多个且分数接近、实体多个 | 新 `answerMode=clarify` + `clarify.slots[]` + `reasonCode=E_ANSWER_CLARIFY_REFERENT/SLOT`；不写 refusal PROV，写 clarify activity | 不能把"候选指标"当成已选中指标去作答 |
| 协同 | 先判 clarify，再判 refusal；clarify 不通过则不进入 `_qa_answer` 的模板作答 | wrapper 顺序：rewrite → clarify check → `_qa_answer` | 不能先拒答再让用户重问；澄清要能带候选和"继续"入口 |

**改造点**：
- `_qa_answer` 的 `refused` / `reasonCode` 链（L1148、L1247–1250）保持，新增 clarify 分支在外层 wrapper。
- `/answer/quality` 的拒答统计（L5065、L5138–5144）需要把 clarify 单独计数，否则"澄清"会被误算成拒答。
- `answerMode` 枚举从 `value|definition|none`（L891、L1356）扩展为加 `clarify`。

## 4 风险清单

> 每条都写"用户看到什么"和"怎么防"。风险按档 A 必现/档 B 才出现标注。

### R-01 错误继承导致答非所问（档 A 必现）

- **出错长什么样**：第 1 轮问"13 个月继续率是多少"，第 2 轮问"退保率呢"。系统把上一轮的 `metricId=13个月继续率` 拼进重写结果，实际回答成"13 个月继续率的口径/数值"；用户看到答案里全是继续率，没有退保率，只能认为系统"听不懂人话"。
- **怎么防**：
  - 继承前做**本轮复审**：重新跑 `_qa_metric_candidates`（`api.py` L273），只要本轮出现得分 ≥0.85 的新指标，就丢弃旧 `metricId`。
  - 重写结果里若出现与继承槽位不同的指标名，一律以本轮原文为准；两者冲突时不猜，转澄清。
  - 响应返回 `slotsUsed`（含 `metricId` 及来源轮次），前端可展开；PROV 记录 `inheritedFromTurn`。
  - golden 必须覆盖"同域换指标"（§5.2），并把 WIR-answer 作为发布门槛。
- **兜底**：档 A 不做话题切换检测，但"新指标名优先"这条规则必须硬编码，不能依赖模型判断。

### R-02 隐式上下文误用（档 A 必现，档 B 收敛）

- **出错长什么样**：第 1 轮问"产品包包含哪些产品"，答案列出 5 个产品；第 2 轮问"它的保障期呢"。系统把"产品包"当成上一轮唯一实体，回答"产品包的保障期"；用户实际问的是刚才列表里的某个产品。用户看到的是"答了一个我没问的东西"。
- **怎么防**：
  - 实体继承**仅当上一轮答案只有 1 个候选实体**时才允许；≥2 个候选一律澄清，不选"最可能的那个"。
  - 实体槽位必须记录来源 `turnNo` 与来源字段（答案实体/检索命中/用户显式），跨轮继承深度默认 1 跳；超过 TTL 或轮次上限清空。
  - 本轮出现新实体词（图标签/别名命中）时，旧实体不继承。
  - golden 增加"多实体上一轮 + 指代下一轮"负例，期望输出澄清而不是作答。

### R-03 引用张冠李戴（档 A 部分、档 B 必现）

- **出错长什么样**：第 1 轮引用 `13个月继续率@v7`；口径发布 v8 后，第 2 轮问"这个指标的公式"，界面仍把 v7 的 citation 当作"当前口径"，点开指标卡却是 v8；或者文档重建后 chunk 序号变化，旧 citation 指向了另一段文字。用户看到"引用和答案对不上"。
- **怎么防**：
  - citation 增加 `turnId` 与 `definitionVersion`，会话级 `citation_ledger` 记录 `citationId -> turnId -> targetVersion`。
  - 跨轮复用前必须 `source_ref.resolve`（`source_ref.py` L509）；`E_SOURCE_REF_STALE` / `E_SOURCE_REF_NOT_FOUND` 一律标 stale，不静默沿用。
  - 指标引用与当前 `metric_definition.definition_version` 比对；不一致标 `superseded`，旧轮答案保留但明确"口径已更新"（**推断**：当前无独立 supersede 状态列，只能比版本号）。
  - 前端按轮展示 citation，stale/superseded 用不同徽标；禁止把旧 citation 文本复制到新轮。
  - golden 检查"复用 citation 的可解析率"与"版本一致性"，不只看当轮断链率。

### R-04 重写引入幻觉（档 A 若上 LLM 必现；档 A 规则版可规避）

- **出错长什么样**：用户只说"那它呢"，LLM 重写成"客户 AUM 的口径"——会话里从未出现 AUM，系统却给出一个用户没问过的指标；或用户说"不含退保的继续率"，重写丢掉否定，答成"含退保"，数值直接反向。用户看到"答案很自信，但问的不是这个"。
- **怎么防**：
  - **档 A 只做规则重写，不把 LLM 引入问答主链路**（成本前提见 §6）。
  - 若未来上 LLM：重写输出必须过四道闸——① 指标/实体必须在会话槽位或本轮原文出现；② 否定词、限定词、时间词不得增删（做 token diff）；③ 输出必须是严格 JSON，字段缺失即失败；④ 置信度低于阈值回退原始 query，**失败关闭**而不是"猜一个"。
  - 响应同时返回 `rawQuery` 与 `resolvedQuery`，PROV 记录重写 activity 及 `derivedFrom`；golden 专设"否定继承"与"会话外实体"负例。

### R-05 评测集不足导致"看起来能用"（档 A 最大隐性风险）

- **出错长什么样**：20 例 golden 全是同话题、单指代、无否定，通过率 95%，评审结论"多轮可做"；真实使用中话题切换和多候选占三成，错误继承率 20%，上线后用户频繁遇到答非所问。报表好看，体验不可用。
- **怎么防**：
  - 按 §5.2 的**配比**构造：指代类型、话题切换比例、拒答轮占比都要有下限，不允许"全选容易的例子"。
  - 报表分类型给指标（同话题/切换、单指代/多候选、肯定/否定），不只给总分；WIR-answer 单独列。
  - 用 **turn-depth accuracy**（第 2/3/4/5 轮分别正确率）证明"第 3 轮还对不对"，而不是只测末轮。
  - 验收阈值固定并纳入回归；每次 T-Box/指标口径变更后重跑，防止"一次通过、长期漂移"。

### R-06 术语双路径不一致（档 A 必现）

- **出错长什么样**：重写后 query 是"继续率"，可答性用图标签判定 `covered`，但 `TermLexicon` 没命中、检索 0 chunk，系统返回"可答"却只有一句没有引用的定义；或者 value 模式 facts 缺失，用户看到"可答但答不出"。
- **怎么防**：
  - 同一个 `resolvedQuery` 必须同时喂给 `_qa_answerable`（图标签路径，`api.py` L229）和 `context.resolve`（`TermLexicon` 路径，`termlex.py` L155），禁止两套重写。
  - 增加一致性断言：可答性 `covered` 但检索 0 chunk/0 fact 时，value 问题一律按 `E_ANSWER_FACTS_MISSING` 拒答并标 `degraded`，不输出"半截答案"。
  - golden 覆盖别名（18 个别名至少各 1 次）与缩写；质量报表加"可答-检索不一致率"。

### R-07 澄清与拒答混淆（档 B 引入澄清后必现）

- **出错长什么样**：用户问"量子计算机的制冷功率"（系统根本没有这个指标），系统返回"你指的是哪个指标？"而不是拒答；用户以为系统有数据，反复追问。反过来，真有歧义时系统直接拒答"证据不足"，用户不知道只需说清是哪个指标就能答。
- **怎么防**：
  - 澄清只允许在"有候选/指代不唯一/槽位冲突"时触发；**没有任何候选一律拒答**，不得用澄清掩盖证据缺口。
  - `answerMode=clarify` 与 `refused=true` 互斥；`reasonCode` 分开（`E_ANSWER_CLARIFY_*` vs `E_ANSWER_*`）；quality 端点分别计数，澄清不能计入"可答"。
  - golden 设"必须拒答且不得澄清"的负例；澄清候选必须来自真实图/指标候选，不能由 LLM 编造。

### R-08 时间窗口/版本漂移（档 A 必现）

- **出错长什么样**：第 1 轮问"2025 年继续率"，第 2 轮问"今年退保率"，系统把 2025 窗口一起继承，答成"2025 年退保率"；或第 1 轮钉住 T-Box v7，第 2 轮系统悄悄切到 v8，两轮引用不同版本。
- **怎么防**：
  - 时间窗口**默认不继承**；相对时间词（今年/上月/本季度）必须按本轮锚定日期重算。
  - `ontologyVersion` 会话级钉住，只有本轮显式传新版本才允许切换；切换时在响应标 `versionPinned=false` 并提示。
  - golden 覆盖"相对时间第 1 轮 + 相对时间第 2 轮"，期望两次窗口不同；覆盖版本切换负例。

## 5 评测方案

### 5.1 原则

- **评测单位是"会话"，不是单条 query**：只测单轮会把继承问题全部漏掉。
- **必须有第 3 轮及以后的目标轮**：否则无法回答"第 3 轮还对不对"。
- **分层报告**：总分 + 分类型 + 轮次深度曲线；不用单一通过率下结论。
- **可回放**：每组会话固定 `ontologyVersion` 与事实快照，避免 T-Box/口径更新导致跑分漂移。

### 5.2 多轮 golden 构造规则

| 维度 | 档 A | 档 B | 说明 |
| --- | --- | --- | --- |
| 会话数 | 20 组 | 40–60 组 | 一组 = 一个 conversation，不是一条 query |
| 每组轮次 | 3–5 轮 | 3–6 轮 | 每组至少 1 个 **turn ≥ 3** 的目标轮 |
| 总轮数 | 60–100 轮 | 150–300 轮 | 目标轮只算末轮/第 3 轮以上 |
| 话题切换 | 0（能力外，单独标记、不计入 A 验收） | **25–30% 会话含 1 次切换** | B 的切换类型：同域换指标 50%、跨域换实体 30%、意图翻转 20% |
| 拒答轮占比 | **20% 轮次期望拒答** | 同左 | 无指标/实体不存在/事实缺失各约 1/3；其中一半放在第 2 轮以后，验证"拒答不被继承" |
| 显式指代（它/该指标/这个数） | 40% | 40% | 继承的主路径 |
| 省略/替换（"那退保率呢"） | 25% | 25% | 必须能改写为新指标，不能继承旧指标 |
| 零指代/完整重问 | 15% | 15% | 防止"什么都能继承"的过度设计 |
| 多候选歧义 | 10% | 10% | A 期望按最高分或拒答；B 期望澄清 |
| 否定/限定继承 | 10% | 10% | 如"不含退保的继续率"，重写不得丢否定 |

- **标注字段（每轮）**：`expectedAnswerMode`、`expectedMetricId`、`expectedEntity`、`expectedOntologyVersion`、`expectedRefusalReason`、`expectedCitationKinds`、`expectedClarify`、`requiredInheritedSlots`（本题必须继承的槽位及期望值）。
- **数据来源**：现有 85 个 SKOS 概念 / 18 个别名、`/answerable/panel` 的 24 条查询集、`/answer/quality` 的 10 例 golden，以及现有指标定义与事实；不新造业务口径。事实缺失类负例可在测试库造合成观察值（**推断**：测试库可写，生产库不改）。
- **冻结**：golden 固定 `ontologyVersion` + 指标 `definitionVersion`；每次发布前重跑，版本升级时保留旧快照做对照。

### 5.3 三个核心指标的可计算定义

设一组会话有 `T` 轮，目标轮集合 `G`（末轮 + 所有 `turn ≥ 3` 的轮次）。

**1）末轮正确率（Final-Turn Accuracy, FTA）**

```
FTA = 通过严格校验的目标轮数 / |G|
```

严格校验 = 以下全部成立：
- `answerMode` 与期望一致（value / definition / refusal / clarify）；
- 若为 value/definition，`selectedMetric.metricId == expectedMetricId`；
- 若期望拒答，`reasonCode` 家族与 `missing` 层一致（如 `E_ANSWER_NOT_COVERED` 对应 ontology/terms 缺口）；
- 期望的 citation kind 都存在，且 `source_ref` 可解析（复用现有 `/answer/quality` 的可解析率口径）。

同时报告 **turn-depth accuracy**：按 turn=2/3/4/5 分组算 FTA，用来证明"第 3 轮还对不对"。

**2）跨轮一致性（Cross-Turn Consistency, CTC）**

```
CTC = 一致的状态迁移数 / 总迁移数（turn i → i+1）
```

一次迁移"一致"需同时满足：
- 未显式切换话题时，`metricId`、`ontologyVersion`、主要实体不得无提示变化；
- 显式切换时，响应带 `topicSwitch=true` 且槽位重置符合期望；
- 复用的 citation 必须仍可解析且指向同一目标（同 `metricId@version` / 同 `documentId#chunkId`）；
- 不得出现"上一轮拒答、下一轮无新证据却给出数值"的矛盾。

**3）错误继承率（Wrong Inheritance Rate, WIR）**

分两个口径，分母必须写清楚，避免被总轮数稀释：

```
WIR-slot   = 继承槽位与 golden.requiredInheritedSlots 不一致的轮数 / 实际发生继承的轮数
WIR-answer = 因错误继承导致最终答案错误的轮数 / 实际发生继承的轮数
```

- "实际发生继承"由响应 `slotsUsed` / `inheritedSlots` 判定，不是由 golden 推测；
- `WIR-slot` 测机制，`WIR-answer` 测后果；发布门槛看后者；
- 若某轮没有发生继承（如完整重问），不计入分母。

### 5.4 怎么用现有 `/answer/quality` 机制测出来

**现状可复用的部分**：`/answer/quality` 已经是"逐例调用 + 结构化比对"的闭环——它遍历 `_G4_GOLDEN_SET`（`api.py` L4562），逐例调用 `_qa_answer`，比对拒答状态、citation kind、citation 可解析/断链（L5020–5215），并输出 summary（L5189–5203）。这套"回放 + 断言 + 汇总"的骨架可以直接复用。

**不能直接复用的部分**：`/answer/quality` 是**无状态单轮**，它不知道上一轮槽位，因此**测不出 WIR**；它也不会调用重写与会话存取。

**扩展点（只设计，不实现）**：
1. 在 `_G4_GOLDEN_SET`（L4562）旁新增 `_MULTITURN_GOLDEN_SET`，结构为"会话 → 轮次 → §5.2 标注字段"。
2. 新增 `_g4_multiturn_quality_data(limit=...)`：按会话顺序调用 `POST /conversation/{id}/ask`（内部 rewrite + `_qa_answer`），逐轮拿 `rawQuery/resolvedQuery/slotsUsed/inheritedSlots/answerMode/citations/refused`。
3. 复用 `_g4_citation_view`（L5020 附近）做逐轮 citation 可解析/断链检查；复用现有 summary 结构，新增 `fta`、`turnDepthAccuracy`、`ctc`、`wirSlot`、`wirAnswer`、`clarifyPrecision`、`refusalReasonAccuracy`。
4. 新增路由 `GET /answer/multi-turn/quality`（与 `/answer/quality` 同构，参数 `limit` / `conversationId`），返回 per-conversation/per-turn 明细 + summary；**不实现，只登记扩展点**。
5. 另加一个"单轮回放"开关：把每轮 `resolvedQuery` 单独喂给现有 `_qa_answer`，用于区分"重写错"还是"单轮链路错"；这正是现有 `/answer/quality` 已经能做的方式，可直接复用。

**"第 3 轮还对不对"的证明方式**：
- 每组会话至少 1 个 `turn ≥ 3` 的目标轮，且该轮必须依赖 turn1 的槽位（`requiredInheritedSlots` 非空）；
- 报表给 `turn=2/3/4/5` 的 FTA 曲线；档 A 要求第 3 轮 FTA 不明显低于第 2 轮（例如差距 ≤10 个百分点，**推断**阈值待首批跑完校准）；
- 对失败样例保留 `rawQuery → resolvedQuery → slotsUsed → answer` 全链路快照，可人工归因。

## 6 结论

**建议做档 A，30–45 AI 小时；档 B 暂缓，档 C 不做。**

理由：现状 `/answer` 的确定性链路、四层覆盖度、引用与拒答码都可直接复用，档 A 只需要在**外层**加会话与重写，不动单轮语义；真正的难点是"错误继承"和"跨轮引用"，前者档 A 用"新指标优先 + 单实体才继承"的硬规则可以压住，后者档 A 只做轮次命名空间、把一致性留给档 B。档 A 的 30–45h 里约 40% 花在 golden 与边界测试，这个比例是必要的，否则会落入 R-05。

**成本前提（必须单独确认，不能藏在风险清单里）**：

> C2 预算护栏（token/请求配额、超限降级）已被用户撤回，当前系统**没有任何配额兜底**。因此档 A 的设计**只做规则化重写，不把 LLM 引入问答主链路**。如果将来要上 LLM 重写，必须**先补配额或限流**（每会话 token/请求上限、超限降级为规则重写或直接拒答），否则成本与延迟都不可控；在配额补齐之前，LLM 重写不进入排期。

**档 A 的出口条件（做到什么程度算完成）**：
- 20 组多轮 golden（每组 3–5 轮、含第 3 轮目标、20% 拒答轮）跑通；
- 目标轮 FTA ≥80%，WIR-answer ≤10%，CTC ≥95%；
- 现有 `/answer/quality` 10 例与 `/answerable/panel` 24 条无回归；
- 响应稳定返回 `turnId/rawQuery/resolvedQuery/slotsUsed`，可回放。

**档 B 的启动条件**：档 A 实测 WIR-answer >5% 或话题切换失败率 >20%，且业务确认需要澄清追问与跨轮引用一致性；否则不启动。档 B 的成本重心在 golden 与一致性治理（§3.3），不是检索。

**档 C**：开放闲聊不做，原因见 §3.4；若未来要做，也必须先完成档 B 的澄清与引用一致性，再讨论生成式回答。
