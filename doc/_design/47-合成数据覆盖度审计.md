# 47 · 合成数据覆盖度审计

> 审计对象：`platform` schema 下 28 张事实表，`data_source='synthetic'`，seed=42，scale=1。
> 审计快照：T-Box 版本 `ont-3f57d8ce6636`；总行数 **161,549**（补齐前 161,499，+50）。
> 结论先说：**指标绑定层 0 缺口**（95 列全部有非空数据）；**本体层大量逻辑类无物理实例**（属正常，T-Box 比事实层宽）；**仅 2 类边界 case 不可造**（负值、失联客户，受 schema 约束）。

---

## 1. 审计方法与口径

| 维度 | 方法 | 边界 |
| --- | --- | --- |
| 本体 | 从 T-Box（ont-3f57d8ce6636）导出 turtle，统计 `owl:Class` / `owl:*Property`；类按“词元交集”匹配到事实表或同名列，统计行数/去重值 | 启发式映射；一个逻辑类可能对应多张表，取命中最具体者 |
| 绑定 | 逐行读取 `platform.metric_field_binding`（95 行 / 53 指标），解析 `entity_column/value_expr/window_column` 中的列标识，逐列统计 `count(*)`、`count(non-null)` | 只核“是否有一行非空数据”，不核业务正确性 |
| 口径 | 读取 85 行 `metric_definition`，对“结构性可执行”（非规则集且有公式或 fact_function）逐条调用 `MetricCompiler` / `RuleExecutor`，按 publishable/窗口/分母/无数据分类 | 只证明“能跑或有明确错误码”，不证明口径业务含义 |
| Case | 用命名 SQL 统计空值、0、负值、超大值、跨期、重复、状态流转、退款、DPD 30/60/90、失联 | 负值/失联受表结构约束，见 §6 |

复跑命令：

```bash
platform datagen --schema platform --audit
```

输出为 JSON（`ontology` / `bindings` / `metrics` / `cases` / `rowCounts`），本文所有数字取自该输出。

## 2. 本体覆盖审计

> 口径差异说明：需求描述为 159 类 / 139 属性；从 `ont-3f57d8ce6636` 实际导出并解析得到 **156 类 / 129 属性**（差 3 类 / 10 属性，可能来自未导出的别名或导入时合并的三元组）。本文以可导出、可复核的 156/129 为准。

### 2.1 类（Classes）

| 指标 | 数量 |
| --- | ---: |
| T-Box 类总数 | **156** |
| 有专用事实表且行数 > 0 | **12** |
| 无专用表、但同名列有非空取值（如 region/industry 等） | **2** |
| 无任何实例 | **142** |

结论：**142 类没有实例数据**。其中大部分是 FSLDM 逻辑模型的细分类型（例如 `IndividualInsurancePolicy`、`BaselApproach`、`CollateralHaircut`、`CampaignResponse`），不在本轮 28 张事实表建模范围内；它们不影响 30 条结构性指标，但意味着“全本体 156 类全覆盖”**不成立**，不应对外宣称。

完整未覆盖类清单见附录 A（按命名空间分组）。

### 2.2 属性（Properties）

| 指标 | 数量 |
| --- | ---: |
| T-Box 属性总数 | **129** |
| 能匹配到事实表列且有非空数据 | **8** |
| 能匹配到列但全为 NULL | **0** |
| 无对应列/无取值 | **121** |

可匹配并有值的主要是：`assetId`、`dueDate`、`eventId`、`eventType`、`firstPaymentDate`、`lastPaymentDate`、`maturityDate` 等 7–8 个标识/日期属性。其余 121 个属性（如 `accountFeature`、`collateralHaircut`、`quotationAmount`）在事实层没有物理列，属**不可造**（见 §6）。

完整未覆盖属性清单见附录 B。

## 6. 仍不可造项（明确不硬造）

| 项 | 原因 | 影响 |
| --- | --- | --- |
| 负值样本 | 事实表数值列带 `CHECK >= 0`（如 `cust_transaction.amount`），负值会被数据库拒绝；改约束会污染 schema | 无法验证“负数被拒/负数口径”以外的负值路径 |
| 失联客户 | `cust_master` 无手机号/邮箱/联系方式列，无法表达“失联”状态 | 依赖联系方式的指标只能走拒答/空数据路径 |
| 121 个本体属性 | 事实层无对应物理列（抵押品、Basel 方法、投资组合明细等） | 依赖这些属性的口径在本数据集上不可算 |
| 142 个本体类 | 无对应事实表/枚举列（逻辑模型细分类型） | 不属于本轮 28 表范围 |

以上均属于**结构性不可造**，不是生成器缺陷；需先扩表结构或接入外部数据才能造。

---

## 7. 审计结论

1. **可以放心用的部分**：95 条指标绑定、28 张事实表规模、四项自洽校验、30 条结构指标的出数/拒答/异常路径。
2. **不能宣称的部分**：不能说“T-Box 156 类全覆盖”“129 属性全覆盖”；实际为 14 类有实例、8 个属性有值。
3. **补齐后仍缺的部分**：负值、失联客户、121 属性、142 类，已在上表逐项说明原因。
4. 合成数据仍**不得用于对外报送或业务结论**；本审计只证明“覆盖到哪里、哪里没有”。
