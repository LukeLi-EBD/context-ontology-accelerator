## 0. 结论（先看这 8 条）

1. 术语层是**既有 `owl:Class` 上的 SKOS 注解层**，不建第二个类体系、不建独立 term 图；类同时是 `skos:Concept`（OWL 2 punning）由 `skos:prefLabel` 的 domain 推导，不额外声明。

> 现有 26 个模块里 **146 条 `skos:altLabel` 全部是无语言标签的大写 ASCII 机器码**（`ACCOUNT`、`PARTY`…）。本批**冻结不碰**，SHACL 只校验带 `@zh/@en` 的 altLabel，避免旧数据被新门禁误伤（05 §2.7）；缺口登记与自动检测见 §7-3。

### 1.3 与现有 OWL 类的关系：注解，不是第二套体系

- 类**不重新定义**：`a owl:Class` 声明仍只在 `fsldm-merged.ttl`；候选文件里只加 `skos:prefLabel` / `skos:altLabel` / `term:termBatch` 三类三元组。
- 不为类建 `skos:ConceptScheme` 包装：`codes.ttl` 的 ConceptScheme 只服务**取值词表**（`code:*`），类术语不混进去；这样"类改名但词条没改"由 SHACL 直接发现。
- `skos:Concept` 类型**不显式写**：`skos:prefLabel` 的 `rdfs:domain` 是 `skos:Concept`，一致性门禁可推出 punning 类型；显式写会与既有 `owl:Class` 声明产生重复三元组，增加 diff 噪声。
- 类之外不新增任何 `owl:Class`：候选文件里只有 `term:TermEntry` / `term:EvidenceType` / `term:ConfidenceLevel` 三个**词表元数据类**，它们不进入领域类空间（无 `rdfs:subClassOf` 关联到 `fsldm:Party` 等）。

### 1.4 为什么不用 `skos:broader` / `skos:closeMatch`

| 谓词 | 处置 | 理由 |
|---|---|---|
| `skos:broader` / `skos:narrower` | **类层禁用** | 156 类的上下位已由 `rdfs:subClassOf` 表达；再用 SKOS 层级 = 两套可能冲突的层次。SKOS 层级只保留在 `codes.ttl` 的 ConceptScheme 内（现状不变） |
| `skos:closeMatch` / `exactMatch` | 本批为空 | 本批无跨词表映射需求；将来接 FIBO/监管词表时只在 `term:` 层加映射，不改类 |
| 上位 / 角色 / 分类词（客户、集团客户、关联客户、险种、押品、担保合同…） | 保持 C 档 | 语义是 broader/narrowed，不是同义；改写成 `skos:broader` 会把检索扩到过宽的类。这些词留给"检索扩展词表（非本体）"，见 05 附录 A |

### 1.5 与 `rdfs:label` 的关系：共存且强制相等

- `rdfs:label@zh` 继续是展示与既有查询的兼容字段，本轮**一个字不改**。
- `skos:prefLabel@zh` 与之**强制相等**（SHACL-SPARQL，§3.2），防止"类名改了、术语层忘了改"。
- 检索侧**不删旧谓词**：词表构建时把 `rdfs:label@zh/@en`、`skos:prefLabel@zh/@en`、带标签的 `skos:altLabel@zh/@en` 全部收进内存词典，旧路径继续可用。

## 2. 18 条别名的 confidence 与 provenance

> 口径澄清：任务描述写"18 条 B 档"，实际上游是 **A 6 + B 12 = 18**。confidence 只属于 B 档 12 条；A 档 6 条用 `term:source` 原文定位，本身即最高证据强度，不写 confidence（写了会被 SHACL 判违规）。

### 2.1 两种记法对比

| 方案 | 写法 | 优点 | 代价 |
|---|---|---|---|
| **A. `prov:wasGeneratedBy`（本方案）** | `TermEntry prov:wasGeneratedBy <Activity>`；Activity 挂 `prov:used <model>`、`prov:wasAssociatedWith <runner>`、`term:reviewProtocol`、`term:reviewRecord` | 结构化、可 SPARQL 聚合（按模型/批次/协议统计）；与 05 的"判定留痕"要求同构；外部审计可沿活动节点回溯 | 每批多 1 个 Activity 节点（本批 4 个）；`prov:` 三元组要随 T-Box 一起导出/快照，否则活动节点成孤儿；**评审记录未给逐批时间戳**，不能写 `prov:startedAtTime`（只能给 `dct:source` 指向记录小节） |
| B. 注释三元组 | `term:confidence "high"` + `term:llmBatch "Round1/Batch2 -> Round2/Batch2 keep"` + `rdfs:comment` | 写入最轻，1 条字符串；人工读文档即可看懂 | 不可机读聚合（统计"哪些词来自 medium"只能字符串匹配）；无法关联模型/协议/记录位置；无标准语义，审计要靠人读 markdown |
| C. 两者都写 | A + B | 机器可读 + 人可读 | 双份真相，两处不一致时无门禁；05 已要求"单一账本"，不做 |

### 2.2 选定方案与字段

**选 A**。理由：术语别名是"机器推断产生的事实"，必须能回答"谁、用什么模型、按什么协议、在哪条记录里判定的"；B 方案回答不了。

| 档位 | 字段组合 |
|---|---|
| A 档（6 条） | `term:status term:evidenced` + `term:evidenceType`（`CorpusChunk` / `OntologyComment` / `OntologySource` 可多值）+ `term:source`（必填）+ `term:docRef`（`05#A-01`…） |
| B 档（12 条） | `term:status term:inferred` + `term:confidence`（`term:high` 9 条 / `term:medium` 3 条）+ `prov:wasGeneratedBy`（`term:review-batch1/2/3/5`）+ `term:docRef`（`05#B-01`…） |

`term:docRef` 每条必填，取值精确对应 05 §4.3 两张表的行号，形如 `05#A-01`；`dct:source` 再给出行号（如 `05-术语层-设计与分析.md#L340`），二者构成"条目号 → 文档行 → 表格行"三段可追溯。

### 2.3 撤销语义（不需要新机制）

- 撤销某条别名 = 删 `TermEntry` + 删类上的 `skos:altLabel`；门禁的"集合相等"形状会立刻报违规 → 强制两边一起改。
- 整批回滚 = 按 `term:termBatch` 或 `term:status` 筛出全部三元组移除；B 档无需逐条判断，`term:status term:inferred` 即回滚边界。
- Activity 节点保留（审计需要），孤儿 Activity 不参与检索、不影响一致性。

### 3.2 关键形状（三条必守，可直接落成 `terms.ttl`）

```turtle
@prefix sh:   <http://www.w3.org/ns/shacl#> .
@prefix skos: <http://www.w3.org/2004/02/skos/core#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix term: <https://w3id.org/fsldm/terms#> .

# 1) prefLabel 必填（zh/en 各 1）且 @zh 与 rdfs:label@zh 相等
term:PrefLabelShape a sh:NodeShape ;
    sh:targetSubjectsOf term:termBatch ;
    sh:property [
        sh:path skos:prefLabel ;
        sh:minCount 2 ;
        sh:maxCount 2 ;
        sh:message "每个 batch-1 类必须有且仅有 zh、en 两个 skos:prefLabel"@zh ;
    ] ;
    sh:sparql [
        sh:message "skos:prefLabel@zh 必须与 rdfs:label@zh 完全相等"@zh ;
        sh:select """
            SELECT $this ?value WHERE {
              $this <http://www.w3.org/2000/01/rdf-schema#label> ?l .
              $this <http://www.w3.org/2004/02/skos/core#prefLabel> ?p .
              FILTER(lang(?l) = "zh" && lang(?p) = "zh" && STR(?l) != STR(?p))
              BIND(STR(?l) AS ?value)
            }
        """ ;
    ] .

# 2) 别名唯一性：同语言不得两处使用；不得撞任何类的 prefLabel
term:AltLabelUniqueShape a sh:NodeShape ;
    sh:targetSubjectsOf term:termBatch ;
    sh:sparql [
        sh:message "skos:altLabel 在同语言下必须全局唯一，且不得等于任何类的 prefLabel"@zh ;
        sh:select """
            SELECT $this ?value WHERE {
              $this <http://www.w3.org/2004/02/skos/core#altLabel> ?a .
              FILTER(lang(?a) = "zh")
              BIND(STR(?a) AS ?value)
              {
                ?other <http://www.w3.org/2004/02/skos/core#altLabel> ?b .
                FILTER(?other != $this && lang(?b) = lang(?a) && STR(?b) = STR(?a))
              }
              UNION
              {
                ?other <http://www.w3.org/2004/02/skos/core#prefLabel> ?b .
                FILTER(lang(?b) = lang(?a) && STR(?b) = STR(?a))
              }
            }
        """ ;
    ] .

# 3) 别名 ↔ 词条集合相等（防"类上有词、记录里没出处"）
term:AltLabelProvenanceShape a sh:NodeShape ;
    sh:targetSubjectsOf term:termBatch ;
    sh:sparql [
        sh:message "每个带语言标签的 skos:altLabel 必须有同 (forClass, label) 的 TermEntry"@zh ;
        sh:select """
            SELECT $this ?value WHERE {
              $this <http://www.w3.org/2004/02/skos/core#altLabel> ?a .
              FILTER(lang(?a) = "zh")
              BIND(STR(?a) AS ?value)
              FILTER NOT EXISTS {
                ?e a <https://w3id.org/fsldm/terms#TermEntry> ;
                   <https://w3id.org/fsldm/terms#forClass> $this ;
                   <https://w3id.org/fsldm/terms#label> ?a .
              }
            }
        """ ;
    ] .
```

## 4. 检索扩展接线点（只给落点与签名，不改代码）

### 4.1 扩展放在"查询改写"的哪一步

当前 `ContextResolver.resolve` 的时序是：校验参数 → `_seeds(query, hints, graphs)`（`context.py#L175`）→ `_facts` → `hybrid_search`（L211）。查询改写必须落在 **`_seeds` 内部、SPARQL 拼装之前**：

```
entityHints（调用方显式指定） > 术语词典最长匹配（新） > rdfs:label CONTAINS（旧兜底）
```

理由：`hints` 是接口契约里的显式锚点（`context.py#L163-L172`），不能被动摇；术语扩展是"自动补充 hints"；`CONTAINS` 整句匹配是已知失败路径，只在词典无命中时使用。

### 4.2 新模块（唯一新增文件）

`coa/platform/src/platform_core/termlex.py`

```python
# 建议签名（未实现）
@dataclass(frozen=True)
class TermHit:
    surface: str        # query 中命中的原词
    canonical: str      # 类 IRI
    label: str          # 命中的标签词面
    lang: str           # "zh" / "en"
    source: str         # "pref" | "alt" | "legacy-label"

class TermLexicon:
    @classmethod
    def build(cls, graph: Any, tbox_graph: str) -> "TermLexicon":
        """一次性拉取 T-Box 的 prefLabel/altLabel/rdfs:label，构建内存词典（按 tbox_graph 缓存）。"""

    def match(self, query: str, *, max_hits: int = 5) -> list[TermHit]:
        """最长匹配优先、非重叠；长度相同时按 canonical IRI 字典序，保证确定性。"""

    def canonical_seeds(self, hits: list[TermHit]) -> list[str]:
        """去重后的 canonical 类 IRI；同一 canonical 只保留一条。"""

    def lexical_queries(self, hits: list[TermHit], *, limit: int = 4) -> list[str]:
        """生成扩展词法查询串：canonical prefLabel@zh + 命中 altLabel@zh + prefLabel@en。"""
```

要点：
- 词典只由 **T-Box 图**构建，不读 A-Box；`build` 按 `tbox_graph`（含版本）缓存，版本切换即失效。
- `canonical` 去重契约（T6 已裁定，§7-1）：`agmt:Policy` 是"保单/保险单"的 canonical；`ins:InsuranceAgreement` 通过 `term:canonicalFor agmt:Policy` 让位，并把 prefLabel 中的"（保单）"登记为 `term:suppressedSurface "保单"@zh`，**该词面不进词典**。于是 `match("保单")` 只产出 `agmt:Policy`，`match("保险契约")` 才产出 `ins:InsuranceAgreement`。
- `guardRegex`（§7-2）：`match()` 对每条 `medium` 命中先跑 `re.search(guard, query)`，不匹配则丢弃并累加 `guardRejected`；正则**在 `build()` 时 `re.compile` 一次**，编译失败直接抛 `E_TERM_GUARD_INVALID`，不做静默降级。

## 5. 命中率 before/after 怎么量

### 5.1 语料

用**平台现有语料**，不新建语料：`platform.document` / `platform.document_chunk`（05 §2.3 记录为 1,227 份文档）。评测只 `SELECT`，不写入；不切 embedding 指针、不重建分区。

### 5.2 查询集（24 条，一次冻结，两轮复用）

| 组 | 条数 | 来源 | 构造方式 |
|---|---:|---|---|
| A 失败词面 | 12 | 05 §1.1 表（客户 / 逾期贷款 / 不良率 / 集团客户 / 关联客户 / 风险暴露 / 信用评级 / 险种 / 赔案 / 报案 / 押品 / 担保合同） | 每条包成 1 个最短业务问句，如"押品覆盖率是多少？" |
| B 场景问句 | 5 | 05 §1.2 五个场景 | 原句直接使用，含长句与复合问法 |
| C 指标监管问法 | 7 | `00-口径基准-v1.md` 36 条"可用"指标按比例抽 7（银行 2 / 保险 4 / 客户经营 1） | 用监管全称问法，如"今年报案立案率是多少？" |

每条记录 4 个字段：`query`、`expectedClass`（1–2 个类 IRI，来自 05 §3.1 实体组映射）、`goldChunkId`（可从 05 附录 B / A 档证据定位时填，否则留空）、`note`。

**不做人工全文标注**：`expectedClass` 由既有指标→实体映射直接推出，零新增标注成本；`goldChunkId` 只在 6 条 A 档别名对应的问句上有（附录 B 给了原文片段，可用 `platform.document_chunk.text` 的 `ILIKE` 命中定位）。

### 5.3 指标：取 **MRR@10**（文档级，唯一主指标）

```
对每条 query q：
  取 hybrid_search(q, limit=10, mode="hybrid") 的返回顺序
  rank(q) = 第一个 goldChunkId 出现的位置（1..10），未出现记 0
  rr(q)   = 1/rank(q)（rank=0 时 rr=0）
MRR@10 = mean(rr(q)) over 24 条
```

- 为什么不是 recall@k：24 条查询多数只有 1 个 gold chunk，recall@10 会饱和到 0/1 二值，区分度差；MRR 保留排序信息。
- 辅助诊断（不作为准入）：`seedHit@1`（期望类是否出现在 `_seeds` 首位）、`queriesWithHit@10`、`P95 延迟`。
- 误扩展率：`FP = 扩展产生且不在 expectedClass 集合的 canonical 数 / 扩展产生总数`，目标 ≤ 2%。

### 5.4 跑法与准入

同一进程内跑两遍：`term_expand=false`（baseline）→ `true`（candidate），同一 `SearchService` / `ContextResolver` 实例，同一 `top_k=10`。不改 embedding 指针、不重建任何分区。

准入（四条全满足才允许打开配置默认值）：

| 条件 | 阈值 |
|---|---|
| `MRR@10` | 提升 ≥ 0.05，且不低于基线 |
| `queriesWithHit@10` | 不下降 |
| `FP` | ≤ 2% |
| 既有验收 | acceptance 全绿、purity 0/0 |

### 5.5 没有标注集时的替代做法（诚实说明是代理）

1. **类级 `seedHit@1`**：gold 用 `expectedClass`（由指标映射推出，非人工标注），完全不依赖文档标注，可先跑。但它只测"种子锚点"，不测文档排序。
2. **6 条 A 档微黄金集**：只用附录 B 的 6 条原文片段定位 gold chunk，样本极小，只能看方向、不能下结论。
3. **基线 top-1 保留率**：`baselineTop1Retention@10` = baseline 的 top-1 chunk 是否仍在 candidate 前 10（衡量扩展有没有把好结果挤掉），不需要任何 gold。这是回归护栏，不是效果指标。
4. 以上三条必须标注 **"Proxy，非业务结论"**；正式验收仍以 §5.3 的 24 条 + 人工补 gold 为准。

### 5.6 `real-*.pdf` 定档对 baseline 可信度的影响（§7-5 裁定的直接后果）

`real-*.pdf` 定档 **Q 级（仅作问法来源，不作证据、不作 gold）**，因此：

- 24 条查询集的 gold 只来自**已核实语料**（`SPDB-LDM.pdf`、`FS-LDM-1.txt`、`453_FSLDM课堂练习.pdf`）；有 gold 的只有 **6 条**（A 档 6 条别名对应的问句），覆盖率 **25%（6/24）**。
- baseline 可信度评级：**中低（provisional）**。三个具体偏差：(a) 6 条有 gold 的查询恰好就是 candidate 扩展命中的词，candidate 天然占优 → 提升幅度被高估；(b) 18 条无 gold 的查询在 MRR@10 里只能记 0 或排除，分母口径不同结论会跳变；(c) gold chunk 用 `ILIKE` 定位，一词多处的语料会取首个命中，单条 rank 有 ±1~2 噪声。
- 因此规定：**baseline/candidate 对比只报"有 gold 子集"的 MRR@10（分母 6）+ 24 条的 `seedHit@1`**，两者都标 `Provisional`；在 gold 扩到 ≥18/24 之前，不允许把提升幅度写进验收结论或对外材料。
- 若日后 `real-*.pdf` 被核实为监管原文 → 升 A 档：可新增证据行、把 gold 覆盖率推到 ≥50%，届时重跑同一查询集即可解除 Provisional，无需改代码。

### 7-1 T6 canonical：`agmt:Policy` 胜出，`ins:InsuranceAgreement` 让位

| 项 | 内容 |
|---|---|
| **结论** | "保单/保险单"这一族词的 canonical = `agmt:Policy`。`ins:InsuranceAgreement` 保留为独立的"保险合同（关系）"概念，通过 `term:canonicalFor agmt:Policy` 声明让位，并把 prefLabel 括号里的"保单"登记为 `term:suppressedSurface "保单"@zh`（进图、不进词典）。 |
| **依据** | ① `agmt:Policy` 是三个 v10 实体类（`IndividualInsurancePolicy` / `GroupInsurancePolicy` / `CommercialInsurancePolicy`）的父类，词族扩展可沿 `rdfs:subClassOf` 下钻，而 `ins:InsuranceAgreement` 无子类；② `agmt:Policy` 已被 `owl:AllDisjointClasses` 与 `Account`、`CreditAgreement` 显式互斥，是既有模型里的保单家族锚点；③ `agmt:Policy` 的 `rdfs:comment` 明确写着 v10 无 POLICY 本体、由三子类反推，说明它就是"泛称"的抽象位；④ `ins:InsuranceAgreement` 的注释给的是保单**关系语义**（团单与成员单靠 `AgreementRelation` 对等连接），适合作"保险合同"而不是"保单"总入口。 |
| **影响别名** | 2 条：`05#B-04` 保险单（锁定 `agmt:Policy`，去掉"暂挂"）、`05#B-10` 保险契约（保留 `ins:InsuranceAgreement`，不属被让出的歧义词）。其余 16 条不受影响。 |
