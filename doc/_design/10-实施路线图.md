# 实施路线图（S0–S14）

> 文档编号：10 · 版本：v0.6 · 日期：2026-11-06
> 留痕：逐片流水账见 `_impl/WORKLOG.md`；当前状态看板见 `_design/a_progress.md`（≤30 分钟刷新）。
> 关系：上游为 03（架构与决策台账）、04（端口契约）、05（运行形态）、06（实现候选）、07（存储分层）；本文件只定义**实施切片顺序与验收判据**，不重复论证架构。
> 原则：一次只推进一个切片；每个切片先设计后实现，结束时主干（`docker compose up -d` + S0 smoke）必须仍为绿。
> 运行形态：S0 只交付 `lean` 形态的 3 个常驻容器（`platform` + `postgres` + `oxigraph`）；`learn` 档的 `reasoner`/`embedding` 在 S3/S5 落地后补齐。

| **S14** | 平台验证阶段（部分交付：**对外可出数 0 条**；结构可算 74、有效测数据可算 0） | FS-LDM T-Box 全量导入 + 指标口径可计算性验证（口径卡 + 合成探针，三轮对账） | 平台功能收口（S0–S13 已收口；验收口径见 `29` §8，不笼统写“全绿”） |

**顺序理由：**

1. 先 S0：没有可重复启动的骨架，后面每个切片都会重复处理端口、配置、健康检查与迁移。
2. S1 先于 S2：抽取产物必须落进有版本的图，否则 S4 的候选无处归属；版本指针也是「哪个版本生效」的唯一答案来源（D20）。
3. S2 先于 S3：没有切块就没有可索引的对象；检索是文档入库的派生层。
4. S4 在有版本图（S1）与检索（S3）之后：实体消解需要「唯一键 + 别名 + pgvector + 人工队列」，其中 pgvector 来自 S3。
5. S5 在 S4 之后：先有候选与事实，再校验与物化；否则 SHACL 无对象。
6. S6 收口读路径：ContextResolver 是「编排」，依赖 S3 的召回与 S5 的物化版本。
7. S7 最后：UI 只调用已稳定的 API，不提前造界面再返工。
8. S8 在 S4–S7 之后：先有审批写入与 UI 入口，才谈“哪条写错了、怎么撤回”；治理只加状态与审计，不改已通过的读写语义。
9. S9 紧随 S8：撤回/冲突可见之后，才需要“人工裁决 + 可离线核对的审计”，仍不引入打分或鉴权。
10. S10 收治理闭环：裁决既然能改状态，就必须能撤错；审计既导出，就要能在空库重放出同一状态。
11. S11 回到本体本身：A-Box 已有撤回/裁决/回放，T-Box 还缺「谁能改、改了怎么审、出事怎么回」；复用 S1 的版本图与 S5 的校验/物化，只加治理状态与审计，不改读写语义。
12. S12 只补已交付功能自身的完整性：门禁不能被任何路径绕过、导出的审计必须能自证、清理动作必须进链；不加新能力、不改 A-Box/T-Box 业务语义。
13. S13 最后补“入口规模”：S2 的单文件上传只能灌示例，几十 GB 资料进不来；批量导入复用已稳定的解析/切块/嵌入链路，只加入口、状态机与可观测性，不改检索语义。

## 3. 各切片定义

> 每切片都必须遵守：先写 `_design/impl/<切片>-*.md`；只写胶水与 Web 层（D18）；至少 1 条可执行验收 + 2 条失败路径；跑通留证据；更新本表与 `_impl/OPEN-QUESTIONS.md`。

### S0 骨架

- **目标**：可重复启动的单机骨架，端口边界与失败语义成立。
- **做**：配置加载/校验（YAML + ENV + 默认值）、3 端口最小实现（`GraphStore`=Oxigraph HTTP、`ObjectStore`=FS CAS + PG 小工件、`MetadataStore`=PG）、启动自检子集、`/healthz` `/readyz` `/status`、PG 迁移 V1、CLI（`serve`/`check-config`/`probe`/`smoke`）、compose（learn/lean 开关位）。
- **不做**：鉴权、指标/告警/追踪、队列/事件、多用户、Silo、Fuseki 适配器、SHACL/推理/embedding/LLM、文档解析、检索。
- **验收**：见 §2 全 9 条。
- **产出**：`_impl/` 代码与 compose、`_design/impl/S0-骨架-设计.md`、`_impl/OPEN-QUESTIONS.md`。
- **风险**：Windows 卷上的 `fsync`/`rename` 语义；Oxigraph 镜像为 distroless（无 shell/curl，不能容器内 healthcheck）；PG 18 镜像 tag 取决于镜像仓库。

### S1 本体存储与版本

- **目标**：T-Box 可导入、可版本化、可发布/回滚，`graph_pointer` 可查询。
- **做**：`OntologyRegistry` 状态机（PG：`ontology_version`/`graph_pointer`/`ontology_job`）、命名图规范 `urn:platform:graph:tbox:<version>`、`init_mode=once|watch`、Turtle/TriG 导入（rdflib 解析 → `GraphStore.load` 或 `replaceGraph`）、发布=写新图+切指针、回滚=**新建指向旧内容的新版本并切指针**（同时满足 03 §4 与 04 §5.2，见 S1 设计 §4.2 / OQ-14）。
- **额外并入（原独立选型任务取消）**：**Oxigraph 能力探测**（脚本/集成测试，不做成功能）：① GSP `/store` 的 GET/PUT/POST/DELETE（默认图与命名图各一次），记录状态码、内容协商、命名图标识方式、失败返回体；② SPARQL 关键点：property path（`/`、`p+`、`^`）、`FROM`/`FROM NAMED` 叠加、`SERVICE`、Update 的 `INSERT DATA`/`CLEAR GRAPH`/`DROP GRAPH`。实测结果写入 S1 设计的能力表，并据此回写 `capabilities()`（`GSP_SUPPORT` 只填实测 `full|partial|none`）；与文档不符的偏差记 `_impl/OPEN-QUESTIONS.md` 并给出应对；若 GSP 不足以支撑 D25 共同子集，**只汇报差距，不改设计**。
- **不做**：OWL DL 推理（S5）、diff 的图同构算法（用 SPARQL `MINUS`/`CONSTRUCT`）、多版本叠加读取（默认只读最新，D20）。
- **依赖**：S0。
- **验收**：导入 2 个版本 → `graph_pointer` 指向 v2 → `version=v1` 查询仍可读；重复导入同哈希 → `skipped`；非法 TTL → 不发布且旧指针不变；能力探测脚本产出 GSP 14 项 + SPARQL 9 项实测矩阵。
- **S1 实测结果（2026-11-04）**：`platform smoke-s1` 17/17（v1/v2 发布与历史可读、重复导入 skipped、非法 TTL fail-fast、图不可达 fail-fast、回滚、manifest 与实测一致）；`platform graph-capabilities` → `GSP_SUPPORT=full`；`platform smoke` 7/7、`tests/acceptance.ps1` 13/13 仍绿；schema_version=2。
- **产出**：`adapters/ontology_pg.py`、`sql/V2__s1.sql`、`tests/ontology/*.ttl`、`smoke_s1.py`、`capabilities.py`。
- **风险**：Oxigraph `load` 的格式/图参数行为需实测；版本图体量与 dump 时间。

### S2 文档入库

- **目标**：一份 PDF/Office/TXT 从入口到「文本 + 切块 + manifest」落库。
- **做**：上传端点（流式接收，创建 `document` 记录）、`ObjectStore` 路由（≤10MB→PG bytea，>10MB→FS CAS）、`DocumentParser`（pypdfium2 + pdfplumber + MarkItDown；OCR 关闭时 `warn: NO_OCR_ENABLED`）、切块（固定窗口 + 重叠，参数写配置）、抽取文本/manifest 进 PG、幂等键 `document_id + sha256`。
- **不做**：OCR、Tika 常驻、表格语义理解、Embedding（S3）。
- **依赖**：S0。
- **验收**：上传 3 种格式各 1 份 → `document`/`chunk` 行数正确；同文件重复上传 → 不产生重复行；扫描版 PDF → `degraded=true` + `NO_OCR_ENABLED`；坏文件 → `InvalidArgument` 且不落半成品。
- **产出**：`documents`/`chunks` DDL、解析适配器、入库编排、验收脚本。
- **风险**：第三方解析库在 Windows 容器中的字体/临时文件行为；中文 PDF 断行。
- **S2 实测结果（2026-11-04）**：`platform smoke-s2` 17/17（TXT 4 块、PDF 1 页、DOCX 1 块、重复上传 200/dedup、扫描件 `NO_OCR_ENABLED` 0 块、坏 PDF 400 且行数不变、`.bin` 400、OCR 请求 `Unsupported`、配置 fail-fast 78、DB 不可用 `Unavailable`、source sha256 一致）；`smoke` 7/7、`smoke-s1` 17/17、`acceptance.ps1` 16/16 仍绿；schema_version=3。

### S3 检索

- **目标**：给定查询，返回可引用的 chunk（向量 + FTS + RRF）。
- **做**：`VectorStore`（pgvector HNSW/IVFFlat，维度 1024 校验）、`EmbeddingClient`（local-bge 服务，BGE-M3）、`SearchIndex`（PG FTS/trgm）、`Indexer` 派生索引、`hybrid_search` = 两路召回 + **RRF k=60**（固定公式，D19）。
- **不做**：重排模型、学习型排序、外部向量库、跨语言检索。
- **依赖**：S2。
- **验收**：固定 8 条语料 + 固定查询 → top-3 顺序可复现；维度不符写入 → `InvalidArgument`；embedding 服务停 → 自动退 FTS 且 `degraded=true`。
- **产出**：`sql/V4__s3.sql`（`chunk_embedding`/FTS 列）、embedding 客户端、混合检索编排、`learn` profile 的 `embedding` 服务定义。
- **风险**：BGE-M3 在 CPU 的吞吐/内存（03 §16.5，16G 档偏紧）；本机 12.5G Docker 内存需要限制批次。
- **S3 实测结果（2026-11-04）**：`platform smoke-s3` 18/18（8 语料入库+索引、两类固定查询 top-3 可复现且命中目标、lexical/vector 模式、8 维写入拒绝且零写入、embedding 不可达时索引降级与查询退词法、显式 vector 503、幂等、HTTP `/search` 与 `/documents/{id}/index`、非法 mode 400、空查询 400、配置 78）；`smoke` 7/7、`smoke-s1` 17/17、`smoke-s2` 17/17、`tests/acceptance.ps1` 18/18 仍绿；schema_version=4；TEI CPU 真实 BGE-M3 返回 1024 维（实测 batch 上限 4）。

### S4 抽取到实例

- **目标**：从 chunk 产出候选三元组，人工审批后写入 A-Box。
- **做**：`ExtractionPipeline`（规则优先：唯一键/正则/词表；LLM 辅助：OpenAI 兼容 JSON 输出）、候选表（`extraction_candidate`）、幂等键 `document_id + sha256 + extractor_version + prompt_version`、审批队列 API、promote → `GraphStore.upsertStatements`（带 provenance/命名图）。
- **不做**：概率实体消解（Splink 仅在量化触发后，D21）、自动发布、跨文档推理。
- **依赖**：S1、S2、S3。
- **验收**：同一 chunk 重跑 → 候选数不增；LLM 不可达 → 退规则且标 `degraded`；审批前图无事实、审批后图有事实；非法三元组 → `InvalidArgument`。
- **产出**：候选 DDL、规则/LLM 抽取器、审批 API、验收脚本。
- **风险**：LLM JSON 稳定性（重试 1 次后 `Internal`，04 §11.5）；中文术语边界。

### S5 校验与推理物化

- **目标**：SHACL 校验门禁 + EL 物化到 `urn:platform:inferred:<version>`。
- **做**：pySHACL 校验（形状目录可读）、`ReasoningService` 薄客户端驱动 ROBOT/ELK 容器、物化幂等键 `hash(tbox+abox+profile)`、失败清理目标图、`inferred` 版本指针、`learn` 档 `reasoner` 常驻。
- **不做**：查询时重写、增量推理、自研分类器。
- **依赖**：S1、S4。
- **验收**：`subClassOf*` 蕴含可被普通 SPARQL 命中；不一致本体 → `consistent=false` 且不物化；重复物化 → `skipped`；推理容器停 → `Unavailable` 且源图不变。
- **产出**：`reasoner` 容器/profile、`pySHACL` 适配器、物化作业、`sql/V6__s5.sql`（作业/指针）。
- **风险**：ELK/ROBOT 容器镜像体积与 JVM 内存；12.5G 环境需 `-Xmx2g`。

### S6 Context 组装 API

- **目标**：一次请求产出 `ContextPack`（子图 + 召回片段 + citations + token 预算）。

- **不做**：应用层重排算法、跨版本合并（D20）、对话记忆。

- **风险**：token 计数口径（用模型 tokenizer 或保守字符估算，需登记）。
