# 单机接口契约（端口 / IDL / 能力矩阵）

> 文档编号：04  
> 版本：v0.1（评审稿）  
> 日期：2026-11-04  
> 关系：本文是《03-单机架构方案.md》的契约附件；架构取舍以 03 为准，端口/IDL 以本文为准。  
> 范围：只定义契约与伪代码/IDL，不写实现代码。  
> 原则：**接口按 AWS 级设计，单机只是当前唯一实现**；未来加分布式实现不改端口语义。  
> 形态：单机 = 同一台机器上的 docker compose 多容器。`runtime.mode=learn`（默认）常驻 `platform` + `postgres` + `oxigraph` + `reasoner` + `embedding`（本地 BGE-M3）；`lean` 常驻前三个，`reasoner`/`embedding` 按需。`ollama`/`silo`/`tika` 仅 profile。不是多机、也不强制单进程。  
> 相关：运行形态与推理选型见 05；实现候选与切换成本见 06；存储分层的实现规格（DDL、写入/读取/回收/核对/备份协议）见 07。

## 0. 阅读约定

1. IDL 是规范性伪代码，用于对齐字段、语义、错误与能力；不是某种语言的实现。
2. `?` 表示可选字段；`Page<T>`、`Stream<T>`、`Map<K,V>` 为通用类型。
3. 每个端口有 `v1` 版本；只做加法演进，破坏性变更升 `v2`。
4. 每个 provider 必须提供 **Provider Manifest**，声明 `capabilities` 与 `limits`；启动校验，运行期以 `Unsupported` 显式失败。
5. **不提供的能力必须显式声明为不支持**，不允许“尽力而为”伪装成功。
6. 删除的端口（TaskQueue/EventBus/WorkflowEngine/JobRunner/TableCatalog/DatastoreDAO/Notifier）不在本文定义；本地替代见 03 第 7.2 节。
7. **不自研查询语言**：`GraphStore` 的契约是 SPARQL-first，平台只做模板、护栏与结果映射；不定义自有 `GraphQuery` DSL。

---

> **原则（先于本表）：** 本表所有端口均为**适配器边界，端口内不含算法实现**；有算法一律调用底层库/服务。`capabilities()` 必须如实上报底层能力，**不得虚报**（不支持即 `Unsupported`）。换实现只改对应 adapter 一个文件。

## 2. 通用契约

### 2.1 错误模型

所有端口返回统一 `PortError`，不返回 SDK/驱动异常类型。

```text
type PortError {
  code: ErrorCode
  message: string
  provider?: string
  providerCode?: string
  requestId?: string
  retryable: bool
  retryAfterMs?: int
  details?: Map<string, any>
}

enum ErrorCode {
  InvalidArgument
  NotFound
  Conflict
  PreconditionFailed
  Unsupported
  PermissionDenied
  PolicyRejected
  ResourceExhausted
  DeadlineExceeded
  Unavailable
  Aborted
  Internal
  DataLoss
}
```

| Code | 含义 | 默认可重试 | 备注 |
|---|---|---|---|
| `InvalidArgument` | 参数/格式/查询形状非法 | 否 | 不支持的查询形状也归此类（或 `Unsupported`，见 6.4） |
| `NotFound` | 资源/实体不存在 | 否 | 空结果不是 NotFound；返回空集合 |
| `Conflict` | 版本/唯一性/并发冲突 | 视操作 | 幂等写可重试 |
| `PreconditionFailed` | 条件写/状态前置条件失败 | 否 | 乐观锁/状态机非法迁移 |
| `Unsupported` | provider 不支持能力 | 否 | 上层走降级/逃生口 |
| `PermissionDenied` | 权限不足 | 否 | 鉴权不在 P0，但可能透出 |
| `PolicyRejected` | 内容/安全策略拒绝 | 否 | 不重试 |
| `ResourceExhausted` | 限流/配额/查询超限 | 是 | 退避 + 抖动；尊重 `retryAfterMs` |
| `DeadlineExceeded` | 超时 | 视幂等 | 流式首 token 后不可透明重试 |
| `Unavailable` | 依赖不可用（PG/模型/存储） | 是 | 熔断 + 退避 |
| `Aborted` | 事务/并发中止 | 是 | 重试整个操作 |
| `Internal` | 未分类内部错误 | 视情况 | 适配器 bug/未知状态 |
| `DataLoss` | 校验失败/数据损坏 | 否 | 告警；不要自动覆盖 |

### 2.2 分页、时间、ID

```text
type Page<T> { items: T[], nextToken?: string }
type PageToken = string
type Instant = string       // ISO-8601 UTC
type Duration = { value: int, unit: "ms"|"s"|"m"|"h" }
type Iri = string
type EntityId = string      // 平台内部规范 ID；可为 IRI 或 UUID
type JobId = string
```

- 分页不保证稳定排序；需要稳定排序时显式传 `sort`。
- 时间统一 UTC ISO-8601；本地时区由调用方转换。
- 列表接口返回空数组，不返回 `null`；单对象不存在返回 `NotFound` 或 `null`（在 IDL 中标注）。

### 2.3 Provider Manifest 与能力

```text
type Capability = string
type ProviderManifest {
  provider: string
  port: string
  portVersion: "v1"
  providerVersion: string
  capabilities: Capability[]
  limits: Map<string, any>
  notes?: Map<string, any>
}
```

- 启动期：按“任务类型 → 必需能力”校验；不满足则 fail-fast（生产）或显式禁用任务（dev）。
- 运行期：调用未声明能力返回 `Unsupported`；禁止伪装。
- 降级：上层根据 `Unsupported` 选择注册的退化路径（presign → 内核签名 URL；embedding → FTS；LLM → 规则），并在响应元数据标 `degraded=true`。

### 2.4 版本与兼容

- 端口 `v1` 只加字段/可选方法；删除/改语义升 `v2`。
- Manifest 的 `portVersion` 必须与平台编译期契约一致；否则启动失败。
- 实现版本与底层版本（PG/Silo/模型）的兼容范围在 manifest `notes` 中声明。
- 元数据库锁定 **PostgreSQL 18（≥18.6，<19）**；pgvector ≥0.8.5（PG 18 自 0.8.1 起支持）。跨大版本升级只走 `pg_upgrade`，扩展需随新版本重装/重建。

## 4. 四个重点端口：完整 IDL

### 4.1 `ObjectStore` v1

```text
port ObjectStore v1

put(bucket: string, key: string, body: ReadableStream, opts?: PutOptions) -> ObjectRef
get(bucket: string, key: string, opts?: GetOptions) -> ObjectStream
head(bucket: string, key: string) -> ObjectMeta
delete(bucket: string, key: string, opts?: DeleteOptions) -> void
deleteBatch(bucket: string, keys: string[]) -> BatchResult
list(bucket: string, prefix: string, opts?: ListOptions) -> Page<ObjectMeta>
copy(src: ObjectRef, dst: ObjectRef, opts?: CopyOptions) -> ObjectRef

beginMultipart(bucket: string, key: string, opts?: PutOptions) -> MultipartHandle   // cap MULTIPART
uploadPart(handle: MultipartHandle, partNumber: int, body: ReadableStream) -> PartRef
completeMultipart(handle: MultipartHandle, parts: PartRef[]) -> ObjectRef
abortMultipart(handle: MultipartHandle) -> void

presignGet(ref: ObjectRef, ttl: Duration) -> Url                    // cap PRESIGN
presignPut(ref: ObjectRef, ttl: Duration, opts?: PutOptions) -> Url // cap PRESIGN

listVersions(bucket: string, key: string) -> Page<ObjectVersion>    // cap VERSIONING
getVersion(ref: ObjectRef, versionId: string) -> ObjectStream       // cap VERSIONING
deleteVersion(ref: ObjectRef, versionId: string) -> void            // cap VERSIONING

types:
  PutOptions {
    contentType?: string
    metadata?: Map<string,string>
    checksumAlgorithm?: "sha256"|"crc32c"|"crc32"
    ifNoneMatch?: "*"
    storageClass?: string
  }
  GetOptions { range?: {start:int, end:int}, ifMatch?: string, ifNoneMatch?: string }
  ObjectMeta {
    ref: ObjectRef
    contentType: string
    lastModified: Instant
    metadata: Map<string,string>
    checksum?: {algorithm:string, value:string}
  }
  ObjectVersion { ref: ObjectRef, isLatest: bool, deleteMarker?: bool }
  ListOptions { limit?: int, continuationToken?: string, delimiter?: string }
  BatchResult { deleted: string[], errors: {key:string, error:PortError}[] }
  MultipartHandle { uploadId: string, bucket: string, key: string }
  PartRef { partNumber: int, etag: string, size: int }
```

**能力标志位（按 provider 显式声明，启动时校验）：**

| 标志 | `fs`（默认） | `pg` | `silo` |
|---|---|---|---|
| `presign` | `false` | `false` | `true` |
| `range_read` | `true` | `true`（仅 Large Object；`bytea` 为 `false`） | `true` |
| `multipart` | `stream`（平台分块写临时文件后合并） | `chunked-lo`（LO 按 64 KB 页） | `native` |
| `versioning` | `optional`（CAS 以内容哈希近似） | `table-based`（版本表） | `true` |
| `consistency` | `rename-atomic` | `transactional` | `object-atomic` |
| `object_lock` | `false` | `false` | `true`（可选） |
| `event_notification` | `false` | `false` | `false`（不启用） |

**`presign=false` 时上层如何退化：**

1. 浏览器/外部系统**不直连**存储；下载走 `platform` 流式代理端点（`GET /objects/{key}`），鉴权在 platform（P2 再外置）。
2. 上传走 `platform` 流式接收 → `ObjectStore.put`；不要求前端分片直传。
3. 响应元数据标 `degraded=true, presign=false`，前端不尝试直连。
4. 需要直传/直下时再切 `storage.large_object_provider=silo` 或加 S3 兼容网关；上层调用形状不变。

**契约要点：**

- **实现细节见 07 §3–§6**：表结构、写入顺序（字节 → 元数据 → 引用）、读取命中顺序、删除与 GC 规则。
- `put` 对同 key 覆盖；版本行为由 `VERSIONING` 决定，不写进业务语义。
- `etag` 不保证跨 provider 同格式；只用于条件写/校验。
- `list` 不保证强一致；需要“写后立即可见”用 `head`。
- **不提供事件通知**：单机无事件总线；需要变更感知时由内核在写路径发进程内观察者 + `event_log` 表。
- `PRESIGN` 缺失时，上层用内核签名 URL 或流式代理，不要求适配器伪造。
- 本地 FS 的 `beginMultipart` 若未实现，必须声明 `MULTIPART=false`，上层改单次写或分片合并。

### 4.2 `GraphStore` v1（SPARQL-first，实现 = Oxigraph）

> 设计口径：**标准 SPARQL 在前，强类型便利方法在后**。便利方法内部就是登记过的 SPARQL 模板（见 §6），不是另一套查询语言；不接受外部传入任意 Update。

```text
port GraphStore v1

// ---- 标准 SPARQL 1.1 ----
query(sparql: string, opts?: QueryOptions) -> SparqlResult                 // cap SPARQL_QUERY
ask(sparql: string, opts?: QueryOptions) -> bool                           // cap SPARQL_ASK
construct(sparql: string, opts?: ConstructOptions) -> QuadStream           // cap SPARQL_CONSTRUCT
update(sparql: string, opts?: UpdateOptions) -> UpdateResult              // cap SPARQL_UPDATE；仅内部/迁移用
load(data: ReadableStream, format: RdfFormat, graph: Iri, opts?: LoadOptions) -> LoadResult   // cap LOAD
dump(format: RdfFormat, graph?: Iri, opts?: DumpOptions) -> Stream<Node>                       // cap DUMP

// ---- 便利模板（内部固定 SPARQL；上层优先用这些） ----
describe(id: EntityId, version?: string) -> EntityView                    // T1
neighbors(seed: EntityId, spec: NeighborSpec) -> NeighborPage             // T2
subgraph(seeds: EntityId[], spec: SubgraphSpec) -> Subgraph               // T7
impact(entity: EntityId, spec: ImpactSpec) -> ImpactReport                // T5

// ---- 写入：受控 API，不用 Update 字符串 ----
upsertStatements(statements: Statement[], opts?: WriteOptions) -> WriteResult   // cap UPSERT
deleteStatements(ids: string[], opts?: WriteOptions) -> DeleteResult
listStatements(filter: StatementFilter, page?: PageToken) -> Page<Statement>
replaceGraph(graph: Iri, data: ReadableStream, format: RdfFormat) -> LoadResult   // cap GRAPH_REPLACE（整体替换）
clearGraph(graph: Iri) -> void                                                     // cap GRAPH_CLEAR（清空）
snapshot(version: string) -> SnapshotRef                                  // cap SNAPSHOT

types:
  RdfFormat = "turtle"|"trig"|"ntriples"|"nquads"|"rdfxml"|"jsonld"

  QueryOptions {
    defaultGraphs?: Iri[]        // 数据集白名单；缺省用 platform.default_graph
    namedGraphs?: Iri[]          // 允许读取的 named graph
    timeoutMs?: int              // 默认 30000
    maxRows?: int               // 默认 10000（已按代码对齐，原文档值=100000；见 config.py graph.max_rows）
    allowService?: bool         // 默认 false；true 也只允许白名单端点
    explain?: bool
  }
  ConstructOptions { defaultGraphs?: Iri[], namedGraphs?: Iri[], timeoutMs?: int, maxTriples?: int }
  UpdateOptions { graph?: Iri, timeoutMs?: int, actor?: string }
  LoadOptions { batchSize?: int, replaceGraph?: bool, mappingVersion?: string }
  DumpOptions { contentType?: string, pageSize?: int }

  SparqlResult {
    kind: "select"|"ask"
    variables: string[]
    bindings: Binding[]                 // SELECT
    boolean?: bool                      // ASK
    truncated: bool
    stats?: { rows:int, ms:int, plan?: string }
  }
  Binding { values: Map<string, Term> }

  Term =
      {kind:"iri", iri: Iri}
    | {kind:"bnode", label: string}
    | {kind:"literal", value: string, datatype?: Iri, lang?: string}
    | {kind:"var", name: string}
    | {kind:"entity", id: EntityId}

  Node = Term                             // CONSTRUCT/DUMP 的 quad 节点
  UpdateResult { inserted:int, deleted:int, graph?: Iri, ms:int }
  LoadResult { quads:int, graph: Iri, ms:int }

  // ---- 便利模板的参数 ----
  NeighborSpec { direction:"out"|"in"|"both", predicates?:Iri[], depth?:int, limit?:int, asOf?:string }
  NeighborPage { entities: EntityView[], edges: Statement[], truncated: bool }

  SubgraphSpec { depth:int, predicates?:Iri[], entityFilter?:Iri[], limit?:int, asOf?:string }
  Subgraph { entities: EntityView[], statements: Statement[], truncated: bool }

  ImpactSpec { direction?:"forward"|"reverse", depth?:int, kinds?:("term"|"class"|"property"|"fact"|"mapping"|"query")[], limit?:int }
  ImpactReport {
    root: EntityId
    affected: {kind:"term"|"class"|"property"|"fact"|"mapping"|"query", id:string, count?:int}[]
    total: int
    truncated: bool
  }

  // ---- 实体/事实 ----
  Statement {
    id: string                   // 幂等键：hash(subject,predicate,object,graph,version)
    subject: EntityId
    predicate: Iri
    object: Value
    graph: Iri                   // 必填：版本/数据源隔离
    ontologyVersion: string
    provenance: Provenance
    confidence?: float
    validFrom?: Instant
    validTo?: Instant
  }
  Value = {kind:"iri", value:Iri} | {kind:"literal", value:string, datatype?:Iri, lang?:string}

  EntityView {
    id: EntityId
    types: Iri[]
    properties: Map<Iri, Value[]>
    statements: Statement[]
    ontologyVersion: string
  }

  WriteOptions { dedupe?:bool, expectedVersion?:string, actor?:string }
  WriteResult { written:int, skipped:int, conflicts:{id:string, error:PortError}[] }
  DeleteResult { deleted:int, missing:string[] }

  StatementFilter {
    subject?: EntityId
    predicate?: Iri
    object?: Value
    graph?: Iri
    ontologyVersion?: string
    minConfidence?: float
    asOf?: Instant
  }

  SnapshotRef { version: string, createdAt: Instant, statementCount: int, graphIris?: Iri[] }
```

**能力标志位：**

```text
capabilities = [
  "SPARQL_QUERY",          // SELECT
  "SPARQL_ASK",
  "SPARQL_CONSTRUCT",      // CONSTRUCT / DESCRIBE
  "SPARQL_UPDATE",         // 仅内部/迁移使用，不对外
  "NAMED_GRAPHS",          // 版本隔离/数据源隔离
  "LOAD", "DUMP",
  "UPSERT", "SNAPSHOT",
  "IMPACT",                // 平台模板，非引擎能力
  "TRANSACTIONS",          // Oxigraph Store 的写事务；HTTP 模式下按端点行为声明
  "GRAPH_REPLACE",         // 命名图整体替换（共同子集）
  "GRAPH_CLEAR",           // 命名图清空（共同子集）
  "FROM_NAMED",            // 数据集 FROM / FROM NAMED（共同子集）
  "PROPERTY_PATH",         // 基本 property path（共同子集）
  "GSP_SUPPORT=none|partial|full",
  "GSP_GET", "GSP_PUT", "GSP_POST", "GSP_DELETE",
  "TEXT_INDEX", "FEDERATION_SERVICE"
]
```

**图存储双实现（D25）：** `graph.provider=oxigraph-http`（默认，已按代码对齐，原文档值=oxigraph）与 `graph.provider=fuseki`（profile `graph-fuseki`，互斥）**只使用共同子集**：

| 共同子集操作 | Oxigraph | Jena Fuseki/TDB2 | 契约入口 |
|---|---|---|---|
| 命名图整体替换 | `replaceGraph`（`DROP+LOAD` 或 Update） | `PUT ?graph=` / `replaceGraph` | `replaceGraph` |
| 命名图清空 | `clearGraph` | `DELETE ?graph=` 或 `DROP GRAPH` | `clearGraph` |
| `INSERT DATA` / `DELETE DATA` | ✅ | ✅ | `upsertStatements`/`deleteStatements` |
| `SELECT` / `CONSTRUCT` | ✅ | ✅ | `query`/`construct` |
| 基本 property path（`/`、`^`、`+`、`*`、`?`） | ✅ | ✅ | `query` 模板 |
| `FROM` / `FROM NAMED` | ✅ | ✅ | `QueryOptions` |
| 空图 / 不存在图 | 空结果 / `NotFound` 语义 | 空结果 / `NotFound` 语义 | 统一 |

**GSP 口径（实测 2026-11-05，代码与文档必须一致）：**

| 层面 | GSP 能力 | 证据 |
|---|---|---|
| 平台面（`/store`） | **不支持**：读 `GET /store` → `405`；写 `POST/PUT/DELETE /store` → `403 E_GSP_GOVERNANCE_REQUIRED`（所有图，含 staging） | `gsp_support=none`，`gsp_platform{read:unavailable, write:forbidden}` |
| 后端 Oxigraph 直连 | **full**（无鉴权，可读写任意命名图） | 仅内部使用；oxigraph 容器**不映射宿主端口**，宿主无法直连 |

`Provider Manifest.notes` 字段说明（避免把后端能力误当平台能力）：

```text
gsp_support         平台面 GSP 能力（none|partial|full），/status 与 graph-capabilities 用这个
gsp_platform        平台面读写细则：{read: unavailable|supported, write: forbidden|allowed}
gsp_backend_support 后端直连实测能力（full），仅用于 smoke 能力比对，不得对外表述为平台能力
```

**超出共同子集（GSP 直连、TEXT_INDEX 全文索引、SERVICE 联邦）：必须走兼容层或返回 `Unsupported`**；禁止在 Oxigraph 上使用 GSP 专属语义而在 Fuseki 上行为变化。

**显式不支持（必须声明为 false 或不在 manifest 中）：**

```text
REASONING（OWL DL） / GRAPH_ANALYTICS（PageRank 等）
FEDERATION（SPARQL SERVICE） / GSP（Graph Store Protocol，`/store` 部分支持，契约不启用）
ARBITRARY_UPDATE_EXPOSURE（不对终端用户开放）
```

**`graph.provider=age` 降级声明（P2，默认关闭）：**

```text
provider: age
capabilities: [CYPHER, UPSERT, TRANSACTIONS]
sparql = false        // 无 SPARQL 1.1
gsp = false           // 无 GSP / 协议级 named graph
owl = false           // 属性图不能直接喂 HermiT/ELK
named_graphs = false  // 单会话单图；版本隔离需另建图
```

调用 `query/ask/construct/load/dump` 一律返回 `Unsupported`，**不得**把 Cypher 结果伪装成 SPARQL 结果；上层模板需整体替换为 Cypher（详见 03 §5.6.5）。

**契约要点：**

- `query/ask/construct` 只读；`update` 仅内部迁移与受控运维使用，**不作为对外 API**。
- `SERVICE` 一律拒绝（`Unsupported`），即使 `allowService=true` 也只允许白名单端点。
- `defaultGraphs`/`namedGraphs` 必须来自白名单（当前版本、指定数据源）；禁止隐式跨版本读取。
- 超时 → `DeadlineExceeded`；`maxRows`/`maxTriples` 超限 → `ResourceExhausted`，并置 `truncated=true`（不静默截断）。
- `Statement.graph` 必填；`upsertStatements` 以 `Statement.id` 幂等，同 id 覆盖。
- `EntityId` ↔ IRI 的映射规则由平台统一（默认 IRI 直用）；适配器不做隐式改写。
- 图与 PG **无分布式事务**：发布是“幂等写图 + 幂等写元数据 + 对账任务”，不是跨库事务。
- `impact`/`neighbors`/`subgraph` 是平台模板（§6.2），实现可用固定 SPARQL；超出模板的查询直接走 `query`。

| `llm.model` | 预设给出（必填） | 模型名由供应商决定；火山方舟为 endpoint id |

**协议差异（必须由 adapter 抹平，领域层不感知）：**

| 维度 | OpenAI 兼容 | Anthropic 原生 | 处理 |
|---|---|---|---|
| 鉴权 | `Authorization: Bearer` | `x-api-key` + `anthropic-version` | adapter 各自注入 |
| 系统提示 | `messages[role=system]` | 顶层 `system` 字段 | adapter 提升/合并 |
| 工具描述 | `tools[].function` + `tool_choice` | `tools[].input_schema` | adapter 映射 schema |
| 工具结果 | `role=tool` + `tool_call_id` | `user` 内容块 `tool_result` | adapter 转换为统一 `toolResult` 块 |
| 流式增量 | `choices[].delta` + SSE | 事件类型（`content_block_delta` 等） | 统一映射为 `ChatEvent` |
| 结束原因 | `finish_reason` | `stop_reason` | 统一 `stopReason` |
| 用量 | `usage` | `usage.input_tokens/output_tokens` | 统一 `Usage` |

**不支持 tools 时的降级（写死策略，见 03 D23）：**

1. manifest 标 `TOOLS=false`；适配层用**提示词内嵌 JSON 协议**模拟（prompt 中约定输出 `{"tool":"name","args":{...}}`，解析后转 `toolCall` 块），响应标 `degraded=true, tools=simulated`。
2. 解析失败**只重试一次**（同一 request，`temperature=0`）；仍失败 → `Internal`，**不循环重试、不猜参数**。
3. 若 `requirements.llm.tools_native` 该能力在 `degradation.deny` 中（即必须原生 tools）→ **启动自检 fail-fast**：

```text
E_LLM_NO_TOOLS  provider=openai_compatible preset=ollama model=qwen2.5:7b
  missing=[llm.tools]  task=llm_extraction(required_native_tools)
  fix:    a) 关闭 requirements.llm.tools_native（允许提示词模拟）；或
          b) 切换到声明 TOOLS=true 的模型/预设
  exit:   78 (EX_CONFIG)
```

4. 不得静默假装支持原生 tools；失败的 `degraded` 必须在响应元数据可查。

**契约要点：**

- 角色与内容块是规范；适配器负责各供应商字段映射。
- 工具调用参数统一为 JSON 字符串；领域层负责 schema 校验。
- `stopReason=tool_use` 表示模型请求调用工具；`content_filter` 不重试。
- 流式首 token 后失败：终止流并返回 `Aborted`，携带 `partialText` 与 `requestId`；不能自动重放。
- `usage` 缺失时返回空字段，不伪造 0。
- 模型不可用返回 `Unavailable`；本地模型不支持工具时 manifest 标 `TOOLS=false`，抽取降级为规则。

### 4.5 `ReasoningService` v1（OWL DL / RDFS / SHACL，独立容器）

> **实现边界：** 本端口是**驱动器/薄客户端**——只做请求→推理器 CLI/HTTP 的参数映射、进程/容器生命周期、结果解析与错误映射；**不含任何推理算法**（分类、一致性、解释均来自 ELK/HermiT/Konclude）。

> 定位：**可选能力**，不是查询主路径。`learn` 档默认启用（`reasoning.mode=rdfs` + `service_enabled=true`）；`lean` 档 `off`、按 `materialize|validate` 作业运行。实现候选：HermiT / ELK / Konclude / ROBOT（见 05 文档）。

```text

classify(request: ClassifyRequest) -> ClassificationResult         // cap CLASSIFY（可选）

  Profile = "RDFS"|"OWL2EL"|"OWL2QL"|"OWL2RL"|"OWL2DL"

  }

  }
```

**能力标志位：**

```text
capabilities = [
  "MATERIALIZE",        // 物化到命名图
  "CONSISTENCY",        // 一致性检查
  "CLASSIFY",           // 类层次分类（DL/EL）
  "EXPLAIN",            // 解释（部分推理器支持）
  "INCREMENTAL",        // 增量推理（多数不支持，声明 false）

```

**契约要点：**

- **永不覆盖源图**：产物写 `targetGraph`（如 `urn:platform:inferred:<version>`）；查询时按“源图 + 推理图”组合。
- **超时/不可用不阻塞查询**：返回 `Unavailable`/`DeadlineExceeded`，上层标 `reasoningStale=true`，继续用上一次推理图或纯 RDFS。
- **失败不污染**：物化失败时删除/清空 `targetGraph`，不写入半成品；一致性失败则不物化。
- **幂等**：以 `tboxGraph + aboxGraphs + profile` 的内容哈希为键；已物化且哈希未变则跳过（`MaterializeResult.inferred=0, skipped=true`）。
- **不支持的能力必须显式 false**：例如 ELK 标 `INCREMENTAL=false`、`EXPLAIN=false`；HermiT 标 `INCREMENTAL=false`。
- **不进入在线查询路径**：查询侧只读物化结果或 RDFS 闭包；推理是作业，不是查询代理。

```text
    extractor: {name:string, version:string, mode:"llm"|"rule"|"hybrid"}
    output: {graph?: Iri, collection?: string}
    options?: {maxTriplesPerDoc?:int, minConfidence?:float, language?:string}
  }
  ExtractionStatus {
    jobId:string
    state:"queued"|"running"|"succeeded"|"failed"|"cancelled"
    stats?:{docs:int, triples:int, rejected:int}
    error?:PortError
  }
  CandidateBatch { id:string, statements:Statement[], entities:EntityView[], warnings?:string[] }
  ReprocessFilter { docIds?:string[], extractorVersion?:string, ontologyVersion?:string, since?:Instant }
  CommitResult { committed:int, skipped:int, errors:{id:string,error:PortError}[] }
```

**要点：**

- 抽取幂等键：`docHash + extractorVersion + ontologyVersion`；同键重复提交返回已有 job。
- 候选区与生产图隔离；`promote` 才写 `GraphStore`，并带审批与 provenance。
- LLM 抽取可关闭；纯规则模式仍能产出候选（质量降级）。
- `validate` 至少做形状/必填/实体消歧检查；失败项不得静默丢弃。

## 6. SPARQL 使用规范与查询模板登记（不自研 DSL）

### 6.1 设计目标

1. **标准优先**：查询语言就是 SPARQL 1.1，由 Oxigraph 实现；平台不自研语法、优化器、执行器。
2. **可枚举**：高频本体查询沉淀为模板（T1–T8），可登记、可测试、可限额。
3. **可拒绝**：超出白名单/限额的查询直接拒绝（`Unsupported`/`ResourceExhausted`），不做“尽力而为”。
4. **可逃生**：复杂 SPARQL/OWL 校验/批量推理走独立容器（`owl-dl`）或离线工具链，不走在线主路径。

### 6.2 查询模板登记表（必须维护）

| ID | 用途 | 形态（SPARQL） | 限额 | 测试 |
|---|---|---|---|---|
| T1 | 实体描述 | `DESCRIBE` / `CONSTRUCT` | 单实体 | 固定数据集 |
| T2 | n 跳邻域 | 属性路径 `{n}` 或有界 `+` | depth≤4 | 扇出/环 |
| T3 | 类层次闭包 | `rdfs:subClassOf*` | depth≤6 | 多父/环 |
| T4 | 类型+属性过滤 | BGP + `FILTER` | rows≤1000 | 多谓词 |
| T5 | 影响面 | 反向 `?x ?p <term>` + 有界路径 | depth≤6 | 大扇出 |
| T6 | 约束扫描 | `FILTER NOT EXISTS` | rows≤1000 | 基数/必填 |
| T7 | 子图导出 | `CONSTRUCT` + `LIMIT` | triples≤100000 | 截断 |
| T8 | 标签检索 | `FILTER(contains/strstarts)` | topK≤100 | 中文/别名 |

**新增模板需评审：** 说明用途、图范围、复杂度、限额、测试；禁止“业务直接拼 SPARQL 字符串”。

### 6.3 护栏规则

| 规则 | 实现位置 | 失败返回 |
|---|---|---|
| 只读：对外仅 `query/ask/construct` | 适配器 + 只读端点 | `PermissionDenied` |
| 禁 `SERVICE`（单机无联邦） | 查询预检 | `Unsupported` |
| 图白名单（版本/数据源） | 查询预检 + `defaultGraphs` | `PermissionDenied` |
| 超时（默认 30s） | HTTP 客户端 / 引擎参数 | `DeadlineExceeded` |
| 行数/三元组上限 | 结果包装 | `ResourceExhausted` + `truncated=true` |
| 结果流式/分页 | 适配器 | — |
| 写：仅 `upsertStatements`/内部 `update` | 端口设计 | — |

### 6.4 拒绝规则

| 情况 | 返回 | 提示 |
|---|---|---|
| 含 `SERVICE` | `Unsupported` | 单机不做联邦 |
| 跨白名单 graph | `PermissionDenied` | 指定 `namedGraphs` |
| 超时 | `DeadlineExceeded` | 收窄条件/降跳数 |
| 结果超上限 | `ResourceExhausted` | 加 `LIMIT`/过滤 |
| 需要 OWL DL 结论 | `Unsupported` | 走 `ReasoningService`（`materialize`）或离线 |
| 需要图算法 | `Unsupported` | 导出 NetworkX/GDS（P2） |

### 6.5 逃生口

- **复杂 SPARQL**：直接 `query`（在限额内）→ 不够则 `subgraph` 导出 → 进程内 `pyoxigraph`/`rdflib` 计算。
- **OWL DL / SHACL 高级**：`ReasoningService`（独立 JVM 容器，见 4.5）或在 `owl-dl` profile 下离线跑 ROBOT。
- **图算法**：导出边表 → NetworkX/DuckDB；结果回写 PG 或命名图。
- **约束**：逃生口不接在线高并发；不双写主存储；结果带 `provider=embedded|owl-dl` 标记。

## 8. Provider 错误映射

| 统一错误 | 本地典型来源 | 处理 |
|---|---|---|
| `InvalidArgument` | 参数校验、查询形状非法、维度不匹配 | 不重试；返回字段级错误 |
| `NotFound` | PG 无行、对象不存在、实体不存在 | 不重试；调用方决定默认值 |
| `Conflict` | 唯一约束、版本冲突 | 幂等写可重试；否则返回冲突 |
| `PreconditionFailed` | 条件写失败、状态机非法迁移 | 不重试；重新读取 |
| `Unsupported` | 能力缺失（SPARQL/PRESIGN/OCR/TOOLS） | 不重试；走降级/逃生口 |
| `PermissionDenied` | 文件权限、DB 权限 | 不重试；告警 |
| `PolicyRejected` | 内容安全/规则拒绝 | 不重试；记录原因 |
| `ResourceExhausted` | 查询超限、连接池耗尽、模型限流 | 退避 + 抖动；尊重 retryAfter |
| `DeadlineExceeded` | `statement_timeout`、模型超时 | 幂等可重试；流式不可透明重试 |
| `Unavailable` | PG 连接失败、模型服务不可用、数据目录不可读 | 熔断 + 退避 |
| `Aborted` | 事务中止、流式中断 | 重试整个操作；流式不可重放 |
| `DataLoss` | checksum 不匹配、解析损坏 | 不重试；告警/人工 |

**约定：** 适配器保留 `providerCode`/`requestId`；领域层只按统一 `code` 分支；不要把限流映射成 `InvalidArgument`。

## 9. 幂等与重试

| 端口/操作 | 幂等键 | 语义 | 重试 |
|---|---|---|---|
| `ObjectStore.put` | `bucket+key(+contentHash)` | 覆盖写；版本库新建版本 | 可重试 |
| `ObjectStore.beginMultipart` | 业务 `uploadKey` | 重复 begin 返回已有/新 upload | 可重试；注意泄漏清理 |
| `GraphStore.upsertStatements` | `statement.id` | upsert/去重 | 可重试 |
| `GraphStore.deleteStatements` | `id` | 幂等删除 | 可重试 |
| `VectorStore.upsert` | `point.id` | 覆盖写 | 可重试 |
| `ExtractionPipeline.submit` | `docHash+extractorVersion+ontologyVersion` | 同键返回已有 job | 可重试 |
| `OntologyRegistry.publish` | `version.semver` | 重复发布返回同一版本 | 可重试 |
| `ContextResolver.resolve` | `request.hash` | 可缓存；不保证同结果 | 可重试 |
| `LLMClient.chat` | `requestId` + prompt hash | 服务端不保证幂等；可缓存 | 仅可重试错误；流式首 token 后不重试 |
| `DocumentParser.parse` | `object.versionId/hash` | 可缓存 | 可重试 |
| `ReasoningService.materialize` | `hash(tboxGraph+aboxGraphs+profile)` | 已物化则跳过 | 可重试（先清理 targetGraph） |

**通用重试策略：**

```text
RetryPolicy {
  maxAttempts: 3
  baseDelayMs: 200
  maxDelayMs: 10000
  multiplier: 2
  jitter: true
  retryOn: [ResourceExhausted, DeadlineExceeded, Unavailable, Aborted]
  deadline?: Duration
}
```

- 重试前检查幂等键；非幂等操作不自动重试。
- 熔断/半开由内核统一配置；适配器不自行无限重试。
- 流式 LLM 失败即终止，返回 `Aborted` + partial；上层决定是否新 requestId 重启。

### 10.3 校验规则

1. `providers` 每个值必须在 adapter registry 中存在。
2. manifest `portVersion` 必须为 `v1`。
3. `requirements`（任务类型 → 必需能力）必须被 manifest 声明，否则 fail-fast。
4. 允许降级的能力缺失时输出 `DEGRADED` 清单；禁止降级的缺失直接失败。
5. **存储两层 provider**：`small_object_provider=pg` 时校验 `object_blob` 表存在且可写；`large_object_provider=fs` 时校验 `root` 可读写且 `tmp_dir` 同卷；`silo` 时校验端点健康；`large_object_provider=pg` 时校验连接池与库总量护栏（>15GB 告警、>30GB 拒启，需 `--force`）。任一不可用则 fail-fast（不存在“跳过对象存储”的启动模式）。禁止把 `in-memory` 用于 `single`；`storage.provider` 简写若与显式两层值冲突，显式两层优先并在日志打印最终值。
6. `test` 模式允许 `in-memory`/`fake`；`single`/`dev` 不允许 `fake` 模型。
7. `reasoning.mode != off` 时 `service_enabled=false` 必须显式声明为“离线批处理”，否则 fail-fast（避免查询期误用未物化结果）。
8. `reasoning.mode=materialize` 必须有 `target_graph_prefix`，且不得与 `graph.default_graph` 相同（禁止覆盖源图）。
9. `ontology.init_mode=once` 必须有可解析的 `init_source`；`watch` 必须有 `watch_interval_s`。
10. 所有“关闭”能力必须在启动日志输出降级项（`reasoning=off` → `NO_OWL_DL`；`embedding=disabled` → `SEMANTIC_SEARCH=false`）。
11. **能力交集校验**：对 `requirements` 每个任务，取所需能力与已装配 provider 的 `capabilities` 求交集；缺失项在 `degradation.deny` → fail-fast；在 `degradation.allow` → 注册退化路径并输出 `DEGRADED`；两者都不在 → fail-fast。错误必须写明 `task / missing / provider / impact / fix`（样例见 03 §8.3）。
12. **`limits` 是硬上限**（08 复评 R5）：`manifest.limits` 中的 `max_rows`/`max_construct_triples`/`timeout_ms`/`max_body_bytes` 等由适配器强制截断或拒绝；配置值不得超过 provider 上限（超限 → 启动 fail-fast；运行期 → `ResourceExhausted`）。不允许“配置放大限额”绕过。
13. **配置优先级**：CLI > 环境变量（如 `PLATFORM__STORAGE__LARGE_OBJECT_PROVIDER`）> 配置文件 > 默认值；`config_version` 高于支持版本 → fail-fast（78），低于 → 补默认且不写回。
14. **运行模式推导**：`runtime.mode=learn` 默认推导 `ontology.init_mode=watch`、`reasoning.service_enabled=true`、`embedding.service_enabled=true`、`search.enabled=true`；显式关闭仍允许，但必须输出 `DEGRADED`（两档功能等价，不阻断启动）。
15. **embedding 模型一致性**：启动自检读索引元数据 `embedding_model`/`dim`，与配置的 `embedding.model`/`dimensions` 比对；不一致 → **拒绝启动**（78，`E_EMBED_MODEL_MISMATCH`），错误必须给出“切回旧模型 / 执行重建索引”两条出路；禁止自动混用或静默重写。
16. **OCR 关闭语义**：`ocr.enabled=false` 合法（默认），但解析器遇“无文字层”文档必须返回 `warn: NO_OCR_ENABLED` 并标 `degraded=true`；`ParseOptions.ocr=true` 必须返回 `Unsupported`（不得返回空文本）。
17. **图后端互斥与共同子集**（D25）：`graph.provider` 只能取 `oxigraph-*` 或 `fuseki` 之一；两者同时启用、或同时指向两个端点 → fail-fast（78）。所有图操作必须落在 §4.2「共同子集」内；超出即 `Unsupported`。`capabilities()` 必须如实上报 `GSP_SUPPORT`/`GSP_GET|PUT|POST|DELETE`/`TEXT_INDEX`/`FEDERATION_SERVICE`，且契约测试双跑全部通过后该后端才可标 `usable=true`。

**能力命名对照（`requirements` 的任务键 ↔ manifest 的 `capabilities` 标志）：**

| 任务需求键（小写点分） | manifest 标志（大写） | 所属端口 |
|---|---|---|
| `graph.sparql` | `SPARQL_QUERY` / `SPARQL_ASK` / `SPARQL_CONSTRUCT` | `GraphStore` |
| `graph.update` | `SPARQL_UPDATE` / `UPSERT` | `GraphStore` |
| `graph.named_graphs` | `NAMED_GRAPHS` | `GraphStore` |
| `object.range_read` | `RANGE_READ` | `ObjectStore` |
| `object.presign` | `PRESIGN` | `ObjectStore` |
| `object.versioning` | `VERSIONING` | `ObjectStore` |
| `vector.search` | `SEARCH` / `UPSERT` | `VectorStore` |
| `search.fts` | `SEARCH` / `TRGM` | `SearchIndex` |
| `llm.generate` | `CHAT` | `LLMClient` |
| `llm.tools` / `llm.tools_native` | `TOOLS` / `PARALLEL_TOOLS` | `LLMClient` |
| `embedding` | `EMBED` | `EmbeddingClient` |

> 约定：`requirements` 用“域.能力”小写点分（任务视角），manifest 用大写常量（provider 视角）；两张表必须一一对应，新增能力两侧同时登记，否则启动校验视为未声明。

## 11. 契约测试清单

每个端口至少三类：Happy path、边界/错误、能力缺失/降级。

### 11.1 `ObjectStore`

- [ ] put/get/head/delete/list/copy 基本闭环。
- [ ] 大对象分片上传/完成/中止；FS 未实现时 `MULTIPART=false`。
- [ ] 条件写（ifMatch/ifNoneMatch）；并发覆盖。
- [ ] `PRESIGN` 缺失 → `Unsupported`；内核签名 URL 路径可用。
- [ ] `VERSIONING` 缺失 → 逻辑版本路径可用。
- [ ] checksum/内容类型/元数据往返一致。
- [ ] **两层 provider 分流**：≤`pg_blob_max_file_mb` 进 PG、>阈值进 FS；同一 `ObjectStore` 语义（get/list/head）对两层结果一致。
- [ ] **`storage.provider` 简写**：显式设置时同时覆盖两层；与显式两层值冲突时显式层优先，日志打印最终生效值。
- [ ] **`large_object_provider=pg` 护栏**：库总量 >30GB 时拒绝启动（需 `--force`），错误打印 WAL/备份/TOAST 三条代价。

### 11.2 `GraphStore`（重点）

- [ ] `query/ask/construct` 基本闭环；SELECT/CONSTRUCT 结果映射正确。
- [ ] 属性路径：`subClassOf*` 闭包（含环、多父）；有界 `{n}` 与 `+`。
- [ ] named graph 隔离：只读白名单内 graph；跨 graph 读取被拒。
- [ ] `SERVICE` 查询 → `Unsupported`；`allow_service=true` 仍只放行白名单。
- [ ] 超时 → `DeadlineExceeded`；超行数/三元组 → `ResourceExhausted` + `truncated=true`。
- [ ] `update` 不在对外 API；内部迁移路径可用。
- [ ] `load/dump` 往返一致（Turtle/TriG/N-Quads）。
- [ ] `upsertStatements` 幂等；provenance/version 往返。
- [ ] 模板 T1–T8 在固定数据集 + 固定 SPARQL 上回归（引擎升级必须跑）。
- [ ] **双实现同一套用例**（`oxigraph-http` 与 `fuseki` 各跑一遍，同一断言；共 10 类）：① 命名图读写/隔离；② 默认图；③ `FROM NAMED` 叠加；④ 基本 property path（`/`、`^`、`+`、`*`、`?`）；⑤ 空图与不存在图；⑥ 命名图整体替换（`replaceGraph`）；⑦ 命名图清空（`clearGraph`）；⑧ `INSERT DATA`/`DELETE DATA`；⑨ 并发写冲突（同一图两写者，最后一致、无丢失更新）；⑩ 错误语义（非法 SPARQL → `InvalidArgument`、超大结果 → `ResourceExhausted`、超时 → `DeadlineExceeded`、`SERVICE` → `Unsupported`）。
- [ ] **不通过的后端不得标记可用**：双跑任一用例失败 → 该 provider 在 manifest 标 `usable=false`，启动不得选它。
- [ ] pyoxigraph-memory 与 oxigraph-http 两种实现结果等价（顺序除外）。

### 11.3 `VectorStore`

**分数口径（必须先定，否则换 provider 必然不一致）：**

1. 契约对外统一为 **相似度（similarity，越大越相似）**，范围 `[-1,1]`（余弦）或 `[0,1]`（归一化内积）；**距离（distance）不得直接外泄**。
2. `metric` 由索引元数据声明（`cosine|ip|l2`）；适配器内部若用距离，必须转换：`cosine: sim=1-d`，`l2: sim=1/(1+d)`，`ip: 归一化后同余弦`。
3. 过滤（`filter`）在**相似度阈值之前**应用，且必须与 `topK` 组合定义：`WHERE filter → ORDER BY sim DESC → LIMIT k`。

- [ ] **维度不一致**：写入维度 ≠ 索引维度 → `InvalidArgument`（含 `expected/actual`）；查询向量维度不符同样报错，**不得静默截断/补零**。
- [ ] **分数方向与范围**：固定向量 + 已知相似度；`cosine` 下断言 `sim∈[-1,1]` 且同向向量 ≈1；三实现（pgvector/内存/fake）分数按同一口径，**容差 `|Δ| ≤ 1e-6`**（float32 累积误差；若后端用 float16 则 `1e-3` 并在 manifest 标注）。
- [ ] **top-k 边界**：`k=0` → `InvalidArgument`（不返回空集冒充成功）；`k>size` → 返回全部（`count=size`）；`k` 为负 → `InvalidArgument`；`k` 超 `limits.max_k` → `ResourceExhausted`。
- [ ] **过滤 + 阈值组合**：`filter` 命中子集为空 → 返回空数组（不是 `NotFound`）；阈值过高 → 空数组；`filter` 与阈值同时使用时先过滤后排序，结果满足两者。
- [ ] **空集合与重复 id**：空索引查询返回 `[]`；同一 `id` 重复 upsert → 覆盖（`count` 不增）；`id` 大小写/空白按原样（不做隐式规范化）。
- [ ] **pin 分数回归**：固定 8 条向量 + 固定查询，pin 住 top-3 的 id 顺序与分数；**换 provider 后必须重跑**，任一超容差即视为不兼容（不允许“调大容差蒙过去”）。
- [ ] 删除后查询不再命中；`delete` 不存在 id → 幂等成功。

### 11.4 `EmbeddingClient`（重点：模型/维度一致性）

- [ ] 单条/批量；维度、归一化、inputType；默认 `local-bge` 返回 `dimensions=1024`。
- [ ] 维度不匹配 → `InvalidArgument`；模型不可用 → `Unavailable`。
- [ ] 批量超限 → `InvalidArgument`；截断行为符合 `truncate`。
- [ ] 本地 BGE 与 fake provider 结果形状一致（不要求数值一致）。
- [ ] **模型不一致拒启**：库中索引记录 `bge-m3/1024`、配置为 `bge-small-zh/512` → 启动返回 `E_EMBED_MODEL_MISMATCH`（exit 78），错误含 `configured`/`indexed` 与两条出路；**不得启动成功**。
- [ ] **维度不一致写入拒绝**：索引进 `dim=1024`，向同一命名空间写 `dim=512` → `InvalidArgument`（含 `expected/actual`），不得静默截断/补零。
- [ ] **重建索引后一致**：`index rebuild --embeddings` 完成后，`embedding` 表所有行的 `embedding_model`/`dim` 与配置一致，且 `count(rows)=count(distinct chunk_id)`；重建期间语义检索返回 `degraded=true`（FTS），结束后恢复。
- [ ] **切回旧模型可用**：按错误提示把配置切回旧模型/维度后，启动成功且检索结果可复现（pin 前 N 条 id）。

### 11.5 `LLMClient`

- [ ] 普通 chat/流式/usage/stop reason。
- [ ] 工具调用：单工具、结果回传、错误结果、并行（若声明）。
- [ ] 结构化输出：合法 JSON、非法 JSON、schema 不匹配。
- [ ] 内容过滤 → `PolicyRejected`；限流 → `ResourceExhausted`。
- [ ] 流式首 token 后断开 → `Aborted` + partial。
- [ ] 模型不支持工具时 manifest `TOOLS=false`，上层降级为规则。

## 12. 版本与迁移

| 对象 | 策略 |
|---|---|
| 端口 IDL | `v1` 只加可选字段/方法；破坏性变更 `v2`，双版本并存一个发布周期 |
| Provider Manifest | `portVersion` 必须匹配；`providerVersion` 记录实现版本 |
| 本体 Schema | 版本不可变；`diff/compatibility/rollback`；事实带 `ontologyVersion` |
| 向量索引 | 元数据记录 `embeddingModel/dimensions/metric/normalized`；换模型新建索引 + 回填 + 切别名 |
| 对象 | 版本/校验和用于迁移校验；不使用 list 顺序 |
| 图 | 版本用命名图隔离；迁移用 dump/load + 重放，不双写 |
| 任务表 | `job` 记录 `state/attempt/idempotencyKey`；schema 变更走 migration |

**迁移原则：**

1. 先写新、再读新、最后停旧（expand/contract）。
2. 跨存储迁移用可重放任务，不做双写。
3. 每次迁移有校验（计数、抽样、checksum）与回滚路径。
