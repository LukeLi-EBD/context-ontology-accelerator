### 2.2 标记流程（待批准后执行，本次未执行）

```sql
-- 1) 预览（只读）
SELECT 'lifecycle_transition' AS kind, t.seq::text AS ref, t.version_id, t.reason
  FROM platform.ontology_lifecycle_transition t
 WHERE NOT EXISTS (SELECT 1 FROM platform.ontology_version v
                   WHERE v.version_id = t.version_id)
UNION ALL
SELECT 'evidence', e.evidence_id, e.version_id, e.verdict::text
  FROM platform.ontology_evidence e
 WHERE NOT EXISTS (SELECT 1 FROM platform.ontology_version v
                   WHERE v.version_id = e.version_id);

-- 2) 落标记（唯一键幂等；cause 只允许已知值）
INSERT INTO platform.ontology_orphan_mark
  (entity_kind, entity_ref, version_id, cause, detected_by, note, payload)
SELECT 'lifecycle_transition', t.seq::text, t.version_id,
       CASE WHEN t.reason LIKE 'G-01%' THEN 'test_cleanup_version_deleted'
            ELSE 'unknown' END,
       'orphan-scan-2026-11-06', t.reason,
       jsonb_build_object('reason', t.reason, 'actor', t.actor)
  FROM platform.ontology_lifecycle_transition t
 WHERE NOT EXISTS (SELECT 1 FROM platform.ontology_version v
                   WHERE v.version_id = t.version_id)
ON CONFLICT (entity_kind, entity_ref) DO NOTHING;
-- evidence 同理，entity_ref = e.evidence_id
```

约束：不改写、不删除原行；`cause='unknown'` 必须附证据，不允许猜。

## 四、写侧前置条件（已实现可选参数）

### 4.1 语义

`publish(..., expected_version_id=None)` 与 `rollback_to(..., expected_version_id=None)`：

- `None`：行为完全不变（现有脚本零改动）。
- 传入且与当前指针一致：正常执行。
- 传入但不一致：**不写指针**，追加审计事件
  `pointer_precondition_rejected`（payload：`operation` / `expectedVersionId` / `actualVersionId`），
  返回 `409`，`provider_code=E_ONTOLOGY_POINTER_PRECONDITION`。

HTTP 入口已接受可选字段：`POST /ontology/publish`、`POST /ontology/rollback`、
`POST /governance/publish`、`POST /governance/rollback-to`、
`POST /ontology/imports/{id}/publish`（含 `dryRun` 之外的正式发布路径）。

### 4.2 已知限制

- 校验发生在写入事务之前，与真正写入之间存在毫秒级 TOCTOU；并发下仍可能被后写覆盖。
  下一步应在 `pg_advisory_xact_lock` 事务内重读并做 CAS（本次未做，避免大改）。
- `test_governance_api` 等测试桩已同步支持 `expected_version_id` 并按同一语义返回 409，
  避免“桩落后于生产签名”造成误判。

### 4.3 脚本线接入步骤

1. 发布/回滚前先读 `/readyz` 的 `pointerStatus.versionId`（或 `/ontology/versions`）。
2. 请求体加 `expectedVersionId`。
3. 收到 409：重新读取指针、判断是否放弃或重试，**不要无条件覆盖**。
4. 验收收尾：读 `pointerStatus`，要求 `ok=true`，否则判定失败。
