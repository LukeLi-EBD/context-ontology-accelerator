# 37 · 指标口径判定书（v8）

> 性质：**可审计的业务判定记录**，不是监管原文，也不是“已出数”声明。
> 日期：2026-11-06｜依据：`09-definitions-v4.seed.sql` 原文、V21/V23 推导、V22 事实模型。
> 迁移：`platform/src/platform_core/sql/V24__metric_decisions_v8.sql`（schema 24，可重入）。

## 1. 判定原则

1. 能从原文唯一推出的，直接补齐，并把“哪句话 → 哪个值”写入 `quartet_derivation.fields[*].basis`。
2. 必须业务裁定的，给**推荐默认值 + 理由 + 影响 + 改动点**，写入 `decision_recommendation`，并标记：
   `inference=true`、`publishable=false`、`decision_owner='业务待签'`。
3. 推荐值只进默认配置，**不得**写成“监管原文”。监管原文阈值单独标 `evidence_basis='regulatory'` 与 `threshold_source='definition_text'`。
4. 事实字段不存在的，不建假绑定；四档继续记 `blocked_semantics`，并写清缺哪张表/哪一列。

### 2.1 未补齐为“可出数”的 7 条

以下 7 条四元组已补齐，但因**事实字段缺失**或**非标量/派生**，仍不是可出数：

- `FIN-BANK-017/018`：无账户级 DPD 时点表（`bank_ews_signal` 只有客户级 `dpd`，不能冒充账户口径）。
- `FIN-BANK-019`、`FIN-INS-012`：派生指标，单方言编译器只接受 `numerator/denominator` 算术。
- `FIN-INS-009`：缺“再保后已赚保费”（已赚保费 − 分出保费分摊 + 摊回责任准备金变动）。
- `CUST-004`：`score` 非标量，无 score 执行器。
- `CUST-005`：无统一客户代理事件日；编译器 `value_expr` 不支持按请求 `asOf` 求天数差。

每条规则包含：`id`、`signal`、`level`、`window`、`threshold`、`debounce`、`suppression`、`trigger_fields`、`configurable`、`evidence_basis`、`threshold_source`、`spec`。

**默认值声明**：除 `threshold_source='definition_text'` 的原文阈值外，其余均为行业通行默认值，**不是监管阈值**，需业务确认后调整；`configurable=true` 表示可改，原文阈值另带 `change_control` 要求合规/风险签字。

执行器对每条指标都验证三种结果：
- **命中**：`triggeredCount>0`；
- **未命中**：`triggeredCount=0` 且 `factsEvaluated=1`；
- **无数据**：`facts` 为空返回 `E_METRIC_NO_DATA`；字段缺失记入 `unevaluatedRules`，不静默当“未命中”。

## 5. 业务改口操作

1. 改推荐值：更新 `metric_definition.decision_recommendation` 对应字段，并在 `decision_owner` 写实际签字人；`inference/publishable` 由治理流程调整。
2. 改四元组：按 `changePoint` 改 `formula_expr`、`numerator_agg`、`denominator_agg` 或 `metric_field_binding.value_expr`。
3. 改规则阈值：改 `rule_set_json` 对应规则的 `spec.value` 与 `threshold`；原文阈值需附 `change_control` 签字记录。
4. 每次改动后跑 `test_metric_decisions_v8`、`test_metric_compiler_v7` 与 `acceptance.ps1`。
