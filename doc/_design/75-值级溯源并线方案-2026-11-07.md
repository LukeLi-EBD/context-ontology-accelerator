## 0. 一页结论

1. **1.7% 是伪指标。** 它算的是「registry 行数 / 观测行数」：`642 / 37,477 = 1.71%`。两者粒度不同——一条 `obs-set` 引用覆盖的是**一整批观测**（单个指标窗口最多 5,000 行）。按这个口径报覆盖率，越是有大表的指标越显得"没溯源"，方向是反的。
2. **覆盖必须分 5 层报**（同一次快照，全部只读 SQL 复算）：

   | 层 | 含义 | 当前值 |
   | --- | --- | --- |
   | L0 registry/观测行 | 伪指标，建议退役 | 642 / 37,477 = **1.71%** |
   | L1 集合级活覆盖 | 有 live `obs-set` 指向的观测行 | 37,472 / 37,477 = **99.99%** |
   | L2 逐行活覆盖 | 有 live `obs` 行引用指向的观测行（样本行） | 164 / 37,477 = **0.44%** |
   | L3 结构可构造率 | 自然键完整、引用可被生成 | 37,477 / 37,477 = **100%** |
   | L4 调用路径格覆盖 | 57 指标 × 4 路径 = 228 格中已被证明打通的格 | 65 / 228 = **28.5%** |
   | L5 引用新鲜度 | 观测级引用中仍能解析到活行的比例 | 227 / 371 = **61.2%**（悬空 38.8%） |

3. **对外宣称的瓶颈不是"有没有引用"，而是"引用的新鲜度 + 指标的制度依据"。** 现在挂着 144 条悬空引用（其中 9 条指向已经完全没有观测的指标），任何"点开能回到原始行"的宣称都会在这 144 条上破功。
4. **技术线与业务线要分开宣称。** 技术侧能把"每个数点到行 / 点到哪次计算"做到接近 100%；业务侧卡的是"点到制度条款"（指标口径 G01–G16 与 33 题清单 KG-01–KG-07），这部分不是工程能补的。
5. **最划算的一段：让已发放的观测引用 0 悬空。** 清理 144 条存量悬空 + 9 条孤儿引用 + 加一个断链检测，不改 ref 协议、不改 schema，就能把"已发放引用可解析率"从 61.2% 提到 100%。这一段优先于任何新写入点。

## 2. 第 1 件事：复算比例（按指标 + 按调用路径）

### 2.1 为什么 1.7% 不能对外用

`/metrics/{id}/output?compute=false`（代码 `metrics.py` 的 `output()`）每次调用会：

1. 写 **1 条** `metric_observation_set`（覆盖该指标该窗口的**全部**观测行，`row_count` 记录行数）；
2. 写 **最多 3 条** `metric_observation_row`（`SAMPLE_LIMIT = 3`，`ORDER BY entity_key LIMIT 3`）。

所以"registry 行数"与"观测行数"没有可比性。用 642/37,477 得出的 1.7%，等价于说"CUST-001 有 5,000 行观测但只发了 3 条行引用"，而实际上它的 5,000 行**全部**被那条集合引用覆盖。

### 2.2 四个"真"比例

| 口径 | 计算 | 结果 | 解读 |
| --- | --- | --- | --- |
| 集合级活覆盖 | 被 ≥1 条 live `obs-set` 覆盖的观测行 / 37,477 | **37,472 / 37,477 = 99.99%** | 只有 `FIN-INS-017` 的 5 行没有任何引用 |
| 逐行活覆盖 | 被 live `obs` 行引用指到的观测行 / 37,477 | **164 / 37,477 = 0.44%** | 逐行引用只是"样本行"，不是全量 |
| 结构可构造率 | 自然键完整的观测行 / 37,477 | **37,477 / 37,477 = 100%** | 任何一行都能被生成合法 ref，所缺的只是生成动作 |
| 引用新鲜度 | live 观测级引用 / 全部观测级引用 | **227 / 371 = 61.2%** | 144 条悬空，全部产生于重灌之前 |

### 2.3 按调用路径（这是 registry 目前**没有**记录的一维）

`obs` / `obs-set` 的 locator **只有** `metricId / definitionVersion / entityKey / windowStart / windowEnd / asOf / periodStart / periodEnd / institution / fixture`，**没有 `endpoint`、没有 `caller`、没有 `requestId`**。只有 `metric_computation` 的 locator 带 `endpoint / caller / computedAt`。

因此观测级引用"是哪个端点产生的"目前**无法从库内归因**，下表的后两列是**按代码路径反推**（可信，但不是审计证据）：

| 路径 | 是否写 ref | 指标数 | 当前证据 | 归因方式 |
| --- | --- | --- | --- | --- |
| `/metrics/{id}/output?compute=false` | 1 set + ≤3 row | **56** | 152 set（63 live）+ 219 row（164 live） | 代码反推（locator 无 endpoint） |
| `/metrics/{id}/output?compute=true` | 上述 + 1 `metric_computation`（带 `observationRef`） | **9** | 45 comp，45 条 `observationRef` 全 live | locator 有 `endpoint`，可直接统计 |
| `/metrics/{id}/compute`（G2 方案 A） | 1 `metric_computation`（**只带 `factTables`/`sampleRows`**） | **9** | 193 comp，`observationRef` = **0** | locator 有 `endpoint`，可直接统计 |
| `/qa` | 若干 `document_chunk` + 数值引用的 `obs-set` | **0（无可归因的指标格）** | 28 doc（28 live）；数值引用只写 set、不写行、不带 requestId | 无 per-answer 审计键，无法归因到指标 |
| 实体页 | 0 | **0** | `_g4_citation_view` 只读 `hasSourceRef`，不调 `register_ref` | 代码确认 |
| `/browse/facts` | `fact_row` | — | 5 条（手工/测试） | 非页面自动写入 |

**结论：路径覆盖格 = 56（`/output`）+ 9（`/compute`）+ 0（`/qa`）+ 0（实体页）= 65 / 228 = 28.5%。**

### 2.4 悬空的来源（不是"引用发错了"，是"数据换过版本"）

按 `issued_at` 分小时看观测级引用：

| 发放时段 | 引用数 | live | stale | 备注 |
| --- | --- | --- | --- | --- |
| 2026-11-06 16:xx | 55 | 0 | **55** | 全量悬空，早于重灌 |
| 2026-11-06 23:xx | 261 | 181 | **80** | 跨重灌边界 |
| 2026-11-07 00:xx | 47 | 40 | 7 | 重灌进行中 |
| 2026-11-07 08:xx | 2 | 0 | 2 | 重灌尾部 |
| 2026-11-07 09:xx | 6 | 6 | 0 | 重灌之后，全 live |
| **合计** | **371** | **227** | **144** | **38.8% 悬空** |

观测在 00:16:51–08:31:36 之间被全量重算，`metric_observation` 按自然键 upsert；重灌前发放的引用若自然键没被重新产出（窗口换成 2025 年度、`fixture` 从 true 变 false、旧 fixture 期实体键消失），就变成 `E_SOURCE_REF_STALE`。

另有一类更隐蔽的：**9 条引用指向已经完全没有观测的指标**——`FIN-BANK-035`（4 条）、`FIN-BANK-036-v1`（5 条）。这两条指标现在 0 观测，引用必悬空；它们不出现在 57 行表里，但在 registry 里占位。

`source_ref_registry` **没有数据版本字段**（无 `data_version`、无观测指纹），因此解析器只能做"逐条 EXISTS 命中"，无法回答"这批引用是对哪个数据版本发放的"。

## 3. 第 2 件事：拆缺口

### 3.0 先分清两个"引用终点"

| 引用终点 | 受众问题 | 现状 | 谁能补 |
| --- | --- | --- | --- |
| **观测行 / 计算事件**（值从哪来） | "这个数是怎么算出来的、原始行在哪" | 结构可构造 100%，实际发放只覆盖 28.5% 路径格 | **工程（技术可做）** |
| **制度条款 / 流程规则**（凭什么这么算） | "这个口径有哪条制度依据" | 57 指标中仅 29 条 `EVIDENCED` | **业务（卡输入）** |

这两件事必须分开宣称。把"引用真空"归因为"业务没给口径"是错的；把"依据缺失"归因为"工程没接线"也是错的。

### 3.1 技术可做（T1–T9）

全部是写入点、字段、检测或端点的补齐，不依赖任何业务答复。

| 编号 | 缺口 | 证据 | 补法（只描述，不实施） |
| --- | --- | --- | --- |
| **T1** | 观测级引用**无法按路径归因** | `obs`/`obs-set` 的 locator 无 `endpoint`/`caller`/`requestId`；只有 `metric_computation` 有 | 在 `metrics.py` 调 `metric_source_payload` 处透传 `endpoint`/`caller`，写进 set/row 的 locator；存量 ref 不回填（保留历史语义） |
| **T2** | 逐行引用只有 3 条样本 | `SAMPLE_LIMIT = 3`；L2 活覆盖 0.44% | 二选一：(a) 引用语义升级为"可展开集合"，前端按 `resolveUrl` 拉全量；(b) 新增明细端点，按页写行引用。**不建议**给 5,000 行写 5,000 条 ref（registry 会爆） |
| **T3** | `/compute` 上游断链 | 193 条 comp 只有 `factTables`/`sampleRows`，`observationRef` = 0 | `_record_computation` 已支持 `observationRef` 参数（`/output?compute=true` 在用）；`/compute` 分支补传即可 |
| **T4** | 引用新鲜度**无数据版本** | registry 无 `data_version`；重灌后 144 条悬空 | (a) registry 增 `data_version`/`observed_at` 列（schema 变更）；(b) 先加只读"断链检测"：定时跑活性 EXISTS，把 stale 引用打成告警并出清单 |
| **T5** | 实体页 0 引用 | `_g4_citation_view` 有 `hasSourceRef` 但不 `register_ref` | 实体页取数时复用 `observation_set_descriptor` + `register_ref`；纯读端点，风险低 |

## 4. 第 3 件事：路径与分档

### 4.1 建议的对外口径（先把尺子定下来）

不建议继续用"覆盖率"一个词。建议对外只报 **VCR（Verifiable Citation Rate，可核查引用率）**，定义明确、可复测：

> 在一次固定的验收跑（57 个有观测指标 × 4 条路径，共 228 格）中，返回的每一条 citation 同时满足：
> **(a)** 解析为 live（不是 `STALE`/`NOT_FOUND`）；
> **(b)** 其指标 `evidence_status = EVIDENCED`；
> **(c)** 发放后 24h 内不出现悬空。
> VCR = 同时满足 (a)(b)(c) 的引用数 / 全部引用数。

当前三项分读数：**(a) 61.2%（227/371）**、**(b) 29/57 指标 = 50.9%**、**(c) 0（144 条存量悬空）**。

对外宣称的分界建议：

| 宣称语 | 需要达到 |
| --- | --- |
| "每个数都能点回观测行" | (a) = 100% 且 (c) = 100%（L1 ≥ 99.99% 已满足） |
| "每个数都能追溯到计算过程" | 上面 + 路径格 ≥ 60%（`/output` 与 `/compute` 两段全覆盖） |
| "每个数的口径有制度依据" | 上面 + (b) ≥ 60%（≥ 34/57），这一段**只能靠业务答复推进** |

**A2 集合级 / 逐行覆盖（L1 / L2）**

```sql
WITH refs AS (
  SELECT r.ref_kind, r.locator,
    EXISTS (
      SELECT 1 FROM platform.metric_observation o
      WHERE o.metric_id = r.locator->>'metricId'
        AND o.definition_version = r.locator->>'definitionVersion'
        AND (
          (r.ref_kind = 'metric_observation_row'
             AND o.entity_key = r.locator->>'entityKey'
             AND o.window_start = (r.locator->>'windowStart')::date
             AND o.window_end = (r.locator->>'windowEnd')::date)
          OR
          (r.ref_kind = 'metric_observation_set'
             AND (((r.locator->>'asOf') IS NOT NULL AND o.as_of = (r.locator->>'asOf')::date)
               OR (((r.locator->>'periodStart') IS NOT NULL) AND ((r.locator->>'periodEnd') IS NOT NULL)
                   AND o.window_start >= (r.locator->>'periodStart')::date
                   AND o.window_end <= (r.locator->>'periodEnd')::date))
             AND ((r.locator->>'entityKey') IS NULL OR o.entity_key = r.locator->>'entityKey')
             AND ((r.locator->>'institution') IS NULL OR o.institution = r.locator->>'institution')
             AND ((r.locator->>'fixture') IS NULL OR o.fixture = (r.locator->>'fixture')::boolean))
        )
    ) AS ok
  FROM platform.source_ref_registry r
  WHERE r.ref_kind IN ('metric_observation_row','metric_observation_set')
)
SELECT (SELECT count(*) FROM platform.metric_observation) AS total,
       (SELECT count(*) FROM platform.metric_observation o
        WHERE EXISTS (SELECT 1 FROM refs f
                      WHERE f.ref_kind='metric_observation_row' AND f.ok
                        AND f.locator->>'metricId'=o.metric_id
                        AND f.locator->>'definitionVersion'=o.definition_version
                        AND f.locator->>'entityKey'=o.entity_key
                        AND (f.locator->>'windowStart')::date=o.window_start
                        AND (f.locator->>'windowEnd')::date=o.window_end)) AS row_cov,
       (SELECT count(*) FROM platform.metric_observation o
        WHERE EXISTS (SELECT 1 FROM refs f
                      WHERE f.ref_kind='metric_observation_set' AND f.ok
                        AND f.locator->>'metricId'=o.metric_id
                        AND f.locator->>'definitionVersion'=o.definition_version
                        AND ((f.locator->>'entityKey') IS NULL OR f.locator->>'entityKey'=o.entity_key)
                        AND ((f.locator->>'institution') IS NULL OR f.locator->>'institution'=o.institution)
                        AND ((f.locator->>'fixture') IS NULL OR (f.locator->>'fixture')::boolean=o.fixture)
                        AND ((f.locator->>'asOf' IS NOT NULL AND o.as_of=(f.locator->>'asOf')::date)
                          OR (f.locator->>'periodStart' IS NOT NULL AND o.window_start>=(f.locator->>'periodStart')::date AND o.window_end<=(f.locator->>'periodEnd')::date))) AS set_cov;
```
