# 69 · 验收可证明性与栈隔离（2026-11-06/07）

## 0. 一句话结论

本次改动只动“跑多少、怎么判定、跑在哪”，**没有放宽断言、没有把失败改跳过、没有删除用例**。
两套验收脚本改为：全量发现 + discovered/executed 自检 + `skipped>0` 即不通过 + 证据入仓；
`acceptance.ps1` 在重型锁被他人持有时**直接中止**（exit 75），并把默认目标改为独立栈
`platform-acceptance`（8082/5433/7882/8083 + 独立数据根）。

## 2. 改动清单

### 2.1 `platform/scripts/acceptance-s14.ps1`（S14 全量 unittest）

- 删除 7 个 `-k` 关键词过滤，改为在容器内执行 `tests/_acceptance_runner.py`，
  由 `unittest` 全量发现 `test_*.py`。
- 新增显式排除：`-ExcludeFiles <module,...>`。默认**空**；一旦有排除，打印
  `excluded_files` 与条数，并 **exit 3（覆盖缺口）**，不允许“带缺口还全绿”。
- 自检：runner 在进程内统计 `discovered_total / excluded / discovered / executed`，
  记录实际执行过的 test id；`discovered != executed` 时打印 `ACCEPTANCE_NOT_EXECUTED`
  与 `ACCEPTANCE_MISMATCH`，脚本 **exit 2**。
- 判定：`failed/errors/import_failures/skipped` 任一非 0 → **exit 1**；`skipped` 逐条打印
  reason，reasoner 相关标注 `SKIPPED_DEPENDENCY`，其余 `SKIPPED_OTHER`。
- 证据：`doc/evidence/acceptance-s14-<project>-<ts>-<sha>.log`。
- 锁：改为**按栈**的 `.lock/<project>.heavy.lock`，被占时在跑任何用例前 exit 75。

### 2.2 `platform/tests/acceptance.ps1`（S0–S13）

- 自检：5 个 smoke suite 必须打印 `passed/total` 且 `passed==total`；`exit=0` 但
  `total<=0` 或 `passed!=total` 判 FAIL（防“退出 0 但一条没跑”）。S0 `platform smoke`、
  `smoke-embed` 同样纳入。
- 判定：`skipped>0` → **exit 2（不通过）**；reasoner 缺失的派生跳过标注
  `SKIPPED_DEPENDENCY`；`smoke-s13` 的 75 标注 `SKIPPED_BLOCKED`。没有把任何失败改跳过。
- 负向断言收紧（只收紧不放宽）：`facts-verify` / `facts-replay` 的“应拒绝”不再接受
  125/126/127（docker/命令自身用法错误），避免“因系统错误而看起来通过”。
- 证据：`doc/evidence/acceptance-s0s13-<project>-<ts>-<sha>.log`。
- compose 查询失败（`config --services` / `ps` 非 0）直接中止，不再把 0 个服务误判为
  “containers running”。

### 2.3 锁被占即中止（止血）

旧行为（审计根因）：`heavy.lock` 被他人持有时只跳过“起容器”（约 L175–L188），随后仍
无条件跑全部 smoke（L233+）。锁形同虚设，三个会话在同一栈交替 publish/rollback。

新行为：

1. 读锁快照后、在任何 `compose config / ps / smoke` 之前判断；被他人持有 → 打印
   owner / pid / host / purpose / started_at / heartbeat_at / age / lock_file，
   并给出人工 `release` 与 `check` 命令，**exit 75（E_BUILD_CONFLICT）**。
2. 若快照空闲但 `acquire` 时被抢（竞态），同样中止，不再“warn 后继续”。
3. 锁路径按栈：共享栈 `.lock/heavy.lock`，独立栈
   `.lock/platform-acceptance.heavy.lock`。
4. 释放：正常结束/断言失败/异常都走 `try/finally` 释放（实测日志有
   `released owner=...`）；被强杀无法捕获，靠 **TTL 10 分钟** + 下一轮运行时打印的
   owner/释放命令人工处置。`-OnlyPreflight` 是只读诊断，不跑 smoke，允许在锁占用下执行。

### 2.4 测试隔离（治本）

默认目标从共享栈改为独立栈：

| 项 | 旧默认 | 新默认 |
|---|---|---|
| compose 项目 | `agent-platform` | `platform-acceptance` |
| API | `127.0.0.1:8080` | `127.0.0.1:8082` |
| PostgreSQL | `5432` | `5433` |
| reasoner | `7879` | `7882` |
| embedding | `8081` | `8083` |
| 图库宿主端口 | `7878` | **0（不发布）** |
| 数据根（对象存储/导出/配置） | `D:\agentABC\data` | `D:\agentABC\data-acceptance` |
| 重型锁 | `heavy.lock` | `platform-acceptance.heavy.lock` |

隔离边界：

- 数据库：项目命名卷 `platform-acceptance_pgdata` + 端口 5433，**独立**。
- 图库：项目命名卷，**独立**，且不发布宿主端口（仍受 GSP 治理面约束）。
- 对象存储/导出：bind `D:\agentABC\data-acceptance`，**独立**。
- 指针（`tbox/current` 等）：随独立 PostgreSQL，**独立**。
- 共用：镜像 `agent-platform:0.1-s5`；BGE-M3 模型文件以 `:ro` 只读挂载
  （静态资产，不随运行变化）；宿主 CPU/内存（跨栈不互斥）。

启动方式（可复制执行）：

```powershell
cd D:\agentABC\coa\platform
powershell -ExecutionPolicy Bypass -File scripts\acceptance-stack.ps1 up    # 起 5 个服务
powershell -ExecutionPolicy Bypass -File tests\acceptance.ps1               # S0–S13（默认隔离栈）
powershell -ExecutionPolicy Bypass -File scripts\acceptance-s14.ps1         # S14 全量（默认隔离栈）
powershell -ExecutionPolicy Bypass -File scripts\acceptance-stack.ps1 down  # 停栈（保留数据根）
```

共享栈属**显式少数派**行为，必须同时传：

```powershell
powershell -ExecutionPolicy Bypass -File tests\acceptance.ps1 `
  -ComposeProject agent-platform -ApiBaseUrl http://127.0.0.1:8080 -PgPort 5432 `
  -ReasonerPort 7879 -EmbeddingPort 8081 -DataRoot D:\agentABC\data
```

## 5. 被排除项与理由

**默认排除清单为空，本次两次全量运行 excluded 均为 0。**
若未来必须分组，只能走 `-ExcludeFiles`，脚本会打印被排除文件与条数并 exit 3，
不允许把排除当作“全绿”。

## 6. 已知限制（如实说明）

1. 独立栈的 S14 全量要真正全绿，需要把共享栈的历史夹具（固定版本、词表）导入隔离库，
   或提供独立 seed 流程；本次**没有**做数据搬迁，所以 4.4 的失败按原样保留。
2. BGE-M3 模型文件是唯一跨栈复用的内容，以 `:ro` 挂载；它不随运行变化，但不是
   “完全零共享”。数据库、图库、对象存储、指针均无共用卷。
3. `platform.example.yaml` 当前存在 `canvas.provider: off`（YAML 读成 bool，schema 校验
   失败）的历史缺陷；本次未修改该文件，独立栈 seed 优先复制已跑通的共享
   `platform.yaml`（仅文件复制，不共用卷），并在启动前用 `platform check-config` 预检。
4. 两栈共享同一镜像与宿主资源；跨栈锁不互斥，仍不应同时跑两个重型任务。
5. 强杀进程（Stop-Process / 断电）无法执行 `finally` 释放锁；靠 10 分钟 TTL 与下一轮
   打印的 owner + `release` 命令人工处置。
6. 共享栈容器被其他会话重建时，验收会如实失败（本次两次环境干扰即为例证），
   不会重试掩盖；TTL/锁只能阻止同栈并发脚本，挡不住绕过 guard 的 `compose up -d`。
