### 1.1 `api.py` 追加规则（各组共同）

1. **只允许在文件末尾追加区块**，区块用锚点包裹，形如：

```python
# --- G1 ontology routes ---
def g1_register(app: FastAPI, runtime: Runtime) -> None:
    @app.get("/ontology/proposals")
    def list_proposals() -> dict[str, Any]:
        ...
# --- end G1 ---
```

2. 每个组**只有一个**区块、**只追加一次**；锚点内的所有路由/辅助函数都放在 `gN_register` 内（闭包持有 `app` 与 `runtime`），不在模块级新增全局状态。
3. **禁止**改动 `api.py` L1–L3567 的任何既有函数体（含 `create_app`）；锚点区块必须自带 `# --- G{n} ... ---` / `# --- end G{n} ---` 成对注释。
4. 让路由生效的唯一接缝：`create_app` 的 `return app`（当前 L3567）之前加一行调用 `gN_register(app, runtime)`。**这一行由集成方在集成阶段统一插入**，各组不插入；各组本地验证时在自己的单测里显式调用 `g1_register(app, runtime)`（或等价 `TestClient` 装配）来验证路由。
5. 本组区块内的辅助函数命名统一加组前缀（`_g1_*`、`_g4_*`…），避免与既有 `_qa_*`、`_governance_*` 冲突。

## 8 推送解耦（用户定稿）

> 目标：**不让网络/认证问题卡住开发**。push 不属于任何一条开发线，也不是集成方的职责。

### 8.1 开发线（G1–G5）

1. **一任务一提交**：每个可验证切片完成即本地 `commit`，`commit message` 必须带任务编号，形如：
   - `O-02 G1: T-Box 提案/审批/supersede 状态机`
   - `M-02 G2: 对外出数清单端点与导出`
   - `R-01 G4: 可答性分层覆盖度面板`
   - `R-05 G5: /browse/path 轻量多跳`
2. **绝不 push**：`git push` 在五条线中一律禁止；也不得配置 push 相关的 hook/别名去间接推送。
3. 完成后回报三件套：**commit sha + 变更文件清单 + 单测结果**（单测结果写"命令 + 通过数/失败数"）。
4. 禁止 `git rebase`、`git commit --amend` 已提交的历史（避免推送方拿到变动 sha）；后续修正走新提交。
5. 未跟踪的临时产物（如 `_tmp_*.json`）在提交前清理或加入忽略，不得混入提交。

### 8.2 推送线（单一专职任务）

1. 由**一个专职任务**统一按队列推送，队列固定为：
   `feat/o-gov` → `feat/m-core` → `feat/m-report` → `feat/r-qa` → `feat/canvas` → `feat/integration`。
2. 推送远端是 **`luke`**（`git@github.com:LukeLi-EBD/context-ontology-accelerator.git`），**同名分支**；
   仓库里的 `origin` 指向 `aws/context-ontology-accelerator`（上游），**禁止推送到 `origin`**。
   样例：`git push -u luke feat/o-gov:feat/o-gov`。
3. **逐分支推送**：单分支失败不影响其它分支；失败重试带退避（如 3 次，间隔递增），仍失败则记录该分支状态为 FAILED 并继续下一个。
4. **推送前秘钥扫描**：对该分支"起点 commit..HEAD"的 diff 做扫描（密钥/令牌/私钥/口令模式、`.env`、大文件），命中即**阻断该分支**并回报，不得先推后改。
5. **禁止 force push**（含 `--force-with-lease`）；被拒时只允许 `--ff-only` 重试或新增提交后再推，冲突回报给对应开发线处理。
6. 推送结果回报格式：分支名 / commit 区间 / 结果（OK/FAILED/BLOCKED）/ 失败原因。

### 8.3 集成

1. 合并在本地完成（§5），`feat/integration` 的推送同样交给推送线，**集成方不直接 push**。
2. 集成阶段的镜像重建与两套验收完成后，只回报结论摘要（通过数/失败数/已知失败项），不触发推送动作。
3. 本契约文档本身的提交：只在 `luke` 本地提交，**不 push**。
