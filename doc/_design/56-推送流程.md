# 56 · 推送流程（专职推送任务）

## 1. 背景

开发线各自在本地 `commit`，`push` 到 GitHub 的动作统一交给一个专职推送任务执行。目的是把网络/SSH 抖动、鉴权失败、远端拒绝这类故障**限制在推送任务内**，不阻塞任何开发线。

职责边界：

- 推送任务**不写业务代码、不改业务逻辑、不动已提交内容**。
- 只做：预检 → 推送 → 重试 → 校验 → 汇总回报。
- 推送任务本轮只允许在 `luke` 分支本地提交"脚本 + 本文档"，不执行推送。

## 2. 远端事实（必须先读，避免误推）

| 远端名 | URL | 性质 | 是否可推 |
|---|---|---|---|
| `origin` | `https://github.com/aws/context-ontology-accelerator.git` | **上游只读仓库**（用于 mirror-sync 对比） | **禁止推送** |
| `luke` | `git@github.com:LukeLi-EBD/context-ontology-accelerator.git` | 用户自有的可写仓库（SSH 已配置） | **唯一推送目标** |

结论：

- 所有推送一律 `git push -u luke <branch>:<branch>`。
- **禁止 `git push origin`**。`scripts/push-queue.ps1` 内置硬拦截：`-Remote origin` 或远端 URL 含 `aws/context-ontology-accelerator` 时直接 `FATAL` 退出（退出码 2），不发包。
- `luke` 分支当前**没有 upstream**，首次推送用 `git push -u luke luke:luke` 建立跟踪关系。

## 3. 分支队列

默认队列（`scripts/push-queue.ps1` 的 `$DefaultBranches`）：

```
feat/o-gov  feat/m-core  feat/m-report  feat/r-qa  feat/canvas  feat/integration
```

另外两个分支按需推送（不在默认队列）：

- `luke`：主线，仅在明确要求"推 luke"时执行；首次推送带 `-u`。
- `feat/metric-loader`：历史分支，远端已存在且当前一致。

`main` / `master` 属于保护分支，脚本直接 `REFUSED`，一律人工处理。

## 4. 触发方式

**只有**收到用户明确指令才执行：

| 指令 | 行为 |
|---|---|
| `推 <分支名>` | 只推该分支（例如"推 feat/o-gov"） |
| `推全部` | 按默认队列顺序推 6 个分支 |
| 其他任何表述 | 不执行，先向用户确认 |

没有任何定时触发、没有后台常驻轮询。

## 5. 单分支执行流程

对队列中每个分支依次执行，**单分支失败不影响后续分支**：

1. **保护分支检查**：`main` / `master` → `REFUSED`，跳过。
2. **工作区干净检查**：`git status --porcelain` 非空 → 整批 `SKIPPED`（原因 `worktree dirty`），提示先 commit/stash；除非显式传 `-AllowDirty`。
3. **本地存在性检查**：本地无该分支 → `MISSING`（仅远端存在则为 `ABSENT_LOCAL`），跳过。
4. **明文秘钥扫描**（扫描范围 = 本次真正要推的 diff，见第 6 节）：命中 → `BLOCKED_SECRET`，该分支中止并列出文件，其余分支继续。
5. **推送**：`git push -u luke <branch>:refs/heads/<branch>`；**永不使用** `--force` / `--force-with-lease` / `+refspec`。
6. **失败重试**：最多 3 次尝试，退避 2s / 5s / 10s。
7. **结果校验**：成功后 `git ls-remote luke refs/heads/<branch>` 回读远端 sha，与本地 sha 比对；不一致记 `pushed but remote sha unverified`。
8. **写日志 + 汇总**。

## 6. 秘钥扫描规则

### 6.1 扫描范围

只扫描"即将推送的新增内容"，不扫描历史存量，避免误报阻塞：

- 远端已存在该分支：基线 = 远端分支 tip（`refs/remotes/luke/<branch>`）。
- 远端不存在该分支：基线 = 与 `luke/luke`（退化到 `luke/main`、本地 `luke`）的 `merge-base`。
- 无法确定基线 → 该分支 `BLOCKED_SECRET`（原因 `cannot determine scan base`），不做盲扫。

### 6.2 内容规则（命中即中止该分支）

| 规则名 | 匹配内容 |
|---|---|
| `private-key-header` | `-----BEGIN (RSA/OPENSSH/EC/DSA/PGP/ENCRYPTED) PRIVATE KEY-----` |
| `github-token` | `ghp_` / `gho_` / `github_pat_` 形态的 GitHub token |
| `aws-access-key` | `AKIA` / `ASIA` + 16 位大写字母数字 |
| `openai-style-key` | `sk-` + 32 位以上 token |
| `slack-token` | `xox[abprs]-` 形态 token |
| `assigned-secret` | `password` / `passwd` / `secret` / `token` / `api_key` / `access_key` / `private_key` 后跟 `:` 或 `=` 且值长度 ≥ 12 |

### 6.3 文件路径规则（命中即中止该分支）

`.env`（含 `.env.*`）、`*.pem`、`*.p12`、`*.pfx`、`*.keystore`、`*.jks`、`id_rsa` / `id_dsa` / `id_ecdsa` / `id_ed25519`、路径含 `credential`。

### 6.4 占位符豁免

命中行若含 `your_`、`your-`、`xxxx`、`example`、`sample`、`placeholder`、`changeme`、`redacted`、`dummy`、`fake_`、`<`、`${`、`$(` 之一，视为占位符/模板，不阻断。豁免只作用于内容规则，**不豁免 6.3 的路径规则**。

扫描结论写入日志：`BLOCKED_SECRET` 的 `NOTE` 列出 `规则名:文件:行号`，多命中用 `;` 分隔。

## 7. 失败处理

| 结果码 | 含义 | 处理 |
|---|---|---|
| `OK` | 推送成功且远端 sha 校验一致 | — |
| `FAILED` | 3 次尝试后仍失败 | 报告最后一条原始错误行 |
| `FAILED`（`non-retryable`） | 拒绝类错误：`[rejected]`、`non-fast-forward`、`fetch first`、`[remote rejected]`、`Permission denied (publickey)`、`denied`、`Repository not found` | **不重试**，直接报告；需人工 rebase/鉴权，脚本不做自动合并 |
| `BLOCKED_SECRET` | 秘钥扫描命中 | 列出文件与行号，等用户处理后再推 |
| `SKIPPED` | 工作区不干净 | 提示先 commit/stash |
| `MISSING` / `ABSENT_LOCAL` | 分支不存在 | 报告，等用户确认 |
| `REFUSED` | 保护分支 | 人工处理 |
| `DRY-RUN` | `-DryRun` 预检通过 | 未发包 |

回报要求：

- 汇总表字段：`分支 / 结果 / 远端 sha / 本地 sha / 耗时 / 说明`。
- 失败分支必须给出**原始错误一行**（截断到 200 字符），不得用"网络问题"含糊概括。
- 运行日志：`coa/logs/push/push-<yyyyMMdd-HHmmss>.log`（`logs/` 已在 `.gitignore` 内，不入库）。

## 8. 脚本用法

```powershell
# 预检（不推送）：看队列内 6 个分支的扫描与存在性
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\push-queue.ps1 -DryRun

# 推全部（默认队列）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\push-queue.ps1

# 推单个分支
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\push-queue.ps1 feat/o-gov

# 推 luke 主线（首次会建立 upstream）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\push-queue.ps1 luke
```

参数：`-Remote`（默认 `luke`，传 `origin` 会被拦截）、`-MaxAttempts`（默认 3）、`-BackoffSeconds`（默认 `2,5,10`）、`-AllowDirty`、`-DryRun`、`-LogDir`。

退出码：`0` 全部成功；`1` 存在未成功分支（明细见汇总表）；`2` 环境性致命错误（非 git 仓库、远端未配置、指向 origin）。

## 10. 已知限制

- 脚本不处理非快进（不会 rebase / merge / force），拒绝即上报。
- 无自动 fetch；基线基于本地已有的远端跟踪 ref。若远端被他人更新且本地跟踪 ref 过期，扫描基线可能偏旧，推送本身仍由远端拒绝兜底。
- 单进程、顺序推送，不做并发；避免同一仓库多进程写 `.git` 造成锁冲突。
