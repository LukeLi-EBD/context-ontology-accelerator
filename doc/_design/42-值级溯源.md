## 1. 目标与边界

目标：平台里每一种"值"——指标出数、事实观测行、检索命中文档块——都能携带一个
**稳定引用**，前端徽标点开后能回到产生这个值的行/块，而不是只回到"某张表"。

纳入范围：

| 值来源 | 存储表 | 粒度 |
|---|---|---|
| 指标出数值 | `platform.metric_observation` | 聚合窗口（可下钻到逐行） |
| 事实观测值 | `platform.bank_*` / `platform.cust_*` / `platform.ins_*` / `platform.loan_*` | 单行 |
| 检索命中块 | `platform.document_chunk` | 单块（`document_id` + `chunk_no`） |

非目标：PROV-O 判定链（谁判/依据哪条文本/阈值出处）在 B-02 实现；本项只负责"值→来源行/块"，
并且只追加只读解析，不参与发布门禁、不改变口径判定、不改变任何既有断言语义。

---

## 2. `source_ref` 格式

统一 scheme `src://`，四种 kind，全部由**自然键**构成：

```
src://obs/<metric_id>@<definition_version>?entity=<entity_key>&ws=<window_start>&we=<window_end>
src://obs-set/<metric_id>@<definition_version>?asOf=<d>            # 或 periodStart/periodEnd
                                                 [&entityKey=..][&institution=..][&fixture=true|false]
src://fact/platform.<table>?<key_col>=<value>&<key_col>=<value>...
src://doc/<document_id>#c<chunk_no>
```

编码规则：

* query 一律按 key 字典序、`quote`（空格编码为 `%20`，不是 `+`）后拼接，同一逻辑引用只有一种写法；
* `metric_id` / `definition_version` / 表名 / 列名走白名单正则，不接受任意字符串；
* `document_id` 为现有 sha 前缀（十六进制）；`chunk_no` 为 `document_chunk.seq`（0 基）；
* 不出现 `observation_id`、`chunk_id` 自增/代理 id，不出现内容哈希、不出现行号。

接口返回的徽标最小字段（B-01 验收要求的"类型、定位、可点击参数"）：

```json
"sourceRef": {
  "type": "metric_observation_set | metric_observation_row | fact_row | document_chunk",
  "ref": "src://obs-set/FIN-BANK-008@v3.0?asOf=2025-12-31&fixture=false",
  "targetTable": "platform.metric_observation",
  "locator": {"metricId": "...", "definitionVersion": "...", "asOf": "...", "fixture": false},
  "resolveUrl": "/source/resolve?ref=src%3A%2F%2Fobs-set%2F...",
  "rowCount": 20
}
```

聚合值额外返回 `sourceRefs`（最多 3 条逐行 `metric_observation_row` 引用），用于徽标下钻。

## 3. 为什么重算/版本切换后不漂移

1. **观测行 upsert 在自然键上**：`metric_observation_window_key =
   (metric_id, definition_version, entity_key, window_start, window_end)`。重算走
   `ON CONFLICT ... DO UPDATE`，同一 ref 命中的还是同一行（`observation_id` 不变）。
2. **版本写在 ref 里**：`definition_version` 是 ref 的一部分，旧版本 ref 不可能被悄悄
   重定向到新版本的行；本 schema 的 `metric_definition` 主键是 `metric_id`，一个指标同一时刻
   只有一个活版本，因此版本切换时旧观测行若被清理，解析结果是显式
   `E_SOURCE_REF_STALE`，而不是"解析到新行"——宁可他报错，不可错指。
3. **事实表用声明式自然键**：`platform.fact_source_key` 固化每张业务事实表的唯一键
   （与现有 UNIQUE 约束一致，含 `data_source` 以区分 fixture/business/synthetic）。
   ref 必须逐列匹配该键，多一列少一列都拒绝，避免"用非唯一列定位到一批行"。
4. **文档块用 `(document_id, seq)`**：块内容可重建、可重新切分，但同一文档的块序号是
   稳定定位；`chunk_id` 只是 `document_id:seq` 的拼接，ref 不依赖它。
5. **不在源表里复制"渲染后的 ref 列"**：复制会让键字段与 ref 两份真相漂移；本项一律
   由存储的自然键在解析时重建 ref。

补充：`source_ref_registry` 只记录"这个 ref 曾经发给过调用方"，用于区分
"从未存在"（NOT_FOUND）与"曾发出、现已失效"（STALE）。解析永远以活表为准，registry
不是来源真相。

## 4. 存储

| 存储对象 | 位置 | 说明 |
|---|---|---|
| 观测自然键 | `platform.metric_observation`（既有唯一约束） | 不新增列 |
| 文档自然键 | `platform.document_chunk(document_id, seq)`（既有） | 不新增列 |
| 事实表自然键 | 新增 `platform.fact_source_key(table_name, key_columns text[], grain_note, added_at)` | 28 张业务事实表，逐表与 UNIQUE 约束对齐 |
| 已发出的 ref | 新增 `platform.source_ref_registry(source_ref PK, ref_kind, target_table, locator jsonb, issued_at, resolve_count)` | 追加写；仅用于 stale 判定 |

迁移：`V27__source_ref.sql`，`SUPPORTED_SCHEMA_VERSION = 27`，全部 `IF NOT EXISTS` /
`ON CONFLICT DO NOTHING` 可重入；不改任何既有表的列或约束。

## 5. 接口落地

| 位置 | 新增/变化 | 说明 |
|---|---|---|
| `GET /metrics/{id}/output?compute=true` | 顶层新增 `sourceRef`、`sourceRefs` | 观测集合 ref + 最多 3 条逐行 ref；聚合值可直接下钻 |
| `GET /answer` | `sourceRef`、`sourceRefs` 顶层；`citations[].sourceRef`；新增 `kind=value-source` 引用 | 指标值引用 + 文档块 `document_id`/`chunkNo` 徽标 |
| `GET /browse/facts?table=&limit=` | 新增只读端点 | 返回样例行 + 每行 `sourceRef`（事实表行级示例入口），`readOnly=true`，零写操作 |
| `GET /source/resolve?ref=` | 新增解析端点 | 校验 kind/自然键/白名单，返回活行或明确错误码 |
| `web/browse.js` | 问答答案行加"溯源 · 表名"链接；citation chip 加"溯源"徽标 | 徽标使用 `resolveUrl`，新窗口只读 JSON |

`/browse/facts` 与 `/browse/metrics` 一样保持只读；registry 的写入只发生在
`/metrics/.../output?compute=true`、`/answer`（发给调用方的 ref）与首次解析未登记 ref 时。

## 6. 解析与错误码

| 场景 | 错误码 | HTTP |
|---|---|---|
| scheme/结构/缺自然键/键列不符 | `E_SOURCE_REF_MALFORMED` | 400 |
| 未知 kind | `E_SOURCE_REF_TYPE_UNSUPPORTED` | 400 |
| 表不在 `fact_source_key`、或非事实表（越权/越界） | `E_SOURCE_REF_FORBIDDEN` | 403 |
| 从未发出的 ref 且活表无行 | `E_SOURCE_REF_NOT_FOUND` | 400 |
| 曾发出、活表中行/块已不存在 | `E_SOURCE_REF_STALE` | 400 |

解析成功返回 `found=true`、`issued=true|false`、`state="live"`、`rowCount`，观测集合附
最多 3 行样本，事实行返回整行（Decimal/日期已转 JSON 标量），文档块返回
`chunk_id/document_id/seq/page_from/page_to/text_preview`。

## 8. 已知限制

* `metric_definition` 主键为 `metric_id`，同一指标不能同时保留两个活版本；因此
  "版本切换后旧观测行仍可解析"只在行未清理时成立，行被清理时按设计报 `STALE`。
* 本平台无鉴权：`E_SOURCE_REF_FORBIDDEN` 的"越权"指**越出事实源白名单**（例如指向
  `metric_definition`/系统表），不是用户身份越权。
* 聚合值只给 3 条逐行样本；完整集合由 `obs-set` ref 的 `rowCount` + 解析端点返回的
  前 3 行表达，避免把 16 万行塞进响应。
