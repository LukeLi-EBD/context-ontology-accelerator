# 40 · 合成数据生成器

> 状态：已落地（V26 + `platform_core/datagen.py` + CLI `platform datagen`）
> 定位：在**没有真实数据**时，为 28 张事实表与 30 条结构性可执行指标提供可运行、可校验、可清除的测试数据。
> **合成数据不得用于对外报送、监管披露或任何业务结论。** 它是测试夹具，不是事实。

---

## 1. 目标与边界

| 项 | 要求 | 落地 |
| --- | --- | --- |
| 表/列/类型/主键 | 从 schema 读取，不手写 | `information_schema.columns` + `pg_index` 唯一键 |
| 关系 | 来自本体/事实表定义 | `RELATIONS` 注册表（22 条），列存在性由 schema 校验保证 |
| 字段缺失 | 报错而非静默跳过 | `E_DATAGEN_SCHEMA_DRIFT`（含 missing/unknown/required 明细） |
| 规模 | 每张事实表 ≥1000 行，主实体 ≥5000 行 | 28/28 达标（见 §4） |
| 自洽 | FK 闭合、时间序合理、金额守恒 | §3 四项校验，违规 0 |
| 可复现 | 固定 seed 逐行一致 | §5 摘要比对，两次结果相同 |
| 隔离 | 不写 `metric_observation`/T-Box/口径表 | §6，单测断言前后行数不变 |
| 依赖 | 不引入新依赖 | 标准库 + psycopg/rdflib（已有） |

**代码边界**：只新增 `datagen.py`、CLI 注册、`V26__datagen.sql`、测试与本文件；未改 `api.py`，未改动既有迁移。

## 2. 生成规则

### 2.1 驱动方式（schema 驱动）

1. `discover_tables()`：扫描 `information_schema.columns` 中 `table_schema='platform'` 且含 `data_source` 列的表，排除 `metric_observation`，得到 28 张事实表。
2. `introspect()`：读取每张表的列名、`data_type/udt_name`、可空性、默认值、序号与唯一键（`pg_index`）。
3. `SyntheticFactory` 为每张表提供 `_t_<table>` 生成方法；`supported_tables()` 自动发现。schema 新增事实表但缺配方时抛 `E_DATAGEN_TABLE_UNSUPPORTED`。
4. `_insert_rows()` 先注入默认标注列，再按 `TableInfo.required_columns` 校验；列集合不一致或必需列缺失都抛 `E_DATAGEN_SCHEMA_DRIFT`，**不会静默跳过**。

### 2.2 实体池与锚点

| 池 | 数量 | 说明 |
| --- | --- | --- |
| 客户 `cust_master` | 6000 | 5000 个 2025-12-31 快照 + 1000 个 2025-06-30 历史快照（每 5 个取 1） |
| 保单 `ins_policy` | 6000 | 产品/渠道/机构/状态轮转 |
| 贷款账户 `bank_loan_account` | 5020 | 5000 常账户 + 20 条 2025-12-30 零余额快照（分母为 0 case） |

固定锚点：`AS_OF=2025-12-31`、`WINDOW_START=2025-01-01`、`WINDOW_END=2025-12-31`、`created_at=2025-12-31T00:00:00Z`。
随机数只使用 `random.Random(seed)` 与 `hashlib.md5` 派生，不使用进程随机 `hash()`，保证跨进程一致。

### 2.3 关系自洽规则

| 规则 | 实现 |
| --- | --- |
| 客户 → 保单/账户/额度/申请/存款/预警/交易/活动/投诉/持有/行为/AUM | 全部引用实体池中的 `customer_no`，无悬挂 |
| 账户 → 还款/计划/催收/不良 | 子行 `account_id = parent.account_id`，`status_as_of = as_of` |
| 催收 → 回收 | `case_id` 同源；回收日 2025-11-30，晚于首期到期日 |
| 保单 → 理赔/缴费/事件 | `policy_no` 同源；事件日落在 `[issue_date, as_of]` |
| 不良 → 处置 | `asset_id` 同源；处置完成日不晚于快照日 |
| 金额守恒 | 3 期计划的 `sum(due_amount) = principal × (1 + 5%)`，精确到分，误差 0 |
| 时间序 | 放款日 < 到期日；计划/还款到期日落在贷款存续期；理赔决定日 > 出险日；催收回收日晚于逾期首期；缴费日落在保单有效期内 |

### 2.4 标注与清除

- 每行默认写入 `data_source='synthetic'`、`fixture=false`、固定 `created_at`；不接受调用方覆盖。
- `--clean` 只执行 `DELETE ... WHERE data_source='synthetic'`，并记录删除前后全表行数与 synthetic 行数；断言“删除量 = 删除前 synthetic 量”且“删除后 synthetic = 0”，否则抛 `E_DATAGEN_CLEAN_ASSERT`。
- 账本表 `platform.datagen_run` 记录 `run_id/seed/scale/target_schema/status/row_counts/coverage/checks/时间`，`notes` 固定写明“synthetic test data; never publish as business results”。

## 5. 可复现性与校验方法

- 固定 `seed`、固定时间锚点、不使用 `hash()`。
- 校验方法：对每张表按唯一键排序，`MD5(string_agg(row_to_json))` 得表摘要；再对 28 个表摘要拼接取 sha256。同 seed 生成两次后比较：
  - 第一次：`268e877116f45986f8f15e27f75df714fcc967e62987c53faee5d2f77f3df4a5`
  - 第二次：`268e877116f45986f8f15e27f75df714fcc967e62987c53faee5d2f77f3df4a5`
- 不一致抛 `E_DATAGEN_REPRO_MISMATCH`。`--skip-repro` 可跳过第二次生成（仅用于快速联调）。

## 6. 隔离方案与“测试环境例外”

### 6.1 默认隔离（生产口径）

- `datagen.allow_official_schema` 默认 `false`（`platform.example.yaml` 与 `.env` 均显式声明）。
- 关闭时写 `platform` schema 直接抛 `E_DATAGEN_TARGET_FORBIDDEN`。
- 安全模式使用独立 `synthetic` schema：按 `platform` 的实时 DDL `CREATE TABLE ... (LIKE platform.x INCLUDING ALL)`，schema 变化自动跟随。
- 任何模式下都不写 `platform.metric_observation`、`metric_definition`、`metric_field_binding`、`ontology_version` 与 T-Box 图。

### 6.2 本轮“测试环境例外”

**为什么允许写正式 schema**：当前库是测试环境，事实表尚无真实业务数据；直接灌 `platform` 现有事实表可让 30 条指标走与真实查询完全一致的表名/绑定/口径路径，避免“合成 schema 与正式 schema 漂移”造成的假通过。

**如何标注**：每行 `data_source='synthetic'`，不伪装、不隐藏；`fixture=false`；`created_at` 固定。指标响应中 `dataSource=synthetic` 原样保留。

**如何一键清除**：

```bash
platform datagen --schema platform --clean-only   # 只删 data_source='synthetic'，输出前后对比
```

**上线真实数据前必须做的三件事**：

1. 将 `datagen.allow_official_schema` 改回 `false`（或删除 `.env` 中的 `PLATFORM__DATAGEN__ALLOW_OFFICIAL_SCHEMA`）；
2. 执行一次 `--clean-only`，确认所有事实表 `data_source='synthetic'` 行为 0；
3. 复核 `metric_observation` 无 `synthetic` 行（正常应恒为 0）。

> 若忘记关闭开关，生成器仍会成功写入正式 schema。开关是**部署纪律**，不是运行时自动识别真实数据的机制。

### 6.3 publishable 门禁

- `publishable=true` 指标正常出数，响应保留 `dataSource=synthetic`；
- `publishable=false` 指标仍拒（`E_METRIC_NOT_PUBLISHABLE`）。这是口径门禁，不随环境开关放开。

## 8. CLI 与配置

```bash
# 生成 + 四项校验 + 可复现比对 + 30 指标端到端（默认写 platform，需开关打开）
platform datagen --seed 42 --scale 1 --schema platform --rows-per-table 1000 --clean --verify

# 只生成和校验，跳过第二次复现生成
platform datagen --seed 42 --scale 1 --schema platform --clean --skip-repro

# 预览行数，不落库
platform datagen --seed 42 --scale 1 --schema synthetic --dry-run

# 按 data_source 精准清除
platform datagen --schema platform --clean-only
```

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `datagen.allow_official_schema` | `false` | 本机测试环境 `.env` 显式 `true`；环境变量 `PLATFORM__DATAGEN__ALLOW_OFFICIAL_SCHEMA` |

退出码：`completed/dry-run` → 0；校验失败或 `E_DATAGEN_*` → 非 0。

## 10. 假数据边界声明

- 本生成器的全部数值、日期、客户、保单、账户、理赔、催收与交易均为**程序构造**，不代表任何真实机构、客户或业务事实。
- **不得用于对外报送、监管报告、投资决策、绩效考核或任何业务结论**；只允许用于测试、演示与能力验证。
- 数据中出现的机构编号 `INST-SYN-xx`、ID 前缀 `*-SYN-*` 都是合成标记，便于审计识别。
- 任何引用合成数据结果的文档/报表必须标注 `data_source=synthetic` 与本节声明。
