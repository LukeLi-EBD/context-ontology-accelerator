## 0. 阅读约定

1. **IDL 是规范性伪代码**，用于对齐字段、语义、错误与能力；不是某种语言的实现。
2. `?` 表示可选字段；`Page<T>`、`Stream<T>`、`Map<K,V>` 为通用类型。
3. 每个端口有 `v1` 版本；只做加法演进，破坏性变更升 `v2`。
4. 每个 provider 必须提供 **Provider Manifest**，声明 `capabilities` 与 `limits`；启动时校验，运行期以 `Unsupported` 显式失败。
5. **命名对齐 COA SPI**：`GraphStore`、`VectorStore`、`LLMClient`、`EmbeddingClient`、`DatastoreDAO` 直接沿用 COA v0.3.8 的命名；平台额外定义 `OntologyRegistry`、`ContextResolver`、`ExtractionPipeline`。
6. **COA 是参考实现，不是库**：本文借用其 SPI 契约与语义层概念，不复制其 CDK/装配代码；`stores/factory.py::build_stores` 与 `lexical/store_factory.py` 的 `neptune-db://`/`aoss://` 硬编码不进入平台契约。

## 2. 通用契约

### 2.1 错误模型

所有端口返回统一 `PortError`，不返回 SDK 异常类型。

```text
type PortError {
  code: ErrorCode
  message: string
  provider?: string
  providerCode?: string
  requestId?: string
  retryable: bool
  retryAfterMs?: int
  details?: Map<string, any>
}

enum ErrorCode {
  InvalidArgument
  NotFound
  Conflict
  PreconditionFailed
  Unsupported
  PermissionDenied
  PolicyRejected
  ResourceExhausted
  DeadlineExceeded
  Unavailable
  Aborted
  Internal
  DataLoss
}
```

| Code | 含义 | 默认可重试 | 备注 |
|---|---|---|---|
| `InvalidArgument` | 参数/格式/schema 错误 | 否 | 不要把 provider 400 一律归入此类；要区分限流/权限 |
| `NotFound` | 资源不存在 | 否 | 空查询结果不是 NotFound；返回空集合 |
| `Conflict` | 版本/唯一性/并发冲突 | 视操作 | 幂等写可重试；非幂等追加不可 |
| `PreconditionFailed` | 条件写/状态前置条件失败 | 否 | 乐观锁/状态机非法迁移 |
| `Unsupported` | provider 不支持能力 | 否 | 上层必须走能力矩阵/降级 |
| `PermissionDenied` | 权限不足 | 否 | 鉴权不在本方案，但适配器可能透出 |
| `PolicyRejected` | 内容/安全策略拒绝 | 否 | 不要与限流混淆，不能盲目重试 |
| `ResourceExhausted` | 限流/配额/容量 | 是 | 退避 + 抖动；尊重 `retryAfterMs` |
| `DeadlineExceeded` | 超时 | 视幂等 | 流式请求首 token 后失败不可透明重试 |
| `Unavailable` | 依赖不可用 | 是 | 熔断 + 退避 |
| `Aborted` | 事务/并发中止 | 是 | 重试整个操作 |
| `Internal` | 未分类内部错误 | 视情况 | 适配器 bug/未知状态 |
| `DataLoss` | 校验失败/数据损坏 | 否 | 告警；不要自动覆盖 |

### 2.2 分页、时间、ID

```text
type Page<T> { items: T[], nextToken?: string }
type PageToken = string
type Instant = string   // ISO-8601 UTC
type Duration = { value: int, unit: "ms"|"s"|"m"|"h" }
type Iri = string
type EntityId = string  // 平台内部规范 ID；可为 IRI 或 UUID
```

- 分页不保证稳定排序；需要稳定排序时显式传 `sort`。
- 所有时间用 UTC ISO-8601；provider 本地时间由适配器转换。
- 列表接口不得返回 `null`，用空数组；单对象不存在返回 `NotFound` 或 `null`（在 IDL 中标注）。

### 2.3 能力与降级

```text
type Capability = string
type ProviderManifest {
  provider: string
  port: string
  portVersion: "v1"
  providerVersion: string
  capabilities: Capability[]
  limits: Map<string, any>
  notes?: Map<string, any>
}
```

- 启动期：按“任务类型 → 必需能力”校验；不满足则 fail-fast（生产）或显式禁用任务（dev）。
- 运行期：调用未声明能力必须返回 `Unsupported`；禁止适配器“尽力而为”伪装成功。
- 降级：上层根据 `Unsupported` 选择注册好的退化路径（如 presign → 应用签名 URL；SPARQL → 受限子图查询）；降级必须记录到上下文/响应元数据。

### 2.4 版本与兼容

- 端口 `v1` 只加字段/可选方法；删除/改语义升 `v2`。
- Manifest 的 `portVersion` 必须与平台编译期契约一致；否则启动失败。
- 适配器实现版本与 provider API 版本的兼容范围在 manifest 的 `notes` 中声明。

## 4. 端口 IDL

### 4.1 `ObjectStore` v1

```text
port ObjectStore v1

put(bucket: string, key: string, body: ReadableStream, opts?: PutOptions) -> ObjectRef
get(bucket: string, key: string, opts?: GetOptions) -> ObjectStream
head(bucket: string, key: string) -> ObjectMeta
delete(bucket: string, key: string, opts?: DeleteOptions) -> void
deleteBatch(bucket: string, keys: string[]) -> BatchResult
list(bucket: string, prefix: string, opts?: ListOptions) -> Page<ObjectMeta>
copy(src: ObjectRef, dst: ObjectRef, opts?: CopyOptions) -> ObjectRef

beginMultipart(bucket: string, key: string, opts?: PutOptions) -> MultipartHandle
uploadPart(handle: MultipartHandle, partNumber: int, body: ReadableStream) -> PartRef
completeMultipart(handle: MultipartHandle, parts: PartRef[]) -> ObjectRef
abortMultipart(handle: MultipartHandle) -> void

// 可选能力
presignGet(ref: ObjectRef, ttl: Duration) -> Url                 // cap PRESIGN
presignPut(ref: ObjectRef, ttl: Duration, opts?: PutOptions) -> Url // cap PRESIGN
listVersions(bucket: string, key: string) -> Page<ObjectVersion>   // cap VERSIONING
getVersion(ref: ObjectRef, versionId: string) -> ObjectStream      // cap VERSIONING
deleteVersion(ref: ObjectRef, versionId: string) -> void           // cap VERSIONING
createSubscription(config: NotificationConfig) -> SubscriptionId   // cap EVENT_NOTIFY
deleteSubscription(id: SubscriptionId) -> void                     // cap EVENT_NOTIFY

types:
  PutOptions {
    contentType?: string
    metadata?: Map<string,string>
    checksumAlgorithm?: "sha256"|"crc32c"|"crc32"
    ifNoneMatch?: "*"
    storageClass?: string
  }
  GetOptions { range?: {start:int, end:int}, ifMatch?: string, ifNoneMatch?: string }
  ObjectMeta {
    ref: ObjectRef
    contentType: string
    lastModified: Instant
    metadata: Map<string,string>
    checksum?: {algorithm:string, value:string}
  }
  ObjectVersion { ref: ObjectRef, isLatest: bool, deleteMarker?: bool }
  ListOptions { limit?: int, continuationToken?: string, delimiter?: string }
  BatchResult { deleted: string[], errors: {key:string, error:PortError}[] }
  MultipartHandle { uploadId: string, bucket: string, key: string }
  PartRef { partNumber: int, etag: string, size: int }
  NotificationConfig {
    events: string[]        // s3:ObjectCreated:*, s3:ObjectRemoved:* ...
    prefix?: string
    suffix?: string
    target: { kind: "webhook"|"queue"|"topic"|"function", endpointRef: string }
  }
```

**契约要点：**

- `put` 对同 key 覆盖；版本行为由 `VERSIONING` capability 决定，不写进业务语义。
- `etag` 不保证跨 provider 同格式；只用于条件写/校验。
- `list` 不保证强一致；需要“写后立即可见”用 `head`。
- 事件通知是提示，不是一致性机制；重复/乱序由消费者处理。
- `PRESIGN` 缺失时，上层用应用内签名 URL 或流式代理，不要求适配器伪造。

### 4.2 `LLMClient` v1

```text
port LLMClient v1

chat(request: ChatRequest) -> ChatResponse
stream(request: ChatRequest) -> Stream<ChatEvent>
countTokens(request: ChatRequest) -> TokenCount                  // cap COUNT_TOKENS
chatStructured(request: ChatRequest, schema: JsonSchema) -> StructuredResponse // cap STRUCTURED_OUTPUT

types:
  ChatRequest {
    model: string
    messages: Message[]
    temperature?: float
    topP?: float
    maxTokens?: int
    stop?: string[]
    tools?: ToolSpec[]                 // cap TOOLS
    toolChoice?: "auto"|"none"|"required"|{name:string}
    responseFormat?: {kind:"text"|"json", schema?:JsonSchema}
    metadata?: Map<string,string>
  }
  Message {
    role: "system"|"user"|"assistant"|"tool"
    content: ContentPart[]
    name?: string
    toolCallId?: string
  }
  ContentPart =
      {kind:"text", text:string}
    | {kind:"image", mimeType:string, url?:string, bytesRef?:string}    // cap VISION
    | {kind:"document", mimeType:string, bytesRef:string}              // cap DOCUMENT_INPUT
    | {kind:"toolCall", id:string, name:string, argumentsJson:string}
    | {kind:"toolResult", toolCallId:string, content:ContentPart[], isError?:bool}
  ToolSpec { name:string, description:string, inputSchema:JsonSchema }
  ChatResponse {
    message: Message
    stopReason: "end"|"max_tokens"|"tool_use"|"content_filter"|"error"
    usage: Usage
    provider: {name:string, model:string, requestId?:string}
  }
  ChatEvent =
      {kind:"text_delta", text:string}
    | {kind:"tool_call_delta", id:string, name?:string, argumentsDelta:string}
    | {kind:"usage", usage:Usage}
    | {kind:"done", stopReason:string}
    | {kind:"error", error:PortError}
  StructuredResponse { value: any, raw: string, usage: Usage, provider: ProviderRef }
```

**契约要点：**

- 角色与内容块是规范；适配器负责 Bedrock/OpenAI/Anthropic 的字段映射。
- 工具调用参数统一为 JSON 字符串；领域层负责 schema 校验。
- `stopReason=tool_use` 表示模型请求调用工具；`content_filter` 不重试。
- 流式首 token 后失败：终止流并返回 `Aborted`，携带 `partialText` 与 `requestId`；不能自动重放。
- `usage` 缺失时返回空字段，不伪造 0。

### 4.3 `EmbeddingClient` v1

```text
port EmbeddingClient v1

embed(request: EmbeddingRequest) -> EmbeddingResponse

types:
  EmbeddingRequest {
    model: string
    inputs: string[]
    dimensions?: int
    inputType?: "query"|"document"
    normalize?: bool
  }
  EmbeddingResponse {
    vectors: float[][]
    model: string
    dimensions: int
    usage?: Usage
    provider: ProviderRef
  }
```

**契约要点：**

- `vectors.length == inputs.length`；维度必须与 `dimensions`/模型一致。
- 索引命名空间必须记录 `model/dimensions/metric/normalized`；换模型新建索引。
- `inputType` 不被 provider 支持时，适配器可忽略，但 manifest 要标注 `INPUT_TYPE=false`。

### 4.4 `MetadataStore` / `UnitOfWork` v1

```text
port MetadataStore v1

migrate(targetVersion?: string) -> MigrationResult
health() -> HealthStatus
tx<T>(work: (uow: UnitOfWork) -> T) -> T
outboxAppend(event: OutboxEvent, uow?: UnitOfWork) -> void
outboxPoll(batch: int, lease: Duration) -> OutboxRecord[]
outboxAck(ids: string[]) -> void
outboxNack(ids: string[], retryAfter?: Duration) -> void
advisoryLock(key: string, ttl: Duration) -> LockHandle   // cap ADVISORY_LOCK

interface UnitOfWork {
  query<T>(sql: string, params?: any[]) -> T[]
  execute(sql: string, params?: any[]) -> int
  insert(entity: string, value: Record) -> string
  update(entity: string, id: string, value: Record, expectedVersion?: int) -> int
  delete(entity: string, id: string) -> int
}
```

**契约要点：**

- `tx` 内的 `uow` 不得跨线程/协程共享；事务边界由端口实现管理。
- outbox 与业务写在同一事务；`outboxPoll` 至少一次，消费者幂等。
- `advisoryLock` 仅 PG 系适配器支持；其他 provider 返回 `Unsupported`，上层用条件写。
- SQL 仅允许在适配器/仓储层；领域层不拼 SQL。

### 4.5 `GraphStore` v1（COA SPI）

```text
port GraphStore v1

// COA 对齐：SPARQL / GSP
query(sparql: string, dataset?: DatasetRef) -> SparqlResult        // cap SPARQL
update(sparql: string, dataset?: DatasetRef) -> UpdateResult        // cap SPARQL_UPDATE
getGraph(graph: Iri) -> QuadStream                                  // cap GSP
putGraph(graph: Iri, data: QuadStream, contentType: string) -> void // cap GSP
deleteGraph(graph: Iri) -> void                                     // cap GSP

// 平台便利方法（可由适配器用 SPARQL 或 SQL 实现）
getEntity(id: EntityId, version?: string) -> EntityView             // cap SUBGRAPH
upsertStatements(statements: Statement[], opts?: WriteOptions) -> WriteResult
deleteStatements(ids: string[], opts?: WriteOptions) -> void
listStatements(subject?: EntityId, predicate?: Iri, object?: Value, version?: string) -> Page<Statement>
querySubgraph(seed: EntityId[], depth: int, filters?: GraphFilter, limit?: int) -> Subgraph // cap SUBGRAPH
snapshot(version: string) -> SnapshotRef

// 可选高级能力
materialize(profile: string) -> MaterializationJob                 // cap REASONING
runAlgorithm(name: string, params: Map<string,any>) -> AnalyticsResult // cap GRAPH_ANALYTICS

types:
  DatasetRef { graphIris?: Iri[], defaultGraph?: Iri }
  SparqlResult { head: string[], rows: Map<string,any>[], boolean?: bool }
  UpdateResult { affected: int }
  Statement {
    id: string
    subject: EntityId
    predicate: Iri
    object: Value
    graph?: Iri
    ontologyVersion: string
    provenance: Provenance
    confidence?: float
    validFrom?: Instant
    validTo?: Instant
  }
  Value = {kind:"iri", value:Iri} | {kind:"literal", value:string, datatype?:Iri, lang?:string}
  EntityView { id: EntityId, types: Iri[], properties: Map<Iri, Value[]>, statements: Statement[] }
  Subgraph { entities: EntityView[], statements: Statement[], truncated: bool }
  GraphFilter { types?: Iri[], predicates?: Iri[], minConfidence?: float, asOf?: Instant }
  SnapshotRef { version: string, createdAt: Instant, graphIris?: Iri[] }
```

**契约要点（与 COA 对齐）：**

- `NeptuneDBGraphStore` 用 SPARQL/GSP + SigV4；AWS 适配器必须支持 `SPARQL`、`SPARQL_UPDATE`、`GSP`（是否支持 `NAMED_GRAPHS` 由 manifest 声明）。
- PG 适配器若只实现 `SUBGRAPH`/`upsertStatements`，必须声明 `SPARQL=false`、`GSP=false`；上层不得把 SPARQL 查询直接下发给 PG。
- 要保 SPARQL 契约，PG 侧需叠 Oxigraph/Jena/rdflib 之一；这会新增组件/进程，必须计入降级/依赖清单。
- `querySubgraph` 是平台便利方法，不是 COA 的原始 SPI；实现可用 SPARQL（Neptune）或递归 SQL（PG）。
- 每条 `Statement` 必须带 `ontologyVersion`；事实自身的修订用稳定 `Statement.id` + `upsertStatements` 表达，不再引入与之混淆的 `version` 字段。查询默认按 `ontologyVersion` 隔离，不跨版本。
- `materialize`/`runAlgorithm` 是可选；Neptune 不内置 OWL DL 推理，COA 的 SHACL + HermiT 属语义层校验，不要混为 `GraphStore` 内置能力。

### 4.6 `VectorStore` v1（COA SPI）

```text
port VectorStore v1

upsert(namespace: string, points: VectorPoint[]) -> void
delete(namespace: string, ids: string[]) -> void
searchNearest(namespace: string, vector: float[], k: int, filter?: VectorFilter) -> VectorHit[]
searchHybrid?(namespace: string, text: string, vector: float[], k: int, filter?: VectorFilter) -> VectorHit[] // cap HYBRID
createNamespace(spec: NamespaceSpec) -> void
deleteNamespace(namespace: string) -> void

types:
  NamespaceSpec {
    name: string
    dimensions: int
    metric: "cosine"|"dot"|"l2"
    embeddingModel: string
    metadataSchema?: Map<string,"string"|"int"|"float"|"bool">
  }
  VectorPoint {
    id: string
    vector: float[]
    metadata: Map<string,any>   // entityId, docId, chunkId, ontologyVersion, tenant...
  }
  VectorHit { id: string, score: float, metadata: Map<string,any> }
  VectorFilter { must?: Map<string,any>, should?: Map<string,any>, mustNot?: Map<string,any> }
```

**契约要点（必须写进契约测试）：**

- `VectorHit.score` 统一定义为**余弦相似度**（越大越相似，范围 `[-1,1]`；归一化后通常 `[0,1]`）。若 provider 返回距离，适配器必须转换。
- COA 的 `opensearch_vector.py` 中 `search_nearest` 有既定的余弦分数换算契约；AOSS 适配器必须与之一致，测试用固定向量 pin 住期望分数。
- `namespace` 必须绑定 `embeddingModel`/`dimensions`/`metric`；跨模型混写视为 `InvalidArgument`。
- `filter` 语义要按 provider 能力声明；pgvector 的过滤是 SQL `WHERE`，AOSS 是 DSL，二者在“过滤后召回”上不同，契约测试要覆盖。

### 4.7 `DatastoreDAO` v1（COA SPI）

```text
port DatastoreDAO v1

get(collection: string, key: string, opts?: DaoGetOptions) -> Record?
put(collection: string, key: string, value: Record, opts?: DaoPutOptions) -> void
delete(collection: string, key: string, opts?: DaoDeleteOptions) -> void
query(collection: string, filter: DaoFilter, page?: PageToken) -> Page<Record>
batchGet(collection: string, keys: string[]) -> Record[]
transactWrite(ops: DaoOp[]) -> void    // cap TRANSACTION

types:
  Record { key: string, value: Map<string,any>, version?: int, updatedAt?: Instant }
  DaoGetOptions { consistentRead?: bool }
  DaoPutOptions { condition?: DaoCondition, returnOld?: bool }
  DaoDeleteOptions { condition?: DaoCondition }
  DaoCondition { expression: string, params?: Map<string,any> } // 条件表达式语法由适配器定义，领域层只用平台 DSL
  DaoFilter { expression: string, params?: Map<string,any>, limit?: int }
  DaoOp = {kind:"put", collection:string, key:string, value:Record, condition?:DaoCondition}
        | {kind:"delete", collection:string, key:string, condition?:DaoCondition}
```

**契约要点：**

- COA 的 `DynamoDBDAO` 语义要映射到平台 DSL；不要让 DynamoDB 的 `ConditionExpression` 字符串进入领域层。
- 条件写失败返回 `PreconditionFailed`；不要返回 `Conflict` 混淆。
- 分页 token 不透明；不保证跨 provider 可移植。
- `transactWrite` 不支持时上层用单条条件写 + 补偿；manifest 标注 `TRANSACTION=false`。

### 4.8 `TaskQueue` v1

```text
port TaskQueue v1

send(queue: string, message: QueueMessage, opts?: SendOptions) -> MessageId
reserve(queue: string, max: int, visibility: Duration) -> Reservation[]
ack(queue: string, receipt: ReceiptHandle) -> void
nack(queue: string, receipt: ReceiptHandle, opts?: NackOptions) -> void
heartbeat(queue: string, receipt: ReceiptHandle, extend: Duration) -> void
stats(queue: string) -> QueueStats
purge(queue: string) -> void

types:
  QueueMessage {
    id?: string
    dedupeKey?: string
    groupId?: string          // FIFO 组；不支持的 provider 忽略
    payloadRef: string        // 大对象放 ObjectStore；消息只放引用
    payload?: Map<string,any> // 小消息
    headers?: Map<string,string>
    delay?: Duration
  }
  SendOptions { dedupe?: bool, delay?: Duration }
  Reservation { receipt: ReceiptHandle, message: QueueMessage, attempt: int, visibleAt: Instant }
  ReceiptHandle = string
  NackOptions { retryAfter?: Duration, archive?: bool }  // archive 模拟 DLQ
  QueueStats { visible: int, inFlight: int, archived: int, oldestAgeMs?: int }
```

**契约要点：**

- 至少一次；消费者幂等键用 `message.id`/`dedupeKey` + 业务唯一约束。
- `visibility` 是“再次可见时间”，不是“最大执行时间”；长任务必须 `heartbeat`。
- `archive` 是 DLQ 的近似；不保证重放顺序。
- `groupId` 不支持时忽略，manifest 标注 `FIFO=false`；不要假装 FIFO。
- 大 payload 拒绝（返回 `InvalidArgument`），强制走 `payloadRef`。

### 4.21 MCP Server（入站适配器，不是端口）

MCP 是协议入口，不是能力端口。建议工具集：

| 工具 | 调用端口 | 说明 |
|---|---|---|
| `resolve_context` | `ContextResolver.resolve` | 输入 query/任务/版本，返回 ContextPack 摘要 |
| `get_entity` | `GraphStore.getEntity` | 按实体 ID 取邻居/属性 |
| `query_ontology` | `GraphStore.querySubgraph` / `SparqlQueryable` | 受限图查询；不暴露原始 SPARQL 给不可信调用方 |
| `search_documents` | `VectorStore` + `SearchIndex` | 语义/关键词检索 |
| `propose_ontology_change` | `OntologyRegistry.propose` | 提交候选变更，进入审批 |

**契约要点：**

- MCP handler 不直连 Neptune/AOSS/PG；只调端口。
- MCP 工具不返回内部 provider 错误原文；映射为统一错误码 + requestId。
- 鉴权不在本方案，但 MCP 暴露面由网关/上层控制；不要把 `tenant` 当可信输入。

## 6. Provider 错误映射（示例）

| 统一错误 | AWS 典型来源 | PG/Silo 典型来源 | 处理 |
|---|---|---|---|
| `InvalidArgument` | S3 400、Bedrock ValidationException、Textract InvalidParameter | PG constraint、Silo 400 | 不重试；返回字段级错误 |
| `NotFound` | S3 404、Neptune 无结果、DynamoDB 无项 | PG no rows、对象不存在 | 不重试；调用方决定默认值 |
| `Conflict` | S3 409、DynamoDB ConditionalCheckFailed（部分） | PG unique violation、serialization failure | 幂等写可重试；否则返回冲突 |
| `PreconditionFailed` | DynamoDB ConditionalCheckFailed、S3 412 | PG 条件更新失败 | 不重试；上层重新读取 |
| `Unsupported` | 能力缺失（如 FS presign） | 能力缺失（如 PG SPARQL） | 不重试；走降级 |
| `PermissionDenied` | S3 403、Bedrock AccessDenied | PG 权限、Silo 403 | 不重试；告警 |
| `PolicyRejected` | Bedrock Guardrails/内容过滤 | 规则引擎拒绝 | 不重试；记录原因 |
| `ResourceExhausted` | Bedrock Throttling、SQS 限流、AOSS 429 | PG 连接池耗尽、锁等待超时 | 退避 + 抖动；尊重 retryAfter |
| `DeadlineExceeded` | SDK timeout、Bedrock timeout | PG statement_timeout | 幂等可重试；流式不可透明重试 |
| `Unavailable` | 5xx、连接失败 | PG 连接失败、Silo 不可用 | 熔断 + 退避 |
| `Aborted` | 事务冲突/并发中止 | PG serialization failure | 重试整个操作 |
| `DataLoss` | checksum 不匹配、对象损坏 | PG 数据校验失败 | 不重试；告警/人工 |

**实现约定：**

- 适配器必须保留 `providerCode`/`requestId`，但领域层只按统一 `code` 分支。
- 不要把“限流”映射成 `InvalidArgument`；不要把“内容过滤”映射成 `ResourceExhausted`。
- 重试策略由平台统一注入；适配器不自带无限重试。

## 7. 幂等与重试矩阵

| 端口/操作 | 幂等键 | 语义 | 重试 |
|---|---|---|---|
| `ObjectStore.put` | `bucket+key(+contentHash)` | 覆盖写；版本库新建版本 | 可重试（幂等） |
| `ObjectStore.beginMultipart` | 业务生成的 `uploadKey` | 重复 begin 返回已有/新 upload | 可重试；注意泄漏清理 |
| `TaskQueue.send` | `dedupeKey`/`message.id` | 至少一次；FIFO 去重 | 可重试；消费者幂等 |
| `WorkflowEngine.start` | `workflow.id` | 重复 start 返回同一执行 | 可重试 |
| `ExtractionPipeline.submit` | `docHash+extractorVersion+ontologyVersion` | 同键返回已有 job | 可重试 |
| `GraphStore.upsertStatements` | `statement.id` | upsert/去重 | 可重试（幂等） |
| `VectorStore.upsert` | `point.id` | 覆盖写 | 可重试（幂等） |
| `DatastoreDAO.put` | `collection+key+condition` | 条件写 | 条件失败不重试 |
| `LLMClient.chat` | `requestId` + prompt hash | 服务端不保证幂等；平台可缓存 | 仅可重试错误；流式首 token 后不重试 |
| `Notifier.send` | `notification.id` | 至少一次 | 可重试；接收方去重 |

**通用重试策略：**

```text
RetryPolicy {
  maxAttempts: 3
  baseDelayMs: 200
  maxDelayMs: 10000
  multiplier: 2
  jitter: true
  retryOn: [ResourceExhausted, DeadlineExceeded, Unavailable, Aborted]
  deadline?: Duration
}
```

- 重试前检查幂等键；非幂等操作不得自动重试。
- 熔断阈值与半开策略由平台统一配置；适配器不自行决定。
- 流式 LLM：失败即终止，返回 `Aborted` + `partialText`；上层决定是否用新 requestId 重启。

## 8. 配置 Schema（契约视图）

```yaml
platform:
  profile: aws|self-hosted|dev|test
  region: string?

providers:
  object_store: string
  llm: string
  embedding: string
  metadata: string
  graph: string
  vector: string
  datastore: string?
  task_queue: string
  event_bus: string
  workflow: string
  job_runner: string
  table_catalog: string?
  search: string?
  document_parser: string
  cache: string?
  notifier: string?
  secret: string
  ontology_registry: string
  context_resolver: string
  extraction: string

adapters:
  <provider-name>:
    # provider-specific; secrets 只能用 ref
    endpoint: string?
    region: string?
    credential_ref: string?
    options: map?

requirements:
  # 任务类型 → 必需能力；启动时校验
  extraction:
    llm: [CHAT, TOOLS, STRUCTURED_OUTPUT]
    parser: [PARSE]
    graph: [SUBGRAPH]
  answer:
    llm: [CHAT, STREAM]
    context_resolver: [RESOLVE]
  ontology_admin:
    ontology_registry: [PROPOSE, REVIEW, APPROVE, PUBLISH]
    graph: [SUBGRAPH]

degradation:
  allow: [PRESIGN, VERSIONING, EVENT_NOTIFY, SPARQL, HYBRID, OCR, REPLAY]
  deny: []   # 生产可配置为“禁止降级”的任务类型
```

**Provider Manifest 示例：**

```yaml
provider: neptune-rdf
port: GraphStore
portVersion: v1
providerVersion: "1.3"
capabilities: [SPARQL, SPARQL_UPDATE, GSP, SUBGRAPH, NAMED_GRAPHS]
limits:
  max_query_seconds: 60
  max_result_rows: 100000
notes:
  auth: sigv4
  graph_model: rdf
```

**校验规则：**

1. `providers` 中的每个值必须在 adapter registry 中存在。
2. 每个 adapter 的 manifest `portVersion` 必须为 `v1`。
3. `requirements` 的全部能力必须被对应 manifest 声明；否则 fail-fast。
4. `degradation.allow` 中的能力可以缺失；缺失时启动输出 `DEGRADED` 清单；`deny` 中的能力缺失直接失败。
5. 生产 profile 禁止 dev-only provider（`filesystem`、`inproc`、`local-process`），除非显式 `allow_dev_providers: true`。

## 9. 契约测试清单

每个端口至少三类测试：**Happy path**、**边界/错误**、**能力缺失/降级**。以下为必测项。

### 9.1 `ObjectStore`

- [ ] put/get/head/delete 基本闭环；大对象分片上传/完成/中止。
- [ ] list 分页、前缀、空结果；删除不存在对象的行为一致（幂等或 NotFound，需固定）。
- [ ] 条件写（`ifNoneMatch`/`ifMatch`）语义；并发覆盖行为。
- [ ] `PRESIGN` 缺失时返回 `Unsupported`；上层应用签名 URL 路径可用。
- [ ] `VERSIONING` 缺失时逻辑版本路径可用。
- [ ] `EVENT_NOTIFY` 缺失时 outbox + 对账路径可用。
- [ ] 校验和/内容类型/元数据往返一致。

### 9.2 `LLMClient` / `EmbeddingClient`

- [ ] 普通 chat、流式 chat、usage、stop reason。
- [ ] 工具调用：单工具、工具结果回传、错误结果、并行工具（若声明）。
- [ ] 结构化输出：合法 JSON、非法 JSON、schema 不匹配。
- [ ] 内容过滤 → `PolicyRejected`，不重试。
- [ ] 限流 → `ResourceExhausted`，退避后成功。
- [ ] 流式首 token 后断开 → `Aborted` + partial。
- [ ] embedding 维度/归一化/批量；模型不匹配 → `InvalidArgument`。

### 9.3 `GraphStore`（COA 对齐重点）

- [ ] `SPARQL` 查询（SELECT/ASK/CONSTRUCT）与 `SPARQL_UPDATE`；命名图。
- [ ] `GSP` get/put/delete；content-type 处理。
- [ ] `querySubgraph` k 跳、方向、过滤、截断标记。
- [ ] `upsertStatements` 幂等；版本隔离；provenance 往返。
- [ ] PG 适配器声明 `SPARQL=false` 时：调用 `query` 必须 `Unsupported`，不得静默用 SQL 冒充。
- [ ] 本体版本 A/B 隔离：查询只返回指定版本事实。
- [ ] `snapshot`/diff 的版本一致性。

### 9.4 `VectorStore`（COA 对齐重点）

- [ ] 固定向量 + 固定查询，pin 住 `score`（余弦相似度），验证 AOSS/pgvector 换算一致。
- [ ] 过滤（must/should/mustNot）与 topK；过滤后召回。
- [ ] 维度不匹配 → `InvalidArgument`；namespace 模型不匹配 → `InvalidArgument`。
- [ ] 删除/重建/空 namespace。
- [ ] `HYBRID` 缺失 → `Unsupported`；上层手融合路径可用。

### 9.5 `DatastoreDAO`

- [ ] get/put/delete/query 基本闭环；分页 token。
- [ ] 条件写成功/失败；`PreconditionFailed` 映射。
- [ ] `TRANSACTION` 缺失 → `Unsupported`；补偿路径可用。
- [ ] `consistentRead` 不支持时忽略并标注。

### 9.6 `MetadataStore` / `TaskQueue`

- [ ] 事务提交/回滚；outbox 与业务写同事务。
- [ ] outbox poll/ack/nack；重复投递幂等。
- [ ] 队列 reserve/ack/nack/heartbeat；可见性超时后重新可见。
- [ ] FIFO 组内顺序（若声明）；普通队列不保证顺序。
- [ ] 大 payload 拒绝；`payloadRef` 路径可用。
- [ ] archive/DLQ 行为；`REPLAY` 缺失 → `Unsupported`。

### 9.7 `WorkflowEngine` / `JobRunner`

- [ ] start 幂等；signal/cancel/status。
- [ ] 重试/超时/子流程（若声明）。
- [ ] `COMPENSATION` 缺失 → `Unsupported`；手工补偿路径可用。
- [ ] JobSpec 提交/状态/取消；资源超限 → `InvalidArgument`。

### 9.8 `TableCatalog` / `SearchIndex` / `DocumentParser`

- [ ] 建表/加载/提交/快照；快照时间旅行。

- [ ] 同文档同版本重复抽取不重复写入；强制 reprocess 可重跑。

## 10. 关键 DTO 结构（评审用）

### 10.1 `Statement`（本体事实）

```text
Statement {
  id: string
  subject: EntityId
  predicate: Iri
  object: Value
  graph?: Iri
  ontologyVersion: string
  provenance: Provenance
  confidence?: float
  validFrom?: Instant
  validTo?: Instant
}
```

**约束：**

- `id` 稳定（建议由 `subject|predicate|object|graph|ontologyVersion` 生成 hash）；同 id upsert。
- `ontologyVersion` 必填；查询必须带版本或显式 `allVersions`（默认不跨版本）。
- `provenance` 必填；人工审核也要记录 reviewer。

### 10.2 `ContextPack`（上下文包）

```text
ContextPack {
  id: string
  ontologyVersion: string
  terms: TermRef[]
  entities: EntityView[]
  facts: Statement[]
  chunks: ChunkRef[]
  citations: Citation[]
  provenance: Provenance[]
  tokenEstimate: int
  strategy: "graph"|"vector"|"lexical"|"hybrid"
  degraded: boolean
  warnings?: string[]
}
```

**约束：**

- 所有 `facts`/`chunks` 必须有 provenance；没有来源的内容不得进入 pack。
- `tokenEstimate` 是预算估计；实际 prompt 组装可截断，但必须保留 citation。
- `degraded=true` 必须带 warnings（如“SPARQL 不可用，已用受限子图查询”）。

### 10.3 `JobSpec` / `ExtractionJob`

见 4.11 与 4.20。关键约束：

- `JobSpec` 只描述镜像/命令/资源/输入输出；不包含 provider 专有字段。
- `ExtractionJob` 必须带 `ontologyVersion` 与 `extractor.version`；否则拒绝。

### 10.4 `ProviderManifest`

见 2.3。关键约束：

- 能力声明必须与实际行为一致；契约测试会验证声明。
- `limits` 不是建议，是硬限制；上层据此分片/拒绝。

## 11. 版本与迁移

| 对象 | 策略 |
|---|---|
| 端口 IDL | `v1` 只加可选字段/方法；破坏性变更 `v2`，双版本并存一个发布周期 |
| Provider Manifest | `portVersion` 必须匹配；`providerVersion` 记录实现版本 |
| 本体 schema | `OntologyRegistry` 版本不可变；`diff/compatibility/rollback`；事实带 `ontologyVersion` |
| 向量索引 | 索引元数据记录 `embeddingModel/dimensions/metric`；换模型新建索引 + 回填 + 切别名 |
| 对象 | 版本/校验和用于迁移校验；不使用 list 顺序 |
| 队列/事件 | 消息 schema 带 `schemaVersion`；消费者兼容旧版本 |
| 图 | 命名图/版本字段隔离；迁移用快照 + 重放，不双写 |

**迁移原则：**

1. 先写新、再读新、最后停旧（expand/contract）。
2. 跨存储迁移用 outbox/可重放任务，不做双写。
3. 每次迁移必须有校验（计数、抽样、checksum）与回滚路径。
