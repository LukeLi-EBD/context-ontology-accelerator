# 20 迁移友好的导出 / 导入（bundle）设计

状态：已实现（`export-bundle` / `import-bundle`）
适用范围：单机平台 `_impl`，生产库 `platform` + Oxigraph + 本地 CAS
关联：`_design/03`（架构）、`_design/04`（接口契约）、`_impl/WORKLOG.md`（实施留痕）

## 1. 目标与边界

目标：把一台机器上的平台状态**冻结**成一个自描述目录（bundle），并能在另一台机器/另一个库上
**可核对地**恢复。恢复必须能回答"搬了什么、搬到了什么程度、哪一项没搬"。

明确边界：

- 导出**只读**生产库、Oxigraph 与 CAS，不开事务写、不跑 `reconcile/ensure_chain`。
- 导入目标固定为**测试库**（默认 `platform_restore_test`），生产库 `platform` 绝不被写入。
- 不做压缩、不做加密、不搬 OCR 源文件（默认），后续再加。
- 不重构既有模块；新增 `platform_core/bundle.py` 与两个 CLI 子命令，无新表、无新迁移。
- T-Box 必须走**治理 API**（`import_document` → `publish`），禁止 GSP 旁路直写。
- 向量不参与"必须原样搬"的语义讨论：它是可重算派生数据，但本轮仍**原样搬**以保证零重算、
  可逐条核对（cosine ≥ 0.999）。

## 2. Bundle 目录结构

```
_freeze/<tag>/                     # tag 例：v1-20261105
├── MANIFEST.json                  # 清单 + 校验和 + 总数 + 指针快照
├── graph/
│   ├── tbox.ttl                   # 导出时的当前 T-Box（版本指针指向的图）
│   ├── abox.ttl                   # reasoning.abox_graphs 的并集
│   └── shapes.ttl                 # shapes_registry 各 shapesId 的当前版本（带注释头）
├── meta/
│   ├── ontology_import.jsonl      # platform.ontology_import 全表
│   ├── documents.jsonl            # platform.document 全表
│   └── chunks.jsonl               # platform.document_chunk 全表（含 text）
├── vectors/
│   ├── embeddings.npz             # chunk_ids + float32[N,1024]
│   └── README                     # 模型/维度/归一化/分区键说明
├── ledger/
│   ├── fact_events.jsonl          # 事实审计链（按 event_id 升序）
│   └── verify.json                # 离线哈希链校验结果
└── blobs/                         # 仅 --include-blobs 时存在
    └── <sha 前 2 位>/<sha256>      # 原样复制的 CAS 大件
```

`MANIFEST.json` 之外的所有文件都登记在 `MANIFEST.files[]`；`blobs/` 文件也逐条登记
（用于体积/完整性核对，不做行数统计）。

## 3. 文件格式与校验方式

| 文件 | 格式 | 校验 |
|---|---|---|
| `MANIFEST.json` | JSON（UTF-8，2 空格缩进） | 自身不登记 sha；读取后必须通过结构校验 |
| `graph/*.ttl` | Turtle | sha256 + 字节数 + 行数；导入前用 rdflib 解析 |
| `meta/*.jsonl` | 每行一个 JSON 对象 | sha256 + 字节数 + 记录数（`lines`） |
| `vectors/embeddings.npz` | NumPy `.npz`（zip） | sha256 + 字节数 + 记录数；`shape[1] == dimensions` |
| `vectors/README` | 纯文本 | sha256 + 字节数 + 行数 |
| `ledger/fact_events.jsonl` | 每行一个事件对象 | sha256 + 记录数；`verify_records` 重算哈希链 |
| `ledger/verify.json` | JSON | sha256；`ok=true` 才允许导入 |
| `blobs/**` | 原始字节 | sha256 + 字节数（默认不导出） |

**sha256 口径**：对文件最终落盘的字节做 sha256，不做任何重编码。导入端先算 sha 再解析，
sha 不符直接失败，绝不"先解析后校验"。

**行数口径**：`lines` = 以 `\n` 结尾的行数（JSONL 即记录数）；TTL 按物理行数；二进制为 `null`。

**向量格式**：`embeddings.npz` 内含两个数组：

- `chunk_ids`: `unicode` 字符串数组，顺序与 `embeddings` 一致；
- `embeddings`: `float32[N,1024]`，按 `chunk_embedding` 中 active 分区的原始值，不做归一化、
  不量化、不截断。

`vectors/README` 说明：`provider / model / dimensions / partition`、"向量为 BGE-M3 原样输出，
导入后按原值写入 pgvector，不重新归一化"。

**shapes 的特殊处理**：`graph/shapes.ttl` 是给人看/给 diff 用的合并视图（每个 shapesId 前加
`# shapesId=... version=... namespace=... contentHash=...` 注释）。为了让导入能按
`(shapesId, version)` 精确回填注册表，`MANIFEST.shapes[]` 同时保存每个条目**原始文本**与
`contentHash`；导入用清单内容 `deploy`，并用合并文件做人工核对。

## 4. MANIFEST 字段

```json
{
  "bundleVersion": 1,
  "schemaVersion": 17,
  "tag": "v1-20261105",
  "generatedAt": "2026-11-05T19:00:00+08:00",
  "source": {
    "database": "platform",
    "graphEndpoint": "http://oxigraph:7878",
    "tbox": {"versionId": "ont-...", "semver": "1.0.0",
              "contentHash": "...", "graph": "urn:platform:graph:tbox:ont-..."},
    "embedding": {"provider": "local-bge", "model": "BAAI/bge-m3",
                   "dimensions": 1024, "partition": "local-bge:BAAI/bge-m3@1024"},
    "aboxGraphs": ["urn:platform:graph:abox:main"],
    "shapes": [{"shapesId": "...", "namespace": "...", "version": "...",
                 "contentHash": "...", "triples": 13, "contentFormat": "turtle",
                 "content": "<原始 TTL 文本>"}]
  },
  "totals": {
    "documents": 1098, "chunks": 10874, "embeddings": 10874,
    "triples": 3000, "tripleBreakdown": {"tbox": 2676, "abox": 324},
    "factEvents": 0, "factAssertions": 0, "ontologyImports": 0,
    "shapes": 3, "blobs": {"included": false, "count": 0, "bytes": 0}
  },
  "files": [
    {"path": "graph/tbox.ttl", "kind": "ttl", "bytes": 142661,
     "sha256": "...", "lines": 2300, "records": null}
  ]
}
```

`totals.embeddings` 是 **active 分区**条数，与 `vectors/embeddings.npz` 的记录数必须一致；
其他分区的条数记在 `totals.embeddingPartitions`（可选，用于解释"为什么库里向量更多"）。

导出发生在 ingest 仍在运行时并不具备数据库级快照：因此导出会做**引用闭合过滤**——先取
`document`，再取 `document_chunk` 并丢掉 `document_id` 不在文档快照中的块（记录
`totals.chunksExcluded`），最后取向量并丢掉 `chunk_id` 不在块快照中的向量（记录
`totals.embeddingsExcluded`）。被排除的条数是"导出之后新入库的数据"，会在清单里如实标注，
保证 bundle 内部不存在孤儿引用。

## 5. 哪些可以重建，哪些必须原样搬

| 数据 | 处理 | 理由 |
|---|---|---|
| 文档元数据 + chunk 文本 | **原样搬** | 重解析会因解析器版本/OCR 波动产生新 chunk_id，破坏引用 |
| 向量 | **原样搬**（语义上可重算） | 重算代价高且对外部 TEI 有依赖；原样搬可逐条 cosine 核对 |
| T-Box 图 + 版本指针 | **原样搬** + 治理导入 | 指针 sha 是跨环境可比对的锚点 |
| shapes 注册表 | **原样搬** | 决定同一 T-Box 在不同环境能否复现门禁结果 |
| `ontology_import` 记录 | **原样搬** | 治理历史，审计要求不可丢 |
| 事实账本（事件链） | **原样搬** | 审计哈希链必须连续，不可重排/重算 |
| A-Box 图 | **原样搬**（同时可由账本投影） | 与账本一致性核对；恢复图写入独立 IRI |
| 物化 inferred 图 | **不搬，可重建** | 由 RDFS→OWL→SHACL 链重跑；导入时 `reasoning.mode=validate` 只做门禁不落图 |
| 文档页 (`document_page`) | **不搬，可重建** | 可由原文重新解析；本轮清单未包含，见限制 |
| CAS 大件 | **默认不搬** | 体积大；`--include-blobs` 才复制，导入端不写生产 CAS |

## 6. 导出流程（只读）

1. 读 `graph_pointer(tbox/current)`、`embedding_pointer`、`MAX(schema_version)`；
2. 直接 `SELECT` 四张表（`ontology_import` / `document` / `document_chunk` / `fact_event`）与
   active 分区向量；**不调用** `FactLedger.export_events()`（它会 `reconcile_purges/ensure_chain`
   并写库），改用 `verify_records()` 纯计算校验；
3. `ontology.export_version(pointer, "turtle")` 导出 T-Box；
4. 逐个 `graph.export_graph(iri)` 导出 A-Box 并合并为 Turtle；
5. 从 `shapes_registry` 按 `shapes_id` 取 `created_at` 最新一条，导出当前版本；
6. 可选复制 `blobs/<sha[:2]>/<sha>`，累计体积；
7. 先写内容文件，最后写 `MANIFEST.json`；任一步异常 → 删除半成品目录并报错。

只读保证：导出路径只调用 `query/export_graph/export_version/count_graph`，不调用任何
`INSERT/UPDATE/replace_graph/put`。CLI 对导出命令**不执行** `metadata.migrate()`（避免对生产
库产生任何 DDL/锁行为），只 `open()`。

## 7. 导入流程（测试库）

1. **先校验，后建库**：读 `MANIFEST`，逐文件校验存在性/sha/大小/行数；`schemaVersion` 必须等于
   代码 `SUPPORTED_SCHEMA_VERSION`；`embeddings.npz` 维度必须等于清单维度且等于 1024；
   `ledger/verify.json` 必须 `ok=true`。
2. 建库：默认 `platform_restore_test`，已存在则失败（`--replace` 才先 `DROP ... WITH (FORCE)`）。
3. 迁移到 `V17`（与生产同版本）。
4. shapes：按 `MANIFEST.shapes[]` 的 `(shapesId, version, namespace, 原文)` 逐条 `deploy`。
5. T-Box：`import_document(raw=tbox.ttl, rdf_format="turtle", semver=指针 semver,
   validate_shacl=true, check_consistency=false)`；若 `unresolvedImports` 非空或
   `shacl.conforms=false` → 失败；随后 `publish(versionId, acknowledge_breaking=true)`。
   `publish` 内执行 SHACL + 一致性（ROBOT/ELK）门禁。物化阶段按 A-Box 是否为空分两种：
   A-Box 非空 → `reasoning.mode=validate`，只做校验、不写 inferred 图（inferred 可重建）；
   A-Box 为空 → pyshacl 拒绝空图，改用 `reasoning.mode=materialize` 完整物化恢复后的 T-Box，
   产物写入独立 `urn:platform:inferred:<新版本>`，不触碰生产指针。
6. A-Box：写入**独立恢复图** `urn:platform:graph:restore:<tag>:abox`，绝不覆盖生产
   `urn:platform:graph:abox:main`。
7. 元数据：`ontology_import` → `document` → `document_chunk` 批量写入。
8. 向量：按 `(chunk_id, model)` 写入 active 分区，最后把 `embedding_pointer` 切到清单指针。
9. 事实账本：`verify_records` → `reconstruct` → 插入 `fact_event` + `fact_assertion`。
10. 一致性核对（见第 9 节）。

## 8. 原子性与失败处理

- 校验阶段失败：不建库、不写图，直接返回具体失败项（`E_BUNDLE_SHA` / `E_BUNDLE_MISSING` /
  `E_BUNDLE_SCHEMA_MISMATCH` / `E_BUNDLE_VECTOR_DIM` / `E_BUNDLE_LEDGER_CHAIN`）。
- 建库后失败：`DROP DATABASE ... WITH (FORCE)` 回滚测试库，并 best-effort 删除本次创建的图
  （T-Box 新版本图、restore A-Box 图）；返回 `failedStep` + 原始错误，禁止"部分成功但报成功"。
- 图写与库写不在同一事务（Oxigraph 与 PG 无分布式事务），因此回滚以"删库 + 删图"补偿为准；
  补偿失败会写入 `cleanupError`，不被静默吞掉。
- 导入成功时：所有核对项全绿才 `ok=true`；任一项不绿即视为失败，但保留测试库供排查
  （`--keep-db-on-failure`），默认仍删库。

## 9. 一致性核对（导入最后一步）

| 项 | 口径 |
|---|---|
| documents | `COUNT(document)` vs `MANIFEST.totals.documents` |
| chunks | `COUNT(document_chunk)` vs `MANIFEST.totals.chunks` |
| vectors | `COUNT(chunk_embedding WHERE model=active)` vs `MANIFEST.totals.embeddings`，再抽样 20 条 cosine ≥ 0.999 |
| triples | `count_graph(新 T-Box) + count_graph(restore abox)` vs `MANIFEST.totals.triples` |
| facts | `COUNT(fact_event)` vs `MANIFEST.totals.factEvents`；`fact_assertion` 作为明细 |
| 指针 | 新 T-Box `contentHash == MANIFEST.source.tbox.contentHash` |
| 检索 | 用第一条 chunk 文本做一次 `hybrid_search(limit=1)`，必须命中 |

## 10. 版本与兼容策略

- `bundleVersion`：bundle 结构版本。当前固定 `1`；不匹配 → `E_BUNDLE_FORMAT`。
- `schemaVersion`：导出时数据库迁移版本。导入端要求**严格相等**：
  - 小于当前 → 先按 bundle 的版本迁移不可行（旧代码不可回溯），直接拒绝，提示用对应版本镜像；
  - 大于当前 → 拒绝（`E_BUNDLE_SCHEMA_MISMATCH`），禁止降级导入。
- `embedding.dimensions` / `model`：必须与目标 pgvector 表可容纳的维度一致（当前 1024）；
  不匹配 → `E_BUNDLE_VECTOR_DIM`。
- T-Box `semver` 原样带入，不重排版本号；`contentHash`（源字节 sha256）只作溯源，**不能**用于
  跨环境比较（导出 TTL 会重新序列化，前缀/空白必然变化）。跨环境等价锚点是
  `canonicalHash`：对 rdflib 规范化图（`to_canonical_graph`，空白节点规范化）逐三元组做
  **值规范化**（数值字面量按 Python 值而非词法形式比较，因为 Oxigraph 会把 `"699.0"` 存成
  `"699"`），再排序、拼行、sha256。核对项 `tboxPointerHash` 比较的是 `canonicalHash`。
- 兼容旧 bundle 的预留：`bundleVersion=1` 内新增字段一律"可选 + 有默认值"，导入端忽略未知字段。

## 11. 测试

- 单测（`tests/test_bundle.py`）：sha 不符、schemaVersion 不符、缺文件、向量维度不符。
- 端到端：生产只读导出 `v1-20261105` → 导入 `platform_restore_test` → 打印
  documents/chunks/vectors/triples/facts 五项核对表。

## 12. 与现有治理链路的关系

- T-Box 只走 `OntologyRegistry.import_document` + `publish`，与 G-01 导入是同一条治理路径；
  导入结果（版本、事件、门禁明细）全部落 `ontology_version/ontology_event`（测试库）。
- 平台 GSP 仍然不可用（读 405 / 写 403 `E_GSP_GOVERNANCE_REQUIRED`）；`import-bundle` 不调用
  GSP，也不直接改 `graph_pointer`，指针只能由 `publish` 更新。
- A-Box 不是 T-Box 治理对象，允许通过图适配器写入，但强制使用 `urn:platform:graph:restore:*`
  命名空间，避免污染生产 A-Box。
- 事实账本走 `verify → reconstruct → insert`，与 `facts-replay` 完全相同的链路。

## 13. 已知限制 / 未覆盖

1. `document_page` 不导出：恢复后"按页查看原文"不可用，需重新解析（有原文 CAS 时）。
2. 默认不搬 CAS 大件：恢复后文档下载会 404；需要时用 `--include-blobs` 导出，但导入端
   刻意不写生产 `/data`，需人工把 `blobs/` 同步到目标 CAS。
3. 未做压缩/加密/签名；完整性依赖 sha256 + 事实哈希链。
4. A-Box 图 IRI 与生产不同（`restore:<tag>`），依赖固定 IRI 的查询需要额外映射。
5. 恢复不重建 inferred 物化图；需要时在测试环境单独执行 `reasoning` 物化。
6. `ontology_import.staging_graph` 指向的暂存图不搬，历史记录保留但图可能不存在。
