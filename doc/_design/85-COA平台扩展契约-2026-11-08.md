## 1. 已定框架

### 1.1 命名空间

`coa.platform.extension`。

理由：扩展与上游 `com.amazon.semanticcontext.*` 明确分账。合上游时，上游命名空间里的任何
shape 都不受我们的扩展影响；我们也不往上游命名空间里塞 shape。

代价：跨命名空间引用上游 shape 必须显式 `use`（见 §7 附录），上游 shape 改名会打断扩展编译。
这是有意的：让上游改动在编译期暴露，而不是静默漂移。

### 1.2 单一扩展服务

6 条新增 operation 全挂 `PlatformKnowledgeService`。不把 operation 拆进
`DataLayerService` / `ControlPlaneService`，也不新增第二个扩展 service。

理由：扩展的部署边界是一个独立的本地知识服务，不是上游两个 service 的补丁集合；一个 service
对应一个可独立启停、独立鉴权、独立计价的单元。

### 1.3 暂不落盘 `platform-knowledge.smithy`

本轮不创建 `models/src/main/smithy/platform-knowledge.smithy`。原因三条：

1. `84` 记录的 codegen 前置未修：`smithy-generated/` 缺失、本机 `uv` 低于 `>=0.13.4`，
   新增 smithy 文件会进入 `uv lock` 的解析面，无法在本机验证。
2. 扩展 service 的部署/鉴权/网关绑定尚未定；先落文件会让 codegen 在没有运行时契约的情况下
   生成一批不可部署的 stub。
3. 本轮已有 `GetEntity` 的真实运行证据；契约应以“已验证的形状”落盘，而不是以“设想”落盘。

落盘顺序（等 84 修好后）：

1. 新建 `models/src/main/smithy/platform-knowledge.smithy`，内容即 §7 附录；
2. 只对该文件做独立 Smithy build（`smithy build` 单文件/单 project），确认 model 校验通过；
3. **不进 SDK 生成**（不改 `smithy-build.json` 的 SDK projection）；
4. 独立构建通过后，再评估是否加入 `data-layer-python-server` 之类的生成目标。

### 1.4 `GetOntologyVersion` 保留但不实现

契约里保留该 operation，实现状态固定为“等版本源，暂不实现”。

- 不返回伪造的版本号、时间戳或 hash；
- 本地网关当前**不建该路由**；后续建路由时，未接版本源必须返回 501/`ServiceUnavailableError`，
  不得用 `GetOntology` 的 `updatedAt` 冒充版本；
- 版本源的最小要求：能给出“某一版本体”的不可变标识（内容 hash 或发布序号），且与
  `GraphContext` / `QueryResult.ontologyVersion` 使用同一个源。

## 2. 与 COA 现有 operation 的关系

### 2.1 核查口径

以本仓库 `models/src/main/smithy/` 为准，逐 operation 查 `service` 块；不引用上游文档或记忆。
service 只有两个：`ControlPlaneService`（`control-plane.smithy:126`）、
`DataLayerService`（`data-layer.smithy:36`）。

### 2.2 上游归属事实（对上一轮判断的更正）

上一轮口头判断“COA 的指标 operation 上游未挂 service”。**代码核查结果与此不符**：

- `metric-service.smithy` 定义 11 条 operation：`CreateMetric`、`GetMetric`、`ListMetrics`、
  `UpdateMetric`、`DeleteMetric`、`ValidateMetric`、`BulkDeleteMetrics`、`ImportOsi`、
  `GetImportJob`、`GetOsiUploadUrl`、`ExportOsi`；
- 这 11 条全部列在 `ControlPlaneService.operations`（`control-plane.smithy:176-186`）。

因此本轮的准确表述是：**指标 operation 挂在 `ControlPlaneService`，不在 `DataLayerService`；
不存在“悬空未挂 service”的指标 operation。** 按用户决定，照原样不动，不替它补归属，
也不把 `GetMetric` 迁到扩展 service。

同理，`ListOntologies` / `GetOntology` / `GraphSearch` 等也挂在 `ControlPlaneService`
（`control-plane.smithy:209-222`），不是独立的本体 service。

### 2.3 关系总表

| 扩展 operation | 关系 | 最接近的 COA 现有 operation | 现有 operation 承接不了的原因 |
|---|---|---|---|
| `GetEntity` | 平行 | `GraphSearch`（`ControlPlaneService`） | `GraphSearch` 是文本/IRI 子串检索，返回命中的图元素，不是“按 IRI 精确取一个实体的全部陈述”；`GetGraphClass` 只返回 schema 类 |
| `GetMetricObservations` | 平行 | `GetMetric`（`ControlPlaneService`） | `GetMetric` 只返回指标定义（表达式、数据源、表），不含已落库的观测值 |
| `ComputeMetric` | 平行 | 无 | 上游没有“按定义即时计算一个指标值”的 operation；`Query` 是自然语言路由，不保证绑定到某个指标 |
| `GetOntologyVersion` | 平行 | `GetOntology`（`ControlPlaneService`） | `OntologyRecord` 只有 `updatedAt`，没有不可变版本标识；`updatedAt` 不能当版本 |
| `GetAnswer` | 平行（实现复用 `Query` 的解析链） | `Query`（`DataLayerService`） | `Query` 输出面向“完整结果”（`rows` / `supportingContent` / `graphContext` / `trace`）；扩展只要“答案 + 引用”的窄形状，且要能按 `answerId` 二次取引用链 |
| `GetCitationChain` | 平行 | `KBSearch` / `SupportingContent` | COA 的 `supportingContent` 是平铺 chunk 列表，没有“引用→被引用”的边；`KBSearch` 也不返回链 |

### 2.4 复用（不新增 operation）

| 现有 operation | 复用方式 | 约束 |
|---|---|---|
| `GetMetric` | `ComputeMetric` / `GetMetricObservations` 读取指标定义时，走已有的按名取定义路径 | 不把 `GetMetric` 迁到扩展 service，不复制它的定义 shape |
| `ListOntologies` | `GetOntologyVersion` 校验 `ontologyId` 是否登记时复用其注册表语义 | 不新增“列本体”的扩展 operation |
| `Query` | `GetAnswer` 的实现底座复用 Tier 路由（metric → SQL → KB） | 扩展只做输出裁剪，不重写路由；`Query` 契约与路径不变 |

### 2.5 取代

无。六条新增 operation 没有任何一条声明“替代”上游 operation；上游 operation 继续按原路径、
原形状工作。

## 3. 通用约定

### 3.1 路径与参数

- 命名空间一律 `@httpLabel namespaceId: Uuid`（`com.amazon.semanticcontext.common#Uuid`）。
- IRI 不作 path label：API Gateway 会破坏路径里的 `#`（`DeleteOntology` 的先例已在
  `ontology-graph.smithy` 注明）。需要传 IRI 的 operation 一律走 `@httpQuery`。
- 资源标识（`ontologyId` / 指标 `name` / `answerId`）可以作 path label，因为契约已把它们约束为
  无 `#`、无 `/` 的短标识。
- 只读 operation 标 `@readonly`，HTTP 方法 `GET`；有请求体的标 `POST`。

### 3.2 错误形状

所有错误复用上游 `com.amazon.semanticcontext.common` 与 `datalayer` 的既有错误 shape，
不新造错误类型：

| 错误 | HTTP | 字段 | 何时返回 |
|---|---|---|---|
| `ValidationError` | 400 | `message` | 参数缺失、IRI 非法、UUID 非法、范围越界 |
| `NotFoundError` | 404 | `message` | 指标定义/本体/实体/answerId 不存在 |
| `NamespaceNotFoundError` | 404 | `message`, `namespaceId` | 命名空间不存在（仅 `GetAnswer` 需要区分） |
| `AccessDeniedError` | 403 | `message` | 无读权限 |
| `ConflictError` | 409 | `message` | 指标定义存在但不可执行（缺数据源/表达式） |
| `RateLimitExceededError` | 429 | `message`, `retryAfterSeconds` | 触发限流 |
| `ServiceUnavailableError` | 503 | `message` | 后端（图/库/模型）不可用，或版本源未接 |

**本地实现现状差异**：本地网关把后端异常统一映射为 HTTP 502（`_http_error`），不是契约声明的
503。落盘前要么把扩展路由的后端失败改为 503，要么在契约里显式承认 502；本轮按“契约要 503、
本地是 502”记录为差异，不改全局错误映射（避免影响既有 43 个测试与其它路由）。

### 3.3 空结果与不存在

- `GetEntity`：一个陈述都没有 → 404 `NotFoundError`。IRI 语法合法但图中没有该主语，属于“不存在”。
- `GetMetricObservations`：指标存在但区间内无观测 → 200，`observations: []`，**不** 404。
- `GetAnswer`：Tier 命中但无数据 → 404 `NoResultError`（沿用 `serve.smithy` 语义）；
  路由本身失败 → 5xx。
- `GetCitationChain`：`answerId` 不存在 → 404；存在但链为空 → 200，`nodes: []`。
- `GetOntologyVersion`：未接版本源 → 503；已接但本体不存在 → 404。

### 3.4 时间、数值与分页

- 时间戳一律 ISO-8601 UTC 字符串（`2026-11-08T12:00:00Z`），不带时区偏移。
- 指标数值用 `Double`；单位单独给 `unit: String`，不把单位拼进数值字符串。
- 本扩展 6 条 operation 都**不分页**（`maxResults`/`maxDepth` 只是硬上限）；
  以后要列表化再引入 `nextToken`，不预留空字段。

### 3.5 本地限制（必须写进实现说明，不得隐藏）

- 本地图是单命名空间：`namespaceId` 只校验 UUID，不分区数据。
- `GetEntity` 同时查默认图与命名图（`{ ?s ?p ?o } UNION { GRAPH ?g { ?s ?p ?o } }`）；
  Oxigraph 的验收数据可能只在命名图里。
- 本地**有** embedding：TEI 1.8.3 + `BAAI/bge-m3`（1024 维，OpenAI 兼容 `/v1/embeddings`），
  因此 `KBSearch` 可承接（网关已实现 `POST /namespaces/{namespaceId}/kb/search`，内部先
  embed 再查 pgvector）。`GetAnswer` 的 Tier-3（KB 检索）也不再有 embedding 缺口；
  但 `namespaceId` 仍只校验不分区，检索走全局语料。
- 本地没有版本源：`GetOntologyVersion` 不实现。

## 4. 逐 operation 定义

### 4.1 `GetEntity`

| 项 | 内容 |
|---|---|
| 方法与路径 | `GET /namespaces/{namespaceId}/graph/entity?uri=` |
| 入参 | `namespaceId`（path，Uuid）；`uri`（query，必填，IRI，长度 1–2048） |
| 出参 | `entity: EntityDetail`；`statements: EntityStatementList` |
| 错误 | 400 `ValidationError`；404 `NotFoundError`；503 `ServiceUnavailableError` |
| 关系 | 平行：`GraphSearch` 是检索，`GetEntity` 是精确取一个主语的陈述 |
| 行为差异 | 返回**该实体自身**的陈述，不返回邻居；`label` 取首个 `rdfs:label`，缺省回退 IRI 本地名；`type` 取首个 `rdf:type` |
| 为什么不用上游 `Entity` | 上游 `Entity.properties` 是 `map<String,String>`，会丢多值谓词；扩展用 `EntityPropertyList`（可重复的 `predicate/value`），并另给 `statements` 保留 `objectIsLiteral` |
| 实现状态 | **已实现并真跑**（§5.1） |

`EntityDetail` 字段：`uri`、`label`、可选 `type`、`properties[]`（`predicate` / `value` 均为必填）。
`EntityStatement` 字段：`subject`、`predicate`、`object`、`objectIsLiteral`（Boolean，缺省 false）。

### 4.2 `GetMetricObservations`

| 项 | 内容 |
|---|---|
| 方法与路径 | `GET /namespaces/{namespaceId}/metrics/{name}/observations` |
| 入参 | `namespaceId`（path）；`name`（path，`MetricName`）；`from`、`to`（query，ISO-8601）；`grain`（query，如 `day`/`month`）；`maxResults`（query，1–1000，默认 100） |
| 出参 | `metricName: MetricName`；`observations: MetricObservationList`；`truncated: Boolean` |
| 错误 | 400 `ValidationError`；404 `NotFoundError`（指标不存在）；403；503 |
| 关系 | 平行：`GetMetric` 只给定义，不给值 |
| 行为差异 | 只读已落库观测，不触发计算；`from`/`to` 缺省由实现给默认窗口，但必须在 `trace`/响应头显式说明，不得静默 |
| 实现状态 | 未实现（等观测存储与指标定义读取接线） |

`MetricObservation`：`periodStart`、`periodEnd`、`value`（Double）、`unit`、`dimensions`（map）、
`dataSourceId`、`synthetic`（Boolean）。`synthetic=true` 的数据必须在响应里标出来。

### 4.3 `ComputeMetric`

| 项 | 内容 |
|---|---|
| 方法与路径 | `POST /namespaces/{namespaceId}/metrics/{name}/compute` |
| 入参 | `namespaceId`（path）；`name`（path）；body: `from`、`to`、`grain`、`dimensions[]` |
| 出参 | `metricName`；`value`（Double）；`unit`；`periodStart`；`periodEnd`；`dataSourceId`；`confidence: ConfidenceScore`；`trace: TraceStepList` |
| 错误 | 400；404（指标不存在）；409 `ConflictError`（定义不可执行）；403；503 |
| 关系 | 平行：上游没有“按定义即时算一个值”的 operation |
| 行为差异 | **只读、不落库**：不写 `metric_observation`；要落库走平台既有写路径，不走本 operation |
| 实现状态 | 未实现（等指标执行器 + 定义→SQL 绑定） |

### 4.4 `GetOntologyVersion`

| 项 | 内容 |
|---|---|
| 方法与路径 | `GET /namespaces/{namespaceId}/ontologies/{ontologyId}/version` |
| 入参 | `namespaceId`（path）；`ontologyId`（path） |
| 出参 | `ontologyVersion: String`；`publishedAt: String`；`graphUri: String`；`contentHash: String` |
| 错误 | 400；404；403；503（未接版本源） |
| 关系 | 平行：`GetOntology` 的 `OntologyRecord` 没有版本字段，`updatedAt` 不是版本 |
| 行为差异 | 版本标识必须不可变、可复现；同一 `contentHash` 对应同一份图内容 |
| 实现状态 | **契约保留，暂不实现**（等版本源；不建路由，不返回假数据） |

### 4.5 `GetAnswer`

| 项 | 内容 |
|---|---|
| 方法与路径 | `POST /namespaces/{namespaceId}/answer` |
| 入参 | `namespaceId`（path）；body: `query`（必填，`NaturalLanguageQuery`）；`maxCitations`（1–50）；`includeGraphContext`（Boolean） |
| 出参 | `answerId: String`；`answer: CustomerData`；`confidence: ConfidenceScore`；`citations: SupportingContentList`；`graphContext: GraphContext`；`trace: TraceStepList` |
| 错误 | 400；403；404 `NamespaceNotFoundError` / `NoResultError`；429；503 |
| 关系 | 平行输出 + 实现复用 `Query` 的 Tier 路由 |
| 行为差异 | `Query` 返回完整 `QueryResult`（`rows`/`queryUsed`/`sparqlGenerated`/`partial` 等）；`GetAnswer` 只要答案、引用与可选图上下文。`answerId` 是后续 `GetCitationChain` 的句柄，必须由服务端持久化后才返回 |
| 实现状态 | 未实现（本地网关尚无 Tier 路由；没有 answer 持久化） |

### 4.6 `GetCitationChain`

| 项 | 内容 |
|---|---|
| 方法与路径 | `GET /namespaces/{namespaceId}/answers/{answerId}/citations` |
| 入参 | `namespaceId`（path）；`answerId`（path）；`maxDepth`（query，1–5，默认 2）；`maxCitations`（query，1–100，默认 50） |
| 出参 | `nodes: CitationNodeList`；`edges: CitationEdgeList`；`truncated: Boolean` |
| 错误 | 400；404（answerId 不存在）；403；503 |
| 关系 | 平行：上游 `supportingContent` 是平铺 chunk，无引用链 |
| 行为差异 | 返回有向图（`edges.from`/`to`/`relation`），不是列表；有环时必须截断并置 `truncated=true`，不得死循环 |
| 实现状态 | 未实现（等 answer/引用存储） |

`CitationNode`：`chunkId`、`documentId`、`documentName`、`pageFrom`、`pageTo`、`text`、`relevanceScore`。
`CitationEdge`：`from`、`to`（均为 chunkId 或节点 id）、`relation`（如 `supports` / `derived_from`）。
