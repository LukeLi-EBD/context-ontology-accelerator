# 存储分层实现方案

> 文档编号：07

> 日期：2026-11-04  
> 关系：《03-单机架构方案.md》§3.4 的实现级展开；端口契约见 04 §4.1；运行形态见 05；选型见 06。  
> 范围：分层、布局、DDL、写入/读取/删除/核对/备份/迁移协议、参数与验收。**照此可直接写代码。**  
> 口径：默认 `storage.small_object_provider=pg`（小工件）+ `storage.large_object_provider=fs`（CAS）；`storage.provider` 为两者简写；Silo 仅可选。资料总量 20–50GB（D24）。

---

## 0. 结论摘要

| # | 结论 | 理由 |
|---|---|---|
| 1 | 四层：L0 内存 / L1 PG / L2 本地盘 CAS（默认）/ L3 Silo（可选） | 按“可变性 + 体量 + 一致性要求”分层，而不是按技术偏好 |
| 2 | 默认大件层 = L2 CAS；PG 只接小工件 | 追加型冷数据放文件系统最省事；PG 有 WAL/VACUUM/备份代价 |
| 3 | 写入顺序：**先文件、后元数据、再引用** | 元数据指向不存在的文件是硬故障；孤儿文件可回收 |
| 4 | 删除只摘引用 + 软删，GC 有 24–72h 宽限期 | 防误删、防“删除时仍在被读” |
| 5 | 核对器默认只报告（dry-run），`--apply` 才动作 | 自动删文件/删图数据风险不可接受 |
| 6 | 图（Oxigraph）不在 PG 里；对象元数据在 PG；对象字节在 L2 | 图引擎唯一，PG 不存三元组 |
| 7 | 不做自动冷热分层 | 单机规模下复杂度不值；只给显式迁移命令 |

## 1. 分层定义

### 1.1 四层职责

| 层 | 介质 | 存什么 | 不存什么 |
|---|---|---|---|
| **L0 内存** | 进程内 LRU | 热点实体视图、文档片段、查询结果、对象流缓冲 | 权威数据；超过容量的大对象 |
| **L1 PG** | `postgres:18` | 元数据、状态机、小工件（`bytea`/LO）、抽取文本、manifest、索引状态 | 大原件；三元组（图在 Oxigraph） |
| **L2 本地盘 CAS** | `<root>/blobs` | 文档原件、图片、视频、模型权重、导出快照 | 需要强事务的小工件 |
| **L3 Silo/S3** | `silo` 容器（可选） | 同 L2，外加 S3 API 消费者/迁移 | 默认不启用 |

### 1.2 数据类别 → 层级

| 数据类别 | 层级 | 理由 |
|---|---|---|
| 本体 T-Box / 实例 A-Box / named graph | **Oxigraph（RocksDB）** | RDF 原生 + SPARQL；不是“文件”，也不是 PG 表 |
| 版本状态、审批、任务、审计 | **L1 PG** | 事务与状态机；体量小 |
| 文档原件（PDF/Office/图片/视频） | **L2 CAS** | 追加为主、不可变、体量大；需 Range/流式 |
| 抽取文本（每文档几 KB–几 MB） | **L1 PG**（`bytea` 或 `text`） | 与元数据同事务；可全文检索 |
| 缩略图 / 切块结果 / manifest | **L1 PG**（`bytea`，≤10 MB） | 小、需与元数据强一致 |
| embedding 向量 | **L1 PG（pgvector）** | 索引在 PG；主键 = IRI 或其 sha256 |
| 模型权重 / 大模型文件 | **L2 CAS**（不进 PG） | 大、只读、可重复下载 |
| 备份快照（PG dump / 图 dump / 清单） | **L2**（`backups/`） | 大文件；与 blob 分开目录 |
| 日志 | 文件（`logs/`）或 stdout | 非权威；不进入 CAS |
| 可重建派生索引（tsvector、缓存表） | **L1 PG**，可放 tmpfs | 丢了可重建 |

## 2. 落盘布局

```text
<root>/
  blobs/<hh>/<sha256>          # 权威 CAS；hh = sha256 前 2 位十六进制（256 桶）
  tmp/<uuid>.part             # 写入暂存；必须与 blobs 同卷
  manifests/<name>.jsonl      # 哈希清单（备份/迁移/校验）
  quarantine/<uuid>/          # 核对器隔离的可疑文件（不直接删）
  backups/                    # PG dump / Oxigraph dump
  incoming/YYYY/MM/           # 仅导入中转（不是权威存储）
```

### 2.1 命名与扩展名

- **不保留扩展名**：路径只由内容哈希决定；MIME、原始文件名存 PG。
- 下载时由 PG 读取 `mime` 与原始文件名，设置 `Content-Type`、`Content-Disposition`。
- 哈希：小写十六进制 sha256（64 字符）；统一小写，避免大小写不敏感文件系统冲突。

### 2.2 分片宽度依据

- 2 位 = 256 桶。100 万对象时平均 **~3,900 文件/目录**，ext4（`dir_index`）与 NTFS 均可接受。
- 再分片判据（可配置）：`平均文件数/目录 > 5,000` 或 `对象总数 > 500 万` → 改为 3 位（4,096 桶），提供 `storage reshard` 显式命令（非自动）。
- **不要**按年月分桶 CAS 主体；年月只用于 `incoming/` 中转。

### 2.3 跨卷注意

- `tmp/` 与 `blobs/` **必须在同一卷**，否则 `rename` 不原子（会退化为复制+删除）。
- 启动自检：比较两者 `st_dev`（Linux）/ 卷标（Windows）；不一致直接 fail-fast。

## 3. PG 表结构（真实 DDL）

### 3.1 主表与引用

```sql
-- 对象主表：一行 = 一个内容哈希（全局唯一）
CREATE TABLE blob (
  hash              char(64) PRIMARY KEY,              -- sha256 小写
  size              bigint NOT NULL CHECK (size >= 0),
  mime              text   NOT NULL DEFAULT 'application/octet-stream',
  tier              text   NOT NULL CHECK (tier IN ('pg','fs','silo')),
  path              text,                              -- tier=fs/silo 时的相对 key；tier=pg 为 NULL
  state             text   NOT NULL CHECK (state IN ('staging','committed','missing','deleting')),
  created_at        timestamptz NOT NULL DEFAULT now(),
  deleted_at        timestamptz,
  refcount          integer NOT NULL DEFAULT 0 CHECK (refcount >= 0),
  last_verified_at  timestamptz,
  verified_ok       boolean
);
CREATE INDEX blob_state_created_idx ON blob (state, created_at);
CREATE INDEX blob_gc_idx ON blob (refcount, state) WHERE state = 'deleting';
CREATE INDEX blob_tier_size_idx ON blob (tier, size);

-- 引用表：一行 = 一个持有者引用（唯一约束防重复计数）
CREATE TABLE blob_ref (
  hash        char(64) NOT NULL REFERENCES blob(hash) ON DELETE RESTRICT,
  owner_type  text NOT NULL,          -- ontology|document|extraction|manifest|model|export
  owner_id    text NOT NULL,          -- IRI / document_id / job_id
  created_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (hash, owner_type, owner_id)
);
CREATE INDEX blob_ref_owner_idx ON blob_ref (owner_type, owner_id);

-- 策略参数（单行表；也可放配置文件，DB 便于运行期调整）
CREATE TABLE storage_policy (
  id                       smallint PRIMARY KEY DEFAULT 1 CHECK (id = 1),
  provider                 text NOT NULL DEFAULT 'fs',
  small_object_max_bytes   bigint NOT NULL DEFAULT 10485760,   -- 10 MB
  pg_max_total_ratio       numeric(4,3) NOT NULL DEFAULT 0.200, -- 20% 数据盘可用空间
  gc_grace_hours           integer NOT NULL DEFAULT 48,
  verify_sample_ratio      numeric(4,3) NOT NULL DEFAULT 0.010,
  updated_at               timestamptz NOT NULL DEFAULT now()
);

-- 审计（可选）
CREATE TABLE blob_event (
  id      bigserial PRIMARY KEY,
  hash    char(64) NOT NULL,
  event   text NOT NULL,             -- put|ref|deref|gc|missing|restore|verify
  actor   text,
  detail  jsonb,
  at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX blob_event_hash_at_idx ON blob_event (hash, at DESC);
```

### 3.2 小工件的两种载体

**`bytea`（默认，≤10 MB）**

```sql
CREATE TABLE blob_bytea (
  hash     char(64) PRIMARY KEY REFERENCES blob(hash) ON DELETE CASCADE,
  content  bytea NOT NULL
);
```

- 限制：单值通常 ≤1 GB；大值触发 TOAST；`bytea` 只能整体读，**不支持 Range**。
- 适用：抽取文本、缩略图、manifest、小 JSON。

**Large Object（需要分块流式/较大文件时）**

```sql
CREATE TABLE blob_lo (
  hash  char(64) PRIMARY KEY REFERENCES blob(hash) ON DELETE CASCADE,
  loid  oid NOT NULL
);
```

- 用 `lo_create`/`lo_import` 建，`lo_unlink` 删；按 64 KB 页读写。
- **事实更正**：PG 的 `pg_dump` **默认包含 large objects**；但指定 `--schema`/`--table`/`--schema-only` 时不含，需要用 `lo_export` 单独导出。不要沿用“pg_dump 默认不含 LO”的旧说法。
- LO 不参与 `ON DELETE CASCADE` 的物理清理：删 `blob_lo` 行时必须显式 `lo_unlink`。

### 3.3 约束语义

- `blob.hash` 唯一 → 天然去重；同内容只一行。
- `blob_ref` 主键 `(hash, owner_type, owner_id)` → 同一持有者重复引用不重复计数。
- `refcount` 由应用在同一事务内维护（`INSERT ... ON CONFLICT DO NOTHING RETURNING` 成功才 `+1`）。
- `state=committed` 才对外可见；`missing` 表示“行在、文件不在”，读返回 `DataLoss`，不静默 404。

## 4. 写入协议

### 4.1 步骤

```text
1. 流式读取输入，边写 <root>/tmp/<uuid>.part，边算 sha256（不全量入内存）
2. 得到 hash 后：SELECT tier,state,refcount FROM blob WHERE hash=$1
   - 若 committed：只加引用（步骤 6），跳到 7
   - 若 missing：进入修复流程（不重复写字节，先报告）
3. fsync(tmp 文件)；fsync(tmp 目录)
4. rename tmp -> blobs/<hh>/<hash>（同卷原子）；fsync(blobs/<hh> 目录)
5. INSERT INTO blob(hash,size,mime,tier,path,state)
     VALUES (...,'fs','blobs/<hh>/<hash>','committed')
     ON CONFLICT (hash) DO NOTHING
6. INSERT INTO blob_ref(hash,owner_type,owner_id) ... ON CONFLICT DO NOTHING RETURNING hash
   - 仅当 RETURNING 有行时：UPDATE blob SET refcount = refcount + 1
7. COMMIT
```

### 4.2 每一步崩溃后的恢复

| 崩溃点 | 现象 | 恢复动作 |
|---|---|---|
| 步骤 1–2 | `tmp/*.part` 残留 | GC 扫 `tmp/`，删除超过 `tmp_grace_hours`（默认 6h）的文件 |
| 步骤 3–4 之间 | 临时文件已 fsync，未 rename | 同上；GC 不碰 `blobs/` |
| 步骤 4 之后、5 之前 | **文件在、无行（orphan file）** | reconciler 报告；过宽限期后移入 `quarantine/`，不直接删 |
| 步骤 5 之后、6 之前 | 行 `committed`、`refcount=0` | 正常；GC 按“refcount=0 + 超过 grace”处理 |
| 步骤 6 中 | 引用未写入 | 事务未提交，整笔回滚；重试即可（幂等） |
| 提交后 | `committed` 但文件被外部删除 | 启动校验置 `state='missing'`；读返回 `DataLoss`；从备份恢复 |

### 4.3 并发同哈希写入

- 两个写者同时写同一内容：各自写独立 `tmp/<uuid>.part`；`rename` 相互覆盖但**内容相同**，最终文件一致。
- 行插入用 `ON CONFLICT (hash) DO NOTHING`；引用插入用复合主键去重。
- `refcount` **只在 `blob_ref` 真正插入成功时 +1**，避免双计数。
- 不在应用层加锁；依赖唯一约束与幂等。

### 4.4 为什么“先文件后元数据”

- 元数据先写 → 崩溃后出现“行指向不存在的文件”，读路径必失败且无法自愈（字节不可重建）。
- 文件先写 → 最坏是**孤儿文件**，可检测、可隔离、可回收，不产生错误承诺。
- 因此顺序固定：**字节 → 元数据行 → 引用 → 提交**。反向不提供。

## 5. 读取协议

### 5.1 命中顺序

```text
L0 内存（仅 committed + immutable，key=hash，单条 ≤8 MB，总量上限可配）
  ↓ miss
L1 PG（先查 blob 行拿 tier/state，再按 tier 取 bytea/lo）
  ↓
L2 FS（blobs/<hh>/<hash>）
  ↓
L3 Silo（仅 provider=silo 或 tier=silo）
```

- **先查 `blob` 行**：拿 `state`；`missing` → `DataLoss`；不存在 → `NotFound`。
- L0 缓存不缓存 `missing/NotFound`（或最多 30s 负缓存），避免恢复后仍报错。

### 5.2 Range 读

| 介质 | 实现 |
|---|---|
| FS | `pread(fd, offset, length)`；HTTP 返回 `206 + Content-Range` |
| PG LO | `lo_lseek64` + `lo_read` 按块读；不可一次读全 |
| PG `bytea` | **不支持** Range：整体读出后切片（仅限 ≤ small_object_max），否则 `Unsupported` |
| Silo | 原生 Range |

### 5.3 流式与无预签名退化

- 下载路径**必须流式**：固定缓冲（如 1 MB），`ReadableStream` 直通 HTTP；禁止 `readAll()`。
- `presign=false`：所有下载走 `platform` 代理端点 `GET /objects/{hash}`（支持 Range），鉴权在 platform；前端不直连。
- 响应头：`Content-Length`、`Accept-Ranges: bytes`、`ETag: "<sha256>"`、`Content-Disposition`（来自 PG 原始文件名）。
- 上传同理：platform 流式接收 → `ObjectStore.put`，不要求前端分片直传。

## 6. 删除与回收

### 6.1 删除 = 摘引用

```text
1. DELETE FROM blob_ref WHERE hash=$1 AND owner_type=$2 AND owner_id=$3   -- 必须命中
2. UPDATE blob SET refcount = refcount - 1
3. 若 refcount = 0 → UPDATE blob SET state='deleting', deleted_at=now()
4. COMMIT（不做物理删除）
```

- **宽限期**：`storage.gc_grace_hours`，默认 **48h**（建议 24–72h）。
- `storage gc`：仅处理 `state='deleting' AND deleted_at < now()-grace` 的行 → 删文件（或 `lo_unlink`）→ 删行。
- 保护“正在读”：删除前检查进程内活跃读句柄/租约；有租约则顺延一个 grace 周期。

### 6.2 孤儿

| 类型 | 判定 | 处理 |
|---|---|---|
| 文件有、行无 | 扫 `blobs/` 与 `blob` 表差集 | 默认只报告；`--apply` 且文件 mtime 超过 grace → 移入 `quarantine/`，不直接删 |
| 行有、文件无 | `state=committed` 但 `stat` 失败 | 置 `state='missing'`；从备份恢复；**不删行、不删引用** |
| 图有 IRI、行无 | Oxigraph 有 `urn:platform:object:<hash>`，PG 无对应行 | 报告 `dangling_iri`；由属主修正图；**绝不联动删图** |

## 7. 一致性核对（reconciler）

### 7.1 三方比对

```text
A. PG:      SELECT hash, tier, state, size FROM blob
B. 磁盘:    遍历 blobs/*/*，得到 (hash, size, mtime)
C. 图:      SELECT ?o WHERE { ?s <urn:platform:object> ?o }（或平台登记的引用谓词）
```

输出四类差异：

| 差异 | 含义 | 默认动作 |
|---|---|---|
| `missing_file` | 行在、文件不在 | 置 `missing`；告警 |
| `orphan_file` | 文件在、行不在 | 报告；`--apply` 后隔离 |
| `dangling_iri` | 图引用无对象行 | 报告；交属主修复 |
| `tier_mismatch` | 行 `tier=fs` 但文件不存在/路径不符 | 报告；按迁移流程修正 |

### 7.2 修复顺序（重要）

1. **先置 `missing`**（不删任何东西）——避免把“暂时不可读”误判为可删。
2. **再修引用**：dangling IRI 只报告，由业务侧补对象或删三元组（人工/作业）。
3. **最后处理孤儿文件**：隔离而非删除；确认后再 `--apply --purge`。
4. **禁止联动删除**：reconciler 不得因为“文件没了”就删图里的三元组。

### 7.3 可执行清单

```sql
-- 行数/字节
SELECT count(*), pg_size_pretty(coalesce(sum(size),0)) FROM blob WHERE state='committed';
-- 缺失候选
SELECT count(*) FROM blob WHERE state='missing';
-- 长期 deleting（GC 漏跑）
SELECT count(*) FROM blob WHERE state='deleting' AND deleted_at < now() - interval '72 hours';
-- 无引用但未标记（写入中断）
SELECT count(*) FROM blob WHERE refcount=0 AND state='committed' AND created_at < now() - interval '1 day';
```

```bash
# 文件清单（含大小），供比对
find blobs -type f -printf '%P\t%s\n' | sort > manifests/disk.tsv
# 抽样校验（1%）
storage verify --sample 0.01
```

```powershell
Get-ChildItem -Recurse blobs -File | ForEach-Object { "{0}`t{1}" -f $_.FullName.Substring($PWD.Path.Length+1), $_.Length }
```

## 8. 备份与恢复

### 8.1 三件套

| 对象 | 方式 | 注意 |
|---|---|---|
| Oxigraph | 停机/只读后 `oxigraph dump`（N-Quads）或目录快照 | 运行中直接 `cp` RocksDB 目录**不安全**（LSM 文件不一致） |
| Jena Fuseki/TDB2（备选，D25） | `tdb2.tdbdump` 导出或停机后 TDB2 目录快照 | 与 Oxigraph 互斥；两套备份不得混用 |
| PG | `pg_dump`（默认含 LO；`--schema/--table/--schema-only` 时不含） | 需要 LO 时用完整 dump 或 `lo_export` |
| CAS 文件 | 增量同步 + 清单 | 不要用“镜像删除”模式盲删 |

**示意命令与预期耗时（20–50GB 语料，估算；假设本地 SSD、备份盘同机）：**

```bash
# 1) 图（先备，恢复时最后恢复）
oxigraph dump --output /backup/oxigraph-<ts>.nq        # 1–5 万–百万三元组：秒级–1 分钟

# 2) PG（元数据 + 小工件；库约 1–3GB）
pg_dump -Fc -f /backup/pg-<ts>.dump platform           # 约 20–60 秒

# 3) CAS（内容寻址 + 不可变 → 增量）
rsync -a --checksum /data/blobs/ /backup/blobs/        # 首次 10–30 分钟；之后 < 2 分钟
# 或 restic backup /data/blobs --tag cas               # 首次全量，之后仅新增块

# 4) 清单
sha256sum $(find /data/blobs -type f) > /backup/manifest-<ts>.txt
```

**恢复：** `pg_restore` → 图 `oxigraph load` → CAS 回拷（顺序为“图 → 元数据 → 文件”的逆操作见 03 §3.4.4 口径），最后 **必须跑一次 `reconciler` 全量比对（零差异）** 才算完成。

### 8.2 顺序与静默窗口

```text
进入 maintenance（禁写：DB 标记 + 拒绝写请求）
 → Oxigraph 快照
 → PG dump
 → CAS 文件增量同步（生成 manifests/backup-<ts>.jsonl）
 → 退出 maintenance
```

恢复按**相反顺序**：文件 → PG restore → 图 restore → 跑 reconciler（全量，非抽样）。

### 8.3 校验

- 每份备份生成 hash 清单（`sha256sum` / `Get-FileHash`）。
- 还原后：**完整清单比对**（不是抽样）；抽样 1% 只用于日常巡检（`storage.verify_sample_ratio=0.01`）。
- 清单缺失/大小不符 → 标 `missing`，不静默覆盖。

## 9. 迁移路径

| 方向 | 命令语义 | 双读策略 | 失败回滚 |
|---|---|---|---|
| PG → FS（超阈值下沉） | `storage migrate --from pg --to fs --where "size > policy"`：读 bytea/lo 流式写 CAS，校验 hash，事务内改 `tier/path`，再删 PG 载荷 | 迁移中按 `tier` 字段读；未完成的行仍读 PG | 保留 PG 载荷直到校验通过；失败行不改 tier |
| FS → Silo（有 S3 消费者） | `storage migrate --from fs --to silo`：上传后校验 ETag/sha256，改 `tier/path` | Silo 404 时回退读 FS（一个 grace 周期） | 保留 FS 文件，成功后延迟清理 |
| Silo → FS（回退） | 反向；下载后写 CAS 并校验 | 同上反向 | 保留 Silo 对象 |

- **不做自动冷热分层**（无成本收益，复杂度高）；只提供显式命令。
- 迁移必须单写者：进入 maintenance 或对 `blob` 行加 advisory lock。

## 10. 配置与参数

```yaml
storage:
  small_object_provider: pg        # pg(默认)|fs；小工件层
  large_object_provider: fs        # fs(默认)|silo|pg；大件层（pg 有护栏：>30GB 拒启）
  # provider: fs                   # 简写：显式设置时同时覆盖两层
  root: /data                      # CAS 根（Windows: D:\data）
  tmp_dir: /data/tmp               # 必须与 blobs 同卷
  pg_blob_max_file_mb: 10          # 超过则落 fs；风险：调大 → WAL/备份膨胀
  pg_blob_max_total_pct: 20        # blob 总量/数据盘可用空间（%）；调大 → PG 膨胀
  gc_grace_hours: 48               # 调小 → 误删风险上升
  verify_sample_ratio: 0.01        # 调大 → IO 增加
  require_range_read: true         # 关闭则拒绝 Range 请求（不建议）
  fsync: true                      # 关闭 = 崩溃可能丢最近写入（不建议）
  reshard_threshold_files_per_dir: 5000
  tmp_grace_hours: 6
```

> **参数名映射（与 04 §10 对齐）：** 配置键用 `pg_blob_max_file_mb` / `pg_blob_max_total_pct` / `require_range_read`；DDL 内部列名保留 `small_object_max_bytes` / `pg_max_total_ratio`（见 §4），二者语义等价、单位不同（MB vs 字节，百分比 vs 0–1 比例）。

> **`large_object_provider=pg` 护栏（D24）：** 启动自检按 `pg_database_size` + 近 90 天增长率估算 dump 体积；>15GB 告警、>30GB 拒绝启动（需 `--force`）。三条机制性代价必须打印：WAL 等量放大、`pg_dump`/恢复线性增长、TOAST 行重写整块复制。

| 参数 | 默认 | 含义 | 改动风险 |
|---|---|---|---|
| `small_object_provider` | `pg` | 小工件层 | 切 `fs`：丢掉“文件+元数据同事务” |
| `large_object_provider` | `fs` | 大件层 | 切 `pg` 会放大 WAL/备份；切 `silo` 多一个容器 |
| `root` | `/data` | CAS 根 | 换根需迁移 + 重写 `path` |
| `pg_blob_max_file_mb` | `10` | 小工件上限（MB） | 调大：WAL/VACUUM/备份变重 |
| `pg_blob_max_total_pct` | `20` | PG blob 占数据盘比例（%） | 调大：备份与恢复时间线性上升 |
| `gc_grace_hours` | `48` | 删除宽限 | 调小：误删不可恢复 |
| `verify_sample_ratio` | `0.01` | 巡检抽样 | 调大：IO 压力 |
| `require_range_read` | `true` | 允许 Range | 关闭：大文件只能整取 |
| `fsync` | `true` | 落盘保证 | 关闭：断电丢数据 |

## 11. 失败模式表

| 失败 | 现象 | 检测 | 自动处理 | 人工处理 |
|---|---|---|---|---|
| 磁盘满 | 写入失败、`ENOSPC` | 写前检查可用空间 + 错误码 | 拒绝写、返回 `ResourceExhausted`；保留 tmp 清理 | 扩容/清理 GC |
| 权限不足 | `EACCES`/容器用户不匹配 | 启动自检读写探测 | fail-fast | 修挂载权限/用户 |
| rename 跨卷 | `EXDEV` | 启动比较 `st_dev`/卷标 | fail-fast（不自动复制降级） | 把 tmp 移到同卷 |
| 哈希碰撞 | 同 hash 不同内容 | 写入前若 hash 已存在，比对 size；必要时抽样比对 | 极低概率；发现即拒绝并告警 | 人工核查（理论问题） |
| 并发写 | 双写同 hash | 唯一约束冲突 | `ON CONFLICT DO NOTHING` + 幂等引用 | 无需人工 |
| GC 与读竞争 | 删除时读到半文件 | 活跃读租约/最后访问时间 | 顺延 grace；先摘引用后删 | 恢复备份 |
| 备份中断 | 部分文件/半 dump | 清单校验、dump 退出码 | 标记备份失败，不覆盖上一份 | 重跑备份 |
| 时钟回拨 | grace 误判（提前删/不删） | 用 DB `now()` 而非本机时间；记录单调时间 | 以 DB 时间为准 | 校时 |

## 12. Windows 与 Linux 差异

| 事项 | Windows / NTFS | Linux / ext4·XFS |
|---|---|---|
| 路径长度 | 未启用 LongPaths 时 260 字符；用短根 + 2 级分桶 | 通常 4096 路径限制，2 级分桶足够 |
| 大小写 | **不敏感**：`A`/`a` 冲突；hash 统一小写 | 敏感，但仍统一小写 |
| rename 原子 | 同卷 `MoveFileEx`/`os.replace` 原子；跨卷不原子 | 同卷 `rename(2)` 原子；跨卷 `EXDEV` |
| 文件锁 | 打开的文件不能删/改名，删除常失败 | 可 unlink 打开的文件，但读句柄仍有效 |
| 容器挂载 | 无 POSIX uid；权限映射弱，性能较低 | 命名卷/绑定挂载正常；注意 UID/GID |
| 行尾 | 文本工件 CRLF 会导致 hash 不同 | 统一 UTF-8 + LF（二进制按字节哈希） |
| 目录性能 | 大目录遍历弱 | XFS 更适合大目录/大文件；ext4 注意 inode 预留 |

**口径：** Windows 可用于开发与单机试用；**生产建议 Linux + ext4/XFS + 独立数据盘**。不要用 Windows 开发目录的 IO 数据做容量/性能结论。

## 13. 验收清单（12 条）

- [ ] 1. 同一文件二次上传：`blob` 仍只有一行，`blob_ref` 两条，`refcount=2`，磁盘只有一份。
- [ ] 2. 在 rename 之后、写 `blob` 行之前强杀进程：重启后 reconciler 报 `orphan_file`，不产生错误读。
- [ ] 3. 写 `blob` 行后、文件被手动删除：读返回 `DataLoss` 且行被置 `missing`（不是 404）。
- [ ] 4. 并发两进程写同一 hash：最终 refcount 正确、无重复文件、无唯一约束异常泄漏到上层。
- [ ] 5. 删除后 `gc_grace_hours` 内可恢复（重新加引用即可），grace 后 `storage gc` 才物理删除。
- [ ] 6. `storage gc --dry-run` 只报告；`--apply` 才动作；隔离文件先进 `quarantine/`。
- [ ] 7. Range 请求：FS 返回 206 + 正确 `Content-Range`；`bytea` 对象返回 `Unsupported` 而非错误数据。
- [ ] 8. 1 GB 对象下载：进程 RSS 不随文件大小线性增长（流式生效）。
- [ ] 9. `presign=false` 时代理下载可用，前端不直连；响应含 `degraded=true`。
- [ ] 10. 备份→恢复→reconciler 全量比对：`missing_file/orphan_file/dangling_iri` 均为 0。
- [ ] 11. PG→FS 迁移中断后重跑：幂等；未迁移行仍可从 PG 读；已迁移行 hash 校验通过。
- [ ] 12. Windows 与 Linux 各跑一遍布局/原子写测试：`tmp` 与 `blobs` 跨卷时启动 fail-fast。
