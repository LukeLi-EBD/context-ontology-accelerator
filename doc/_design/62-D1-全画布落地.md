## 2. 能力矩阵（simple vs full）

| 能力 | simple | full |
| --- | --- | --- |
| 跳数上限 | 3（硬上限） | 6（`full_max_hops`，配置 1..6，硬上限 6） |
| 遍历 | 单向分层 BFS（无向） | **双向 BFS**（两端各 `ceil(hops/2)` 层，合并邻接） |
| 路径枚举 | 最短路（父指针回溯） | **多路径**：≤maxHops 的简单路径全枚举，按长度/权重/节点序列排序，节点序列去重 |
| 环处理 | 父指针 + visited | visited 防环 + 路径去重 + `PATH_VISIT_CAP=12000` 访问上限 |
| 谓词过滤 | T-Box 属性白名单 | 白名单 + `predicateTypes`（object/datatype/annotation/rdf 或完整 kind IRI） |
| 命名图过滤 | `graphs`（只允许 `urn:platform:` 可读集） | 同左 + 服务端白名单校验 `E_CANVAS_GRAPH_FORBIDDEN` |
| 服务端聚合 | 无 | 节点入/出/总度数、边权重、按类分桶、按谓词分桶 |
| 分页 | 无（一次返回） | `pageSize`(≤200) + 游标（base64 指纹 + offset），页级 layout |
| 截断原因 | `E_CANVAS_TRUNCATED` | `E_CANVAS_NODES_TRUNCATED` / `E_CANVAS_EDGES_TRUNCATED` / `E_CANVAS_PATHS_TRUNCATED` |
| `hasRef` | 恒 `false` | 真实回填（PROV `src://` 节点 + 已通过抽取候选，节点/边） |
| 预算 | 500ms（硬上限） | `timeout_ms`（硬上限 5000ms） |
| 超限表现 | 抛 `E_CANVAS_TIMEOUT` / `E_CANVAS_HOPS_EXCEEDED` | 同左，另加页大小/游标/谓词类型等专用码 |
| 布局 | `{"mode":"none"}` | `layout.mode=force`，含 page 内节点度数/簇（前端不拉全量） |

## 3. 配置

```yaml
canvas:
  provider: full        # off | simple | full
  simple_max_hops: 3    # simple 硬上限 3
  full_max_hops: 4      # full 生效跳数，允许 1..6
  max_nodes: 200        # 端口默认；请求可下调，不能超过 provider 硬上限
  max_edges: 400
  max_paths: 20
  timeout_ms: 500       # simple 取 min(该值,500)；full 取 min(该值,5000)
```

`limits` 与 `stats.truncation` 记录的是**本次生效上限**（请求值与 provider 硬上限的较小者），
不再回显 provider 硬上限。

## 4. 路由

| 路由 | 条件 | 说明 |
| --- | --- | --- |
| `GET /browse/path` | off/simple/full | 既有端点，签名不变；full 下由 `FullCanvas` 应答 |
| `GET /browse/canvas/manifest` | 任意 | 返回 `provider/port/capabilities/limits/notes`，前端据此决定是否挂载 |
| `GET /browse/canvas/full` | 仅 full | 过滤/分页/聚合/游标；非 full 返回 `E_CANVAS_PROVIDER_MISMATCH` |

前端切换逻辑：`canvas_full.js` 先请求 manifest，只有 `provider=full` 才挂载自己的面板并隐藏
`#canvas-path`；simple/off 下它完全不动作，`browse_path.js` 保持原样。页面由配置决定，
不靠改 HTML/JS。

## 5. 错误码

| 码 | HTTP 语义 | 触发 |
| --- | --- | --- |
| `E_PROVIDER_INVALID` | 配置期 | `canvas.provider` 不是 `off/simple/full` |
| `E_PROVIDER_NOT_IMPLEMENTED` | 配置期 | 已登记未装配（当前已无值命中） |

| `E_CANVAS_HOPS_EXCEEDED` | 400 | `maxHops` 超出 provider 范围 |
| `E_CANVAS_GRAPH_FORBIDDEN` | 403 | 请求的命名图不在可读白名单 |
| `E_CANVAS_BAD_PREDICATE_TYPE` | 400 | `predicateTypes` 不是已知属性种类 |
| `E_CANVAS_PAGE_EXCEEDED` | 400 | `pageSize` 超出 1..200 |
| `E_CANVAS_BAD_CURSOR` | 400 | 游标损坏、指纹不匹配、offset 越界 |

## 6. `hasRef` 与覆盖率实测

语义：节点/边对应的事实行有 source key 才 `hasRef=true`，并给 `src://` 引用与
`/source/resolve` 链接；没有就是 `false`，**不伪造**。

实测（真实 PostgreSQL 元数据 + 真实 Oxigraph）：

| 场景 | 结果 |
| --- | --- |
| `urn:platform:entity:广州` 的已通过抽取候选（`abox:main`） | 节点与边均 `hasRef=true`；引用 `src://doc/a5a6…bd3#c0`，可经 `/source/resolve?ref=src%3A%2F%2F…` 解析 |
| `urn:platform:entity:中国`（无候选） | `hasRef=false` |
| synthetic ABox 2 跳子图 | 107 节点 / 0 有引用（0.0%）；300 边 / 0 有引用（0.0%） |
| PROV `urn:platform:prov` | 只填节点；`src://` 直链 0 条 |
| 事实层 source key（28 张事实表） | 161,549 行，自然键完整 **100.00%** |

结论：**画布实测覆盖率 0%**。原因不是实现问题，而是当前数据没有把事实落到图上：
`abox:main` 的图三元组为空（候选只停在抽取候选表），synthetic 图没有候选/PROV 链接。
事实层 100% 的自然键完整率说明“有 source key 的事实行占比”是满的，一旦事实物化进图，
`hasRef` 会真实回填；真/假两态已由单测与上面的真实候选路径覆盖。

### 7.4 查询形状与硬约束

- 禁止“变量图 + UNION”：全文件没有 `UNION`（单测断言）；每层拆成 outgoing/incoming 两条普通查询。
- 命名图白名单：walk 用 `VALUES ?g { <可读图…> }`；PROV 引用同样 `VALUES ?g { <urn:platform:prov> }`。
- 每个查询带 `LIMIT`：walk 用 `LIMIT remaining`，enrich/whitelist/refs 各自带上限（单测断言）。
- 分页而非全量：`/browse/canvas/full` 每页 ≤200，layout 只保留本页节点。

实测中还纠正了两个 Oxigraph 陷阱（simple 同步修复，见 §9）：

1. `FILTER(?k IN (...))` 必须逗号分隔；空格分隔会 400 `expected ENCODE_FOR_URI`。
2. `GRAPH ?g { OPTIONAL { … } }` 在 50 个 subject 上 **35s 不返回**（与 `VALUES ?g` 变量图组合时更差）；
   改为“每图一条 `GRAPH <g> { VALUES ?s {…} ?s <label|type> ?value }`”后单批约 3ms。
   同一批 50 点：变量图 109ms vs 常量图 3ms（约 35×）。

这两条已固化为静态守卫 `platform/tests/test_sparql_query_shape.py`：扫描 `platform/src/**/*.py`，
按函数提取 SPARQL 字符串模板，检测三类形状——变量图 + `UNION`、变量图 + 分组 `BIND`、
变量图内嵌 `OPTIONAL`（用花括号配平取 `GRAPH ?v { … }` 的 body，避免把图块之后的 `OPTIONAL` 误报）。
白名单条目必须写原因与实测耗时。本轮全仓：`80` 文件 / `24` 个变量图模板 / `3` 处命中且均已白名单 /
`0` 处未白名单（基线 `luke` 树 81 文件，`canvas_simple.py:648 _enrich` 仍命中未修，见 §9）。

## 8. 已知限制

1. **`expand()` 的 delta 无语义基线**：端口没有“已有画布”参数，`merged=true` 的
   `addedNodes/addedEdges` 是相对空画布的全量，不是增量。
2. **PROV 只填节点**：`prov:used` 链路能定位到节点引用；边引用只认“已通过抽取候选”的精确
   `(s,p,o)`，不拿节点证据去凑边。
3. **metadata 降级**：没有元数据连接时 `hasRef=false`，`info.error` 写明原因；不伪造。
4. **当前数据下画布 `hasRef` 覆盖率 0%**：见 §6，事实尚未物化到图。
5. **G10 路由仅 full**：simple/off 访问返回 400 mismatch；前端面板只在 full 挂载。
6. **simple 预算**：500ms 硬上限，在大图（30 万三元组）上 2 跳起就可能 `E_CANVAS_TIMEOUT`，
   这是 53 已定的行为，不是回归。
7. **共享环境漂移（P02 证据已定位）**：测量期间另一个工作流把 ontology 指针从
   `ont-11f92ebb3326` 切到 `ont-1ac17152bfab`（6 triples：`owl:Ontology` + 3 个 smoke 类，故只有
   4 个类型；contentHash `0e6fd105…`），期间所有档位短暂返回 `E_CANVAS_TBOX_EMPTY`；
   §7 数据统一在 `ont-11f92ebb3326` 下测得。共享 Oxigraph 还存在与画布无关的
   `Internal server error while streaming results: The port 9 is not allowed…` 崩溃/重启，
   会造成偶发 503 `E_GRAPH_UNAVAILABLE`，重试即可。

   P02 切换的精确时间与来源（`platform.ontology_event` 审计链 + `agent-platform-api` 日志）：

   | 时间（+08 / UTC） | 事件 |
   | --- | --- |
   | 2026-11-06 23:54:02.975 / 15:54:02.975Z | `ont-1ac17152bfab` imported（turtle, semver 1.0.0, 6 triples, onConflict=reject） |
   | 2026-11-06 23:54:04.214 / 15:54:04.214Z | published（`implicit_governed`，actor=`operator`，previous=`ont-11f92ebb3326`） |
   | 2026-11-06 23:54:10.338 / 15:54:10.338Z | 并发 `context.resolve` 记录 version=`ont-1ac17152bfab`（多消费者解析到该版本） |
   | 2026-11-06 23:54:12.820 / 15:54:12.820Z | superseded（replacedBy=`ont-29df234e79f6`；该版本仅 current 8.6s） |
   | 2026-11-07 00:03:16.293 / 16:03:16Z | `graph_pointer` 恢复为 `ont-11f92ebb3326`（updated_by=`smoke-restore`） |

   操作来源：同一时间窗内 `shacl.validate` 记录 `urn:platform:test:d76fc32054:s5`（15:53:58Z），
   且紧邻版本的 breaking 项使用 `urn:platform:smoke:…` 命名空间，指向 smoke 套件的 S5 用例
   `platform_core/smoke_s5.py:84-85`（`import_source(path, "1.0.0")` + `publish(acknowledge_breaking=True)`）
   直接发布；即“另一个工作流”是 smoke 自检，不是画布流程。

8. **多路径规模**：`PATH_VISIT_CAP=12000` 是防止组合爆炸的硬闸；触发时给
   `E_CANVAS_PATHS_TRUNCATED`，不静默丢弃。
