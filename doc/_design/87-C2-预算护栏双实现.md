## 1 目标与非目标

**目标**：把"预算/成本护栏"做成一个端口、三档实现（`off` / `simple` / `full`），通过配置切换，不引入新中间件；轻量版可独立上线，全功能版随时替换而不改调用方。

**非目标（本切片明确不做）**：按用户/租户配额、人民币计价、告警、看板、CSV 导出、分端点限流、Redis/外部限流器。这些全部属于 C2-2，逐项列在 §4.3 与 §8。

## 2 现状证据与落点选择

- 当前代码里**唯一的 LLM 调用点是抽取**：`ExtractionService` 通过 `LlmClient.complete_json` 取候选；`/answer` 是检索 + 确定性计算，不调用 LLM。
- 因此"超限 → 跳过 LLM、只返回检索/规则结果、保持可读"的落点是 **LLM 客户端包装层**，而不是改 `/answer` 既有函数体：
  - 超限时 `QuotaAwareLlm.complete_json` 在调用前抛 `PortError(providerCode=E_QUOTA_EXCEEDED)`，内部客户端一次都不调用；
  - 抽取 `mode=auto` 已有降级契约，捕获后返回 `degraded=true`、`reasons=["E_QUOTA_EXCEEDED"]`、规则候选照常可读；
  - `/answer` 与纯检索端点不经过 LLM，超限时仍完整可读。
- `api.py` 只追加 `# --- G7 quota routes ---` 区块（模块级 `g7_register`），不改既有路由；集成方在 `create_app` 的 `return app` 前加一行 `g7_register(app, runtime)`（与 `54` §3 的锚点规则一致）。

## 3 端口契约 `QuotaPort`

`ports.py` 新增（`QuotaDecision` 为返回值，对应任务描述里的 `Decision`）：

| 方法 | 签名 | 语义 |
| --- | --- | --- |
| `manifest` | `() -> Manifest` | 实现自述：provider、能力、限额、切片。与既有端口一致，供 `/status` 与排障使用 |
| `check` | `(scope, units=1) -> QuotaDecision` | **只读预判**：以当前用量 + 本次 `units` token + 1 次请求判断是否放行；不写库 |
| `record` | `(scope, units, cost=0.0) -> None` | 记账：原子累加 tokens/requests/cost，一次调用 = 一次请求 |
| `status` | `(scope) -> dict` | 当前用量、上限、剩余、是否触顶、当日窗口与策略 |

`QuotaDecision` 字段：`allowed`、`action ∈ {allow, degrade, reject}`、`reason`（超限时固定 `E_QUOTA_EXCEEDED`）、`provider`、`scope`、`units`、`used_tokens/used_requests`、`limit_tokens/limit_requests`（`None` = 不限）、`remaining_tokens/remaining_requests`、`day`。`to_dict()` 供日志与错误 `details` 复用。

契约约定：

1. 上限 `0` 表示不限；`simple` 在不限时仍计数，`status` 里 `limit` 与 `remaining` 为 `null`。
2. `check` 不写库，`record` 是唯一写入点；**调用方必须"先 check、成功后 record"**。
3. `simple` 的 `check`-then-`record` 不是预留（reservation）：并发极值下可能多放行一次。计数器本身是原子 upsert，不会丢增量；该限制写在 §10，不隐藏。
4. `scope` 非空字符串；`simple` 以 `(UTC 日, scope)` 为键。C2-1 生产消费方用 `quota.default_scope`（默认 `global`），测试与未来 full 可用 `user:*` / `tenant:*`。
5. `cost` 在 C2-1 仅原样落库（`cost_units`），不参与判定；C2-2 才按单价折算成钱。

## 4 三个实现

### 4.1 `quota_off.py`（默认值）

- `check` 恒放行（`action=allow`，`reason=null`），`record` 空操作，`status` 返回 `provider=off`、`counted=false`、用量 0、上限 `null`。
- **不持有 metadata 依赖**：off 在结构上无法读写数据库，不改变任何既有端点行为。
- `manifest.capabilities=[]`，`notes` 明确 `quota.provider=off`。

### 4.2 `quota_simple.py`（C2-1，本次完整实现）

| 能力 | 实现 |
| --- | --- |
| 每日 token 计数 | `platform.quota_usage.tokens`，按 `(quota_day, scope)` 唯一 |
| 每日请求计数 | 同表 `requests`，每次 `record` +1 |
| 上限可配 | `quota.daily_token_limit` / `quota.daily_request_limit`，`0`=不限 |
| 超限行为 | `check` 返回 `E_QUOTA_EXCEEDED` + `action` 取 `quota.on_exceed`（默认 `degrade`，可选 `reject`） |
| 跨重启不丢 | 计数在 PostgreSQL（迁移 V50），不依赖进程内存；单测用"同一存储 + 新建实例"模拟重启验证 |
| 状态查询 | `status()` 输出当日用量/上限/剩余/触顶；`GET /quota/status` 暴露 |
| 记账原子性 | 单条 `INSERT ... ON CONFLICT DO UPDATE` 累加，避免读改写竞态 |
| 失败姿态 | `record` 写库失败直接抛 `PortError`（守卫不能悄悄丢账），由 API 统一映射为 503 |

`status` 响应形状（`GET /quota/status` 原样返回）：

```json
{
  "provider": "simple",
  "scope": "global",
  "counted": true,
  "day": "2026-11-06",
  "window": "UTC day",
  "tokens":   {"used": 20, "limit": 100, "remaining": 80, "exceeded": false},
  "requests": {"used": 1,  "limit": 5,   "remaining": 4,  "exceeded": false},
  "cost":     {"used": 0.0, "unit": "provider_units"},
  "onExceed": "degrade"
}
```

### 4.3 `quota_full.py`（C2-2，本次只建骨架）

- `check` / `record` / `status` **方法体显式抛** `PortError(code=Unsupported, providerCode=E_PROVIDER_NOT_IMPLEMENTED)`，不返回任何计数、价格或占位数据。
- `manifest.notes.pending` 列出待做项；类文档逐条列清将来职责：

| C2-2 待做 | 说明 |
| --- | --- |
| 按用户/租户配额 | `scope` 升级为 `user:<id>` / `tenant:<id>`，并做层级汇总 |
| 单价折算 | `quota.unit_price_per_1k_tokens`（元/千 token），按模型分别计价 |
| 告警 | `quota.alert_threshold_pct` 阈值事件，在硬限前推送 |
| 看板 | 按 scope/日/模型的用量、剩余预算聚合 |
| CSV 导出 | 与看板同一聚合口径的可下载报表 |
| 分端点限流 | `/answer`、`/documents/*/extract` 分开桶；账本需增加"请求类别"维度 |

**与 simple 的方法面差异**：端口面 `check/record/status` 保持一致，不新增方法；差异只在 `status` 的附加字段（价格、告警状态、分端点明细）与 `cost` 的语义（从"原样落库"变为"计价输入"）。任何新增端口方法都必须同时更新 87 与两个实现。

## 5 配置项（`config.py` 的 `# --- G7 quota config ---` 区块）

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `quota.provider` | `off` | `off` / `simple` / `full`；三档同端口 |
| `quota.daily_token_limit` | `0` | 每日 token 上限，`0`=不限（仍计数） |
| `quota.daily_request_limit` | `0` | 每日请求上限（按 LLM 调用计），`0`=不限 |
| `quota.on_exceed` | `degrade` | 超限动作：`degrade` 跳过 LLM 保留检索/规则结果；`reject` 请求失败 |
| `quota.default_scope` | `global` | 记账维度；full 才扩展为用户/租户 |
| `quota.chars_per_token` | `4` | 调用前 token 预估；记账优先用 provider 回报的 `usage` |

分码（沿用 Q8）：

| 输入 | 码 | 字段 | 实测文案（节选） |
| --- | --- | --- | --- |
| `provider: nope` | `E_PROVIDER_INVALID` | `quota.provider` | `quota.provider='nope' is not a known provider; known values: off, simple, full` |
| `provider: full` | `E_PROVIDER_NOT_IMPLEMENTED` | `quota.provider` | `quota.provider=full is a known provider but no adapter is assembled (C2-2 full stays behind this switch)` |
| `simple` 且两条上限均为 0 | 告警（不报错） | — | `quota.provider=simple with both daily limits 0: usage is counted but nothing is enforced` |
| `provider: off` / `simple` | 加载通过 | — | 默认 `off` |

装配（`assembly.py`）：`quota = build_quota(cfg.quota, metadata)` 三分支；`provider=simple` 时用 `QuotaAwareLlm` 包装 `LlmClient`（scope/预估长度来自配置），`off` 原样返回客户端；`full` 分支保留（与 canvas 一样，配置层已用 `E_PROVIDER_NOT_IMPLEMENTED` 拦住）。

## 6 端点与集成接缝

`api.py` 末尾追加（模块级函数，集成方在 `return app` 前调用）：

| 端点 | 返回 |
| --- | --- |
| `GET /quota/status?scope=` | 上述 `status` 结构；`scope` 省略时用 `quota.default_scope` |
| 未装配的 full | 400，`error.providerCode=E_PROVIDER_NOT_IMPLEMENTED`（由既有 `PortError` 处理器映射） |

不改既有 `/answer`、`/search`、`/browse/*`、`/documents/*`；前端本次不需要展示用量，因此**不新增前端文件、不改既有 js**（状态接口已可被外部消费）。

## 7 错误码表

| 码 | 产生层 | HTTP/退出 | 触发 | 调用方动作 |
| --- | --- | --- | --- | --- |
| `E_PROVIDER_INVALID` | 配置加载 | 退出 78 | provider 不在 `off/simple/full` | 改配置 |
| `E_PROVIDER_NOT_IMPLEMENTED` | 配置加载 / full 方法 | 退出 78 / 400 | 已知但未装配（本次 `full`） | 改回 `simple` 或 `off` |
| `E_QUOTA_EXCEEDED` | `check` / LLM 闸门 | `ResourceExhausted`→413；`PolicyRejected`→422；`auto` 抽取内部降级 | 当日 token 或请求触顶 | 降级走检索/规则，或拒绝请求 |
| `E_QUOTA_SCOPE_INVALID` | `simple` 参数校验 | 400 | scope 为空 | 调用方修正 |
| `E_PROVIDER`（数据库类） | `record` 写库失败 | 503 | PostgreSQL 不可用 | 修依赖；不吞错、不伪造计数 |

## 10 已知限制与不做的事

1. `check`-then-`record` 非预留：并发下最后 1 个单位可能被两次放行；计数器不丢增量。要严格预留需在 C2-2 做 token 预扣/回冲。
2. 窗口固定 UTC 日（容器时区）；跨时区结算属于 C2-2。
3. 调用前 token 数是 `chars_per_token` 预估；记账优先用 provider 返回的 `prompt_tokens+completion_tokens`，provider 未返回时才用预估值，不伪造。默认 4 字符/token 对中文偏低估，预判可能晚拦一次；需要更保守可调小 `chars_per_token`。
4. 每次 LLM 调用计 1 次请求；`/answer`、`/search` 不计请求（它们不走 LLM，也不消耗预算）。
5. 不做前端面板（需求为"如需"）；`/quota/status` 已可被外部消费，后续加独立 js 文件即可，不改既有 js。
6. 不改 `api.py` 既有函数体；`config.py` 只加 G7 区块 + 两处单行接入（字段与语义调用）。合入后迁移链在 `coa_control_plane.platform_db.registry`（V50），`platform_core/adapters/metadata_pg.py` 保持只委托，不再持有 `SUPPORTED_SCHEMA_VERSION` 与 `MIGRATIONS` 副本。
