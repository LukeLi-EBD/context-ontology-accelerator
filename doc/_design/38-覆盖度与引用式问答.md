# 38 · 分层覆盖度校验与带证据引用的问答（可拒答）

> 参照 NVIDIA Auto Ontology 的 `check_answerable` 与 Helix Analyst，但在本平台做成**四层可解释、可拒答、可回溯到真实对象**的实现。
> 本文只描述契约与判定规则；不改 SQL、不改 `facts`/`metrics`/`rules` 实现，端点逻辑全部在 `src/platform_core/api.py` 内编排。

## 1. 目标与边界

- 输入：自然语言问题，或指标名 / 指标 ID。
- 输出必须回答四件事：**哪层命中、哪层缺失、缺什么、怎么补**。
- 数值只在“结构性可执行 + 事实层有观察值”时给出；否则给定义/公式/规则，并明确 `valueRefused=true`。
- 引用只能来自真实响应：T-Box 版本 id、术语 IRI、`metricId@definitionVersion`、事实表.字段、公式；禁止拼接不存在的版本号或字段。
- 四层资产：
  - `ontology`：T-Box 类/属性的 `rdfs:label`；
  - `terms`：SKOS `prefLabel`/`altLabel` + term 层别名；
  - `metrics`：`platform.metric_definition`；
  - `facts`：`platform.metric_observation` + `metric_field_binding` + 事实表行数 + `fact_function`。

## 2. `GET/POST /answerable` 契约

### 2.1 入参

| 字段 | 类型 | 说明 |
|---|---|---|
| `q` / `query` | string | 问题；与 `metricId` 至少给一个 |
| `metricId` | string | 指标 ID；给了就强制按指标路由 |
| `ontologyVersion` | string | 缺省用 `tbox/current` 指针 |
| `minCoverage` | 0..1 | 缺省用 `context.answerable_min_coverage` |
| `layers` | bool | 默认 `true`；`false` 只返回旧版字段 |

### 2.2 出参（兼容旧字段 + 分层字段）

```jsonc
{
  "query": "13个月继续率是多少",
  "inputType": "question",           // question | metric
  "intent": "value",                 // value | definition
  "answerable": true,                // 是否有足够“已治理”证据作答（定义型可答）
  "valueAnswerable": false,          // 数值是否可出
  "answerMode": "definition",        // value | definition | none
  "degraded": true,

  "layers": [
    {"layer":"ontology","status":"missing","coverage":0.0,"matched":[],"missing":["13个月继续率"]},
    {"layer":"terms","status":"not_applicable","coverage":0.0,"matched":[],"missing":[]},
    {"layer":"metrics","status":"covered","coverage":1.0,"matched":[{"id":"FIN-INS-021","label":"13 个月继续率（有效保单件数）"}],"missing":[]},
    {"layer":"facts","status":"degraded","coverage":0.0,"matched":[
      {"id":"FIN-INS-021@v3.0","status":"degraded","code":"E_FACTS_NO_OBSERVATION",
       "observationRows":0,"factFunction":"platform.metric_fact_fin_ins_021"}
    ],"missing":["metric_observation 无记录"]}
  ],

  "missing": [
    {"layer":"ontology","code":"E_LAYER_ONTOLOGY_GAP","text":"13个月继续率",
     "what":"T-Box 未声明该中文概念","howToFix":"补 rdfs:label 或收窄问题"},
    {"layer":"facts","code":"E_FACTS_NO_OBSERVATION","metricId":"FIN-INS-021",
     "what":"口径有、事实表无数据","howToFix":"装载事实表后运行 facts-project"}
  ],

  "candidates": [
    {"layer":"metrics","id":"FIN-INS-021","label":"13 个月继续率（有效保单件数）","reason":"name_substring","score":0.95},
    {"layer":"metrics","id":"FIN-INS-012","label":"13 个月继续率（保费口径）","reason":"fuzzy_name","score":0.72}
  ],

  // 旧版字段保持不变，调用方无需迁移
  "coverage": 0.0, "threshold": 0.5, "coverageChars": {"covered":0,"total":6},
  "ontologyVersion": "ont-3f57d8ce6636", "ontologyGraph": "urn:platform:graph:tbox:ont-3f57d8ce6636",
  "termSource": "skos+rdfs:label", "termCount": 123,
  "matchedTerms": [], "reasonCode": null, "hint": null, "reasons": []
}
```

`missing[]` 的每一项都是可执行的补救动作；`facts` 层额外区分：

- `covered`：`metric_observation` 有行；
- `degraded`：口径/绑定存在，但事实表 0 行或无观察值（**不判不可答**）；
- `missing`：连字段绑定/投影函数都没有；
- `unavailable`：读取事实层失败；
- `not_applicable`：问题没有命中指标。

### 2.3 四层判定规则

| 层 | 命中 | 缺失/降级 |
|---|---|---|
| ontology | `rdfs:label` 命中问题内容字符 | 未命中片段 → `E_LAYER_ONTOLOGY_GAP`；对已命中指标不阻断 |
| terms | SKOS 别名命中，或问题使用本体规范名 | 规范名直接命中时 `not_applicable`；否则 `E_LAYER_TERMS_GAP` |
| metrics | 指标 ID 精确 / 名称子串 / 去括号名称命中 | 数值意图无指标 → `E_LAYER_METRICS_GAP`，附最近候选 |
| facts | 观察值 > 0 且窗口足够 | 见 2.2 的五种状态；`missing` 阻断数值，`degraded` 只阻断数值 |

判定顺序：**先指标后事实**。指标已命中时，本体/术语缺口只作为“资产缺口”报告，不把问题一律判死。

## 3. `GET/POST /answer` 契约

### 3.1 入参

| 字段 | 类型 | 说明 |
|---|---|---|
| `q` / `query` | string | 必填 |
| `metricId` | string | 可选，强制指标 |
| `ontologyVersion` | string | 可选 |
| `topK` | 1..20 | 缺省 5 |
| `strategy` | `lexical`/`vector`/`hybrid` | 缺省 `lexical`（问答只做轻量检索） |

### 3.2 出参

```jsonc
{
  "query": "13个月继续率（有效保单件数）的口径是什么",
  "refused": false,
  "valueRefused": true,
  "reasonCode": "E_ANSWER_VALUE_DEGRADED",
  "answerMode": "definition",
  "answerType": "definition",        // definition | value | rule_set | ontology | none
  "answer": "「13 个月继续率（有效保单件数）」（FIN-INS-021@v3.0）口径：……；事实层 degraded，不给出数值。",

  "steps": [
    {"step":"retrieve","status":"ok","input":{"query":"...","strategy":"lexical"},
     "output":{"chunks":0,"facts":0},"durationMs":12},
    {"step":"terms","status":"ok","input":{"ontologyVersion":"ont-..."},
     "output":{"ontologyMatched":0,"termsMatched":0},"durationMs":1},
    {"step":"metric","status":"covered","input":{"query":"..."},
     "output":{"metricId":"FIN-INS-021","definitionVersion":"v3.0","outputMode":null},"durationMs":2},
    {"step":"facts","status":"degraded","input":{"metricId":"FIN-INS-021"},
     "output":{"observationRows":0,"factFunction":"platform.metric_fact_fin_ins_021"},"durationMs":3},
    {"step":"compute","status":"skipped","input":{"metricId":"FIN-INS-021"},
     "output":{"reason":"facts.degraded","value":null},"durationMs":0}
  ],

  "citations": [
    {"id":"ont-3f57d8ce6636","kind":"ontology-version","ref":"urn:platform:graph:tbox:ont-3f57d8ce6636","versionId":"ont-3f57d8ce6636"},
    {"id":"metric:FIN-INS-021@v3.0","kind":"metric-definition","ref":"FIN-INS-021@v3.0","metricId":"FIN-INS-021","definitionVersion":"v3.0","fields":{"formula":"numerator / denominator * 100"}},
    {"id":"formula:FIN-INS-021@v3.0","kind":"formula","ref":"numerator / denominator * 100"},
    {"id":"factfn:platform.metric_fact_fin_ins_021","kind":"fact-projection","ref":"platform.metric_fact_fin_ins_021","metricId":"FIN-INS-021"},
    {"id":"doc:...","kind":"chunk","ref":"...","documentId":"..."}
  ],

  "missing": [{"layer":"facts","code":"E_FACTS_NO_OBSERVATION","metricId":"FIN-INS-021",
               "what":"口径有、事实表无数据","howToFix":"装载事实表后运行 facts-project"}],
  "layers": [ ...与 /answerable 相同... ],
  "candidates": [ ... ],
  "ontologyVersion": "ont-3f57d8ce6636"

```

### 3.3 步骤语义

1. `retrieve`：优先 `runtime.context.resolve`（`strategy=lexical`），失败降级到 `search.hybrid_search`；只做检索，不产出断言。
2. `terms`：T-Box `rdfs:label` 与 SKOS 别名命中；记录两层的命中数。
3. `metric`：候选指标排序；无指标则 `missing`，不进入事实层。
4. `facts`：检查 `metric_observation`、`metric_field_binding`、事实表行数、`fact_function`、`rule_set`。
5. `compute`：
   - 结构可执行 + 观察值存在 → 调 `metrics.compute`，返回 `value` 与 `dataSource`；
   - 规则型 → 调 `rules.execute`（空事实会得到真实 `E_METRIC_NO_DATA`），**绝不返回标量**；
   - 事实缺失/降级/非标量 → `skipped`。

### 3.4 拒答条件

| 条件 | `refused` | `valueRefused` | `reasonCode` |
|---|---|---|---|
| 数值意图，无指标 | true | true | `E_ANSWER_METRIC_NOT_FOUND` |
| 数值意图，指标有但事实字段绑定缺失 | true | true | `E_ANSWER_FACTS_MISSING` |
| 数值意图，规则型指标无事实输入 | true | true | `E_ANSWER_RULE_SET_NEEDS_FACTS` |
| 数值意图，事实层 degraded | false | true | `E_ANSWER_VALUE_DEGRADED` |
| 定义意图且指标/本体可答 | false | false | `null` |
| 既无指标也无本体覆盖 | true | true | `E_ANSWER_NOT_COVERED` |

数值必须带 `dataSource`（`fixture` / `business`）；`degraded` 时 `value=null`，不写 0、不写估算。

## 4. 与 NVIDIA / Helix 的差异

| 维度 | NVIDIA Auto Ontology `check_answerable` | Helix Analyst | 本实现 |
|---|---|---|---|
| 覆盖度 | 主要看本体/术语能否覆盖问题 | 看检索与工具链证据 | 四层分离：本体/术语/口径/事实，逐层给 `status` 与补救动作 |
| 事实缺失 | 容易一刀切“不可答” | 依赖检索证据 | `degraded` 与 `missing` 分开：口径有、事实空 → 可答定义、拒答数值 |
| 引用 | 回溯到 ontology 对象 | 回溯到文档 chunk | ontology 版本 + 术语 IRI + `metricId@definitionVersion` + 事实表.字段 + 公式 + chunk，全部来自真实响应 |
| 拒答 | 二元 | 模型判断 | 二元 `refused` + `valueRefused` + `reasonCode` + 可执行 `missing[]`；定义型与数值型分级 |

### 我们更强的地方

1. **事实层降级而非一刀切**：口径卡、公式、规则集仍可答，只有数值被拒；NVIDIA 的布尔门通常会把“事实无数据”直接归为不可答。
2. **引用粒度到字段/版本**：`FIN-INS-021@v3.0`、`platform.metric_observation`、`platform.metric_fact_fin_ins_021` 都是运行时读取的真实对象，可被审计复现。
3. **可执行的缺口清单**：`missing[]` 直接写“缺哪层、缺什么、怎么补”，并且能区分“缺字段绑定”和“事实表 0 行”。

### 我们更弱的地方

1. 没有 NVIDIA 那样成熟的向量化概念匹配；当前仍以确定性子串/别名匹配为主，语义近义词覆盖有限。
2. 没有 Helix 的多轮工具编排与模型自省；`compute` 只覆盖 `ratio/duration/sum` 三类结构可执行指标，规则型仍依赖外部事实输入。
3. 事实层覆盖面受当前事实表装载进度限制；在事实表为空时，只能证明“口径可答”，不能证明“数值可答”。
