# 53 · D1 画布多跳双实现（同端口 / 两实现 / 配置切换）

> 文档编号：53 · 日期：2026-11-06 · 性质：**设计文档**（只写文档，不改代码）
> 上游：[`52-后续路线图-v1`](52-后续路线图-v1.md) §8（D1 两阶段）。
> 结论：D1 不引入两套 API。**一个 `CanvasPort` 端口，`simple`（D1-1）与 `full`（D1-2）两个实现，`canvas.provider` 配置切换，调用方与前端不改。**

---

## 1 目标与非目标

| 项 | 内容 |
| --- | --- |
| 目标 | 同一画布多跳场景，可在 `simple` / `full` / `off` 间只改配置切换；返回结构一致；切换不动调用方代码 |
| 目标 | D1-1 先交付 `simple`：受控跳数、节点/边上限、单点邻域展开、路径解释、只读 |
| 目标 | D1-2 后置交付 `full`：更广展开、增量合并、布局/视图结构；接口与 `simple` 完全一致 |
| 非目标 | 不在本批实现 `full`；不改现有 `/ui/api/neighbors` 的 1 跳行为；不引入图数据库客户端库 |
| 非目标 | 不做写操作、不做图编辑；不做跨版本历史图浏览；不做 C2 成本护栏 |

## 2 现状证据（为什么需要双实现）

| 事实 | 证据 |
| --- | --- |
| 实体页只做 1 跳，边上限 200，超出标 `truncated` | `49` §2；`api.py` `/ui/api/neighbors`、`/ui/api/entity` |
| 现有邻居查询刻意拆成两条：`VALUES ?g { ... } GRAPH ?g { <iri> ?p ?o }` 与反向查询 | `webui.py` L271–L293；注释明确"避免 `GRAPH ?g { ... UNION ... }`，Oxigraph 在该形状下 30s 超时/504" |
| 无路径/多跳端点 | `api.py` 无 `path`/`maxHops` 路由（本轮检索） |
| 原评估把"力导向画布 + 多跳"判为架构冲突 | `39` §5 HX-U1 |
| 图集合由当前 T-Box + inferred + 配置 ABox 组成 | `webui.py` `_graphs()` L39–L56 |

**设计含义**：`simple` 必须复用"两条普通查询 + 批量化"的形态，不得回到"变量图 + UNION"的挂起形状；`full` 也必须从同一查询底座扩展，避免两个实现各写一套图访问逻辑。

## 3 端口设计（`ports.py`）

在 `ports.py` 增加 `CanvasPort`，与 `GraphPort`/`ReasonerPort` 同级；只定义方法与返回契约，不放算法。

```python
class CanvasPort(Protocol):
    def manifest(self) -> Manifest: ...

    def subgraph(
        self, start: str, *,
        hops: int = 1,
        max_nodes: int = 200,
        max_edges: int = 400,
        include_types: bool = True,
        include_source: bool = True,
    ) -> dict[str, Any]: ...

    def path(
        self, source: str, target: str, *,
        max_hops: int = 3,
        max_paths: int = 20,
        max_nodes: int = 200,
        include_types: bool = True,
        include_source: bool = True,
    ) -> dict[str, Any]: ...

    def expand(
        self, node: str, *,
        hops: int = 1,
        max_nodes: int = 100,
        max_edges: int = 200,
        include_types: bool = True,
        include_source: bool = True,
    ) -> dict[str, Any]: ...
```

| 方法 | 方法面覆盖 | 说明 |
| --- | --- | --- |
| `subgraph(start, hops, max_nodes, max_edges, include_types, include_source)` | 起点节点、跳数/展开深度、节点/边上限、返回子图（含邻居） | `hops=1` 即"一跳邻居"；`hops>1` 为多跳邻域 |
| `path(source, target, max_hops, max_paths, ...)` | 两端点 + 跳数上限 + 路径数上限 | 返回 `paths[]`，用于"为什么 A 与 B 有关" |
| `expand(node, hops, ...)` | 以节点为中心的增量展开 | `simple` 等价于以该节点为起点的 `subgraph`（`merged=false`）；`full` 支持并入已有子图（`merged=true`） |
| `include_types` | 是否含类型标注 | 关闭时 `types=[]`，键仍存在 |
| `include_source` | 是否含来源标注 | 关闭时 `source` 为 `{"graph": null, "hasRef": false}`，键仍存在 |

**返回契约（两实现必须一致，值可不同）**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `provider` | `simple` / `full` | 当前实现，便于比对与排障 |
| `mode` | `subgraph` / `path` | 调用模式 |
| `start` / `target` | IRI / null | 输入回显 |
| `graphs` | list[str] | 本次允许读取的图集合 |
| `nodes[]` | `{iri, label, types, source}` | `source={graph, hasRef}` |
| `edges[]` | `{s, p, o, dir, source}` | `dir=out/in`；`source` 同上 |
| `paths[]` | `{nodes, edges, length}` | `mode=path` 时；`subgraph` 时为空数组 |
| `layout` | `{mode: none/force, nodes[], seed}` / null | `simple` 固定 `none`；`full` 返回结构提示（不返回坐标） |
| `truncated` | bool | 触达节点/边/路径上限时为 true |
| `limits` | `{hops, maxNodes, maxEdges, maxPaths}` | 本次生效上限（已按 provider 硬上限截断） |
| `stats` | `{nodes, edges, paths, elapsedMs}` | 供前端与验收 |
| `emptyReason` | str / null | 无结果时为 `E_PATH_NOT_FOUND` 等，不抛错 |
| `degraded` | bool | 预留给未来超时降级；D1-1 固定 false |

**端口错误**：参数与运行期错误统一走 `PortError`（沿用 `api.py` `PortError → HTTP` 映射），provider 配置错误走启动期分码。

## 4 两个实现

### 4.1 `simple`（D1-1，先做）

| 项 | 设计 |
| --- | --- |
| 文件 | `adapters/canvas_simple.py`，类 `SimpleCanvas` |
| 图集合 | 复用 `webui._graphs()` 语义：当前 T-Box 图 + inferred 图 + 配置 ABox；**只读当前版本** |
| 邻域展开 | 有界 BFS：第 1..hops 层，逐层按 frontier 批量查询；每批 `VALUES ?s { <iri> ... }`（≤50 个） |
| 查询形状 | **每层两次查询**：正向 `VALUES ?g/GH {points} GRAPH ?g { VALUES ?s {frontier} ?s ?p ?o }`、反向同形；**禁止 `GRAPH ?g { ... UNION ... }`**（`webui.py` L271–L274 已证明会挂起） |
| 路径 | 在 BFS 中记录前驱；`path()` 用双向 BFS（1–3 跳），返回最短路径 ≤`max_paths` 条；环用 `(s,p,o)` 去重 |
| 类型/标签 | 批量补 `?s a ?t` 与 `rdfs:label`，一次 `VALUES` 查询，避免 N+1 |
| 来源 | `source.graph` 取三元组所在图；`hasRef` 仅当实体/事实有 `source_ref` 映射（没有则 false） |
| 上限 | `hops ≤ 3`（配置可达 4，硬上限 3）；`max_nodes ≤ 200`；`max_edges ≤ 400`；`max_paths ≤ 20`；单查询 500ms |
| 布局 | `layout.mode="none"`；节点按 BFS 层排序，前端画 ≤12 节点静态 SVG |
| 工作量 | **3–5h**（含单测与空态） |

### 4.2 `full`（D1-2，后置）

| 项 | 设计 |
| --- | --- |
| 文件 | `adapters/canvas_full.py`，类 `FullCanvas`；方法签名与 `SimpleCanvas` 完全一致 |
| 图集合 | 与 `simple` 相同（当前版本 + 配置 ABox），不扩大可读范围 |
| 展开 | 支持更广跳数（`hops ≤ 4`，硬上限 6）、`max_nodes ≤ 500`（硬上限 1000）、`max_edges ≤ 1500` |
| 路径 | 双向 BFS + k-最短路径，`max_paths ≤ 50`；同长度路径按属性权重排序 |
| 增量 | `expand()` 返回 `merged=true`，携带 `addedNodes`/`addedEdges` 与已加载子图的差量 |
| 布局 | 返回 `layout={mode:"force", nodes:[{iri, degree, cluster}], seed}`；**不返回 x/y**，布局在前端执行 |
| 来源 | 在 `source.graph` 基础上，若元数据可关联则补 `source_ref` 摘要；关联不到标 `hasRef=false` |
| 前端 | ≤300 节点力导向画布、拖拽、增量展开；超出节点上限时 `truncated=true` 并提示收窄条件 |
| 工作量 | **16–24h**（含前端与性能验收） |

### 4.3 共同硬约束

1. 只读：只调用 `runtime.graph.query`，不调用 update/insert/delete；验收断言三元组计数不变。
2. 图集合：只读 `_graphs()` 返回的图；请求里带历史图/越权图一律拒绝（`E_CANVAS_GRAPH_FORBIDDEN`）。
3. 禁止形状：任何实现都不得生成 `GRAPH ?g { ... UNION ... }`；不得无界 `?s ?p ?o`；不得无界 `+`/`*` property path。
4. 上限先截断再查询：`hops`、`maxNodes`、`maxEdges` 先按 provider 硬上限截断，再拼 SQL/SPARQL，避免"先查后截"。
5. IRI 安全：复用 `_require_iri`/`_iri` 校验，拒非法 IRI；`VALUES` 只放已校验 IRI。
6. 去重：节点按 IRI、边按 `(s,p,o)` 去重；路径按节点序列去重。
7. 超时：`simple` 单请求 500ms；`full` 5s；超时返回 `E_CANVAS_TIMEOUT`（504），不返回半成品。

## 5 装配与配置

### 5.1 配置项

在 `config.py` 增加 `CanvasConfig(_Strict)`，并挂到 `PlatformConfig.canvas`：

```yaml
canvas:
  provider: simple          # off | simple | full
  simple_max_hops: 3
  full_max_hops: 4
  max_nodes: 200
  max_edges: 400
  max_paths: 20
  timeout_ms: 500
```

| 键 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- |
| `canvas.provider` | `off` | 字符串，启动期分码 | `off` 不装配；`simple` 装配；`full` 在 D1-2 前"认识但未实现" |
| `canvas.simple_max_hops` | 3 | 1–4 | simple 硬上限 3，配置超过按 3 截断 |
| `canvas.full_max_hops` | 4 | 1–6 | full 硬上限 6 |
| `canvas.max_nodes` / `max_edges` | 200 / 400 | 1–1000 / 1–2000 | 请求可下调，不可超过 provider 硬上限 |
| `canvas.max_paths` | 20 | 1–50 | `simple` 硬上限 20 |
| `canvas.timeout_ms` | 500 | 100–5000 | `full` 可配到 5000 |

### 5.2 provider 分码（沿用 Q8 规则）

| 输入 | 结果 | 时机 | 码 |
| --- | --- | --- | --- |
| `off` | 不装配 `CanvasPort`，`runtime.canvas=UnsupportedCanvas` | 启动 | 无错误；端点返回 `E_CANVAS_DISABLED`（503） |
| `simple` | 装配 `SimpleCanvas` | 启动 | 无 |
| `full`（D1-2 前） | 启动失败 | `_apply_semantics` | `E_PROVIDER_NOT_IMPLEMENTED`（exit 78） |
| 未知值（如 `canvas2`） | 启动失败 | `_apply_semantics` | `E_PROVIDER_INVALID`（exit 78） |

实现方式与 `GraphConfig.provider` 一致：`CanvasConfig.provider` 用 `str` 接收全部已知值，`_apply_semantics` 用 `canvas_known = {"off","simple","full"}` 与 `canvas_implemented = {"off","simple"}` 判定；分码逻辑集中在配置层，`assembly.py` 只做分支装配。

### 5.3 装配分支

```python
if cfg.canvas.provider == "off":
    canvas = UnsupportedCanvas(port="CanvasPort", reason="canvas.provider=off",
                               code="E_CANVAS_DISABLED")
elif cfg.canvas.provider == "simple":
    canvas = SimpleCanvas(config=cfg.canvas, ontology=runtime.ontology,
                          reasoning=runtime.reasoning, graph=runtime.graph)
elif cfg.canvas.provider == "full":   # D1-2 打开
    canvas = FullCanvas(...)
```

`Runtime` 增加 `canvas: CanvasPort`；`/browse/path` 只依赖 `runtime.canvas`，不判断 provider 名称。

## 6 切换与回退

| 场景 | 操作 | 调用方影响 | 结果 |
| --- | --- | --- | --- |
| `simple` → `full`（D1-2 后） | 改 `canvas.provider=full`，重启 | 无（同 URL、同参数、同响应键） | 返回更多节点/路径与 `layout.mode=force`；`provider` 变为 `full` |
| `full` → `simple` | 改回 `simple`，重启 | 无 | 自动按 simple 上限截断；`truncated` 可能变 true |
| 任意 → `off` | 改 `off`，重启 | 画布接口不可用（503） | `/healthz`、`/health/dashboard`、`/answer`、`/browse/triples` 均不受影响 |
| 回退 | 配置回滚 + 重启 | 无 | 无 schema/数据迁移；只读接口，无脏数据 |

**约束**：切换只改配置，不改 `api.py` 路由、不改前端请求；响应键集合固定（§3），差异只体现在值与 `layout.mode`。服务重启生效，沿用现有配置加载方式。

| 维度 | `simple`（D1-1） | `full`（D1-2） | 是否 full-only |

## 8 API 契约（两实现共用）

`GET /browse/path`

| 参数 | 必填 | 默认 | 约束 |
| --- | --- | --- | --- |
| `from` | 是 | — | 绝对 IRI |
| `to` | 否 | null | 绝对 IRI；给出时 `mode=path`，否则 `mode=subgraph` |
| `maxHops` | 否 | 3 | 1–provider 硬上限；超过即 `E_CANVAS_HOPS_EXCEEDED` |
| `maxNodes` | 否 | provider 默认 | 1–provider 硬上限 |
| `maxEdges` | 否 | provider 默认 | 1–provider 硬上限 |
| `includeTypes` | 否 | true | bool |
| `includeSource` | 否 | true | bool |

响应示例（`simple`，字段省略号表示同契约）：

```json
{
  "provider": "simple",
  "mode": "path",
  "start": "urn:platform:entity:company:1",
  "target": "urn:platform:entity:metric:ROE",
  "graphs": ["urn:platform:tbox:current", "urn:platform:inferred:...", "urn:platform:graph:abox:main"],
  "nodes": [{"iri": "...", "label": "...", "types": ["..."], "source": {"graph": "...", "hasRef": true}}],
  "edges": [{"s": "...", "p": "...", "o": "...", "dir": "out", "source": {"graph": "..."}}],
  "paths": [{"nodes": ["..."], "edges": ["..."], "length": 2}],
  "layout": {"mode": "none", "nodes": [], "seed": null},
  "truncated": false,
  "limits": {"hops": 3, "maxNodes": 200, "maxEdges": 400, "maxPaths": 20},

  "emptyReason": null,
  "degraded": false

```

**HTTP 码**：

| 情况 | HTTP | providerCode |
| --- | --- | --- |
| `off` | 503 | `E_CANVAS_DISABLED` |
| 非法/相对 IRI | 400 | `E_CANVAS_BAD_IRI` |
| `maxHops` 超硬上限 | 400 | `E_CANVAS_HOPS_EXCEEDED` |
| 请求历史/越权图 | 403 | `E_CANVAS_GRAPH_FORBIDDEN` |
| 查询超时 | 504 | `E_CANVAS_TIMEOUT` |
| 无路径 | 200 | `emptyReason=E_PATH_NOT_FOUND` |
| 触达节点/边上限 | 200 | `truncated=true` |
| 配置 provider | 启动 exit 78 | `E_PROVIDER_INVALID` / `E_PROVIDER_NOT_IMPLEMENTED` |

## 10 验收判据

| 编号 | 判据 | 方法 |
| --- | --- | --- |
| A-01 | 同一场景（`from/to/maxHops=2/maxNodes=60`）切换 `simple`→`full` 前后，响应键集合完全一致；`nodes`/`edges` 集合一致（`full` 允许附加 `layout` 与更多 `paths`） | 固定用例 + JSON schema 比对 |
| A-02 | `canvas.provider=full`（D1-2 前）启动 exit 78 且 `E_PROVIDER_NOT_IMPLEMENTED`；`canvas.provider=nope` 为 `E_PROVIDER_INVALID` | 配置负例 |
| A-03 | 切换 `simple`/`full`/`off` 只改 yaml + 重启；`curl` 与前端请求不变 | 切换脚本 + 同一 curl |
| A-04 | `off` 时画布端点 503 `E_CANVAS_DISABLED`；`/health/dashboard`、`/answer`、`/browse/triples` 仍 200 | 冒烟 |
| A-05 | `maxHops=99` 返回 400 `E_CANVAS_HOPS_EXCEEDED`；节点超限返回 200 + `truncated=true` | 边界用例 |
| A-06 | 无路径返回 200 + `emptyReason=E_PATH_NOT_FOUND`，不是 500 | 反例 |
| A-07 | 只读：调用前后图三元组计数不变 | 计数断言 |
| A-08 | `simple` 3 跳 p95 ≤300ms（合成 ABox 304,919 三元组）；`full` 300 节点 p95 ≤3s | 压测脚本 |
| A-09 | 查询形状回归：录制 SPARQL，断言不含 `UNION`、不含无界 `?s ?p ?o`、必含 `VALUES ?g` + `GRAPH ?g` | fake graph recorder 单测 |
| A-10 | 图集合只读当前 T-Box + inferred + 配置 ABox；请求历史图 403 | 权限用例 |
| A-11 | 3 组固定实体对各返回 ≥1 条路径；环不重复；`maxPaths` 生效 | 固定用例 |

## 11 风险与取舍

| 编号 | 风险 | 应对 |
| --- | --- | --- |
| C-01 | 变量图 + UNION 挂起（曾 30s 超时/504） | 强制两条普通查询 + `VALUES` 批量；A-09 回归断言 |
| C-02 | 3 跳谓词组合爆炸（304,919 三元组） | 谓词白名单、`maxHops≤3`、`max_nodes`/`max_edges` 先截断、500ms 超时 |
| C-03 | 批量 `VALUES` 过大导致查询变慢 | frontier 每批 ≤50 个 IRI；跨层分批 |
| C-04 | 标签/类型补齐 N+1 | 每层一次批量 `rdfs:label` 与 `?s a ?t` |
| C-05 | `full` 返回 500 节点导致前端卡顿 | 前端节点上限 300；超出 `truncated=true` 并提示收窄 |
