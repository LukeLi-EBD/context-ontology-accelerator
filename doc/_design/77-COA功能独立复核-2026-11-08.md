## 6. 附：#5 consistency 门禁根因

**根因：draft 版本 `ont-587cc7df09a5` 的 T-Box 声明了 `owl:imports` 指向不可解析的 IRI；ROBOT 在 `reason` 时尝试加载 import，两个 IRI 都返回 404，抛 `UnloadableImportException`，reasoner 返回 HTTP 500，平台映射为 `E_REASONER_BAD_RESPONSE`。**

证据：

1. 症状（`/governance/publish`，`dryRun=true`，version `ont-587cc7df09a5`）：
   `consistency: {"ok":false,"code":"E_REASONER_BAD_RESPONSE","message":"reasoner returned HTTP 500: {\"detail\":{\"message\":\"robot reason failed\",\"exit\":1,\"stderr\":\"...UnloadableImportException: Could not load imported ontology: <https://w3id.org/fsldm/merged>...\"}"}`
2. 该版本 Turtle 导出实际包含：
   ```
   <urn:platform:fsldm:tbox-v1-1> a owl:Ontology ;
       owl:imports <https://w3id.org/fsldm/merged>,
                   <https://w3id.org/fsldm/terms> .
   ```
3. 可达性实测：`https://w3id.org/fsldm/merged` 与 `/terms` 在宿主机和 reasoner 容器内均返回 **404**（不是 DNS/网络不可达）。
4. reasoner 服务命令：`platform/reasoner/app.py:100-120` 直接 `java -jar robot.jar reason ... --input merged.ttl`，未传 `--catalog`，也未做 import 剥离；ROBOT 只能尝试远程解析 import。
5. ROBOT 的 `reason` 只提供 `--catalog`（实测 `robot reason --help` 无 `--ignore-imports`）。
6. 本地并非没有文件：
   - `doc/_fsldm/fsldm-merged.ttl`（多 ontology 文档）存在；
   - `doc/_fsldm/fsldm-terms.ttl`、`platform/seed/shapes/fsldm/{terms,metrics}.ttl` 存在；
   - 但没有 IRI → 本地文件的 catalog 映射，且 reasoner 容器**无任何挂载**（`docker inspect` mounts 为空）。
7. 当前已发布版本 `ont-11f92ebb3326` 的 Turtle **没有 `owl:imports`**，所以历史 materialize 成功（`inferredTriples=1171, consistent=true`）。问题只出在这个 4 三元组的旧 draft 上。

**最小修复方案（先不改，按代价排序）：**

1. **数据修复（最小、推荐立刻做）**：撤回或修正 draft `ont-587cc7df09a5`。它只有 4 个三元组，dry-run 显示发布将删除 3,625 三元组、产生 520 项 breaking，本身就是不可发布状态；删除/重建该 draft 后 consistency 门禁自然恢复。无代码/镜像改动。
2. **通用离线 import 支持（中期）**：给 reasoner 增加 catalog 映射：
   - 生成 `catalog-v001.xml`，把 `https://w3id.org/fsldm/merged` → `doc/_fsldm/fsldm-merged.ttl`、`https://w3id.org/fsldm/terms` → `doc/_fsldm/fsldm-terms.ttl`；
   - `platform/reasoner/app.py` 的 robot 命令增加 `--catalog`；
   - compose 只读挂载 catalog 与两份 TTL。
   - 代价：改 reasoner 代码 + 重建 reasoner 镜像 + compose 变更，属较大改动。
3. **平台侧兜底（可选）**：在组装发往 reasoner 的 N-Triples 时识别 `owl:imports`，要么显式内联本地闭包，要么剥离并在门禁结果中返回稳定的 `E_ONTOLOGY_IMPORT_UNRESOLVED`（而不是 500 `E_REASONER_BAD_RESPONSE`）。代价：改 `reasoning.py`，会改变一致性检查语义，需单独评审。

建议顺序：先做 1；2 作为后续正式方案；3 只在需要「门禁错误可读」时做。

### 6.3 `fsldm-merged.ttl` OWL 2 DL 违规修复（2026-11-08）

结论：`party:riskGradePrecedes` **不需要** asymmetric。

- 语义上它是一条全序上的“严格先后”关系；但实际推理只依赖**传递性**（`A→B→C→D` 推出 `A→D`，A-Box 也已显式写全闭包），asymmetric 仅用于“数据成环即不一致”，而环检测在设计里本就交给尚未执行的 SHACL-SPARQL。
- OWL 2 DL 全局限制：`TransitiveProperty` 属非简单属性；非简单属性不得出现在 asymmetric / irreflexive / functional / inverseFunctional / disjoint 公理中。两者只能二选一。
- 最小改动：删除 `owl:AsymmetricProperty`，保留 `owl:TransitiveProperty`（1 个 token），并重写 `rdfs:comment` 说明该限制、给出 SHACL-SPARQL 环检测 `ASK { ?a party:riskGradePrecedes+ ?b . ?b party:riskGradePrecedes+ ?a }`（仍属“未执行”清单），同时记录“若必须 OWL 层拒环，唯一合法改法是去掉 Transitive 恢复 Asymmetric，代价是失去隐式闭包”。

实跑证据（ROBOT 1.9.6 / HermiT，临时容器，未触碰 8080）：

| --- | --- |
| 改前 `robot reason --reasoner HermiT` | exit 1：`Non-simple property '...riskGradePrecedes' ... appears in asymmetric object property axiom` |
| 改后 `robot reason --reasoner HermiT` | **exit 0**，正常输出推断图 |
| 改后 `/v1/consistency`（8099 临时容器 + catalog 挂载） | **`consistent=true`，1352ms**，`reasonedLen=205750` |
