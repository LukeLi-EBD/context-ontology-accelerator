#### 1.5.4.1 PROV-O 判定溯源落地规格（B2）

**要溯源的三类判定**

| 判定类型 | 必须回答的问题 | 埋点位置 | 37 号判定书对应 |

| 规则触发 | 命中哪条规则、阈值是多少、阈值来源（原文/行业默认/可配置） | 规则执行处（`rule_set_json` 解析与命中） | §3 11 条规则 spec L39-L64；`threshold_source` 分 `definition_text`（原文）与行业默认，`configurable=true` 可改（L57-L59） |

**图模型（RDF/OWL 命名图，独立于 T-Box 与事实图）**

| 元素 | 表达 |
|---|---|
| `prov:Activity` | 一次判定 / 一次规则执行 / 一次拒答 |
| `prov:Entity` | `metricId@definitionVersion`、规则集、T-Box 版本 |
| `prov:Agent` | 系统（platform）或 actor（触发人/服务） |
| 关系 | `prov:used`、`prov:wasGeneratedBy`、`prov:wasDerivedFrom`、`prov:wasAttributedTo` |
| 命名图 | `urn:platform:prov`，与 T-Box/事实图隔离 |
| 审计 | 纳入同一审计哈希链；只追加、不物理删 |

**依赖与顺序（写死）**

1. 值级溯源（`source_ref`）
2. **PROV-O 判定溯源**
3. 实体页 + 溯源徽标
4. 本体健康看板与 diff
5. 指标词表并入术语层
6. 数据字典接入

理由：没有稳定的 `source_ref`，PROV-O 的 `wasDerivedFrom` 会指向不稳定来源；没有 PROV-O，实体页徽标只能显示"有来源"，不能显示"哪次判定、依据哪条文本"；健康看板/diff 应复用同一批判定记录，而不是另造一套状态；术语层与数据字典是更外延的语义资产，放最后。

**验收标准**

- 口径判定可反查：谁判（`decision_owner`）、依据哪条文本（`quartet_derivation.fields[*].basis` 的"哪句话→哪个值"，37:§1-L9）、何时、改前值；
- 示例（37 号推荐默认值）：FIN-BANK-002 的 `decision_recommendation` —— 推荐 `band(dpd, 30, 6)`、理由"原文已给分段公式、只补未写的 M6 封顶"、改动点 `formula_expr` 与 `rule_set_json` R01–R06 阈值（37:§2-L19）；PROV 记录应能指回这条推荐，而不是只存一个最终值；
- 规则触发可反查：规则 ID（`id`）、阈值（`threshold`/`spec.value`）、阈值出处（`threshold_source` = `definition_text` / 行业默认，`evidence_basis`、`configurable`，37:§3-L57-L59）；
- 拒答可反查：缺哪层哪项、基于哪次检索；
- 判定记录只追加，不物理删；
- `urn:platform:prov` 与 T-Box/事实图零混写；审计 `verify` 通过。

**定位**：把 YAML 语义模型/指标定义翻译成可复用 SQL 并执行；开源可拿到的只有"定义 + 编译成 SQL"，服务层/API 是云专有（35:L27-L40）。

**优点（5 条）**

| # | 优点 | 出处 |
|---|---|---|
| 1 | 5 类对象模型（semantic model / entity / dimension / measure / metric），抽象边界清晰 | 35:L74-L88 |
| 2 | measure 支持 9 种聚合，metric 支持 5 型（simple/ratio/derived/cumulative/conversion） | 35:L83-L88 |
| 3 | join 由 entity 图推导，禁止 fan-out/chasm，多跳上限 2 跳 | 35:L97 |
| 4 | 编译链完整：query spec → dataflow plan → SQL plan → execute；支持 `--explain` 只编译不执行 | 35:L104-L106；35:L113 |
| 5 | 校验分两层：语义 manifest + 数仓（表/列/函数/join 歧义），可 `--skip-dw` | 35:L114 |

**缺点 / 边界（5 条）**

| # | 缺点 / 边界 | 出处 |
|---|---|---|
| 1 | 不做 RDF/OWL/SHACL/SPARQL、不做术语同义词、不做指标到监管条款血缘 | 35:L123 |
| 2 | 未找到指标级版本化/废弃/迁移与指标级影响面机制 | 35:L115-L116 |
| 3 | `measure` 已被官方废弃，spec 仍在演进，照抄会学到退场抽象 | 35:L86-L88 |
| 4 | 必须先有物理关系与 time spine 物理表，指标本身默认不物化 | 35:L105；35:L95 |
| 5 | 云服务层、GraphQL/JDBC API、缓存、Exports 是专有产品，开源只有引擎 | 35:L36-L38 |

**可借（4 条，已借鉴）**

| # | 我们的缺口 | 借哪一部分 | 落到哪个文件/端点 | 优先级 | 状态 |
|---|---|---|---|---|---|
| MF-1 | 只有"口径文本 + 二元算术 + 每指标一个 PL/pgSQL 函数"，无维度/实体/度量模型 | 5 类对象模型 | `sql/V23__semantic_*.sql`（`semantic_entity/dimension/measure`）+ `metric_definition` 新字段 | P0 | 设计完成/在途（35:L211-L218） |
| MF-2 | 79 条要写 79 个函数，改口径要改 SQL | 单方言编译器（measures → entity_grain → time_window → metric_algebra → group_by） | `src/platform_core/metrics.py` 编译路径 | P0 | 已落地（本轮口径；35:L211-L220 记录为设计） |
| MF-3 | 只有运行期 `compute`，口径错误只能在跑数时暴露 | `compile`/`validate` 干跑（--explain 思路） | `/metrics/{id}/compile` + CLI | P1 | 未开始（35:L220） |
| MF-4 | 只支持 ratio，无 derived/cumulative 与时间绑定 | `metric_type`/`metric_inputs`/`time_binding`；时轴用 `generate_series` | `metric_definition` + 编译器 | P1 | 未开始（35:L270-L278） |

**用不上（6 条）**

| # | 用不上项 | 为什么用不上 | 分类 |
|---|---|---|---|

## 3. 判断准则（可被反驳）

| # | 准则 | 如何反驳/如何执行 |
|---|---|---|
| 1 | **先证缺口再借**：必须能指出一个现有失败用例、缺失字段或不可用端点，才允许借；不为"看起来先进"而借 | 若一条"可借"写不出对应缺口与验收断言，直接删掉；本文件 20 条可借均带缺口列，缺列即不合格 |
| 2 | **借交互与契约，不借存储与运行时** | 任何会替换 Oxigraph/PG/文件 CAS，或引入独立服务/第二存储的借法，一律降级为"用不上"；本文件 0 个运行时替代候选即此准则的结果 |
| 3 | **引入后不得绕过 SHACL/ELK 门禁、版本治理、审计链** | 若某借法产生一条不经过 `/ontology/publish` 三道门禁的写入路径，则该借法无效，不论收益多大 |
| 4 | **单机少用户形态下，需独立服务/多套存储的方案默认不引入** | 除非能证明该服务可嵌入现进程且不新增常驻容器；否则默认拒绝，并登记复查触发条件 |

## 6. 借鉴的风险账单

| 项目 | 维护成本 | 耦合点 | 风险等级 |
|---|---|---|---|
