关键事实：单测样本只有 **0.0** 和 **1.0** 两端，0.6 落在两端之间，**任何 (0,1) 内的值都能让这 3 个单测通过**。所以 0.6 不是从数据标定出来的门限，而是一个经验魔数。同一份文档批评 NVIDIA 的 0.75 是魔数，却没有解释自己的 0.6，口径不一致。

### 1.2 判定算法（决定了"问法长短"直接影响结果）

[answerable.py L113-L129](file:///D:/agentABC/coa/platform/src/platform_core/answerable.py#L113-L129) 与 [L252-L286](file:///D:/agentABC/coa/platform/src/platform_core/answerable.py#L252-L286)：

1. 去掉空白、停用词、标点，得到"内容字符"并作分母；
2. 用 T-Box 的 `skos:prefLabel` / `skos:altLabel` / `rdfs:label` **整条标签**在问句里做最长子串匹配；
3. `coverage = 被标签覆盖的内容字符 / 内容字符总数`；
4. `answerable = coverage >= threshold and bool(matched)`。

这不是"关键概念是否齐全"的判定，而是"问句里有多少字能被术语标签原样盖住"的判定。**问句越长、越口语化，分母越大，越难通过；标签越短、越通用，越容易通过。** G06 恰好是最不利的形状：长口语句 + 通用施动者/动作词。

### 3.4 业务自然词为什么覆盖不到

1. **匹配要求整条标签出现在问句里**，不是"问句里的词被标签包含"。所以"押品""重估""处置流程""银行处理"即使作为业务词存在，只要不是完整标签原文，就不会命中；反过来，标签"残值处置"也不会因为问句里有"处置"两字而命中。
2. **业务自然词与 T-Box 现有标签不在同一词面**：业务会说"押品价值下跌怎么处置"，T-Box 只有"抵押物项""资产估值""残值处置"，没有"押品""重估""处置流程"。
3. **问句里的通用字天然不可覆盖**："银行""处理""时"不是本体概念，却占 5/16；除非往术语里塞"银行处理"这种伪概念，否则它们永远拉低覆盖率。
4. **长问句稀释**：同样命中"抵押物项"4 个字，短问"抵押物项如何重估和处置"是 0.5，长问 G06 是 0.0 或 0.1875；问法越长越吃亏。
5. **补知识不等于补词面**：Q-15～Q-22 是"流程/阈值/岗位/时限"知识，落成正常业务标签后，G06 问句仍然不会原样包含它们；上表"可信制度标签集"只有 0.3125。

### 4.2 方案 B：改门限

- 8082 现状 `matched = []`。判定式是 `answerable = coverage >= threshold and bool(matched)`（[answerable.py L129](file:///D:/agentABC/coa/platform/src/platform_core/answerable.py#L129)）。**只要 matched 为空，阈值取 0.0 也不会 answerable**，所以改门限对 8082 的 G06 **完全无效**。

- 这正是任务明令禁止的"把门限调到刚好过线"。

因此 B 不成立。
