## 2 决策 D1：单一一套权威栈怎么定义

### 2.1 唯一性与角色

1. **同一时间只有一台栈有权产生对外数字与验收结论**：`AS-8080`（`agent-platform`）。
2. **8082 只作回归栈**：数据自持（39 文档 / 8,540 三元组 / `abox:main` 单图），可用于 R02/回归，**不得对外引用任何数量级结论**。
3. **qa-fill、8087（`platform-reload`）、`abox-probe` 为死栈**：其容器或数据面不可再跑；文档中引用过它们的数字（322,021、74/62/12 等）只能当历史快照，必须标注“不可复算”。

### 2.2 权威栈身份：五元组（缺一项即视为不可复现）

| 维度 | 必须登记 | 现状 |
| --- | --- | --- |
| 代码 | commit SHA | `fd8c5ef` ✅ |
| 镜像 | image id（不是 tag） | `7cee41c43cd9` ✅ |
| 库结构 | `MAX(schema_version)` | `42` ✅ |
| 数据 | 数据快照 id + 六项计数（docs/chunks/obs/facts/triples/A-Box） | ❌ 只有卷，无快照 id |
| 配置 | 生效 `platform.yaml` 的 sha256 + 脱敏副本 | ❌ 文件在仓库外 |

补充：**容器 id 与启动时间**是第五元组的部署锚点，换栈票必须记录（本轮 R3 已因缺此项留下审计缺口）。

### 2.3 可复现的五个层次（当前只到第 2 层）

| 层次 | 含义 | 现状 |
| --- | --- | --- |
| L1 代码可复现 | 从 commit 可检出 | ✅ |
| L2 镜像可复现 | 从 Dockerfile 干净构建，tag→commit→id 可追 | ✅（73 台账） |
| L3 配置可复现 | 生效配置在仓库内（脱敏） | ❌（`D:/agentABC/data/platform.yaml`） |
| L4 数据可复现 | 数据快照可导出/导入并校验计数 | ❌（只有 Docker 卷） |
| L5 运行态可复现 | 换机换人用一条命令达到同状态 | ❌ |

### 2.4 非权威栈的引用规则

- 对外/验收文档中的数字只能来自 `AS-8080` 的当次只读快照；引用其他栈必须同时写“仅交叉校验、不可复算”。
- 任何“新鲜度 100%”必须同时披露 raw 61.19% 与 144 条已标记失效（见 R4）。

## 6 决策 D5：剩余优先级（按“最痛缺口”排序）

1. **权威栈可校验（P0-A）**：配置脱敏入仓 + V43 + 五元组台账 + 换栈票 + `stack verify`。
   - 为什么第一：本日所有数字都建立在 8080 运行态上，而该运行态无法由仓库重建；换机即失去证据。它也是成本最低、能立刻止住“多套栈”扩散的一步。
2. **B 线闭环（P0-B）**：AS-8080 跑一次 A-Box 离线全量；溯源从档 1 推到档 2/3（路径归因 + L2 展开 + 读标记）。
   - 为什么第二：值级溯源是 76 矩阵里唯一“领先项”，但 28.5% 路径格 / 61.19% raw 新鲜度不足以支撑“领先”话术。
3. **知识供给（P1-A）**：33 题 7 confirmed / 21 assumed / 5 undecidable；术语别名 0/18；业务数据 0 条。
   - 为什么第三：这是产品“可出数”的真实瓶颈，但需要业务方决策，不是工程单方面能补。
4. **门禁可信度（P1-B）**：G06 重设计、R02 复跑；否则“通过率”不可信。
5. **文档残留与栈收缩（P2）**：45:460 的 82/5、52:263 的 schema 34、45 模块表；root README；清理死栈。

**结论**：下一步先做 1，不是因为它最“显眼”，而是因为不做它，2–5 的结论都无法被别人复算。2 可与 1 并行；3 需另起业务窗口。
