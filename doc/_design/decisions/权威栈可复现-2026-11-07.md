## 2 R1：仓库默认值与 8080 实际值不一致

### 2.1 处置选择：**保留代码默认，文档写死“默认值仅用于开发”**

**没有**把 `CanvasConfig.provider` 默认改成 `full`，也没有把默认 `abox_graphs` 加上 `synthetic`。
理由：

1. 用户本轮硬约束“**不改运行时行为**”。改默认值会让所有按仓库默认启动的栈（含单测、qa-fill、验收栈）
   从“关闭画布 / 单 A-Box”变成“开启全画布 / 双 A-Box”，属于行为变更。
2. `off` 在代码里是**真实禁用开关**（`DisabledCanvas` 返回 503 `E_CANVAS_DISABLED`），
   不是“未完成占位”。把它改掉等于删除一个受支持的部署形态。
3. 权威栈的可复现不应依赖“代码碰巧默认正确”，而应依赖**显式基线配置 + 校验**。
   本轮的 `platform/config/authoritative-8080.yaml` + `stack verify` 就是这条路径。
4. 若未来仍要改默认，需走单独决策并跑全量回归；不在“可校验性”这一单里夹带。

**规则（写死）**：

- 仓库内 `platform.example.yaml`、`config.py` 的默认值**仅用于开发/单测/最小栈**。
- `AS-8080` 权威栈**必须**加载 `platform/config/authoritative-8080.yaml`（或内容等价的脱敏副本）；
  不得只跑 `stack.ps1 up` 用 example 默认值起栈后对外出数。
- 任何对外证据必须附 `stack verify` 的 PASS 输出；不 PASS 的数字不得引用。

### 2.2 不加载基线的具体症状（换栈后会出现）

| 缺失键 | 换栈后的症状 |
| --- | --- |
| `canvas.provider=off`（仓库默认） | `/browse/canvas/manifest` 返回 `provider=absent`；`/browse/path`、`/browse/canvas/full` 返回 **503 `E_CANVAS_DISABLED`**；B04 画布类验收归零；758 行的 4 跳路径证据无法复现 |
| `abox_graphs` 只有 `abox:main` | `abox:synthetic` 图被排除；依赖合成 A-Box 的实体/路径查不到，B04 与 synthetic 相关计数归零；`/reasoning/status` 的 `aboxGraphs` 只剩一张图 |
| `datagen.allow_official_schema=false`（默认） | 合成数据写入 `platform` 事实表被拒；无法复现 37,477 行观测，`metric_observation` 会显著低于权威栈 |
| `materialize_online` 若被改成 `true` | 治理发布/回滚会触发全量 A-Box 物化，发布窗口不可控；8080 的“离线物化”SOP 失效 |
| `max_source_bytes` / `max_assembly_bytes` 若小于 50MiB | 大 T-Box/A-Box 组装直接报超限，推理任务失败 |
| `terms.smoke_token_env` 改名 | `purpose=smoke` 拿不到 token，术语门禁 fail-closed，验收表现为 `409 E_TERM_GATE_BLOCKED` |
| `entity_view.ignore_types` 缺失 | 实体详情把 `owl:Thing` / `owl:NamedIndividual` 当邻居/类显示，前端计数与验收数字漂移 |

一句话：**换台机器按仓库默认起栈，得到的是“无画布、无 synthetic、无 37,477 行”的另一个系统**，
`stack verify` 会以非零退出直接暴露这一点。

## 3 V43 迁移登记

### 3.1 新增文件

`platform/src/platform_core/sql/V43__source_ref_stale_mark.sql`

- 表结构与[值级溯源档1 附录 A](file:///D:/agentABC/coa/doc/_design/decisions/值级溯源档1-2026-11-07.md)逐字段一致：
  `mark_id bigserial PK`、`source_ref text NOT NULL`、`ref_kind text NOT NULL`、`metric_id text`、
  `cause text NOT NULL CHECK (4 值)`、`detected_by text NOT NULL`、`marked_at timestamptz NOT NULL DEFAULT now()`、
  `note text`、`payload jsonb NOT NULL DEFAULT '{}'`、`active boolean NOT NULL DEFAULT false`、
  `UNIQUE(source_ref)`。
- 两个索引同名同列：`source_ref_stale_mark_metric_idx(metric_id)`、
  `source_ref_stale_mark_cause_idx(cause, marked_at DESC)`。
- 全部使用 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`，对已有 8080 幂等。
- **append-only / `active` 语义不变**：只插入不删除；`active=false` 表示“仍视为已失效”，
  撤销标记用 `UPDATE ... SET active=true`，不改表结构、不改读侧语义。

### 3.2 登记同步

| 位置 | 变更 |
| --- | --- |
| `platform/src/platform_core/adapters/metadata_pg.py` | `SUPPORTED_SCHEMA_VERSION = 42` → `43`；`MIGRATIONS` 追加 `(43, "V43__source_ref_stale_mark.sql", ...)` |
| `platform/tests/test_migration_gap.py` | 升序期望追加 `"V43"`；新增 `test_registered_migration_files_exist` 防止登记了文件却漏文件 |
| V35/V36 退休逻辑 | **未动**：`RETIRED_MIGRATION_VERSIONS=(35,36)`、缺口判定、`migration_gap_versions` 全部保持原样 |
| 迁移登记表 | 由 `metadata.migrate()` 在应用 V43 时写入 `platform.schema_version(43, ...)`；`ON CONFLICT DO NOTHING` |

### 3.3 8080 幂等验证（已实跑）

Docker 在 15:40 左右恢复。为避免把 `schema_version` 写成 43 后让仍在运行的 42 镜像报
`E_DB_MIGRATION_MISMATCH`，本轮**只把 V43 SQL 放进事务里执行并 ROLLBACK**，不写迁移登记行：

```powershell
$sql | docker exec -i agent-platform-postgres psql -U platform -d platform -v ON_ERROR_STOP=1 -tA
# BEGIN; <V43 SQL>; SELECT count(*) ...; ROLLBACK;
```

实跑结果（2026-11-07 15:43 CST）：

| 检查 | 结果 |
| --- | --- |
| `CREATE TABLE IF NOT EXISTS` | `NOTICE: relation "source_ref_stale_mark" already exists, skipping` → 未重建 |
| `CREATE INDEX IF NOT EXISTS` ×2 | 均 `already exists, skipping` → 未重建 |
| DDL 后行数（事务内） | `144`，与 DDL 前一致 |
| 事务提交 | **ROLLBACK**，8080 数据与 `schema_version` 均未改变（仍为 42） |
| 字段逐字段比对 | `mark_id bigint NOT NULL default nextval(...)`、`source_ref text NOT NULL`、`ref_kind text NOT NULL`、`metric_id text`、`cause text NOT NULL`、`detected_by text NOT NULL`、`marked_at timestamptz NOT NULL default now()`、`note text`、`payload jsonb NOT NULL default '{}'`、`active boolean NOT NULL default false` —— 与 V43 SQL 完全一致 |
| 约束比对 | `source_ref_stale_mark_ref_uniq UNIQUE(source_ref)`、`source_ref_stale_mark_pkey PRIMARY KEY(mark_id)`、`cause_check` 4 值 —— 完全一致 |
| 索引比对 | `source_ref_stale_mark_metric_idx(metric_id)`、`source_ref_stale_mark_cause_idx(cause, marked_at DESC)`、pkey、ref_uniq —— 完全一致 |

**重要**：8080 当前运行的镜像 `canvas-full-48c4840` 不含 V43 代码，所以没有把 43 写入
`schema_version`。真正“跑一次迁移”必须等换到含 V43 的新镜像；换栈票须写明 `applied=["V43"]`，
换后校验 144 行不变、`schema_version=43`、业务计数不变。若先写 43，旧镜像会报版本不匹配。

Docker 恢复后的正式迁移验证命令（换新镜像后执行）：

```powershell

docker exec agent-platform-postgres psql -U platform -d platform -tAc "SELECT count(*) FROM platform.source_ref_stale_mark"
# 2) 执行迁移（由已加载 V43 的镜像启动时自动执行，或 CLI 触发）
docker exec agent-platform-api python -m platform_core.cli migrate --config /data/platform.yaml
# 3) 再查行数与 schema max
docker exec agent-platform-postgres psql -U platform -d platform -tAc "SELECT count(*) FROM platform.source_ref_stale_mark"
docker exec agent-platform-postgres psql -U platform -d platform -tAc "SELECT MAX(version) FROM platform.schema_version"
# 4) 幂等：再跑一次 migrate，应为空操作
```

> 注意：8080 当前运行的镜像 `canvas-full-48c4840` 构建于 `48c4840`，**不含本轮 V43 代码**。
> 要让 8080 真正应用 V43，必须换到含 V43 的新镜像；本轮不构建、不换镜像。
