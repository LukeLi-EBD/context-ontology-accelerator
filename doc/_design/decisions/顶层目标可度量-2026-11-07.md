## 3 为什么这些数字能当验收标准

1. **每个数字都有精确定义与代码/SQL 位置**：schema 42 来自 `SUPPORTED_SCHEMA_VERSION` 与 `schema_version.max(version)`；结构可算 74 来自 `computability_tier='structurally_computable'`；有观测 57 来自 `count(distinct metric_id)`；对外可出数 42 来自 manifest 逐条 `publishable && executable`；对外候选 35 来自 `externalEligible` 资格式。
2. **每个数字都在指定实例上现场重算过**：8080 `agent-platform:merged-42`，2026-11-07 12:27，只读 manifest + 只读 SQL，两条路径互证。不是从旧文档抄的。
3. **三层口径不混用**：74 是定义级、57 是数据级、42 是运行时判定级。分开写，才能回答"哪一条算不出来、为什么"。
4. **35 的结构可复算**：`35 = 28 compute + 7 rule_set + 0 不可计算`，28 条 `observationCount` 全部 > 0 且 `windowSufficient=true`；7 条 rule_set 有明确 ID 集合；0 条不可计算来自 manifest `meta.execution.unavailable=0`。
5. **42 的边界可审计**：全部依赖 `synthetic` 观测、0 条业务数据，避免了"有数就是业务就绪"的误读。
