> 文档编号：impl/S12 · 版本：v1.0 · 日期：2026-11-05
> 范围：只补已交付功能的完整性，不新增能力、不改 A-Box/T-Box 业务语义。
> 闭环：OQ-47（治理后门）、OQ-46（过滤导出自证）、OQ-45（清理入链与精确重放）。

## 1. 关闭治理后门（OQ-47）

### 1.1 选择

采用用户给出的方案二：**无 proposal 的 publish 在内部强制转为隐式 proposal，并跑同一套门禁**。没有删除入口，避免 S1 bootstrap 与既有 smoke 全部改写；同时保证“没有任何路径能跳过门禁”。

### 1.2 行为

`OntologyRegistry.publish(version_id, proposal_id=None, acknowledge_breaking=False, ...)`：

1. 先做图完整性检查（`_load_graph` + 三元组计数），保证坏图在任何分支前失败且不留状态。
2. 若给了 `proposal_id`，或该版本存在 `status in ('proposed','approved')` 的待审提案 → 走原有 governed 流程（含 `E_ONTOLOGY_NOT_APPROVED`）。
   - 已发布/被取代的旧提案**不再**被当作审批放行（否则就是新的后门）。
3. 否则进入隐式提案路径：
   - `published` → 幂等 no-op（内容已经过门禁，只做图完整性检查）；
   - `draft | approved | superseded` → 计算 diff、跑 SHACL 与一致性门禁；
   - `breaking=true` 且未显式 `acknowledgeBreaking=true` → `E_ONTOLOGY_BREAKING`，**此前的任何写入都未发生**，`ontology_version` 与指针零变化；
   - 全部门禁通过后，才在同一个 PG 事务里：创建 `ontology_proposal(status='approved', implicit 事件 payload=true)` → 追加 `proposed`/`approved` 事件 → 版本转 `published` → 旧版本 `superseded` → 指针切换 → 追加 `published`（`mode=implicit_governed`）。
4. 物化失败仍走 `_restore_after_failed_publish`：版本回到 `approved`、指针回旧版本、提案回 `approved`。

`acknowledgeBreaking` 在 API/CLI 的默认值保持 `false`，只能由调用方显式传入。

### 1.3 验收

`smoke-s12`：

- `legacy.breaking_rejected`：直接发布 breaking 变更 → `E_ONTOLOGY_BREAKING`；版本仍 `draft`；指针不变。
- `legacy.implicit_gated_publish` / `legacy.breaking_acknowledged`：隐式提案成功，审计含 `proposed/approved/published`，确认 breaking 时含 `breaking_acknowledged`。

## 2. 过滤导出必须可自证（OQ-46）

### 2.1 语义

- `events.ndjson` **永远是到截止事件 `cutoff_seq` 的完整前缀链**（从 event 1 开始，不裁剪）。
- `--from/--to/--source` 只作用于视图：
  - `assertions.ndjson`（仅窗口内断言）；
  - `summary.md`（窗口事件统计）；
  - `export.json` 的窗口统计。
- `export.json` 固定写入：`cutoff_seq`、`cutoff_hash`、`cutoff_at`、`verified_prefix`、`events_total`、`events_window`、`assertions_count`、`excluded_count`、`filter`。
  - `excluded_count = fact_assertion 总数 - 窗口断言数`，与“全部减窗口”的差额逐数一致。
- `facts-verify` 校验完整前缀链：首事件 `prevEvent` 必须为空；链碎片（中途起头）即使哈希自洽也判失败，并明确输出 `verified_prefix=false`。

### 2.2 验收

`smoke-s12`：

- `export.prefix_verified`：`--from` 导出 verify 通过且 `verified_prefix=true`，`cutoff_seq/cutoff_hash` 与文件末事件一致，且 `events_total > events_window`。
- `export.assertions_window_only`：`assertions.ndjson` 只含窗口断言；`excluded_count == assertion_count - 窗口断言数`。
- `export.tamper_fails`：删掉前缀链中间任意一条 → `ok=false`。
- `export.truncated_fails`：删掉最后一条（截断）→ 通过同目录 `export.json` 的 `cutoff_seq` 比对判失败。

CLI 实测（2026-11-05）：`facts-export --from <latest>` → `facts-verify` 返回 `ok=true, verified_prefix=true, checked=1131, cutoff_seq=1132`（event_id 有 1 个历史空洞，属正常序列跳号）。

## 3. 重放要能复现 purge（OQ-45）

### 3.1 事件

- V11 迁移把 `fact_event.action` 白名单扩展到 `purged_test_graph`。
- `purge_test(graph)` 在同一事务内：先删 `fact_assertion`，再为**每条被删断言**追加 `purged_test_graph` 事件（payload `{graph, reconciled:false}`），哈希链照常延伸。
- `reconstruct()` 遇 `purged_test_graph` 直接 `pop` 该事实；`compare.ok` 现在要求 `mismatched=[]` **且** `extra=[]`。

### 3.2 历史数据修复

S12 之前的 purge 只有删除、没有事件。这类“孤儿事实”会让全量重放多出 `extra`。导出前执行 `reconcile_purges()`：

- 只处理“有 asserted/merged 事件、无断言行、无 purge 事件”的事实；
- 只对 `urn:platform:test:` 图补写（`purge_test` 是唯一删除断言的路径且只接受 test 图）；
- 补写事件 payload `reconciled=true`，时间戳为补写时刻，如实暴露这是回填而非原始记录；
- 非 test 图的孤儿不补写，仍以 `extra` 暴露。

### 3.3 验收

`smoke-s12`：

- `purge.audited`：`purge_test` 返回删除数，事实的 `events()` 可见 `purged_test_graph`。
- `replay.purge_exact`：含 purge 的库全量导出 → 空库 `dry-run` 与真实重放均 `mismatched=[]`、`extra=[]`。

## 4. 错误码与状态

| 场景 | 码 |
|---|---|
| 隐式发布 breaking 未确认 | `E_ONTOLOGY_BREAKING`（`details.breakingItems`、`mode=implicit`） |
| 不可发布状态（如 `published` 以外的非法流转） | `E_ONTOLOGY_STATUS` |
| SHACL / 一致性门禁失败 | `E_ONTOLOGY_SHACL_FAILED` / `E_ONTOLOGY_INCONSISTENT` |
| ROBOT 因不可满足类返回 500 | 映射为 `E_ONTOLOGY_INCONSISTENT`（`reason=unsatisfiable`，见 OQ-52） |
| 链碎片 / 篡改 | `facts-verify` 退出 1，`verified_prefix=false` 或 hash/prev 错误 |

`/status` `slice=S12`，`schema_version=11`。

## 5. 已知边界

- **OQ-53**：窗口导出只承诺“完整前缀可 verify + 窗口视图”；把它重放到空库会相对窗口快照报窗口外前缀事实的 `extra`。只有全量导出承诺精确重放。
- **OQ-54**：历史 purge 的补写事件时间不是真实清理时间，仅以 `reconciled=true` 标注。
- **OQ-52**：一致性门禁依赖 ROBOT 的文本输出把“不可满足类”映射为不一致；reasoner 若改为结构化字段，应删除文本匹配。
