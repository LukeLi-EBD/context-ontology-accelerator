# S4 抽取到实例 · 设计

> 切片：S4 · 版本：v0.1 · 日期：2026-11-04
> 上游：03 §3.4/§4（抽取与治理）、04 §4.5/§4.6（`ExtractionPipeline`/`LLMClient`）、04 §5.9（候选审批）、10 §3（S4）
> 原则：D18 只写胶水与 Web 层；规则用配置化正则（`re` 是标准库），LLM 用 OpenAI 兼容 HTTP；不自研实体消解/概率模型（D21 未触发）；审批前不写图。

---

## 1. 目标与范围

### 1.1 目标

从已入库的 chunk 产出**候选三元组**，人工审批后写入 A-Box 命名图：

1. 规则抽取：按配置的正则规则从 chunk 文本抽主语/宾语，套模板生成三元组；
2. LLM 辅助：外部 OpenAI 兼容 `/chat/completions` 返回 JSON 三元组；不可用时不阻塞，退规则并标 `degraded`；
3. 候选落 PG（`platform.extraction_candidate`），状态 `pending|approved|rejected`；
4. 审批通过 → `INSERT DATA` 写入 `urn:platform:graph:abox:main`；拒绝 → 图不变；
5. 幂等键保证同一 chunk 重复抽取不产生重复候选。

### 1.2 做什么

| # | 内容 |
|---|---|
| 1 | `LlmConfig`（provider/base_url/model/api_key_env/timeout/retries/temperature） |
| 2 | `ExtractionConfig`（规则列表、每 chunk 上限、LLM 最多处理的 chunk 数） |
| 3 | `LlmClient`（OpenAI 兼容，JSON 输出，错误映射） |
| 4 | `ExtractionService`：`extract_document` / `list_candidates` / `approve` / `reject` / `counts` |
| 5 | V5 迁移：`platform.extraction_candidate` |
| 6 | API：`POST /documents/{id}/extract`、`GET /candidates`、`POST /candidates/{id}/approve|reject` |
| 7 | `platform smoke-s4` 验收 |

### 1.3 明确不做

- 概率实体消解 / Splink（D21 未触发）、自动发布、跨文档推理；
- 规则 DSL / 自研抽取算法；规则只是配置化正则；
- 候选编辑 UI（S7 前不做）；批量审批的复杂事务（逐条处理，失败即停并返回错误）；
- SHACL 校验、推理（S5）；文档重解析（S2）。

## 2. 接口与数据模型

### 2.1 `LlmClient` v1

```text
complete_json(system: string, user: string) -> object      # chat/completions + response_format=json_object
configured() -> bool                                      # base_url 与 model 都非空
manifest() -> Manifest
```

- `POST {base_url}/chat/completions`，body：`{model, messages:[{role:system},{role:user}], temperature, response_format:{type:"json_object"}}`。
- `Authorization: Bearer <api_key_env>`（env 缺失 → 不发送该头；不阻塞，交给服务端 401）。
- 错误映射：连不上 `Unavailable/E_LLM_UNAVAILABLE`、超时 `DeadlineExceeded/E_LLM_TIMEOUT`、401/403 `PermissionDenied/E_LLM_AUTH`、429 `ResourceExhausted/E_LLM_RATE`、非 JSON/结构不符 `DataLoss/E_LLM_BAD_RESPONSE`。
- 畸形 JSON 重试 1 次（`llm.max_retries`），仍失败为 `DataLoss`。
- `provider=disabled` 或 `configured()=false` → `Unsupported/E_LLM_NOT_CONFIGURED`（不伪装成功）。

### 2.2 `ExtractionService`

```text
extract_document(documentId, mode="auto"|"rules"|"llm") -> {
  documentId, mode, chunks, rulesMatched, inserted, skipped, degraded, reasons[]
}
list_candidates(state?, documentId?, limit=100) -> [{candidateId, ...}]
approve(candidateId) -> {candidateId, state, graph, triples}
reject(candidateId, reason?) -> {candidateId, state}
counts() -> {pending, approved, rejected, total}
```

`mode` 语义：

| mode | 行为 |
|---|---|
| `rules` | 只跑规则；永远不调用 LLM |
| `llm` | 只跑 LLM；未配置/不可达 → 直接失败 |
| `auto` | 先规则；LLM 已配置则再跑 LLM，不可用则**只降级不失败**（`degraded=true` + `reasons`） |

### 2.3 规则格式（配置）

```yaml
extraction:
  rules:
    - name: located_in
      pattern: "(?P<subject>[\\u4e00-\\u9fa5A-Za-z0-9]{2,20})位于(?P<object>[\\u4e00-\\u9fa5A-Za-z0-9]{2,20})"
      predicate: "urn:platform:rel:locatedIn"
      subject: "urn:platform:entity:{subject}"
      object: "urn:platform:entity:{object}"
```

- 必须包含命名组 `subject` 与 `object`；缺失 → 启动 `E_CONFIG_EXTRACTION_RULE`（78）。
- 正则无法编译 → 同上。
- 生成的三元组必须通过 IRI 校验（与 `GraphStore` 同一正则）；不合法的匹配跳过并计入 `skipped`。
- 每 chunk 每规则最多 `max_candidates_per_chunk` 条。

### 2.4 PG 表（V5）

```sql
CREATE TABLE platform.extraction_candidate (
  candidate_id      text PRIMARY KEY,
  document_id       text NOT NULL REFERENCES platform.document(document_id) ON DELETE CASCADE,
  chunk_id          text NOT NULL REFERENCES platform.document_chunk(chunk_id) ON DELETE CASCADE,
  extractor         text NOT NULL CHECK (extractor IN ('rules','llm')),
  extractor_version text NOT NULL,
  subject_iri       text NOT NULL,
  predicate_iri     text NOT NULL,
  object_kind       text NOT NULL CHECK (object_kind IN ('iri','literal')),
  object_value      text NOT NULL,
  confidence        real NOT NULL CHECK (confidence >= 0 AND confidence <= 1),
  state             text NOT NULL CHECK (state IN ('pending','approved','rejected')),
  dedupe_key        char(64) NOT NULL UNIQUE,
  evidence          jsonb NOT NULL DEFAULT '{}'::jsonb,
  graph_iri         text,
  created_at        timestamptz NOT NULL DEFAULT now(),
  decided_at        timestamptz,
  reject_reason     text
);
CREATE INDEX extraction_candidate_state_idx ON platform.extraction_candidate (state, created_at);
CREATE INDEX extraction_candidate_document_idx ON platform.extraction_candidate (document_id);
```

`dedupe_key = sha256(document_id|chunk_id|extractor_version|subject|predicate|object_kind|object_value)`。
`extractor_version`：规则 `s4-rules.1`；LLM `s4-llm.1`。

### 2.5 审批与图写入

- A-Box 命名图固定 `urn:platform:graph:abox:main`（单机单租户；A-Box 不做版本化，provenance 保留在候选行）。
- 审批顺序：**先写图，再更新候选状态**。图失败 → 候选保持 `pending`，可重试。
- 写图 SPARQL：`INSERT DATA { GRAPH <urn:platform:graph:abox:main> { <s> <p> <o> . } }`；literal 用 `rdflib.Literal(...).n3()` 转义。
- 幂等：同一候选重复 approve 因状态已非 `pending` → `Conflict/E_CANDIDATE_NOT_PENDING`。
- 已批准候选不因后续抽取变化而回滚（没有 update/delete 流程，S5 前的已知限制）。

## 3. 配置项与默认值

```yaml
llm:
  provider: openai-compatible       # openai-compatible | disabled
  base_url: ""                      # 空 = 未配置
  model: ""
  timeout_ms: 30000
  max_retries: 1
  temperature: 0.0
  api_key_env: LLM_API_KEY

extraction:
  enabled: true
  max_candidates_per_chunk: 10
  llm_max_chunks: 20
  rules: []                         # 见 §2.3；生产配置在 data/platform.yaml 给 2 条示例规则
```

校验：

| 键 | 规则 | 错误码 |
|---|---|---|
| 规则 `pattern` | 必须可编译且含 `subject`/`object` 命名组 | `E_CONFIG_EXTRACTION_RULE`（78） |
| `max_candidates_per_chunk` | 1..100 | Pydantic 边界 |
| `llm.temperature` | 0..2 | Pydantic 边界 |
| `extraction.enabled=false` | 允许；启动 `degraded` 标 `extraction:disabled` | warning |

`llm` 未配置**不阻塞启动**：`mode=auto` 退规则并 `degraded`，`mode=llm` 显式 `E_LLM_NOT_CONFIGURED`。

## 4. 失败语义与错误码

| 场景 | 端口码 | HTTP | 平台错误码 |
|---|---|---|---|
| 文档不存在 | `NotFound` | 404 | `E_DOC_NOT_FOUND` |
| mode 非法 | `InvalidArgument` | 400 | `E_EXTRACT_MODE` |
| LLM 未配置（mode=llm） | `Unsupported` | 503 | `E_LLM_NOT_CONFIGURED` |
| LLM 连不上 / 超时 / 鉴权 / 限流 | `Unavailable` / `DeadlineExceeded` / `PermissionDenied` / `ResourceExhausted` | 503/504/403/429 | `E_LLM_UNAVAILABLE` / `E_LLM_TIMEOUT` / `E_LLM_AUTH` / `E_LLM_RATE` |
| LLM 返回非 JSON 或结构不符 | `DataLoss` | 400 | `E_LLM_BAD_RESPONSE` |
| 候选不存在 | `NotFound` | 404 | `E_CANDIDATE_NOT_FOUND` |
| 候选已决策 | `Conflict` | 409 | `E_CANDIDATE_NOT_PENDING` |
| 非法 IRI（候选行/匹配） | `InvalidArgument` | 400 | `E_CANDIDATE_BAD_IRI` |
| 图库不可用（审批写图） | `Unavailable` | 503 | `E_GRAPH_UNAVAILABLE` |
| 图 HTML/JSON 响应异常 | `DataLoss` | 500 | `E_GRAPH_BAD_RESULT` |
| 配置规则非法 | 启动失败 | — | `E_CONFIG_EXTRACTION_RULE`（78） |

`mode=auto` 的降级不改 HTTP 状态：200 + `degraded=true` + `reasons`。

## 5. 验收用例（`platform smoke-s4`）

前置：S2/S3 数据在；`docker compose up -d` 全 Up；`/healthz` 200。

| # | 用例 | 判定 |
|---|---|---|
| 1 | 入库固定语料（含“北京位于中国”等 3 条规则命中） | `chunkCount>0` |
| 2 | `extract_document(mode=rules)` | `inserted>=2`，`state=pending` |
| 3 | 再次 `mode=rules` | `inserted==0`（幂等），候选总数不变 |
| 4 | `mode=llm` 且 `llm` 未配置 | `Unsupported / E_LLM_NOT_CONFIGURED` |
| 5 | `mode=auto` 且 LLM 指向不可达端点 | 200 语义：有规则候选 + `degraded=true` + `E_LLM_UNAVAILABLE` |
| 6 | `approve(candidate)` | 候选 `approved`；`count_graph(abox:main)` 增加 1 |
| 7 | `GET /candidates?state=pending` | 不含已批准候选；`state=approved` 含 |
| 8 | 再次 `approve` 同一候选 | `Conflict / E_CANDIDATE_NOT_PENDING` |
| 9 | `reject(another)` | `rejected`；图计数不变 |
| 10 | 直接插入非法 IRI 候选并 approve | `InvalidArgument / E_CANDIDATE_BAD_IRI`，状态仍 `pending` |
| 11 | 图端点不可达时 approve | `Unavailable / E_GRAPH_UNAVAILABLE`，候选仍 `pending` |
| 12 | 不存在的候选 approve | `NotFound / E_CANDIDATE_NOT_FOUND` |
| 13 | 不存在的文档 extract | `NotFound / E_DOC_NOT_FOUND` |
| 14 | HTTP `POST /documents/{id}/extract`、`GET /candidates`、`POST /candidates/{id}/approve` | 200 且字段完整 |
| 15 | HTTP `mode=bogus` | 400 `E_EXTRACT_MODE` |
| 16 | 配置含坏正则 | `check-config` 退出 78 `E_CONFIG_EXTRACTION_RULE` |
| 17 | `/status` | `slice=S4`，含 extraction 统计与 llm provider |

回归：`smoke` 7/7、`smoke-s1` 17/17、`smoke-s2` 17/17、`smoke-s3` 18/18、`acceptance.ps1` 20/20。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| LLM 输出结构不稳定 | `response_format=json_object` + 严格校验 + 重试 1 次；失败 `DataLoss`，不落候选 |
| 规则覆盖窄 | 规则是配置；S4 只验证管线，不承诺召回率 |
| 中文实体边界 | 正则捕获组限制长度；未命中不写候选，宁可少抽 |
| A-Box 不版本化 | 单机单租户；provenance 在候选行；S5 物化独立命名图不覆盖 A-Box |
| 审批并发 | 状态更新用 `UPDATE ... WHERE state='pending'` 乐观并发，0 行即 `Conflict` |

### 9.3 实施过程中的调整（已同步代码与文档）

| 现象 | 处理 |
|---|---|
| `smoke-s3` 的 `http.status` 硬断言 `slice=="S3"`，S4 后必然红 | 改为接受 `S3..S7`；不改变被测语义 |
| 24 条用例原计划 17 条 | 实际拆成 22 条（把 HTTP 路由、state 过滤、图断开、坏 IRI 各自独立判定） |
| 首轮 `approve.graph_write` 失败 | nonce 语料把 nonce 放在**主语**，断言查**宾语** → 语料改为 `测试点位于库{nonce}`，并加显式失败而非 `StopIteration` |
| `E_INTERNAL detail:` 空消息 | 同上（`StopIteration` 无消息）；`cli._report_error` 兜底分支增加 `traceback.print_exc()` |

### 9.4 与设计偏差

- **`Unsupported` 的 HTTP 映射为 400，而非 §4 表中的 503**：沿用 S0 `_HTTP_STATUS` 既有映射，避免改动已跑通的契约；`E_LLM_NOT_CONFIGURED`/`E_EXTRACTION_DISABLED` 都按此返回。记录于 OPEN-QUESTIONS OQ-29。
- **A-Box 写入不校验 SHACL**：S5 才校验；当前只做 IRI 合法性检查。
- **`counts()` 的 `aboxTriples` 图不可用时返回 `null`**：不阻断统计接口。
