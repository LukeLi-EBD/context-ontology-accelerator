# S3 检索 · 设计

> 切片：S3 · 版本：v0.1 · 日期：2026-11-04
> 上游：03 §3.5（BGE-M3/1024、pgvector）、04 §4.3/§4.4（`VectorStore` / `EmbeddingClient`）、04 §5.7（`SearchIndex`）、07 §5（检索索引）、10 §3（S3）
> 原则：D18 只写胶水与 Web 层；不自研向量检索/排序算法；混合召回只实现 **RRF 固定公式 k=60**（D19）；embedding 缺失必须显式 `degraded`。

---

## 1. 目标与范围

### 1.1 目标

给定查询，返回可引用的 chunk（`documentId + page + chunkId + text`），由两路召回合成：

1. **向量路**：本地 BGE-M3（1024 维）→ pgvector HNSW cosine；
2. **词法路**：PostgreSQL `tsvector`（FTS）+ `pg_trgm`（中文/子串）；
3. **融合**：RRF `score = Σ 1/(60 + rank)`，同分按 `chunk_id` 稳定排序；
4. 任一运行期依赖不可用 → 保留可用路并在响应中 `degraded=true` + `reasons`。

### 1.2 做什么

| # | 内容 |
|---|---|
| 1 | `EmbeddingClient`：`local-bge`（HTTP OpenAI 兼容）、`openai-compatible`、`fake`（仅测试）、`disabled` |
| 2 | `VectorStore`：pgvector `vector(1024)`、HNSW `vector_cosine_ops`、按 `(chunk_id, model)` 幂等 upsert |
| 3 | `SearchIndex`：`document_chunk.text_search`（生成列）+ `pg_trgm` GIN |
| 4 | `SearchService`：`index_document` / `index_all` / `hybrid_search`（RRF） |
| 5 | API：`POST /documents/{id}/index`、`GET /search`；`/status` 增加索引统计 |
| 6 | `platform smoke-s3` 验收（含 fake 向量与 FTS 降级路径） |
| 7 | `learn` 档 `embedding` 容器定义（TEI CPU + 本地模型目录） |

### 1.3 明确不做

- 重排模型 / 学习型排序 / 查询扩展 / HyDE
- 外部向量库（Qdrant/Milvus/Weaviate）
- 跨语言检索、同义词词典、中文分词扩展（`zhparser` 不在镜像内）
- 增量 embedding 的队列/事件（索引是显式 API/CLI 触发的同步作业）
- OCR（仍关闭）、LLM（S4）

## 2. 接口与数据模型

### 2.1 `EmbeddingClient` v1

```text
embed(texts: string[], model?: string) -> float[][]
dimensions() -> int
available() -> bool          // 仅探测，不保证一定成功
```

- `local-bge` / `openai-compatible`：`POST {endpoint}/embeddings`，body `{model,input}`；OpenAI 响应 `data[].embedding`。
- `fake`：进程内确定性哈希向量（**仅供测试**，模型名 `fake-hash-1024`，绝不进入生产索引）。
- 维度校验：返回维度 ≠ `embedding.dimensions` → `InvalidArgument / E_EMBED_DIM_MISMATCH`。
- 连接失败/超时 → `Unavailable` / `DeadlineExceeded`；401 → `PermissionDenied`；429 → `ResourceExhausted`。
- `provider=disabled` → 所有 `embed` 返回 `Unsupported / E_EMBED_DISABLED`。

### 2.2 `VectorStore` v1（PG）

```text
upsert(documentId, items: [{chunkId, vector}]) -> {upserted}
search(vector, model, limit) -> [{chunkId, documentId, pageFrom, pageTo, text, score}]
deleteDocument(documentId, model) -> {deleted}
```

- 表 `platform.chunk_embedding`：PK `(chunk_id, model)`；`embedding vector(1024) NOT NULL`；`dimensions int` 冗余校验。
- SQL 用 `1 - (embedding <=> $1::vector)` 得 cosine 相似度；`ORDER BY embedding <=> $1` 走 HNSW。
- 模型隔离：查询只匹配当前 `model`，fake 向量不会污染真实模型索引。

### 2.3 `SearchIndex` v1（PG FTS/trgm）

```text
search(query, limit) -> [{chunkId, documentId, pageFrom, pageTo, text, score}]
```

- `document_chunk.text_search` 为 `GENERATED ALWAYS AS (to_tsvector('simple', text)) STORED`，GIN 索引。
- 词法分数 = `ts_rank_cd(text_search, plainto_tsquery('simple', q)) + word_similarity(q, text)`；候选条件 = FTS 命中 **或** `word_similarity(q, text) >= search.min_similarity`。
  - 实现偏离（已记 OPEN-QUESTIONS OQ-24）：用 `word_similarity` 而不是 `similarity`。`similarity` 的分母是整段文本的 trigram 并集，1200 字 chunk 里出现 4 字查询会得到接近 0 的分数，等于屏蔽中文命中；`word_similarity` 取查询在文本中的最佳匹配窗口，仍是 `pg_trgm` 现成函数，没有自写算法。
- 中文说明：`simple` 不做中文分词，中文主要靠 `pg_trgm`；不引入 `zhparser`（D18/依赖纪律）。

### 2.4 `SearchService`（编排）

```text
index_document(documentId) -> {chunks, indexed, embedded, model, dimensions, degraded, reasons}
index_all(limit) -> {documents, chunks, embedded, degraded}
hybrid_search(query, limit, mode) -> {query, mode, rrfK, routes[], degraded, reasons[], results[]}
```

`hybrid_search`：

```text
candidates = candidate_k (default 30)
vectorList = vectors.search(embed(query), model, candidates)      // 可失败
lexicalList = index.search(query, candidates)                    // PG 生成列，无需外部依赖
if mode == vector and embedding unavailable -> Unavailable
if mode == hybrid and embedding unavailable -> lexical only + degraded + reason
result = RRF([vectorList, lexicalList], k=60)  // 只对出现的列表计分
```

`results[]`：`chunkId, documentId, pageFrom, pageTo, text, score, ranks{vector,lexical}`。

## 3. 配置项与默认值

```yaml
embedding:
  provider: local-bge          # local-bge | openai-compatible | fake | disabled
  model: BAAI/bge-m3
  dimensions: 1024             # 固定 1024（pgvector 列宽）
  endpoint: http://embedding:80/v1
  timeout_ms: 30000
  batch_size: 16                # 类默认；本机 TEI CPU 后端实测上限 4，data/platform.yaml 置 4
  service_enabled: true
  api_key_env: EMBEDDING_API_KEY

search:
  enabled: true
  top_k: 10                    # 1..100
  candidate_k: 30              # 每路候选
  rrf_k: 60                    # D19 固定公式；默认 60
  min_similarity: 0.05         # trgm 候选阈值
```

校验：

| 键 | 规则 | 错误码 |
|---|---|---|
| `embedding.dimensions` | 必须 1024 | Pydantic `Literal[1024]` |
| `search.top_k` / `candidate_k` | `candidate_k >= top_k`，且都在范围内 | `E_CONFIG_SEARCH_RANGE` |
| `embedding.provider=fake` | 允许，但启动 `degraded` 标 `embedding:fake(test_only)` | warning |
| `embedding.provider=disabled` | 允许，`SEMANTIC_SEARCH=false` | warning |

> `service_enabled=true` 但容器不在线**不阻塞启动**：在线检索退 FTS 并 `degraded`（05 §1.2）。

## 4. 失败语义与错误码

| 场景 | 端口码 | HTTP | 平台错误码 |
|---|---|---|---|
| embedding 服务连不上 | `Unavailable` | 503（显式 vector 模式） | `E_EMBED_UNAVAILABLE` |
| embedding 超时 | `DeadlineExceeded` | 504 | `E_EMBED_TIMEOUT` |
| embedding 维度不符 | `InvalidArgument` | 400 | `E_EMBED_DIM_MISMATCH` |
| embedding 401/429 | `PermissionDenied` / `ResourceExhausted` | 403 / 429 | `E_EMBED_AUTH` / `E_EMBED_RATE` |
| 向量写入维度错 | `InvalidArgument` | 400 | `E_EMBED_DIM_MISMATCH`（S13b 起；旧名 `E_VECTOR_DIM_MISMATCH` 已废弃） |
| 向量写入模型与指针不符 | `InvalidArgument` | 400 | `E_EMBED_MODEL_MISMATCH`（仅 `enforce_active=true`，见 §10.4） |
| 索引时 embedding 不可用 | 不失败 | — | `degraded=true` + `E_EMBED_UNAVAILABLE`（仅词法索引） |
| hybrid 查询时 embedding 不可用 | 不失败 | 200 | `degraded=true` + routes=`["lexical"]` |
| 显式 `mode=vector` 且不可用 | `Unavailable` | 503 | `E_EMBED_UNAVAILABLE` |
| 无向量索引（未 index） | 不失败 | 200 | `degraded=true` + `E_NO_VECTOR_INDEX` |
| PG 不可用 | `Unavailable` | 503 | `E_DB_UNAVAILABLE` |

## 8. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 中文 FTS | `simple` 解析器不切中文，FTS 主要对英文/空格文本有效 | 用 `pg_trgm` 补中文；不引入分词扩展 |
| BGE-M3 体积 | 2.27 GB，CPU 推理首查慢、内存 ~2 GB | 容器限 `--max-batch-tokens`；只常驻 learn；lean 按需 |
| 模型下载 | 官方 HF 在本机不可用，镜像 ~330 KB/s → 约 2 小时 | 已后台下载到本地缓存；未完成时 FTS 降级并如实上报 |
| fake 向量 | 仅测试，质量无意义 | 模型名隔离 `fake-hash-1024`，生产配置禁止使用（启动 degraded 提示） |
| RRF 并列 | 同分结果不稳定 | 同分按 `chunk_id` 升序，保证可复现 |
| 索引同步耗时 | 文档多时 `index_all` 阻塞 HTTP | 单机显式触发；批量走 CLI，后续切片再考虑作业化 |

### 10.4 补充：多 embedding 模型分区（S13b，2026-11-05）

- **背景**：S3 把 `chunk_embedding.embedding` 固定为 `vector(1024)` + 单一 HNSW，导致任何非 1024 维模型都无法入库。
- **V13 迁移**：`embedding` 改为无约束 `vector`；按维度建表达式 HNSW 索引（`dimensions=1024` → `vector(1024)`；`dimensions=2048` → `halfvec(2048)`，因为 pgvector 0.8.7 的 `vector` HNSW 上限 2000 维，`halfvec` 上限 4000 维）；新增单行指针表 `platform.embedding_pointer(provider, model, dimensions)`，默认值 `('local-bge','BAAI/bge-m3',1024)`。
- **读写强校验**：写入/查询都必须与指针的 `model` 与 `dimensions` 一致，否则 `E_EMBED_MODEL_MISMATCH` / `E_EMBED_DIM_MISMATCH`；同一 `chunk_id` 在不同 `model` 下各有独立向量行（PK `(chunk_id, model)`），互不覆盖。
- **reindex**：`platform reindex --provider=<local-bge|ark|fake> [--batch-size N] [--max-seconds S] [--activate-only]`，按目标分区补算缺失 chunk，可中断续跑；全部补齐后切换指针；旧分区不删除、`--activate-only` 可一键切回。
- **探测事实（2026-11-05）**：`doubao-embedding-vision` 在 Ark coding plan（`/api/coding/v3`）返回 **2048 维**；与本地 BGE-M3 的 1024 维 **不可互换**（不可做向量级比较，也不可复用同一条向量）。2048 维分区索引走 `halfvec`，精度为半精度，检索结果兼容但非全精度。
- **契约测试**：`platform smoke-embed` 覆盖三条契约（分区互不可见 / 切指针后查询非空 / 切回旧分区可用）+ 两条守卫错误码。
