## 1. 目标与范围

### 1.1 目标

1. **SHACL 门禁**：对 T-Box / A-Box 命名图跑 pySHACL，返回 `conforms`、违规数与逐条违规（focusNode / path / message）。
2. **EL 物化**：把 T-Box（当前发布版本）+ A-Box 交给 ROBOT/ELK 推理，把**新增**三元组写入独立命名图 `urn:platform:inferred:<tboxVersionId>`，绝不覆盖源图。
3. **物化前 SHACL 门禁**：A-Box 非空时先跑形状校验，违规即拒绝物化（`E_SHACL_VIOLATION`），源图含违规实例时**绝不写入** inferred 图。
4. **一致性前置**：物化前先做一致性检查，`consistent=false` 则不写目标图。
5. **幂等**：`hash(tboxNT + aboxNT + profile + engine)` 未变且目标图就绪 → `skipped=true`。
6. **失败不污染**：推理服务不可用/超时/结果非法 → 目标图保持上一次成功内容（首次失败则保持空），作业记 `failed`，源图不变。
7. **learn 档第 5 容器**：compose 增加 `reasoner`（profiles `learn`/`reasoning`）。

### 1.2 做什么

| # | 内容 |
|---|---|
| 1 | `ReasoningConfig`（mode/profile/engine/service_enabled/endpoint/prefix/shapes_dir/…）与 fail-fast 校验 |
| 2 | `adapters/reasoner_robot.py`：`ReasonerClient`（HTTP → 容器内 ROBOT CLI），错误映射 |
| 3 | `_impl/reasoner/`：薄 HTTP 包装（FastAPI + `robot reason` 子进程），`/healthz`、`/v1/reason` |
| 4 | `validation.py`：`ShaclValidator`（pySHACL，形状目录 `/data/shapes`，图内容经 GraphStore 导出） |
| 5 | `reasoning.py`：`ReasoningService`（幂等键、advisory lock、作业表、目标图替换、指针） |
| 6 | `sql/V6__s5.sql`：`platform.reasoning_job` + `platform.inferred_pointer` |
| 7 | API：`POST /reasoning/materialize`、`GET /reasoning/status`、`POST /validation/run`、`GET /validation/shapes` |
| 8 | `platform smoke-s5`（正常 + 失败路径） |

### 1.3 明确不做

- 查询时重写（query rewriting）、增量推理、自研分类器（D18/05 §2.1）；
- OWL DL（HermiT/Konclude）在线能力——`profile` 仅允许 `EL|OWL2EL`；`RDFS`/`OWL2DL` 配置直接 `E_CONFIG_REASONING`（78）。
  原因：ROBOT 1.9.6 的 `reason` 只支持 ELK/HermiT/JFact，**没有 RDFS 推理器**，S5 也不在平台进程内自研闭包（实测见 §9.2，OQ-34）；
- 自动发布门禁联动（本切片只提供 `validate` 端点，S7 再接到 UI）；
- 推理产物版本 GC、跨版本合并（D20）；
- Fuseki 适配器、事件/队列驱动（作业同步执行，HTTP 阻塞到完成或 504）。

## 2. 接口与数据模型

### 2.1 `ReasonerClient` v1（薄客户端）

```text
health() -> {available, robotVersion, engine, riot}
reason(tbox_nt: bytes, abox_nt: bytes, profile: str, consistency_first: bool) -> {
  consistent: bool, inferredNT: bytes, reasonedCount: int, ms: int, robotVersion: str
}
rdfs_closure(tbox_nt: bytes, abox_nt: bytes) -> {
  closureNT: bytes, count: int, ms: int, stages: {rdfs: ms}
}
manifest() -> Manifest
```

- `POST {reasoning.endpoint}/v1/reason`，body：`{tbox, abox, profile, consistencyFirst}`（N-Triples 文本）。
- 连接失败 → `Unavailable/E_REASONER_UNAVAILABLE`；超时 → `DeadlineExceeded/E_REASONER_TIMEOUT`；
  非 200 → `DataLoss/E_REASONER_BAD_RESPONSE`；`consistent=false` 不做错误，由上层决定不物化。
- 容器内执行：`robot reason --reasoner ELK --axiom-generators "SubClass ClassAssertion" -d true --input merged.ttl --output reasoned.ttl`。
  - `--axiom-generators` 是必需的：ROBOT 默认只回吐源公理，不产生实例类型的蕴含；
  - `-d true`（include indirect）让 ELK 输出传递超类（`alice a Person, Thing`）。
  - ROBOT 1.9.6 **没有** `--fail-on-inconsistency` / `--input-format` / `--output-format` 参数（v0.1 的错误写法已删除，见 §9.2）。
- RDFS 闭包（OQ-34/39）：`POST {reasoning.endpoint}/v1/rdfs`，body 同上（N-Triples 文本）；容器内把 T-Box+A-Box 合并后执行
  `riot --rdfs=<merged> --output=nt <merged>`（Apache Jena 5.5.0 / Java 17），闭包从 **stdout** 返回。
  - 超时 → `DeadlineExceeded/E_REASONER_TIMEOUT`；不可达 → `Unavailable/E_REASONER_UNAVAILABLE`；非 200 → `DataLoss/E_RDFS_FAILED`。

### 2.2 `ReasoningService`（编排）

```text
validate(graph="tbox"|"abox"|iri) -> {conforms, violations, shapes, graph, ms}
materialize(profile?, force=false) -> MaterializeResult {
  jobId, targetGraph, inferred, skipped, consistent, inputHash, mode, ms,
  stages: {rdfs, owl, shacl}, warnings[]
}
status() -> {mode, provider, available, pointer, lastJob, inferredTriples}
```

流程（OQ-39：RDFS 闭包 → OWL 物化 → SHACL 门禁，一次原子提交）：

1. 取 T-Box 当前发布版本 → `urn:platform:graph:tbox:<versionId>`；取 A-Box（`reasoning.abox_graphs`，默认 `urn:platform:graph:abox:main`）。
2. `GraphStore.export_graph()` 导出 N-Triples（新增端口方法，见 §2.4）。
3. `input_hash = sha256(tboxNT | aboxNT | profile | engine | mode)`。`mode` 参与哈希：切换 `validate`/`rdfs`/`materialize` 必须重算。
4. 查指针：`input_hash` 相同且目标图三元组数 == `inferred` → `skipped=true`，**不调用任何推理器**、不改图。
5. 抢 advisory lock（key=`reasoning:<target>`，超时 0 则 `Aborted/E_REASONING_BUSY`）。
6. **阶段 A：RDFS 闭包**（`mode in {rdfs, materialize}`）——`ReasonerClient.rdfs_closure()`；返回闭包去掉源三元组得 `closureΔ`。
7. **阶段 B：OWL 物化**（`mode=materialize`）——把 `closureΔ` 并入输入再调 `ReasonerClient.reason()`（ELK）；`consistent=false` → 作业 `failed`（`E_REASONING_INCONSISTENT`）；新增三元组 = reasoned − (tbox ∪ abox ∪ closure) 得 `owlΔ`；最终候选 `inferred = closureΔ ∪ owlΔ`。
8. **阶段 C：SHACL 门禁**——A-Box 导出非空时跑 `ShaclValidator.validate(abox)`；`conforms=false` → 作业 `failed`（`E_SHACL_VIOLATION`），**尚未写图**，目标图不变。
9. 全部阶段通过后，才 `GraphStore.replace_graph(target, inferredNT)`（同一 `urn:platform:inferred:<versionId>`）；成功后更新指针与作业 `succeeded`。
10. 任何阶段异常：作业 `failed`，指针不变，目标图**保持上一次内容**（若写图步骤自身失败，`clear_graph(target)`；绝不半途落图）。
11. `mode=validate`：**不进入锁/幂等分支**，只调 `validate("abox")`，返回 `validation` 与 `stages.shacl`，不调推理器、不写 inferred；`mode=rdfs`：只跑 A + C。

返回 `stages` 逐阶段给出 `triples`/`ms`（`shacl` 额外含 `conforms`/`violations`），失败信息带 `mode` 与失败阶段。

### 2.3 `ShaclValidator`

```text
validate(graph_iri, data_nt: bytes) -> {conforms, violations[], shapesVersion, ms}
```

- 形状目录 `reasoning.shapes_dir`；加载目录下全部 `*.ttl` 合并为一个 shapes graph（文件名排序）。
- `pyshacl.validate(target_graph=rdflib.Graph().parse(data_nt, format="nt"), shacl_graph=shapes,
  inference="rdfs", abort_on_first=False, allow_infos=True, allow_warnings=True)`。
- 目录缺失或无形状 → `Unsupported/E_SHACL_SHAPES_MISSING`（绝不“无形状=通过”）。
- 违规摘要：`{focusNode, path, severity, message}`，最多返回 `reasoning.max_violations`（默认 200）。

### 2.4 `GraphStore` 新增（S5 唯一扩展）

```text
export_graph(graph_iri, rdf_format="nt") -> bytes     // CONSTRUCT { ?s ?p ?o } WHERE { GRAPH <g> {...} }
```

只用于推理/校验的“读取整个命名图”，不进入业务查询路径。

### 2.5 PG（V6）

```sql
CREATE TABLE platform.reasoning_job (
  job_id text PRIMARY KEY, kind text NOT NULL CHECK (kind IN ('materialize','validate')),
  ontology_version text, profile text, target_graph text, input_hash char(64),
  state text NOT NULL CHECK (state IN ('queued','running','succeeded','failed','skipped')),
  inferred int, consistent boolean, error_code text, error_message text,
  started_at timestamptz NOT NULL DEFAULT now(), finished_at timestamptz,
  result_summary jsonb NOT NULL DEFAULT '{}'::jsonb
);
CREATE INDEX reasoning_job_started_idx ON platform.reasoning_job (started_at DESC);

CREATE TABLE platform.inferred_pointer (
  name text PRIMARY KEY, ontology_version text NOT NULL, target_graph text NOT NULL,
  input_hash char(64) NOT NULL, inferred int NOT NULL, job_id text NOT NULL,
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

单例行 `name='default'`。指针是“当前生效推理图”的唯一答案来源（对齐 D20）。

### 2.6 A-Box 图名

S4 用 `urn:platform:graph:abox:main`；05 §2.4 写 `urn:platform:abox:<version>`。本切片**不改 S4**，配置项 `reasoning.abox_graphs` 默认 `["urn:platform:graph:abox:main"]`，差异记 OPEN-QUESTIONS。

## 3. 配置项与默认值

```yaml
reasoning:
  mode: materialize                 # off | rdfs | materialize | validate
  profile: EL                       # EL | OWL2EL（RDFS 无 ROBOT 推理器，见 §1.3）
  engine: robot                     # 仅 robot（ELK 由 ROBOT 内部调用）
  service_enabled: true             # learn 档 true；lean 档 false（作业化）
  endpoint: http://reasoner:7879
  timeout_ms: 300000
  inferred_graph_prefix: "urn:platform:inferred:"
  abox_graphs: ["urn:platform:graph:abox:main"]
  shapes_dir: /data/shapes
  consistency_first: true
  max_violations: 200
  max_source_bytes: 52428800     # stage 1（RDFS）源输入上限
  max_assembly_bytes: 52428800   # stage 2（ROBOT/ELK）组装输入上限
```

校验：

| 键 | 规则 | 错误码 |
|---|---|---|
| `mode != off` 且 `profile in {RDFS,OWL2QL,OWL2RL,OWL2DL}` | 无对应推理器（ELK 只有 OWL 2 EL） | `E_CONFIG_REASONING`（78） |
| `mode=materialize` 且 `inferred_graph_prefix` 为空 | 必须有目标前缀 | `E_CONFIG_REASONING`（78） |
| `inferred_graph_prefix` 与 `graph.default_graph` 相同 | 禁止覆盖源图（04 §10.1 #8） | `E_CONFIG_REASONING`（78） |
| `mode != off` 且 `service_enabled=false` | 允许（离线批处理），但启动 `degraded: reasoner:offline_only` | warning |
| `mode=off` | 允许；启动 `degraded: reasoning:off(NO_OWL_DL)` | warning |
| `engine != robot` | 未实现 | `E_PROVIDER_UNSUPPORTED`（78） |

`runtime.mode=learn` 默认 `mode=materialize` + `service_enabled=true`；`lean` 默认 `mode=off`（配置覆盖可开）。

`reasoning.mode` 决定链走到哪一步（OQ-39）：

| `mode` | RDFS 闭包（Jena） | OWL 物化（ROBOT/ELK） | SHACL 门禁 | 写 `inferred` |
|---|---|---|---|---|
| `off` | — | — | — | 否（`E_REASONING_DISABLED`） |
| `validate` | — | — | ✅ | 否 |
| `rdfs` | ✅ | — | ✅ | ✅（闭包） |
| `materialize` | ✅ | ✅ | ✅ | ✅（闭包 ∪ OWL 增量） |

> `reasoning.profile=RDFS`（推理器档位）与 `mode=rdfs`（流水线层级）是两回事：前者仍 78 fail-fast（OQ-34），后者合法。

## 4. 失败语义与错误码

| 场景 | 端口码 | HTTP | 平台错误码 |
|---|---|---|---|
| 推理容器不可达 | `Unavailable` | 503 | `E_REASONER_UNAVAILABLE` |
| 推理超时 | `DeadlineExceeded` | 504 | `E_REASONER_TIMEOUT` |
| 推理器输出非 N-Triples / 解析失败 | `DataLoss` | 500 | `E_REASONER_BAD_RESPONSE` |
| 本体不一致 | 作业 `failed` | 409 | `E_REASONING_INCONSISTENT` |
| 源图违反 SHACL（物化门禁） | 作业 `failed` | 409 | `E_SHACL_VIOLATION`（details 含 `focusNodes`/`violationCount`） |
| 同一目标图并发物化 | `Aborted` | 409 | `E_REASONING_BUSY` |
| 无已发布 T-Box | `NotFound` | 404 | `E_ONTOLOGY_NO_PUBLISHED` |
| 目标图写入失败 | `Unavailable` | 503 | `E_GRAPH_UNAVAILABLE`（目标图被清理） |
| 形状目录缺失/为空 | `Unsupported` | 400 | `E_SHACL_SHAPES_MISSING` |
| 校验对象图不存在/为空 | `InvalidArgument` | 400 | `E_VALIDATE_EMPTY_GRAPH` |
| 非法 graph 参数 | `InvalidArgument` | 400 | `E_VALIDATE_TARGET` |
| 配置非法 | 启动失败 | — | `E_CONFIG_REASONING`（78） |

`mode=off` 时 `materialize` 返回 `Unsupported/E_REASONING_DISABLED`（不伪装成功）。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| ROBOT 镜像首次构建需下载 ~26MB `robot.jar` | Dockerfile `ADD` 直连 GitHub release；失败时回退“宿主机下载 + COPY”，版本与 sha256 写死 |
| JVM 内存（12.5G 环境） | 容器 `mem_limit: 3g` + `JAVA_OPTS=-Xmx2g` |
| ELK 对非 EL 公理静默忽略 | 配置仅允许 EL/OWL2EL；RDFS/DL fail-fast；结果附 `engine=robot/ELK` |
| 大图 N-Triples 传输 | `reasoning.max_source_bytes`（stage 1 源输入）与 `reasoning.max_assembly_bytes`（stage 2 组装输入）默认均 50MB；超限 `ResourceExhausted/E_REASONING_INPUT_TOO_LARGE`，错误信息与 `details.layer` 标明 source/assembly |
| 目标图替换非原子（DROP+INSERT） | 先取全量结果再替换；写入失败 `clear_graph` 并记 failed；下次重跑收敛（OQ 记录） |
| 校验形状缺失导致“假通过” | 无形状即 `Unsupported`，绝不返回 `conforms=true` |

### 9.2 与 v0.1 设计的偏差（均已回写正文）

| # | 设计写法 | 实测 | 落点 |

### 9.4 OQ-34 实测与 RDFS 闭包作业（2026-11-05）

**实测 1：ROBOT/ELK（现有 `--reasoner ELK --axiom-generators "SubClass ClassAssertion" -d true`）**

探针 `rdfs-probe2.ttl`：`Person ⊑ Thing`、`Agent ⊑ Person`、`locatedIn subPropertyOf relatedTo`、`locatedIn domain Place`、`locatedIn range Country`、`alice a Agent`、`alice locatedIn beijing`。inferred 图结果：

| 目标 | ELK 是否推出 |
|---|---|
| `alice a Person` / `alice a Thing`（`rdfs:subClassOf` 传递） | ✅ |
| `alice a Place`（`rdfs:domain` 类型断言） | ✅ |
| `beijing a Country`（`rdfs:range` 类型断言） | ❌ |
| `alice relatedTo beijing`（`rdfs:subPropertyOf` 断言传播） | ❌ |

补测：`--axiom-generators "SubClass ClassAssertion ObjectPropertyAssertion"` 被 ROBOT 拒绝（`ObjectPropertyAssertion is not a valid inferred axiom generator`）。**结论：ELK 不能承担完整 RDFS 闭包。**

**实测 2：Jena `riot --rdfs`（采用方案）**

镜像与作业（`rdfs/Dockerfile`，`eclipse-temurin:21-jre-alpine` + Apache Jena 6.2.0）：

- 镜像：`agent-rdfs:0.1-s5`；compose 服务 `rdfs`，`profiles: ["job"]`，**一次性作业，不是常驻服务**（`restart: "no"`，`mem_limit: 1g`，挂载 `./data:/data`）。
- 命令（`docker compose --profile job run --rm rdfs`，entrypoint `rdfs-closure`）：
  `riot --rdfs=<vocab> --output=nt <input> > <output>.tmp && mv`；默认 `input=/data/jobs/rdfs/in.ttl`、`output=/data/jobs/rdfs/out.nt`、`vocab=input`（T-Box + A-Box 合并文档）。
- 注意：Jena 6.2.0 的 class 文件版本 65 需要 **Java 21**（先用 Java 17 实测报 `UnsupportedClassVersionError`，故基础镜像改为 temurin 21）；`riot` 没有 `--rules` 参数（实测 `Unknown argument: rules`），RDFS 闭包用 `--rdfs=<vocab>`。

实测输入 `data/jobs/rdfs/in.ttl`（OQ-34 探针，类/属性/数据同上），实跑输出 `data/jobs/rdfs/out.nt` 含：

### 9.5 OQ-39：RDFS → OWL → SHACL 链式集成（2026-11-05）

`ReasoningService.materialize()` 现在按 `reasoning.mode` 执行一条**单目标图、单次原子提交**的链：

1. **RDFS 闭包**：`ReasonerClient.rdfs_closure()` → reasoner 容器 `POST /v1/rdfs` → Jena 5.5.0 `riot --rdfs=<merged> --output=nt`；闭包从 stdout 返回，平台用 `_closure_diff` 去掉 T-Box/A-Box 源三元组，得 `closureΔ`。
2. **OWL 物化**：把 `closureΔ` 并入 ELK 输入（`reason()`），`_diff(..., closure_nt)` 只保留 OWL 新增，与 `closureΔ` 合并为最终候选。
3. **SHACL 门禁**：`validate(abox)`；违规 → `E_SHACL_VIOLATION`，此时**尚未写图**。
4. 三步全过才 `replace_graph("urn:platform:inferred:<versionId>")` + 指针；任一步异常 → 作业 `failed`，目标图保持原内容（写图自身失败则 `clear_graph`）。

**幂等**：`input_hash` 纳入 `mode`；同版本、同 mode 重跑命中指针 + 图计数一致 → `skipped=true`，不调用任何推理器，`stages={}`。

**实测**：

| 场景 | 结果 |
|---|---|
| `POST /reasoning/materialize`（`mode=materialize`） | `status=200`，`stages=['rdfs','owl','shacl']`，`skipped=false` |
| 同版本重跑 | `skipped=true`，`stages={}` |
| 停 `reasoner` 后重跑（改 A-Box 触发重算） | `503 E_REASONER_UNAVAILABLE`，目标图不变 |
| A-Box 故意违反形状 | `409 E_SHACL_VIOLATION`，`inferred` 计数不增 |
| Jena 版本 | 5.5.0（archive.apache.org）+ Java 17；`/healthz` 增加 `riot` 字段 |
