## 2. 目录结构与代码组织

代码放 `_impl/`，不写进 `_arch/`、`coa/`、`_design/`（`_design/impl/` 只放设计文档）。

```text
_impl/
  docker-compose.yml            # 3 常驻服务；learn/lean 由 COMPOSE_PROFILES 控制
  .env                          # COMPOSE_PROFILES、POSTGRES_PASSWORD（开发默认）
  Dockerfile                    # 多阶段；运行镜像不含编译工具链
  requirements.txt              # 全部 == 锁版本
  pyproject.toml                # 包元数据 + console_scripts: platform
  data/
    platform.yaml               # 容器内 /data/platform.yaml（唯一配置文件）
    blobs/ tmp/ exports/ backups/ owl/
  src/platform_core/
    __init__.py                 # 版本号
    config.py                   # Schema、默认值、YAML/ENV 合并、来源记录
    errors.py                   # PortError / ConfigError / StartupError / 退出码
    ports.py                    # 端口协议（Protocol）+ Capability 常量
    adapters/
      metadata_pg.py            # MetadataStore（psycopg）
      graph_oxigraph.py         # GraphStore（Oxigraph HTTP）
      object_fs.py              # ObjectStore：FS CAS
      object_pg.py              # ObjectStore：PG bytea（小工件层）
      object_layered.py         # 按大小分流的 ObjectStore
      placeholder.py            # 未实现端口的显式占位（Unsupported）
    sql/
      V1__s0.sql                # 仅当前切片需要的表
    bootstrap.py                # 启动自检（03 §16.1 子集）
    assembly.py                 # 按配置装配 adapter（唯一装配点）
    api.py                      # FastAPI：/healthz /readyz /status
    smoke.py                    # smoke 用例集（CLI 调用）
    cli.py                      # serve / check-config / probe / smoke
  tests/
    bad_config.yaml             # 类型错误，预期 78
    acceptance.ps1              # 宿主机一键验收（含两条失败路径）
  OPEN-QUESTIONS.md
```

**为什么包名是 `platform_core`**：`platform` 是 Python 标准库模块名，作为包名会遮蔽标准库；对外命令仍叫 `platform`（`console_scripts`）。

## 4. 配置

### 4.1 文件形态与优先级

`/data/platform.yaml`（单文件）；优先级 **CLI 覆盖（本轮不提供）< 环境变量 < YAML < 内置默认值**，实现为「默认 → YAML → ENV」，ENV 键形如 `PLATFORM__STORAGE__SMALL_OBJECT_PROVIDER`（双下划线映射层级）。启动日志逐键打印生效来源（`default|yaml|env`）。

### 4.2 S0 生效字段与默认值

| 键 | 默认 | 说明 |
|---|---|---|
| `mode` | `single` | `single` 为唯一允许值；`test` 保留给替身（S0 不实现） |
| `config_version` | `1` | 高于 1 → 78 |
| `data_dir` | `/data` | 容器内绝对路径 |
| `http.port` / `http.bind` | `8080` / `0.0.0.0` | 容器内监听；宿主机仅绑 `127.0.0.1` |
| `database.url` | **必填** | 缺失 → 78 |
| `database.pool_max` | `10` | |
| `graph.provider` | `oxigraph-http` | S0 仅实现该值；其余显式 78 |
| `graph.endpoint` | `http://oxigraph:7878` | |
| `graph.timeout_ms` / `max_rows` | `30000` / `10000` | 护栏 |
| `storage.small_object_provider` | `pg` | 小工件（≤10MB）进 PG bytea |
| `storage.large_object_provider` | `fs` | 大件进 CAS |
| `storage.root` / `tmp_dir` | `/data` / `/data/tmp` | tmp 必须与 blobs 同卷 |
| `storage.pg_blob_max_file_mb` | `10` | 分流阈值（定死） |
| `storage.min_free_pct` | `10` | 低于则拒启（74） |
| `storage.gc_grace_hours` | `48` | S0 只记录，GC 在 S2 |
| `runtime.mode` | `learn` | learn/lean 在 S0 均起 3 容器；learn 的下属服务未落地时打印 DEGRADED |
| `log.level` / `log.format` | `info` / `json` | |

> `llm`/`embedding`/`ocr`/`reasoning`/`ontology`/`jobs`/`search` 键在 S0 允许出现但不装配；出现时在 `/status` 标 `not_implemented`，不阻断启动。

### 4.3 校验与 fail-fast

三层顺序：① 类型/语法（Pydantic）→ ② 语义（版本、端口范围、provider 组合、必填）→ ③ 能力（S0 requirements × manifest）。任一层失败：打印 `E_CONFIG_* / E_CAP_*` + 键名 + 期望值，退出码 **78**。

S0 `requirements`（只校验已装配能力）：

```yaml
requirements:
  sparql_query: [graph.sparql]
  fact_write:   [graph.update]
  object_put:   [object.put]
  object_get:   [object.get]
degradation:
  deny: [sparql_query, fact_write, object_put, object_get]
```

## 5. 端口骨架

### 5.1 `GraphStore`（实现：Oxigraph HTTP）

| 方法 | S0 行为 | 失败语义 |
|---|---|---|
| `query(sparql)` | POST `/query`，`application/sparql-query`，Accept `application/sparql-results+json` | 连接失败 → `Unavailable`；超时 → `DeadlineExceeded`；语法错误 → `InvalidArgument`；行数超 `max_rows` → `truncated=true` 并截断 |
| `ask(sparql)` | 同上，读 `boolean` | 同上 |
| `update(sparql)` | POST `/update`，`application/sparql-update` | 含 `SERVICE` → `Unsupported`；语法错误 → `InvalidArgument` |
| `clearGraph(iri)` | `DROP SILENT GRAPH <iri>` | 同上 |
| `construct/load/dump` | **显式占位**：返回 `Unsupported`（错误码 `E_PORT_NOT_IMPLEMENTED`），S1/S2 补 | — |

`capabilities()` 如实上报：`SPARQL_QUERY, SPARQL_ASK, SPARQL_UPDATE, NAMED_GRAPHS, GRAPH_CLEAR`；`GSP_SUPPORT=none`、`TEXT_INDEX=false`、`FEDERATION_SERVICE=false`。

### 5.2 `ObjectStore`（实现：分层 = PG bytea + FS CAS）

| 方法 | S0 行为 | 失败语义 |
|---|---|---|
| `put(bucket,key,body,content_type,metadata)` | 边算 sha256；`size ≤ pg_blob_max_file_mb*1MB` 且小层=pg → bytea；否则 FS CAS：`tmp/<uuid>.part` → fsync → `blobs/<hh>/<sha256>` → fsync 目录。S0 的用户 metadata 存于 `blob.metadata`（同内容共享；按 key 的 metadata 在 S2 随 document 元数据落 PG） | 磁盘低于 `min_free_pct` → `ResourceExhausted`；无权限 → `PermissionDenied` |
| `get(bucket,key)` | 按 `blob` 行读；FS 读文件后校验 sha256；返回 bytes + meta | 行缺失 → `NotFound`；行在文件不在 → `DataLoss`；sha256 不符 → `DataLoss` |
| `head(bucket,key)` | 只读 `blob` 元数据 | `NotFound` |
| `delete(bucket,key)` | 删 `blob_ref` 行；`refcount=0` → `blob.state='deleting'`、`deleted_at=now()`（软删，物理 GC 在 S2） | 幂等：重复删除成功 |
| `list(bucket,prefix)` | 按 `blob_ref.owner_id` 前缀查询 | 空列表（不是 `NotFound`） |
| `copy/presign/multipart/versioning` | 显式占位 `Unsupported` | 能力位如实 `false` |

写入顺序固定为 **字节 → 元数据行 → 引用 → 提交**（07 §4.4）；同哈希并发依赖 `ON CONFLICT DO NOTHING` 与复合主键去重，不做应用层锁。

### 5.3 `MetadataStore`（实现：PG）

| 方法 | S0 行为 |
|---|---|
| `migrate()` | `pg_advisory_lock(hashtext('platform:migrate'))` → 应用 `V1__s0.sql` → 记录 `schema_version`；库版本 > 代码版本 → `E_DB_MIGRATION_MISMATCH`（78） |
| `query/execute` | psycopg 同步，连接池 |
| `tx()` | 上下文管理器，正常提交/异常回滚 |
| `advisory_lock(key, ttl)` | 会话级 `pg_advisory_lock`；S0 仅迁移使用 |

### 5.4 未实现端口（占位，不做功能承诺）

| 端口 | S0 返回 |
|---|---|
| `VectorStore` | `Unsupported`，`E_PORT_NOT_IMPLEMENTED port=VectorStore slice=S3` |
| `EmbeddingClient` | 同上（S3） |
| `LLMClient` | 同上（S4） |
| `SearchIndex` | 同上（S3） |
| `DocumentParser` | 同上（S2） |
| `OntologyRegistry` | 同上（S1） |
| `ContextResolver` | 同上（S6） |
| `ExtractionPipeline` | 同上（S4） |
| `ReasoningService` | 同上（S5） |
| `Cache` / `SecretProvider` | S0 提供进程内最小只读实现：`Cache` 不启用；`SecretProvider` 从 env 读，缺失 → `NotFound` |

**占位规则**：调用即抛 `PortError(code=Unsupported, providerCode=E_PORT_NOT_IMPLEMENTED, details={slice:...})`；绝不返回空结果/假数据。

## 6. 启动自检（03 §16.1 的 S0 子集）

| 顺序 | 检查 | 失败错误码 | 退出码 |
|---|---|---|---|
| 1 | 配置解析 + Schema + `config_version` | `E_CONFIG_*` | 78 |
| 2 | `data_dir`/`storage.root`/`tmp_dir` 存在且可写；tmp 与 blobs 同卷 | `E_IO_PERM` / `E_IO_VOLUME` | 73 / 74 |
| 3 | 磁盘余量 ≥ `min_free_pct` | `E_DISK_LOW` | 74 |
| 4 | PG 连接（重试 ≤60s）+ `schema_version` 匹配 | `E_DB_UNAVAILABLE` / `E_DB_MIGRATION_MISMATCH` | 69 / 78 |
| 5 | Oxigraph `ASK {}` + 写探针（临时图写读删） | `E_GRAPH_UNAVAILABLE` | 69 |
| 6 | 存储探针：4KB（PG 层）与 11MB（FS 层）put→head→get→delete+sha256 | `E_STORAGE_*` | 69 / 74 |
| 7 | 能力交集（S0 requirements × manifests） | `E_CAP_MISSING` | 78 |
| 8 | `runtime.mode=learn` 但 reasoner/embedding 未装配 | **不退出**，记 `DEGRADED` | — |

失败输出统一格式（03 §16.1）：

```text
E_<DOMAIN>_<CODE> stage=<config|io|db|graph|storage|capability> key=<config_key> provider=<name>
  detail: <人话>
  hint: <下一步动作>
  log_id: <uuid>   exit: <code>
```

`docker compose up` 的启动顺序：`platform` 的 `depends_on` 用 `service_started`（Oxigraph 镜像为 distroless，无法在容器内执行 HTTP 探针），真实图探针由平台自检完成；PG 用 `pg_isready` healthcheck。

## 7. 数据库迁移（S0 唯一 DDL）

`platform/sql/V1__s0.sql`，只建当前切片需要的表（不预建全量）：

```sql
CREATE SCHEMA IF NOT EXISTS platform;

CREATE TABLE IF NOT EXISTS platform.schema_version (
  version      integer PRIMARY KEY,
  description  text NOT NULL,
  applied_at   timestamptz NOT NULL DEFAULT now()
);

-- 对象主表（07 §3.1）
CREATE TABLE IF NOT EXISTS platform.blob (
  hash         char(64) PRIMARY KEY,
  size         bigint NOT NULL CHECK (size >= 0),
  mime         text NOT NULL DEFAULT 'application/octet-stream',
  tier         text NOT NULL CHECK (tier IN ('pg','fs')),
  path         text,
  state        text NOT NULL CHECK (state IN ('staging','committed','missing','deleting')),
  metadata     jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at   timestamptz NOT NULL DEFAULT now(),
  deleted_at   timestamptz,
  refcount     integer NOT NULL DEFAULT 0 CHECK (refcount >= 0),
  last_verified_at timestamptz,
  verified_ok  boolean
);

CREATE TABLE IF NOT EXISTS platform.blob_ref (
  hash        char(64) NOT NULL REFERENCES platform.blob(hash) ON DELETE RESTRICT,
  owner_type  text NOT NULL,
  owner_id    text NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (hash, owner_type, owner_id)
);

CREATE TABLE IF NOT EXISTS platform.blob_bytea (
  hash    char(64) PRIMARY KEY REFERENCES platform.blob(hash) ON DELETE CASCADE,
  content bytea NOT NULL
);
```

不建：`blob_lo`、`storage_policy`、`blob_event`、`job`、`graph_pointer`、`ontology_*`（S1+ 各自迁移）。

## 8. Smoke 与失败路径（可执行）

`platform smoke`（容器内执行，direct adapter + HTTP health）：

| 用例 | 断言 |
|---|---|
| `healthz` | HTTP 200 |
| `readyz` | HTTP 200，`database/graph/storage` 三项 ok |
| `graph_roundtrip` | INSERT→ASK true→SELECT 1 行→DROP→ASK false |
| `pg_object_roundtrip` | 4KB put→head(tier=pg)→get→sha256 相等→delete→head=NotFound |
| `cas_roundtrip` | 11MB put→head(tier=fs)→get→sha256 相等→文件存在→delete→head=NotFound |
| `config_failfast` | 子进程 `platform check-config tests/bad_config*.yaml` 退出 78，输出含 `stage=config` 与错误码 |

失败路径（宿主机 `tests/acceptance.ps1`）：

1. 错误配置 → 78（`http.port` 越界；`graph.provider=fuseki` 未实现）。后者不受容器 ENV 覆盖影响，可稳定复现。
2. 依赖不可用：`docker compose stop oxigraph` → `platform probe --retry-seconds 0` 退出 69、`/readyz` 503；恢复后 smoke 全绿。
