# S2 文档入库 · 设计

> 切片：S2 · 版本：v0.1 · 日期：2026-11-04
> 上游：03 §3.4.7（解析链路 / D22 OCR 关闭语义）、04 §5.6（`DocumentParser` v1）、07 §3（对象分层）、10 §3（S2 定义）
> 原则：D18 只写胶水与 Web 层；解析调用现成库，切块是固定窗口（非算法研究）；不做 OCR、不做 Embedding、不做表格语义理解。

---

## 1. 目标与范围

### 1.1 目标

一份 PDF / Office（docx/pptx/xlsx）/ TXT / Markdown / HTML 从 HTTP 入口进入后：

1. 原件按大小路由到对象存储（≤10 MB → PG bytea，>10 MB → FS CAS）；
2. 解析出**页级文本**与 manifest；
3. 按固定窗口 + 重叠切块；
4. `document` / `document_page` / `document_chunk` 落 PG；
5. 同一内容重复上传 → 幂等，不产生重复行；
6. 扫描件（无文字层）→ `degraded=true` + `warn: NO_OCR_ENABLED`，不返回空文本冒充成功；
7. 坏文件 → `InvalidArgument`，**不落任何半成品**。

### 1.2 做什么

| # | 内容 |
|---|---|
| 1 | `POST /documents` 上传端点：流式写入临时文件、边写边算 sha256、大小上限保护 |
| 2 | `DocumentParser` 适配器：`pypdfium2`（PDF 文字层 + 扫描判定）、`pdfplumber`（PDF 表格）、`MarkItDown`（docx/pptx/xlsx/html）、纯文本读取 |
| 3 | 固定窗口切块（字符窗口 + 重叠，参数可配），保留页码与页内字符偏移 |
| 4 | `DocumentService` 入库编排：CAS → 解析 → 切块 → PG 事务落库 |
| 5 | 查询端点：文档详情、列表、分块列表、原件下载代理 |
| 6 | `V3__s2.sql` 迁移（只建本切片需要的表） |
| 7 | `platform smoke-s2` 验收套件 + `tests/bad_config_documents.yaml` |

### 1.3 明确不做

- OCR（`ocr.enabled=false`，D22；`parse(ocr=true)` → `Unsupported`）
- Tika 常驻 / Tika CLI fallback
- 表格**语义**理解（只把表格行列作为 manifest 记录，不把表格转成三元组）
- Embedding / 检索索引（S3）
- 抽取 / 实体消解（S4）
- 鉴权、指标、告警、链路追踪、任务队列、事件总线、多用户
- 删除/回收站/版本语义（S2 只做内容寻址幂等；物理 GC 不在本切片）
- 文档重解析作业（parser 升级后重跑留给后续切片）

## 2. 目录与代码组织

```
_impl/src/platform_core/
  documents.py            # DocumentService：上传编排 + 切块 + PG 落库 + 查询
  parsers.py              # DocumentParser 适配器（格式路由，调用第三方库）
  api.py                  # 增加 /documents 路由与 PortError → HTTP 映射
  assembly.py             # 装配 parser/documents，移除 DocumentParser 占位
  config.py               # DocumentsConfig / OcrConfig
  sql/V3__s2.sql          # 本切片 DDL
  smoke_s2.py             # 验收套件（含 PDF/DOCX/TXT 夹具生成）
_impl/tests/
  bad_config_documents.yaml  # 切块参数非法（期望 exit 78）
```

代码边界：

- `parsers.py` 只做“格式 → 引擎”路由、结果规整、错误映射；不含版面分析算法。
- `documents.py` 只做顺序、事务、幂等、切块（固定窗口）；切块是字符串窗口，不是语义分句。
- `api.py` 只做 HTTP 适配与错误码映射。

## 3. 接口与数据模型

### 3.1 `DocumentParser` v1（本切片实现）

```text
port DocumentParser v1
parse(ref: DocumentRef, opts?: ParseOptions) -> ParsedDocument
capabilities() -> {ocr:false, tables:true, pdf:true, office:true, text:true}

ParseOptions { ocr?:bool, tables?:bool, language?:string }
ParsedDocument {
  documentId, pages:[{number,text,charCount}], blocks:[{id,kind,page,text}],
  tables:[{id,page,rows,header?}], metadata, provider, warnings:[{code,message}],
  degraded: bool
}
```

- `parse(ocr=true)` → `PortError(Unsupported, E_DOC_OCR_UNSUPPORTED)`。
- `parseAsync/status` 不实现：`Unsupported`（S2 同步解析；04 §5.6 的 ASYNC 为可选能力）。
- `capabilities()` 如实上报 `ocr=false`。

### 3.2 `DocumentService`

```text
ingest_path(path, filename, mime_type?, metadata?) -> IngestResult
get(document_id, include_pages=false) -> DocumentView
list(limit, offset) -> {items,total}
chunks(document_id, limit, offset) -> {items,total}
source(document_id) -> (bytes, meta)        # 代理下载，presign=false
```

`IngestResult`：`documentId, status(parsed|degraded), deduplicated, ingested, pageCount, chunkCount, warnings, sha256, sizeBytes`。

### 3.3 数据模型（V3）

**`platform.document`**（一行 = 一份内容）

| 列 | 类型 | 说明 |
|---|---|---|
| `document_id` | `char(64)` PK | 规范 ID = 内容 sha256（内容寻址，天然幂等） |
| `sha256` | `char(64)` UNIQUE | 冗余校验列 |
| `bucket` / `object_key` | text | 原件在 `documents/<sha256>` |
| `filename` | text | 首次上传文件名（重传相同内容不覆盖） |
| `mime_type` | text | 由扩展名推导 |
| `size_bytes` | bigint | 原件大小 |
| `status` | text | `parsed` / `degraded` |
| `page_count` / `char_count` / `chunk_count` | int/bigint | 统计 |
| `parser` / `parser_version` | text | 解析器与版本 |
| `warnings` | jsonb | `[{code,message}]` |
| `manifest` | jsonb | pages 摘要 + tables + provider + options |
| `metadata` | jsonb | 调用方元数据（key 级，弥补 OQ-03） |
| `created_at` / `parsed_at` | timestamptz | |

**`platform.document_page`**：`(document_id, page_number)` PK；`text`、`char_count`。非 PDF 文档按 1 页处理（便于统一引用）。

**`platform.document_chunk`**：`chunk_id` PK = `"{document_id}:{seq:04d}"`；`document_id`、`seq`、`page_from/page_to`、`char_start/char_end`（相对页文本）、`text`、`token_estimate`、`created_at`；`UNIQUE(document_id, seq)`。

> 命名说明：路线图写 `documents`/`chunks`，本设计用单数 `document` / `document_chunk`，与 S1 `ontology_version` 的“领域表单数”风格一致；不改上游语义。

### 3.4 HTTP 路由

| 方法 | 路径 | 语义 |
|---|---|---|
| `POST` | `/documents` | multipart 上传；201 新建 / 200 幂等命中 |
| `GET` | `/documents` | `limit`/`offset`，返回 `items,total` |
| `GET` | `/documents/{id}` | 详情；`include=pages` 时带页文本 |
| `GET` | `/documents/{id}/chunks` | 分块分页 |
| `GET` | `/documents/{id}/source` | 流式代理下载原件 |

上传表单字段：`file`（必填）、`filename`（可选，覆盖表单文件名）、`metadata`（可选 JSON 字符串）。

### 3.5 入库顺序与幂等

```text
1. 流式读入 tmp/<uuid>.part，边算 sha256、边计数；超过 documents.max_upload_bytes → ResourceExhausted
2. 由扩展名推导 mime；不支持 → InvalidArgument
3. 先解析（此时不写任何业务表）；解析失败 → InvalidArgument，删除 tmp，不落半成品
4. 将原件写入 ObjectStore（bucket=documents, key=<sha256>）
5. 单事务插入 document + document_page + document_chunk
   - INSERT document ... ON CONFLICT (document_id) DO NOTHING
   - 无插入（并发/重复）→ 返回已存在记录 + `deduplicated=true` / `ingested=false`；不重复写 page/chunk
6. 提交后返回
```

- 幂等键：`document_id = sha256`，等价于路线图的 `document_id + sha256`。
- `status` 始终描述文档状态（`parsed|degraded`）；是否本次新建由 `deduplicated` / `ingested` 表示。
- 同内容不同文件名：返回首次记录的 `filename`，不覆盖（内容寻址语义）。
- 事务失败：删除本次新增的对象引用（`objects.delete`），避免半成品引用；若并发者已写入同 key，删除是幂等的且会移除共享引用——因此只在“document 行未存在”时清理。

### 3.6 解析行为矩阵

| 扩展名 | 引擎 | 结果 |
|---|---|---|
| `.pdf` | `pypdfium2` 文字层；`pdfplumber` 表格（`tables=true`） | 页文本；每页字符数 `< ocr.min_chars_per_page` 计入无文字页 |
| `.docx` | MarkItDown | Markdown 文本，按 1 页 |
| `.pptx` | MarkItDown | 幻灯片文本按 1 页（页码在 manifest 记录） |
| `.xlsx` | MarkItDown | 工作表文本按 1 页 |
| `.html/.htm` | MarkItDown | 文本按 1 页 |
| `.txt/.md/.csv` | 纯文本读取（UTF-8 / UTF-8-SIG / GB18030 依次尝试） | 按 1 页 |
| 其他 | — | `InvalidArgument E_DOC_FORMAT_UNSUPPORTED` |

OCR 关闭语义（D22）：

- PDF 所有页 `charCount < min_chars_per_page` → `warnings += NO_OCR_ENABLED`，`degraded=true`，`status=degraded`，chunk 可为 0；
- PDF 部分页无文字 → `warnings += PARTIAL_NO_TEXT_PAGES`，`degraded=true`，其余页正常切块；
- 非 PDF 解析结果为空 → `warnings += EMPTY_TEXT`，`degraded=true`；
- 以上均**不**返回“空文本 + 成功”。

### 3.7 切块

固定窗口（字符）：

```text
for page in pages:
  text = page.text.strip()
  pos = 0
  while pos < len(text):
      end = min(pos + chunk_max_chars, len(text))
      window = text[pos:end]
      trimmed = window.strip()
      if trimmed: emit(chunk(page, pos + offset_of_first_nonspace, ..., trimmed))
      if end == len(text): break
      pos = end - chunk_overlap_chars
```

- 不按标点/句法断句（那是语义算法）；只做固定窗口。
- `chunk_overlap_chars < chunk_max_chars` 在配置校验强制，非法 → 78。
- `token_estimate = max(1, ceil(len(text)/2))`：中文保守估算（约 2 字符/token），写入行内用于 S6 预算；口径记录在 OQ。

## 4. 配置项与默认值

```yaml
documents:
  bucket: documents                 # 对象桶名
  max_upload_bytes: 209715200       # 200 MB
  chunk_max_chars: 1200
  chunk_overlap_chars: 200
  min_chunk_chars: 1
  extract_tables: true              # PDF 表格（仅记录，不做语义）
  parser: local                     # 预留 provider 名；本切片仅 local

ocr:
  enabled: false                    # D22；true → 启动 fail-fast（本切片无 OCR 引擎）
  engine: paddleocr
  lang: chi_sim+en
  min_chars_per_page: 20
```

校验（fail-fast，exit 78）：

| 键 | 规则 | 错误码 |
|---|---|---|
| `documents.chunk_overlap_chars` | `< documents.chunk_max_chars` | `E_CONFIG_CHUNK_OVERLAP` |
| `documents.chunk_max_chars` | 100–20000 | Pydantic 范围 |
| `documents.max_upload_bytes` | 1 MB–2 GB | Pydantic 范围 |
| `ocr.enabled` | 必须 false | `E_OCR_UNSUPPORTED` |
| `documents.bucket` | 非空 | Pydantic |

## 5. 失败语义与错误码

| 场景 | 端口码 | HTTP | 平台错误码 |
|---|---|---|---|
| 文件为空 | `InvalidArgument` | 400 | `E_DOC_EMPTY` |
| 扩展名不支持 | `InvalidArgument` | 400 | `E_DOC_FORMAT_UNSUPPORTED` |
| PDF/docx 损坏、无法解析 | `InvalidArgument` | 400 | `E_DOC_PARSE_FAILED` |
| 纯文本编码无法识别 | `InvalidArgument` | 400 | `E_DOC_ENCODING` |
| 超过上传上限 | `ResourceExhausted` | 413 | `E_DOC_TOO_LARGE` |
| `ParseOptions.ocr=true` | `Unsupported` | 400 | `E_DOC_OCR_UNSUPPORTED` |
| 磁盘低于 `min_free_pct` | `ResourceExhausted` | 507 | `E_DISK_LOW` |
| PG 不可用 | `Unavailable` | 503 | `E_DB_UNAVAILABLE` |
| 文档不存在 | `NotFound` | 404 | `E_DOC_NOT_FOUND` |
| CAS 对象丢失/哈希不符 | `DataLoss` | 500 | `E_STORAGE_*` |
| 解析器库缺失 | 启动 `PlatformError` | — | `E_PARSER_MISSING`（exit 78） |

HTTP 映射集中在新加的 `PortError` 异常处理器；响应体：

```json
{"error":{"code":"InvalidArgument","providerCode":"E_DOC_PARSE_FAILED","message":"...","details":{}}}
```

失败不留痕：

- 解析在写对象与写表之前；解析失败 → 无 document/page/chunk 行、无 `documents/<sha>` 引用。
- 入库事务失败 → 回滚全部行；若本次首次插入 document 失败，删除对象引用。
- 不写 `status=failed` 的文档行（避免“半成品”被列表看到）。

## 9. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| Windows/WSL2 卷上的 `rename` | 临时文件与 CAS 均在 `/data` 下，同卷 | 启动自检已校验 `root`/`tmp` 同设备 |
| 中文 PDF 断行 | pypdfium2 按文字层输出，可能插入换行 | 切块前只做 CRLF→LF，不做激进重排；记录为已知限制 |
| MarkItDown 体积/依赖 | 首次构建下载较大 | 多阶段构建；只装所需 extras；版本 pin |
| 大文件内存 | `pypdfium2`/`pdfplumber` 需要文件路径 | 上传先落临时文件，按路径解析；CAS 大对象走 `commit_from_path` 避免全量读入 |
| 解析阻塞 | 同步 CPU 解析 | 端点用同步 `def`，由 FastAPI 线程池执行；单用户场景可接受 |
| 内容地址同名不同文 | 同内容不同文件名只能保留首个 | 语义明确（幂等）；文件名不是身份 |
| 页码引用 | 非 PDF 统一记为第 1 页 | S6 引用显示“文档/页”；后续可加 block 定位 |
