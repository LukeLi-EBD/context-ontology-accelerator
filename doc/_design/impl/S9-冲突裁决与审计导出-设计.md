# S9 冲突裁决与审计导出 · 设计

> 切片：S9 · 版本：v0.1 · 日期：2026-11-05
> 上游：S8（OQ-30 事实治理）、OQ-31（测试图隔离）、`_design/impl/S8-ABox撤回与事实治理-设计.md`
> 纪律：不新增依赖；不重构已通过部分；不做鉴权/指标。

## 1. 目标与边界

S8 让冲突“可见”，S9 让它“可处置”并让审计“可离线核对”。

- 冲突裁决只有人工三选一：`keep` / `keep_both` / `merge`。
- 不做自动打分、启发式选择、按时间取最新——没有可信规则时机器不替人决定事实。
- 审计导出为 NDJSON + Markdown；每条事件带 `id/prev_event/hash`，可独立校验。
- UI 只在审批队列页加“冲突裁决”分区，不新增页面。

## 2. 数据模型（`V8__s9.sql`）

`platform.fact_assertion` 追加：

| 字段 | 用途 |
|---|---|
| `accepted_conflict` | `keep both` 后为 `true`；冲突仍标 `conflict`，但视为已裁定 |
| `resolution` | `keep` / `accepted_conflict` / `merge` |
| `resolved_by` / `resolved_at` | 裁决人（当前固定 `operator`）与时间 |
| `merged_from` | `merge` 生成的新断言记录原断言 id 列表 |
| `superseded_by` | 被 `merge` 取代的原断言指向新断言（S8 已存在） |

`platform.fact_event` 追加 `prev_event`、`hash`，并把 `action` 约束扩为：
`asserted / retracted / restored / batch_retracted / conflict_kept / conflict_accepted / merged / merge_superseded`。

## 3. 裁决语义

### 3.1 `keep`

- 入参 `keep` 必须是当前 active 值之一。
- 保留值：`accepted_conflict=false`、`resolution=keep`，写 `conflict_kept`（payload `role=kept`）。
- 其余值：`state=retracted`，写 `conflict_kept`（payload `role=retired`、`previousState=active`、`kept`、`retired`）。
- 若某三元组已无 active 断言支撑，才从命名图删除。

### 3.2 `keep both`

- 该 `(s,p)` 所有 active 断言置 `accepted_conflict=true`、`resolution=accepted_conflict`，写 `conflict_accepted`。
- `GET /facts/conflicts` 默认只返回 `pending`；`includeAccepted=true` 可看全部。
- 查询与 `ContextResolver` 仍标 `conflict`，并附 `acceptedConflict=true`。

### 3.3 `merge`

- 必须显式给 `mergedObject`（IRI 或字面量）；**平台不自动选值**。
- 新建一条 active 断言：`source_kind=manual`、`merged_from=[原 id]`、`resolution=merge`，写 `merged`。
- 原断言：`state=retracted`、`superseded_by=新 id`、`resolution=merge`，写 `merge_superseded`（互链）。
- 被合并的原断言禁止 `restore`（`superseded_by` 非空即拒绝），避免把裁决结果又拉回冲突。

## 4. 审计链

- 事件写入时取上一条的 `hash`，按
  `sha256(prev_hash + "\n" + canonical_json(eventId,factId,action,actor,reason,batchId,payload))`
  计算；同一事务内写入 `prev_event` 与 `hash`。
- 迁移前已有事件由 `FactLedger.ensure_chain()` 按 `event_id` 顺序补链（幂等）。
- 校验只依赖导出文件本身：逐条重算 hash、核对 `prev_event` 是否等于上一条 id；任何字段篡改、
  删行、换序都会失败。
- 单写者假设：同一进程内串行写事件；多实例并发会分叉链，单机版本体不涉及（见 §8）。

## 5. 接口与 CLI

| 方法 | 路径 / 命令 | 说明 |
|---|---|---|
| `GET` | `/facts/conflicts?includeAccepted=` | 冲突对 + `facts[]`（来源/证据片段）+ `pending` |
| `POST` | `/facts/conflicts/resolve` | `{subject,predicate,action,keep?,mergedObject?,graph?,actor,reason}` |
| `GET` | `/facts/events/export?from=&to=&sourceDocumentId=` | 返回 `items/count/ndjson/markdown/chain` |
| CLI | `platform facts-export --out DIR [--from --to --source-document]` | 写 `events.ndjson` + `summary.md` |
| CLI | `platform facts-verify --file FILE` | 离线校验链，失败退出码 1 |

Markdown 摘要含事件总数、asserted/retracted/restored/裁决/合并计数、按来源分布、待裁冲突列表。
NDJSON 与 Markdown 均由 Python 字符串拼接，无模板引擎、无新增依赖。

## 6. UI

审批队列页新增“冲突裁决”分区：展示 `(s,p)`、每个值及其来源（文档/候选证据片段），
三个动作：每个值一个“保留此值”、一个“两者都保留”、一个“合并…”。
裁决后刷新冲突与事实列表；`keep both` 的条目默认不再出现在待办分区。
不新增页面、不引入前端框架。

## 7. 验收映射（`smoke-s9`）

| # | 要求 | 断言 |
|---|---|---|
| 1 | `keep A` → B retracted、context 不含 B、事件链完整 | `keep.retracted` + `keep.audit` + `keep.context` |
| 2 | `keep both` → 两值在、标 `accepted_conflict`、不再进待办 | `keepboth.active` + `keepboth.accepted` + `keepboth.not_pending` |
| 3 | `merge` → 新断言 active、原两条 retracted 且互链 | `merge.new` + `merge.linked` + `merge.context` |
| 4 | 裁决后重跑物化 → 不含被弃值推导 | `conflict.pre`（先证有）+ `keep.materialize`（后证无） |
| 5 | 导出条数与 `fact_event` 一致、`verify` 通过 | `export.count` + `export.verify` |
| 6 | 篡改一条事件后 `verify` 必须失败 | `export.tamper_detected`（内存篡改）+ acceptance 文件篡改 |

## 8. 已知边界

- 哈希链按 `event_id` 顺序；若未来多写入者并发，需要数据库层序列化或外部排序服务。
- `keep both` 的冲突仍参与物化推导（两个值都成立），直到人工 `merge`/`keep`。
- 导出包含 `source` 快照；断言行被测试清理后事件仍导出，`source` 可能为 `null`（审计不删）。
- `merge` 目标的正确性由操作者负责；平台只记录，不做语义校验（不做鉴权/打分）。
- `merge` 目前不可逆（`restore` 拒绝 `superseded_by`），记为 OQ-44。

## 9. 实施结果（2026-11-05）

- `platform smoke-s9`：**18/18**；六条验收对应断言全部通过，含内存篡改 `export.tamper_detected`。
- 全量 `tests/acceptance.ps1`：**36/36**；新增 `platform smoke-s9`、`facts-export count`、
  `facts-verify ok`、`facts-verify rejects tampering`，原 32 条保持。
- 导出实测：`count=129`、NDJSON 行数 `129`、`chain.ok=true`；acceptance 对文件做真实篡改后
  `facts-verify` 退出码 1（`expected!=0`）。
- 裁决实测：`keep` 后 `retired=1` 且 context 仅剩保留值；`keep_both` 两值 `acceptedConflict=true`
  且默认冲突队列不再包含；`merge` 新断言 `active`、原断言 `retracted` 且 `supersededBy` 互链。
- 物化实测：裁决前 `regionY a Region` 为真，`keep` 后重跑 inferred 该推导消失、保留值推导仍在。
- UI：`/ui/approvals.html` 含 `conflicts` / `conflicts-refresh`，`app.js` 含 `loadConflicts`（`ui.conflicts_panel`）；
  `keep both` 条目因默认只查 pending 而退出待办分区。
- schema `V8__s9.sql` 已应用，`schema_version=8`；未新增依赖。
