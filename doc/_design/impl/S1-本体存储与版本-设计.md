## 1. 目标

1. T-Box（Turtle/TriG 源文件）可导入、去重、落到版本目录。
2. 每个版本写入独立命名图，发布 = 切换 `graph_pointer`，历史版本仍可按版本读取（D20：默认只读最新）。
3. 回滚可用且不删除历史。
4. `ontology.init_mode=once|watch|off` 能让 `data/ontology/` 下的 bootstrap 文件在启动时自动就位。
5. 能力探测（GSP + SPARQL）产出一份**实测**矩阵，并回写 `capabilities()`；不把文档描述当事实。

## 2. 范围

**做**

- `OntologyRegistry` 子集：`import`（解析 + 去重 + 版本行）、`publish`、`rollback`、`get`、`listVersions`、`status`（含当前指针）。
- `GraphStore` 增加 `load`/`replaceGraph`/`countGraph`（rdflib 解析，Oxigraph 执行 `INSERT DATA`）。
- PG 迁移 V2：`ontology_version`、`graph_pointer`、`ontology_job`。
- CLI：`platform ontology import|publish|rollback|status|show`；`platform graph-capabilities`。
- 启动钩子：`serve` 时按 `ontology.init_mode` 执行一次或轮询 bootstrap 目录。

**明确不做**

- `propose/review/approve/supersede/diff/checkCompatibility/validate/deprecate`：S1 返回 `Unsupported`（`E_PORT_NOT_IMPLEMENTED`, details.slice=S4/S5），不是"以后再说"的空承诺。
- SHACL / OWL 推理 / 版本图叠加读取（D20）。
- 本体编辑 UI、审批 UI（S7 之前不做）。
- Fuseki 适配器（D25 只保留端口）。
- 自研 RDF 解析、图差分、图同构、规范哈希（RDFC-1.0）。解析用 rdflib；差异留给 SPARQL `MINUS`（S4/S5）。

## 3. Oxigraph 能力实测（2026-11-04，0.5.7，`platform graph-capabilities`）

命令：`docker compose exec -T platform platform graph-capabilities --json`
实测环境：`graph.provider=oxigraph-http`，endpoint `http://oxigraph:7878`，默认图初始为空。

### 3.1 GSP（`/store`）

| # | 检查 | 请求 | 实测 | 结论 |
|---|---|---|---|---|
| 1 | PUT 默认图 | `PUT /store?default` + `text/turtle` | 204 | 支持，整图替换 |
| 2 | GET 默认图 | `GET /store?default` + `Accept: text/turtle` | 200 `text/turtle` | 支持 |
| 3 | POST 默认图 | `POST /store?default` | 201 | 支持，合并语义 |
| 4 | DELETE 默认图 | `DELETE /store?default` | 204 | 支持 |
| 5 | PUT 命名图 | `PUT /store?graph=<iri>` | 201 | 支持 |
| 6 | GET 命名图 | `GET /store?graph=<iri>` | 200 `text/turtle` | 支持 |
| 7 | POST 命名图 | `POST /store?graph=<iri>` | 201 | 支持（合并） |
| 8 | DELETE 命名图 | `DELETE /store?graph=<iri>` | 204 | 支持 |
| 9 | 删除后读 | `GET /store?graph=<iri>` | 404 `The graph ... does not exists` | 平台映射为空图 |
| 10 | 内容协商 | `Accept: text/turtle / application/n-triples / application/ld+json` | 200，返回对应格式 | 生效 |
| 11 | 不支持的 Accept | `Accept: application/x-unknown` | 406 | 如实拒绝 |
| 12 | 非法 Turtle | `PUT` + `text/turtle`（坏内容） | 400 + 解析错误文本 | 失败体可读 |
| 13 | 路径式图标识 | `GET /store/<iri>` | 404 | **不支持**；命名图只能用 `?graph=` |
| 14 | 裸 `/store` | `GET /store` + `Accept: application/n-quads` | 200 | **裸 `/store` 是整个数据集**；用 `Accept: text/turtle` 读会 400（Turtle 不能表达命名图） |

**实测 `GSP_SUPPORT=full`**（默认图形与命名图各 `GET/PUT/POST/DELETE` 全通）。
**命名图标识方式：`?graph=`；默认图标识方式：`?default`。**

> 与 03 §5.2.1 的差异：文档只写 "GET/POST/PUT + `?graph=`/`?default`，DELETE 未文档化"。实测 DELETE 两个作用域都可用；裸 `/store` 是数据集而非默认图。已记入 `_impl/OPEN-QUESTIONS.md`（OQ-12）。

### 3.2 SPARQL 1.1

| # | 检查 | 实测 | 结论 |
|---|---|---|---|
| 1 | property path `/`（序列） | 200，返回 `o2` | 支持 |
| 2 | property path `p+`（传递闭包） | 200，3 条闭包边 | 支持 |
| 3 | property path `^`（反向） | 200，返回 `o1` | 支持 |
| 4 | `FROM <g>` 作为默认图 | 200，返回期望行 | 支持 |
| 5 | `FROM NAMED <g>` + `GRAPH ?g` | 200，返回 `g` | 支持 |
| 6 | `SERVICE` 联邦 | HTTP 200，但响应体是**损坏的 JSON**（错误文本嵌在 `bindings` 内） | **不可用**；平台护栏继续拦截 `SERVICE` |
| 7 | `INSERT DATA` | 204 | 支持 |
| 8 | `CLEAR GRAPH` | 204；随后 `ASK`=false | 支持 |
| 9 | `DROP GRAPH` | 204 | 支持 |

结论：D25 共同子集所需的 property path、`FROM`/`FROM NAMED`、命名图整体替换/清空、`INSERT/DELETE DATA`、`SELECT/CONSTRUCT` 均可用；`SERVICE` 超出共同子集且实测不可靠，继续由平台拒绝。

> 2026-11-05 复测（`--allow-destructive`，run id `73eb7d1de0`）结论不变：GSP `full`、D25 共同子集全过、`SERVICE` 仍不可用。见 S5 设计 §9.3。

## 4. 接口与数据模型

### 4.1 `OntologyRegistry`（S1 子集）

```text
importSource(sourcePath: string, semver: string, label?: string, format?: "turtle"|"trig") -> ImportResult
publish(versionId: string) -> PublishedVersion
rollback(toVersionId: string) -> PublishedVersion
get(versionId: string) -> OntologyVersion
listVersions() -> OntologyVersion[]
current() -> Pointer
status() -> { pointer, versions, init }
```

其余 04 §5.2 方法返回：

```text
PortError(code="Unsupported", provider_code="E_PORT_NOT_IMPLEMENTED",
          details={port:"OntologyRegistry", method:"...", slice:"S4"})
```

**不伪造审批状态**：S1 没有 `review/approve`，因此 `import` 直接产出 `draft`，`publish` 只做"内容落图 + 切指针"，不宣称走完审批。审批状态机属于 S4（抽取候选需要审批时）。

### 4.2 版本与指针

- `version_id`：`ont-<12 hex>`（随机，不承担语义）。
- `semver`：调用方提供，原样保存（不做排序/范围比较）。
- `content_hash`：**按 N-Triples 行排序后取 sha256**。用于"同内容重复导入"去重。仅对无空白节点（blank node）的本体稳定；含空白节点时可能每次不同（记为已知限制，见 §9）。
- 命名图：`urn:platform:graph:tbox:<version_id>`。
- 指针：`graph_pointer.name='tbox/current'`，`version_id` 指向当前生效版本。
- 回滚：**新建一个版本行**（新 `version_id`，`content_hash`/`graph_iri` 复用目标版本，`semver=<target>+rollback.<n>`，`status=published`，`rollback_of=<target>`），再把指针切到新行。这同时满足：
  - 03 §4「回滚=切读指针」：指针确实切换；
  - 04 §5.2「rollback 是发布一个指向旧内容的新版本，不删除历史」：历史行不被修改或删除。
  这是两份文档的合并解释，不是偏离；实现与验收都按此口径。

### 4.3 PG 表（V2，仅 S1 需要）

```sql
CREATE TABLE platform.ontology_version (
  version_id    text PRIMARY KEY,
  semver        text NOT NULL,
  status        text NOT NULL CHECK (status IN ('draft','published','superseded','deprecated','rejected')),
  content_hash  char(64) NOT NULL,
  triple_count  bigint NOT NULL CHECK (triple_count >= 0),
  source_format text NOT NULL CHECK (source_format IN ('turtle','trig')),
  source_key    text NOT NULL,
  graph_iri     text NOT NULL,
  rollback_of   text REFERENCES platform.ontology_version(version_id),
  label         text,
  created_at    timestamptz NOT NULL DEFAULT now(),
  published_at  timestamptz
);
CREATE INDEX ontology_version_hash_idx ON platform.ontology_version (content_hash);
CREATE INDEX ontology_version_status_idx ON platform.ontology_version (status);

CREATE TABLE platform.graph_pointer (
  name       text PRIMARY KEY,
  version_id text NOT NULL REFERENCES platform.ontology_version(version_id),
  updated_at timestamptz NOT NULL DEFAULT now(),
  updated_by text NOT NULL DEFAULT 'local'
);

CREATE TABLE platform.ontology_job (
  job_id     text PRIMARY KEY,
  kind       text NOT NULL,
  status     text NOT NULL CHECK (status IN ('running','done','failed','skipped')),
  detail     jsonb NOT NULL DEFAULT '{}'::jsonb,
  error      text,
  started_at timestamptz NOT NULL DEFAULT now(),
  finished_at timestamptz
);
```

源文件落 CAS：`bucket=ontology`，`key=sources/<content_hash>.<ttl|trig>`，走既有 `ObjectStore`（≤10MB 进 PG，超 10MB 进 FS），复用 S0 的分层与 sha256 校验。

### 4.4 发布顺序（跨库一致性）

1. 读 CAS 源文件 → 解析 → 生成 `INSERT DATA`（整图一次写入）。
2. 图侧：`CLEAR GRAPH <graph_iri>` → `INSERT DATA { GRAPH <graph_iri> {...} }` → `COUNT(*)` 校验等于 `triple_count`。
3. PG 侧事务（`pg_advisory_xact_lock('platform:ontology:publish')`）：
   - 旧指针版本置 `superseded`（若存在且不是本次版本）；
   - 本次版本置 `published`, `published_at=now()`；
   - upsert `graph_pointer('tbox/current')`。
4. 任一步失败：PG 不变（版本仍 draft，指针不动）；图里可能留下半成品，下次 `publish` 先 `CLEAR` 再写，天然收敛（03 §5.1 幂等重放）。

## 5. 配置项与默认值

```yaml
ontology:
  init_mode: watch                  # off | once | watch，默认 watch（03 §8.2）
  init_source: /data/ontology/bootstrap.ttl
  init_semver: 0.0.0                # bootstrap 落版本时使用的 semver
  watch_interval_seconds: 30        # ≥5
  max_source_bytes: 5242880         # 5MB；超过直接拒绝，避免单次 INSERT DATA 过大
```

- `once`：`serve` 启动自检通过后执行一次；`watch`：执行一次后起守护线程轮询（同一 `content_hash` 不重复发布）。
- `off`：不执行。
- 初始化失败不阻塞 `serve`（记录 `ontology_job.status=failed` + `/status` 可见）；因为 bootstrap 不在时系统仍应可用（S0 判据不受影响）。

## 6. 失败语义与错误码

| 场景 | 错误 | 退出码（CLI） |
|---|---|---|
| 源文件不存在 | `E_ONTOLOGY_SOURCE_MISSING` stage=ontology | 78 |
| 源文件超过 `max_source_bytes` | `E_ONTOLOGY_SOURCE_TOO_LARGE` | 78 |
| Turtle/TriG 解析失败 | `E_ONTOLOGY_PARSE`（附 rdflib 行号/列号） | 78 |
| `semver` 为空或格式非法 | `E_ONTOLOGY_BAD_SEMVER` | 78 |
| 版本不存在 | `E_ONTOLOGY_VERSION_NOT_FOUND`（PortError NotFound） | 78 |
| 回滚目标不存在 | 同上 | 78 |
| 图库不可用 | `Unavailable` / `E_GRAPH_UNAVAILABLE` | 69 |
| 图写入后计数不一致 | `DataLoss` / `E_ONTOLOGY_TRIPLE_MISMATCH` | 69 |
| CAS 内容 sha256 不符 | `DataLoss` / `E_STORAGE_HASH_MISMATCH` | 69 |
| 未实现的端口方法 | `Unsupported` / `E_PORT_NOT_IMPLEMENTED`（details.slice） | 78 |

CLI 统一 `platform` 退出码：配置/非法输入 78、依赖不可用 69、内部 70。

## 7. 验收用例（可执行）

全部在容器内执行：

```bash
docker compose exec -T platform platform ontology import \
  --file /app/tests/ontology/tbox_v1.ttl --semver 1.0.0
docker compose exec -T platform platform ontology publish --version <id>
docker compose exec -T platform platform ontology import \
  --file /app/tests/ontology/tbox_v2.ttl --semver 2.0.0
docker compose exec -T platform platform ontology publish --version <id>
docker compose exec -T platform platform ontology status
docker compose exec -T platform platform ontology show --version <v1-id>
docker compose exec -T platform platform smoke-s1
docker compose exec -T platform platform graph-capabilities --json
```

`platform smoke-s1` 覆盖：

1. 正常路径：v1 导入→发布（指针=v1、图计数正确）→v2 导入→发布（指针=v2、v1 图仍可读）。
2. 重复导入同内容：返回同一 `version_id`，不新增行（幂等）。
3. 失败路径 A：非法 TTL → `E_ONTOLOGY_PARSE`，版本数不变、指针不变。
4. 失败路径 B：图不可用（独立 adapter 指向 `127.0.0.1:1`）→ `Unavailable`，指针不变。
5. 回滚：`rollback --to <v1>` → 新版本行（内容哈希=v1）且指针=新版本；v1/v2 图仍可读。
6. 能力探测与 manifest 一致：`gsp_support` 实测值 = manifest `notes.gsp_support`。

## 9. 风险与已知限制

1. **空白节点哈希不稳定**：没有引入 RDFC-1.0（自研算法禁区）。含空白节点的本体重复导入可能生成新版本；用 `label`/`semver` 人工判别。
2. **单次 `INSERT DATA` 体积**：S1 限制源文件 ≤5MB；超过走"拆图"需要 skolemization（推迟到有真实大本体时再评估）。
3. **回滚行共享命名图**：回滚新版本复用目标版本 `graph_iri`；S1 不实现"删除单个版本图"，因此安全。未来若支持版本删除，需先复制图或改为内容寻址图。
4. **`watch` 轮询是进程内线程**：不做文件事件监听（避免引入 watchdog）；Windows 挂载卷的事件不可靠，轮询更稳。
5. **图与 PG 跨库无事务**：依赖"先写图、再提交指针 + 每次发布先清图"的幂等收敛；崩溃窗口内 `/status` 可能显示 draft 版本已落图但未发布（可重放）。
