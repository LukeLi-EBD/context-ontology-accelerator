# S10 可逆裁决与审计回放 · 设计

> 文档编号：S10 · 状态：已实施 · 日期：2026-11-05
> 上游：`S9-冲突裁决与审计导出-设计.md`、`S8-ABox撤回与事实治理-设计.md`、`_design/10-实施路线图.md`
> 原则：裁决能改状态，就必须能撤错；审计能导出，就必须能在空库重放出同一状态。

## 1. 目标与边界

### 做

- `merge` 可逆：`unmerge(mergeEventId)` 把新断言置 `retracted`、原两条恢复 `active`，审计追加 `unmerged` 事件。
- `keep` / `keep_both` 可逆：同一个 `undo_resolution` 入口，按当前 `resolution` 分派，追加 `resolution_undo`。
- 批量 `keep A`：按谓词/主体/来源筛选冲突组，先 `dry_run` 报受影响条数，再逐组执行并返回逐条结果。
- `facts-replay <events.ndjson>`：在新库上重放导出链，逐断言与 `assertions.ndjson` 快照比对；`--dry-run` 只校验不写库。
- 审批页冲突分区新增「撤销上次裁决」「按谓词批量」入口；执行前必须显示受影响条数，不加新页面。

### 不做

- 不做自动打分、不做自动批量决策：批量只执行人给定的 `keep=<值>` 规则。
- 不做鉴权/多用户；不引入新依赖（NDJSON/Markdown/重放全部用现有 psycopg + 标准库）。
- 不重构 S8/S9 已通过语义；`restore` 仍拒绝 `superseded_by`（只允许 `unmerge` 走反向事件）。

## 2. 数据模型：V9

`V9__s10.sql` 只扩展事件动作词表，不新增断言列：

```sql
CHECK (action IN (
  'asserted','retracted','restored','batch_retracted',
  'conflict_kept','conflict_accepted','merged','merge_superseded',
  'unmerged','resolution_undo'))
```

撤销所需的前值全部已在 V8 中：

| 字段 | 用途 |
|---|---|
| `resolution` | `keep` / `accepted_conflict` / `merge`，同一次裁决事务内 `resolved_at` 相同 |
| `resolved_by` / `resolved_at` | 谁、何时裁决；撤销后清空，回到裁决前 |
| `superseded_by` | merge 原断言指向新断言；unmerge 清空 |
| `merged_from` | 新断言的来源列表；unmerge 保留以便追溯 |
| `accepted_conflict` | keep_both 标记；undo 后清为 false |

`fact_event` 仍是 append-only：撤销追加新事件，不删任何旧事件。

## 3. 撤销语义

统一入口：

```python
undo_resolution(event_id=None, subject=None, predicate=None,
                actor="operator", reason=None, dry_run=False)
```

- `event_id`：取该事件所属断言，再按 `(subject, predicate)` 找**最新一次**裁决；若事件不属于最新裁决组 → `E_FACT_STALE_RESOLUTION`。
- 不给事件、只给 `(s,p)`：按 `resolution IS NOT NULL` 中最大 `resolved_at` 取裁决组。
- 无裁决 → `409 E_FACT_NO_RESOLUTION`。
- `dry_run=true` 只返回 `undoOf / restoredFactIds / retiredFactIds / affected`，不写库。

### 3.1 merge → unmerge

- 新断言：`state=retracted`、清 `resolution/resolved_by/resolved_at`，保留 `merged_from`。
- 原断言：`state=active`、清 `retracted_at/retract_reason/superseded_by/resolution`。
- 事件：新断言 `unmerged role=merged_fact`；原断言 `unmerged role=restored`，均带 `undoOfEventId`。
- 图：删新断言三元组（若无其他 active 同三元组），重新插入原断言三元组。
- API 另有 `POST /facts/conflicts/unmerge`，强制要求整数 `eventId`。

### 3.2 keep → undo

- 被弃值（`state=retracted AND resolution='keep'`）：恢复 `active`，清撤回/裁决字段，重新插入三元组。
- 保留值：清 `resolution/resolved_by/resolved_at`。
- 事件：每条 `resolution_undo`，`role=retired_restored` 或 `role=kept`。
- 撤销后该 `(s,p)` 重新进入待办冲突列表。

### 3.3 keep_both → undo

- 组内 `accepted_conflict=true` 全部清为 false，并清 `resolution/resolved_by/resolved_at`。
- 事件：`resolution_undo role=accepted`。
- 两个值保持 active，重新进入待办。

## 4. 批量裁决

`POST /facts/conflicts/batch`，`dryRun` **默认 true**（写入必须显式 `dryRun=false`）：

```json
{"predicate": "...", "subject": "...", "sourceDocumentId": "...",
 "keep": "...", "actor": "operator", "reason": "...", "dryRun": true}
```

- 至少给一个筛选条件；`keep` 必填。没有规则就不做任何事。
- 对每个**待办**冲突组：`keep` 值存在 → 执行 `resolve_conflict(keep)`；不存在 → `skipped`。
- 返回：`matched / kept / skipped / affectedFacts / results[]`，每条含 `status` 与原因。
- 事件带同一个 `batchId`（`resolve-<10hex>`），便于按批次审计。
- 默认 `dryRun=true` 的理由：批量会写多组状态，先预演是安全默认；UI 一定先调一次预演并展示条数。

## 5. 审计回放

`facts-export` 现在同时写出：

- `events.ndjson`：事件链；
- `summary.md`：人类可读摘要；
- `assertions.ndjson`：导出时刻的断言快照（只覆盖导出链涉及的事实）。

`facts-replay`：

1. 读 NDJSON，先 `verify_records`；链不通过 → 拒绝重放（退出 1）。
2. 按事件顺序在内存重建断言状态（`asserted/retracted/restored/conflict_*/merged/merge_superseded/unmerged/resolution_undo`）。
3. `--dry-run`：只做第 1–2 步并与快照比对，不建库。
4. 真重放：
   - 在配置的 PostgreSQL 上 `CREATE DATABASE platform_replay_<nonce>`；
   - 跑同一套 `V1..V9` 迁移；
   - 只从事件写入 `fact_event` 与重建后的 `fact_assertion`；
   - 读回逐条与 `assertions.ndjson` 比对；
   - 结束 `DROP DATABASE ... WITH (FORCE)`（`--keep-db` 可保留）。
5. 结果：`matched / mismatched / extra`。`ok` 要求快照内每条一致且无 missing；`extra` 是事件链里存在、但已被 `purge_test` 从当前库清掉的测试断言（见 OQ-45），如实列出。

不改图的理由：本次证明对象是「断言账本状态」，A-Box 只是 active 投影；重放范围限定在 PG，避免在空库里再造一套图服务。

## 7. UI

审批页「冲突裁决」分区，不新增页面：

- `撤销上次裁决`：提示输入 `subject` / `predicate` → 先 `dryRun` 拿到 `affected` → `confirm` 展示条数 → 执行。
- `按谓词批量`：提示 `predicate` + `keep` → 先 `dryRun` → `confirm` 展示 `matched/kept/skipped/affectedFacts` → 执行；完成后显示逐条跳过原因。
- 保留原有 `conflicts-refresh`、单值「保留此值」、「两者都保留」、「合并…」。

## 8. 六条验收映射

| 验收 | 实现证据 |
|---|---|
| merge → unmerge → 查询与 context 回到合并前 | `smoke-s10`：`unmerge.restore`（图三元组回到 P/Q，无 merged 值）+ `unmerge.context`（2 个值） |
| 再 undo 一次 keep → 被弃值回 active | `keep.undo`（state=active、resolution=null、context 两个值） |
| 两次操作后审计链仍 verify | `audit.chain`（actions 含 `unmerged`/`resolution_undo`，verify ok） |
| 批量 dry_run / 执行 / 逐条结果 | `batch.dry_run`（matched=4/kept=3/skipped=1，pending 不变）+ `batch.execute`（剩余 1 组）+ `batch.audit`（batchId 落事件） |
| 导出 → 空库重放 → 逐断言一致 | `replay.dry_run` 13/13 + `replay.empty_db` matched=13、mismatched=[] |
| 篡改导出事件 → 重放前拒绝 | `replay.tamper`（`audit chain verification failed; replay refused`） |

补充：`keepboth.resolve/undo` 覆盖 keep_both 可逆；`undo.no_target` 覆盖无裁决时 409；
`ui.undo_batch` 覆盖两个新入口；`cleanup.test_graph` 保证不留测试图。

## 10. 已知边界

- **OQ-45**：`purge_test` 清掉断言行但保留事件，重放会重建出 `extra` 条历史测试断言；`ok` 只对快照内断言做强一致，`extra` 如实报告。正式环境不用 `purge_test` 时 extra=0。
- 重放只重建 PG 账本，不重建 A-Box/inferred 图；图的 active 投影由既有 `materialize` 负责。
- `resolved_at` 依赖同事务 `now()` 相同来分组；若未来改成跨事务分步裁决，需要引入显式 `resolution_id`。
- 批量规则只做「值必须已存在」的 keep；不会为了规则去新增/改写断言。
- 撤销是**逐条最新裁决**，不做“撤到任意历史时刻”；需要时按事件链多次撤销。
- **OQ-46**：按时间窗/来源导出的子集无法离线自证（`prev_event` 指向被过滤掉的事件）；S10 重放只对全量导出成立。实测 `--from` 过滤导出 `verify` 报 hash mismatch，CLI 退出 1。
