## 6. 归档引发的真实回归（已修复，未放宽断言）

归档后第一次全量 acceptance：`passed=42 failed=1`，链路：

```
[FAIL] publish.v1: E_ONTOLOGY_STATUS version ont-009583f0b831 is deprecated; only a draft, approved or superseded version can be re-published
[FAIL] publish.v2: E_ONTOLOGY_STATUS version ont-96cd7c838835 is deprecated; ...
[FAIL] pointer.v2
[FAIL] platform smoke-s1 exit=1
```

根因：`import_source` 的去重查询 `WHERE content_hash=%s ORDER BY created_at LIMIT 1` **不区分状态**，把已归档的旧版本当成"同内容可复用"，返回 deprecated 版本；随后 `publish` 正确拒绝。这不是断言问题，而是归档后"重新导入同内容"的真实语义缺陷。

修复（`adapters/ontology_pg.py`）：去重只认**未作废**版本（`AND status <> 'deprecated'`）；已归档内容再次导入时新建 draft，而不是隐式复活归档版本。`publish` 的 `E_ONTOLOGY_STATUS` 守卫、smoke 断言均未改动。

修复后重建镜像并复验：`platform smoke-s1` → `S1 SMOKE 17/17`；全量 acceptance：

```
ACCEPTANCE passed=43 failed=0 skipped=0 degraded=0
```

## 11. 开放项

- `restore-deprecated` 只支持批次粒度；单条恢复需构造单条批次。
- `latest` 沿用既有语义 = `list_versions()` 升序首项（当前指向最早创建的非作废版本，即 1.1.0 draft）；当前生效版本应以 `pointer` 为准，本轮未改该语义。
- smoke 创建的版本行因 FK（`ontology_proposal` / `rollback_of`）无法物理删除，长期仍需归档（本轮已建立批次化流程）。
