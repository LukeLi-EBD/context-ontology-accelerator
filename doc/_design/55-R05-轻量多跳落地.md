## 2 与 53 的差异

| 编号 | 53 的写法 | 实际落地 | 原因 / 影响 |
| --- | --- | --- | --- |
| D-1 | `SimpleCanvas(cfg.canvas, graph, ontology, reasoning)` | 构造收**整个** `PlatformConfig`（内部取 `config.canvas` 与 `config.reasoning.abox_graphs`） | 可读图集合要与 `webui._graphs` 语义一致，ABox 列表在 `config.reasoning`；对外无影响 |
| D-2 | `path()` 用双向 BFS | 单向有界 BFS + 前驱回溯枚举最短路径 | 跳数 ≤3、上限 200 节点，双向收益为 0；前驱枚举天然保证同长多路径且无环。功能等价，代码面更小 |
| D-3 | “单查询 500ms 超时” | 每请求 500ms **预算**，每次图查询返回后立即校验，超预算抛 504，不返回半成品 | 图适配器未暴露 per-query timeout，HTTP 客户端超时是全局的；无法中断阻塞调用，故用预算校验。已知限制，D1-2 再评估 |
| D-4 | `paths[].edges` 示例为字符串 | 三元组字典 `{s,p,o,dir,source}` | 前端与测试直接可读；两实现都按此键集返回 |
| D-5 | 节点/边可带来源标注 | 只带 `source.graph`；`hasRef` 恒 `false` | adapter 无 `source_ref` 查询能力；不编造映射，等 D1-2/元数据端口接入后再填 |
| D-6 | simple 遍历谓词白名单 | 白名单 = 当前 T-Box 中 `owl:ObjectProperty/DatatypeProperty/AnnotationProperty/rdf:Property`；空则空态 `E_CANVAS_TBOX_EMPTY` | 与“谓词取 T-Box 白名单”一致；缓存按 T-Box 图 IRI 失效 |
| D-7 | 只遍历 IRI 节点 | 字面量客体不成节点、不入边 | 避免把属性值当画布节点；也是节点上限可控的前提 |
| D-8 | API 表未列 `maxPaths` / `graph` | 端点加可选 `maxPaths`（可下调）与 `graph`（越权即 403） | 落实“请求可下调”和“越权图 403”；缺省仍由配置决定 |
| D-9 | `emptyReason` 只列 `E_PATH_NOT_FOUND` | 追加 `E_CANVAS_TRUNCATED / TBOX_EMPTY / NO_GRAPH` | 空态必须“有原因”，不把截断说成没路径 |

## 3 错误码表

| HTTP | `error.code` | `providerCode` | 触发 | 提示文案（要点） |
| --- | --- | --- | --- | --- |
| 400 | `InvalidArgument` | `E_CANVAS_BAD_IRI` | `from/to/graph` 不是安全绝对 IRI | 该参数不是安全绝对 IRI |
| 400 | `InvalidArgument` | `E_CANVAS_HOPS_EXCEEDED` | `maxHops` 超出实现上限（simple=3，full=6） | 跳数超出 simple 范围 1..3 |
| 400 | `InvalidArgument` | `E_PROVIDER_NOT_IMPLEMENTED` | 装配到骨架实现（`canvas.provider=full`） | 该 provider 已认识但未装配（D1-2） |
| 403 | `PermissionDenied` | `E_CANVAS_GRAPH_FORBIDDEN` | 请求 `graph` 不在当前可读集合（T-Box+推断+ABox） | 请求图超出当前可读集合 |
| 504 | `DeadlineExceeded` | `E_CANVAS_TIMEOUT` | 单请求超出 `canvas.timeout_ms`（simple 硬上限 500ms） | 预算耗尽，不返回半成品 |
| 503 | `Unavailable` | `E_CANVAS_DISABLED` | `canvas.provider=off` | 画布接口不可用（其它端点不受影响） |
| 启动 | `E_PROVIDER_INVALID` | — | `canvas.provider` 不是已知值 | 已知值：off/simple/full |
| 启动 | `E_PROVIDER_NOT_IMPLEMENTED` | — | 已知值但未装配（`full`） | 改用 simple 或 off |
| 200 | — | `emptyReason=E_PATH_NOT_FOUND` | 跳数内无路径 | 结构化空态，非错误 |
| 200 | — | `emptyReason=E_CANVAS_TRUNCATED` | 先撞节点/边上限，仍未找到目标 | 结果被截断 |
| 200 | — | `emptyReason=E_CANVAS_TBOX_EMPTY` | T-Box 无可声明谓词 | 多跳图不可用 |
| 200 | — | `emptyReason=E_CANVAS_NO_GRAPH` | 三个命名图都不可读 | 无图可查 |

Q8 分码口径与其它 provider 一致：非法值 `E_PROVIDER_INVALID`、认识未装配 `E_PROVIDER_NOT_IMPLEMENTED`。

## 4 端点与查询形状

`GET /browse/path?from=&to=&maxHops=3&maxNodes=&maxEdges=&maxPaths=&includeTypes=&includeSource=&graph=`

- `to` 缺省 → 邻域模式（`subgraph`）；有 `to` → 路径模式（`path`）。
- 只读：不写图、不启任务；`layout` 固定 `{"mode":"none","nodes":[],"seed":null}`。
- 每层两条普通查询（出边/入边），一律 `VALUES ?g {…} GRAPH ?g { VALUES ?s/?o {…} ?s ?p ?o }`；**不生成** `GRAPH ?g { … UNION … }`（历史上导致 Oxigraph 挂起 504）。单测对每条查询断言无 `UNION`、有 `VALUES ?g` 与 `GRAPH ?g`。
- 上限先截断再查询（`LIMIT 剩余边预算+1`），一次请求预算 500ms。
