## 7 高级架构师整体结论（R2 更新版）

> 视角：需求 × 实现 × 本体原理三方对齐；判断开发路径与架构走向是否合理、项目是否走偏、如何改善。
> **本版相对上一版的修订**：把「验收脚本 `-k` 过滤 / skipped 容错」从现状问题改为**已修复**；把「多消费者版本漂移」从现象降级为**架构隐患**；把「两条出数路径默认值互不兼容」改为**共同强制显式参数**；新增「双栈分裂带来的可证明性缺口」。

### 7.1 三方对齐

| 维度 | 实际 | 判断 |
| --- | --- | --- |
| **需求** | `52` 收窄到本体治理 / 口径与指标 / 检索问答；`30` 与 `N-03~N-17` 明确放掉运维、CI、备份、多用户、鉴权、真实数据源。本质是**单机、合成数据、口径治理优先、可演示可审计** | 边界守得住，没有膨胀成多租户云化平台 |
| **实现** | S0–S14 + 17 条 O/M/R + B-03~B-06；127 端点、迁移到 V42、200+ 文档；8 小时内修掉 M-01、R-02 断链、O-05 门禁、验收脚本、QA 采集器多类问题 | 工程能力与响应速度**很强**；但横向铺得仍远快于纵向闭环 |
| **本体原理** | 价值不在端点数量，而在 **T-Box → A-Box → 推理 → 溯源** 是否闭合，以及**版本切换是否原子** | 这条链仍未闭合（§7.2），且现在多了「哪套栈才代表系统」的问题 |

### 7.2 语义内核断点（按 T2 实证更新）

1. **命名图缺一等公民注册表**（未改善，P-01 仍 FAIL）：推理器 / 看板 / 实体页 / 术语覆盖各写各的图名常量。O-01 给物理列做了绑定注册表，图命名空间没有等价物。
2. **定义层与实例层脱节**（部分改善）：M-01 从「默认恒空」变成「显式参数下 8 条可算」，`/output` 与 `/compute` 参数契约已对齐，`metric_observation` 两栈均有 37471 行。但 `fact_assertion` 恒 0、默认调用仍 400，端到端「不带非默认参数即出可引用数值」没打通。
3. **推理与 Context 语义层空转**（未改善）：S06 三项为空、R02 10 例仅 6 过、R01 ontology 层 4.17%、S05 `aboxGraphs` 只 main。检索能召回片段，本体没有真正参与答案生成与校验。
4. **版本原子性**（从「现象」降级为「隐患」）：T2 双栈内 `tbox/current`、tree、reasoning、terms graph 解析到**同一版本**，P-02 的「漂移」不成立；但各模块仍各写常量、无统一 Version Resolution Service，且指针由 `smoke-restore` 反复改写（23:51、05:37），切换不是事务。
5. **新增 · 可证明性断点**：验收在独立空库栈跑（422/422），业务数据在另一个旧代码栈；同一份结论若不标注「时间 + 栈 + 镜像 + git HEAD」就不可复现。连 QA 报告自身都曾有 15 条结论不可靠（已修），说明**可证明性必须覆盖证据链每一环，而不只是验收脚本**。

一句话：**建成了完整的「本体元数据治理平台」，还不是「能工作的本体系系统」；现在又多了一层「两套栈各自证明自己」的分裂。**

### 7.3 开发路径与架构走向

- **S0–S13 合理**：切片 + smoke 立起依赖可替换、可审计、可回放的骨架，留下了 PROV 哈希链、错误码体系、图分离这些真资产。
- **S14 之后偏移仍在**：17 条本轮特性里 14 条是只读台账 / 面板 / 清单 / 状态机，唯一触及「真算出数」的 M-01 本轮从 FAIL 抬到 PARTIAL，但**仍需要非默认参数**。合起来看，排期仍在绕开最难的一件事：让一条指标从定义走到真实数值，并让数值被本体约束与溯源链验证。
- **验收体系这 8 小时确实修好了**（`69` 号）：去掉 `-k`、`skipped>0` 即失败、日志入 `doc/evidence/`、栈隔离、锁占用即中止、全新库可全绿。这是真实且可核对的进步，上一版对这一点的批评已不成立。**但修好的是「跑多少、怎么判定、跑在哪」，不是「断言是否检验语义产出」**：422 条全绿在空库上证明的是结构与契约，语义层空转（§7.2-3）一条都没被这些用例挡住。
- **流程复杂度仍超过产品复杂度**：单机、合成数据、无并发用户的演示阶段，同时存在数据栈、验收栈、6 条并行 worktree、多个 QA 复评脚本（`_qa` / `_qa-v2` / `_evidence-audit`）。本轮实测后果是评估期间库被持续写入、指针被改、同一端口跨时间换镜像。**并行带来的漂移成本仍大于收益。**

### 7.4 整体结论：项目是否走偏

**方向没有走偏，层次走偏了；是局部走偏，而且可逆。本轮证据让这一点更清楚，而不是更模糊。**

- 没有跑去做多租户、云化、真实数据源、鉴权（明确列为不做），边界守住。
- 8 小时内修掉多类真实缺陷，说明**瓶颈不是工程能力，而是排期优先级**：能快速修默认值、断链、门禁、验收脚本，却一直没去打通那条纵向闭环。
- 「把口径治理做成了口径台账」仍是实质偏移：对外最有价值的一句话本应是「**我们能算出 X，并说清它为什么可信**」，现在仍只能说「**我们有 85 行清单，说明哪些理论上能算**」。
- **叙事与实现分离**仍是最该先问清的一件事：仓库外壳是 AWS COA（Agent 上下文层），实际交付是金融指标口径治理。两边都占着，后续所有架构决策都会失去判据。
- **可信度评级（R2）**：代码与数据 **B+**；验收脚本与证据入仓 **B**（较上轮 C 明显改善）；叙述口径与时间标注 **C+**（仍有多处未回写）；语义内核完整性 **C-**（未闭合）。「生产可用」按 `52` 号自己的口径仍是 **0 项**，本轮无证据推翻。

### 7.5 改善方案（按优先级，每阶段带可验收判据）

**阶段 0 · 统一坐标与止血（最先做，本轮新增）**
- 冻结并行写入，指定唯一可写环境；把 V41/V42 迁移应用到数据栈或明确删除，让 `schema_version` = 容器内迁移头；8080 与 8082 用同一镜像或明确各自职责。
- **强制所有验收 / QA 结论记录四元组：`采集时间 + 栈 + 镜像短 ID + git HEAD`**；报告模板内置该表头。
- 判据：同一时刻两栈的 `schema_version`、迁移头、容器内代码、`tbox/current` 四方一致；`doc/README` 索引篇数 = 实际篇数；`/status.slice` 回写真实值。

**阶段 1 · 打通一条纵向闭环（最高优先，其余都排在它后面）**
`定义 → 字段绑定 → 事实行 → compute 出非空数值 → metric_observation 落一行 → source_ref 可解析 → PROV 链可回溯 → SHACL 校验通过`，选 `FIN-BANK-008` 一条。
- 判据：**不带任何非默认参数**即可出数（或把显式 `dataSource` 写进默认配置并回写文档）；人为改一条事实后数值可复算且变化可解释；`/output` 与 `/compute` 结果一致或明确声明各自语义。
- 打通 1 条后再复制到 8 条、79 条。**不要用「再补 20 条定义」代替这一步。**

**阶段 2 · 修本体架构（把版本与图变成一等公民）**
- **Named Graph Registry**：所有图 IRI 从注册表读，禁止模块内常量；推理、看板、实体页、术语覆盖统一取图集合。
- **Version Resolution Service**：单一函数解析「当前版本 → T-Box 图 / shapes / 词表 / 推理输入 / A-Box 校验规则」，版本切换原子化，启动与发布 fail-fast 校验。
- 判据：切换版本后 terms coverage 仍 ≥95%、`/reasoning/status` 的 `aboxGraphs` 与真实 A-Box 一致、实体页与推理器解析到同一 `ontologyVersion`。

**阶段 3 · 验收从「结构存在」改为「语义产出」**
- 在独立栈注入**代表性数据**（不是空库），把语义断言加入验收：推理产物可查、SHACL 命中、溯源链端到端、指标数值可复算、Context 包本体层非空、golden set 10 例全过。
- 重新定义「可出数」为三条件同时满足：默认调用返回非空数值 + 存在观测行 + 存在可解析 `source_ref`。
- 保留 `69` 号已修的全量发现 / skipped 非零退出 / 证据入仓，并把同样的纪律推广到 QA 报告自身（采集器不得静默截断、不得写死结论）。

**阶段 4 · 流程减重**：单机演示阶段暂停多线并行与多套并行 QA 报告，回到单线闭环；等阶段 1–2 完成、产品定位明确后再决定是否恢复。

**阶段 5 · 产品定位二选一（决策项）**：A 承认是「指标口径治理 / 元数据平台」（建议，改文档与产品表达，代价小）；B 回到上游 COA 的「Agent 上下文层」（需做 MCP、真实数据源、鉴权、可观测，量级接近重做）。**建议选 A**，选定后再砍掉不匹配的外围端点。

### 7.6 给决策层的三句话

1. **不是造假，是没闭环，且证据链刚修好**：代码、数据、PROV 链都真实；上一轮 QA 报告自身有 15 条不可靠（已修），修完后绿灯 21→17，语义内核仍未闭合。
2. **这 8 小时证明团队能快速修工程缺陷，但排期一直绕开纵向闭环**：最急的仍是「冻结环境 + 统一栈与迁移头 + 打通一条指标从定义到可引用数值」，比再补台账有价值得多。
3. **所有结论必须带时间与栈**：现在两套栈、多个镜像、持续的并发写入，任何不带坐标的「全绿 / 可出数 / 已修复」都不可复现；先定产品定位（口径治理平台 vs Agent 上下文层），再谈架构演进。
