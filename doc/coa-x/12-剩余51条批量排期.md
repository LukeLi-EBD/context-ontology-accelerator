## 0. 排序规则与结论

排序按用户口径「消空白优先 + 依赖少优先」，落地成三步：

1. 先按「这一包能把某个功能组清零多少条」降序；
2. 同档看「需要新增/扩展的契约 op 数」升序；
3. 再看本地闭环成本（能不能只用现有本地栈验完）。

**spike 实测（2026-11-10，结论：本地可跑，F40/F41 归 P3，不退回「待本地化」）**

输入：本地命名空间 `ed70a15c-2d42-4dc9-8c61-33b2584f05fd` 的 T-Box（158 类 / 130 属性）+ A-Box（18,020 实例），合计 123,826 三元组；镜像 `agent-reasoner:0.1-s5`（ROBOT 1.9.6 + Jena，ELK 内置）：

- `POST /v1/rdfs`：2.5s，**510,761 行 / 176,939 条唯一三元组**（RIOT 输出含重复；管线只把与输入差集算作新增，即 53,366，与在线 job 的 `rdfs` 阶段一致）；
- `POST /v1/reason`（ELK，`--axiom-generators "SubClass ClassAssertion" -d true`）：10.9s，`consistent=true`，输出 212,648 条唯一三元组；
- 容器峰值内存 855MB；CLI 全流程（RDFS + ELK）约 1.0GB；无 license 依赖、未触发 600s 超时、exit 0。

**「212,648」不是新增推理，是输出总量**（含原样保留的输入）。按 N-Triples 行集合做差：

| 口径 | 数值 | 说明 |
|---|---:|---|
| 输入 | 123,826 | T-Box + A-Box 导出 |
| ELK 输出 | 212,648 | 含输入 + 推断；**不是新增** |
| added（集合差） | 89,174 | 输出比输入多出来的行 |
| dropped（集合差） | 352 | 输入有、输出没有的行 |
| **净增** | **88,822** | added − dropped；占输出 41.8% |
| 其中类断言净增 | 88,843 | `rdf:type` 18,507 → 107,350（间接类型） |
| 其中命名类 subClassOf 净增 | 9 | 220 → 229；T-Box 已接近传递闭包 |
| 其余净减 | −30 | 元数据/序列化差异 |

dropped 352 条已逐条归因，**没有一条是丢失的个体事实**：253 条涉及匿名节点（`rdf:first/rest` 列表、`hasKey`、限定基数结构）→ 重编号，对应结构同时出现在 added（`rdf:first/rest` 各 63、`onProperty` 18、`onClass` 17、`hasKey` 14）；85 条是 14 个主题域模块的 ontology 头（`owl:Ontology` 类型、`versionInfo`、`rdfs:label/comment`、`dc:source`、`dc:modified`），合并输出后不再保留；8 条是 `xsd:decimal "700"` → `xsd:integer "700"` 的字面量归一（RiskGrade 上下界）；4 条 `owl:inverseOf` 方向归一（输入 11 → 输出 10）；2 条是 ROBOT 默认 `-s true` 删除的冗余子类公理（`GLSubAccount/LedgerBatch ⊑ TimeBound`，已由 `⊑ FinancialItem ⊑ TimeBound` 蕴含）；`-s false` 复跑输出 212,956，这两条直接公理回来，进一步证实是冗余移除而非漏推。

**EL profile 内 vs 被忽略的公理**（`robot validate-profile --profile EL` 对 T-Box 报 960 行，去掉「未声明的 skos 注解/类引用」后，真正影响推理的是 52 处）：

| 类别 | 数量 | 明细 | 后果 |
|---|---:|---|---|
| 非 EL 公理类型 | 20 | `InverseObjectProperties` 10（featureOf/hasFeature、hasParty/partyOf、hasMetric/metricOf、hasProduct/productOf、hasLocator/locatorOf、hasAgreement/agreementOf、assetOf/hasAsset、channelOf/hasChannel、eventOf/hasEvent、campaignOf/hasCampaign）；`FunctionalObjectProperty` 10（hasLocator、metricOf、inScheme、identificationType、hasStatus、hasClassValue、metricType、locatorUsage、hasRole、eventType） | ELK 静默忽略：不推反向属性断言，也不做函数性/唯一性推理 |
| 非 EL 类表达式 | 18 | `ObjectExactCardinality` 15、`ObjectMinCardinality` 2、`ObjectAllValuesFrom` 1 | 基数与全称限制不参与分类 |
| 数据范围不在 profile | 12 | `xsd:date` 11、`xsd:boolean` 1 | 数据类型推理不参与（库中无相关个体断言） |
| 保留词误用 | 2 | `owl:qualifiedCardinality` 被当注解属性 | 忽略 |

另外 2 条 `owl:onDatatype` 三元组 OWLAPI 无法解析（匿名 datatype 定义），解析期即丢弃，已计入上面的 8 条字面量差异之外。**ELK 对这些忽略不打印 warning**（复跑确认日志无 ignor/unsupported 行），所以「有没有漏推」不能看日志、也不能看 `consistent=true`——只能看 profile 报告。`consistent=true` 只代表 EL 片段内无矛盾；`owl:disjointWith`/函数性/基数这类冲突不归 ELK，P3 接线时仍需 `/v1/consistency`（HermiT）作 DL 闸门。

命令：`docker run --rm -d -p 127.0.0.1:7879:7879 agent-reasoner:0.1-s5`，输入由 Oxigraph `CONSTRUCT` 导出后 POST。结论：P3 要补的是接线（起栈脚本拉起 7879 + `MaterializeReasoning` 路由 + 阶段结果落账），不是引擎能力。
