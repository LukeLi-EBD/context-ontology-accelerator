1. 先按「这一包能把某个功能组清零多少条」降序；
2. 同档看「需要新增/扩展的契约 op 数」升序；
3. 再看本地闭环成本（能不能只用现有本地栈验完）。

## 1. 每包细节

### P1 A 组概览/画布/路径（F04–F14，11 条）

- **覆盖**：F04–F07 路径四件（表单/结果表/边表/SVG）、F08–F12 画布五件（筛选/加载更多/清空/统计与截断/节点边表）、F13 manifest 能力探测、F14 概览交叉链接。
- **依赖**：`GetOntologyOverview`（已落）、`GetSystemHealth`（已落）、Oxigraph 命名图（27 个，已实测）。新 op 三个，均在 `ontology-graph.smithy`。
- **契约**：`FindGraphPath`（起点/终点/hops，返回 paths + edges，需定义无路径空态）、`GetCanvasSubgraph`（kinds/graph/limit + cursor + `truncated`）、`GetCanvasManifest`（capabilities + limits，只读）。
- **存储**：不改。全部读 Oxigraph。
- **闭环**：可以。5173 打开 `/` 与 `/ontology/canvas`，用现有命名图数据验；F04 需要两个真实 IRI（`urn:coa:entity:合同台账` 与 `https://w3id.org/fsldm/product#featureValue` 可用）。
- **风险**：`FindGraphPath` 在 121k 三元组上做 BFS 要限 hop 与节点预算，否则重演 `GraphTraverse` 的 180 秒超时；`GetCanvasSubgraph` 的分页序沿用 `ListStatements` 的「后端索引序」，**不加 ORDER BY**。
- **切片顺序**：`GetCanvasManifest`（0.3）→ `GetCanvasSubgraph`（2–2.5）→ 画布页 F08–F13 → `FindGraphPath`（1.5–2）→ 路径区 F04–F07 → F14 概览交叉链接（0.5）。

### P2 I 组健康看板（F126–F131，6 条）

- **存储**：不改；覆盖率从 Oxigraph 聚合，推理状态从现有 worker 状态读。
- **闭环**：覆盖率/diff/schema 三项可以；SHACL 一项取决于本地校验器，取证前不算可闭环。
