## 3. 数据来源与后端缺口（= 阶段 7 的接口清单）

`web-app` 只依赖 **`@coa/control-plane-client`**（83 个 HTTP 绑定），`@coa/data-layer-client` 在 `src/` 内没有被直接引用；Playground/MCP 走 AgentCore serve runtime，由 runtime-config 的 `serveRuntimeArn` / `mcpRuntimeArn` 驱动（本地未配置，页面显示 "not configured"）。

本机 8080 是 Platform Kernel 契约（`/documents`、`/search`、`/answer`、`/browse/*`、`/metrics*`、`/governance/*`、`/ontology/*`、`/prov/*`、`/healthz`），**与上游契约不重合**：实测 `GET /namespaces` → 404，上游用到的 `/system-health`、`/health` 也没有（本地只有 `/healthz`、`/health/dashboard`）。

按页面整理（表格里的 HTTP 路由目前在本机全部 404）：

| 页面 / 组件 | 前端 hook | 命令（control-plane） | 需要后端提供的路由 |
|---|---|---|---|
| NamespaceList / GetNamespace | `use-list-namespaces`、`use-namespace` | List/Get/Create/Update/Delete/UpdateNamespaceStatus | `GET/POST /namespaces`、`GET/PUT/DELETE/PATCH /namespaces/{id}`、`/namespaces/{id}/status` |
| SourceList / ConnectSource / SourceDetail / TableDetail | `use-list-sources`、`use-list-source-tables`、`use-source-*` | List/Create/Get/DeleteSource、GetSourceUploadUrls、Rescan、Approve/Reject、scan/jobs、tables/keys/metadata/review | `/namespaces/{id}/sources`（含 `upload-urls`、`/{sid}/scan`、`/approve|reject`、`/rescan`、`/tables/*`） |

## 4. 现有能力怎么挂上去（粗粒度）

| 本地能力（platform-core） | 挂载位置 | 做法要点 |
|---|---|---|
| 端口/依赖健康（`/healthz`、`/readyz`、`/health/dashboard`） | **System Health** 页（`/system-health`，路由 635） | 后端补 `GET /system-health`，把 compose 各容器探活 + 8080 自身的 `/readyz` 归一成上游字段（DynamoDB / S3 / Bedrock 之类换成 Postgres / Oxigraph / BGE-M3 / Reasoner） |
| 本地 provider 配置与切换（`/status` 目前只读展示） | **System Health 页内新增 "Providers" 卡片**（不新开路由，500 行内） | platform-core 新增 `GET/PUT /admin/providers`；前端用一个只读卡片 + 切换下拉，走新 hook |
| 指标校验（`/metrics/{id}/rules`、`/metrics-readiness`、`/validation/run`） | **MetricDetail**（`/namespaces/:id/metrics/:name`，路由 627）新增 "Rules / 校验" 选项卡 | 上游已有 `validate` 按钮（`/metrics/validate`），把我们的规则校验结果映射成同一响应形状即可，页面不新增 |
| 摄入审批（`/documents`、`/candidates/{id}/approve|reject`） | **Sources 组的 SourceDetail**（路由 591）加 "Documents / 审批" 选项卡；或按第 2 节新增 Ingest 页 | 建议先做选项卡（改动最小），等文档摄入成为主流程再升级为独立页 |
| 治理控制台（`/governance/*`、`/ontology/versions*`、`/prov/*`） | **新增 `/namespaces/:id/governance`**（24 条路由里没有） | 新页面 + 4 处注册（第 2 节路径）；治理动作（publish/rollback/proposal 审批）复用上游 proposal 的交互范式 |

原则：**在 8080 侧做契约适配层**，让 `/namespaces/...` 这层壳由后端提供，`web-app` 保持零改动；不要把本地路由硬塞进前端分支逻辑。

## 5. 不建议进 web-app 的能力

| 能力 | 理由 | 归宿 |
|---|---|---|
| 只读浏览（`/browse/facts|triples|sparql|canvas/full`）的原始视图 | 调试向，字段粒度是内核内部的（fact_id / chunk_id），没有产品语义 | 留在 `platform-core/web` |
| 本体画布 `browse/canvas/full` 大图 | 依赖后端 manifest，交互是排障用 | 留在 `platform-core/web` |
| 文档库上传/分块查看（`/ui/api/documents`） | 与上游 Sources → Ontology 的产品叙事冲突，且涉及本地文件路径 | 留在 `platform-core/web` |
| 检索与问答面板（`/ui/api/search`、`answer/panel`） | 上游已有 Playground 承载同一职责，重复 | 产品化走 Playground；调试面板留在 `platform-core/web` |
| 参数/来源追溯面板（`/prov/*`、`/entity/provenance`） | 深度排障 | 留在 `platform-core/web` |
| 指标报告导出（`/metrics/report/*`） | 验收交付物，非产品功能 | 留在 `platform-core/web` 或走离线脚本 |

## 6. 回退方式

删除 `packages/web-app/.dev-local/`、`packages/web-app/vite.dev-local.config.mjs`、`packages/web-app/public/runtime-config.json`，再删 `node_modules` 与 pnpm store 即可完全回到上游原状；被跟踪文件从未被修改过。
