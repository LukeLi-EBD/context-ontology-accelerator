# D 组缺口评审：指标三字段来源 / SPARQL·Links·Paths

日期：2026-11-10。范围：F48–F50 动手前的字段来源结论；SPARQL / Links / Paths 三页签的评审提纲。**本文不含实现**，契约未改。

## 1. `domain` / `evidenceBasis` / `publishable` 从哪来

### 现状（按代码与本地实测）

- COA 契约里 `MetricDefinition` 没有这三个字段；`ListMetrics` 目前只接受 `dataSourceId` / `sourceTable` 两个筛选入参。
- COA 指标服务的存储是导入后落到指标图的 OSI 模型；OSI 的 COA 扩展只承载 `data_source_id`、`source_table`、`unit`、`return_type`、`time_dimension`、`ontology_concepts`、`defined_by`、`effective_from`、`label`（`packages/metric-service/src/coa_metrics/osi_parser.py` 499–509），没有领域 / 依据 / 可发布。
- 这三个字段在**旧平台侧是存在的**：`packages/platform-core/src/platform_core/metrics.py` 读取的元数据列就是 `metric_id, name_zh, domain, evidence_basis, publishable, ...`。也就是说，**值在旧平台元数据里，坑在 COA 指标服务没有承载**。

### 三个候选

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）随 bundle 走** | OSI `custom_extensions` 增三个 key → 导入解析、指标图落库、导出对称 → 契约加字段 → 筛选用精确匹配；旧值按指标名一次性回填 | 改指标导入/导出 + 契约 + UI，一处迁移脚本 | 回填只跑一次，之后新导入的指标必须自带这三个 key，否则为空 |
| B 运行期读旧表 | `ListMetrics` 时 join 旧平台元数据表 | 前端和契约改动最小 | 服务耦合旧库；旧表退役即断；本地/新命名空间导入的指标没有值 |
| C 新建关系存储 | 为三个字段单开一张表/一次迁移 | 多一套存储与同步 | 只为 3 列建表，收益最低 |

推荐 **A**：这三个是业务元数据，跟着指标定义一起走语义才对；B 只能当过渡，C 不建议。

### A 的落地顺序（动手前先做第 0 步）

0. **先摸底**：把旧平台 `metric_definition` 里本命名空间指标的 `domain` / `evidence_basis` / `publishable` 取值分布 dump 出来。如果空值率极高，就只做字段搬运、不建筛选 UI——**字段来源没定就改契约，等于把一个洞挖成三个**。
1. OSI 扩展：解析、校验（类型/枚举不合法只让该指标失败，不拖垮整批）、导出对称。
2. 指标图：三个值随指标落库，`GetMetric` 返回。
3. 契约：`MetricDefinition` 加三字段；`ListMetrics` 加三个精确匹配入参（domain 的多值用重复参数，不发明通配语法）。
4. UI：`/metrics` 加 Domain / Evidence basis / Publishable 三个筛选与列；空值统一显示「—」，不填默认值。
5. 验收：三个筛选各命中一次、非命中返回空、URL 可回放（刷新后筛选仍在）。

### 明确不做

- 不自造枚举值，不把旧表没有的取值补出来。
- 不把 `publishable` 做成前端开关（它是元数据，不是 UI 状态）。
- 不在 F48–F50 里顺手改指标卡布局。

## 2. SPARQL / Links / Paths（单列评审，先不实现）

三个页签在契约里都没有对应 op：裸 SPARQL 无 `RunSparql`，Links 无 `FindLinks`，Paths 无 `FindGraphPath`。**评审通过前保持未落位**，不随只读浏览悄悄上线。

### 必答项

- **超时**：服务端 10 秒硬上限 + 客户端可 abort；结果行上限 5000，截断必须显式标记（不能悄悄只返回前 N 行）。
- **图范围**：只允许本命名空间的命名图；禁止 `FROM` / `FROM NAMED`、`SERVICE`、`LOAD`；默认图不参与，避免跨命名空间串读。
- **注入边界**：语句类型白名单 `SELECT` / `ASK`，拒绝多语句；只读端点（只读副本或只读 Oxigraph 视图）；拒绝 `CONSTRUCT` / `DESCRIBE` / `UPDATE` / `INSERT` / `DELETE` / `CLEAR` / `DROP`。
- **规模**：Links 深度 ≤3；Paths 只用最短路径且限制节点数；两者都要显式「无结果」空态，不返回空数组装成功。
- **配额**：每命名空间每分钟查询数上限，超限 429 并给可读原因。
- **审计**：记录查询文本哈希、耗时、行数、是否截断；不记录结果内容。

### 结论

三个 op 要一起评审、一起上，避免只放一半（例如只做 Links 不做 Paths）。评审通过前不动契约、不加页签。
