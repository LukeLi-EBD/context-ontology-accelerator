## 1. 起（约 1 分钟）

在仓库根目录 `D:\agentABC\coa` 打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1
```

看到最后一行 `结论：OK` 就是起来了。会同时打印地址、步骤耗时和收栈命令。

如果明确要固定在 9400 这套端口，加 `-BasePort 9400`。
不传就自动从 9300 往后找一块连续空闲端口，不会碰 8080/7878/8131/8210/8321/5331/5944/5432/8799。

### 第一次打开前，如果前端白屏

现象：浏览器里一片空白，控制台报下面两种之一——

- `Failed to resolve entry for package "@coa/control-plane-client"`
- `does not provide an export named 'ListIngestionRunsCommand'`

含义：前端依赖或它依赖的 SDK 是旧的。在仓库根目录执行，然后重启前端或重起栈：

```powershell
pnpm install --frozen-lockfile
pnpm --filter @coa/control-plane-client build
```

本次实测就是先修好这一处才能打开页面；修完首页、命名空间、画布、版本、文档页都正常。
若仍白屏，找维护人（前端还有一个 data-layer SDK 需要一并重建）。

## 3. 先看这五页

### 3.1 首页：http://127.0.0.1:9404/

看到的是「环境概览」，不是命名空间列表。这一页用来看整套栈活没活：组件状态、命名空间数量、流程说明。

### 3.2 命名空间：http://127.0.0.1:9404/namespaces

这才是命名空间列表。刚起栈时是 **0 条**（演示种子只灌了本体，没有建命名空间记录，见 §5）。

自己建一个，列表就有数据了：

1. 点 `Create namespace`
2. 名称填英文（如 `bank-demo`）。**中文会被过滤成空名，校验不过**
3. 描述可留空；语言只能选 `en` / `ja`，建完不能改
4. 确认弹窗点 `Confirm and create`

实测：建完回到列表，计数从 1 变 2，新命名空间状态 `Active`。

> 注意：自己新建的命名空间里是**空的**，看不到演示本体。演示本体挂在另一个预置命名空间下（见 §4、§5）。

### 3.3 本体画布：要直连这个地址

```
http://127.0.0.1:9404/namespaces/ed70a15c-2d42-4dc9-8c61-33b2584f05fd/ontology/canvas
```

这是唯一能看到「真实节点和边」的地方。实测首屏：

- `Loaded 17 nodes / 11 edges · last page 17/11 · truncated — more pages exist`

- 边示例：`InvestmentObjective → subClassOf → Classification`

页顶显示 `Namespace: —`（没有名字）是预期现象，不影响看图。

> 左侧菜单里的「Ontology」走的是 `/ontology/graph`，打开默认是**类列表**（表格里有 Basel I 风险权重等），不是画布。想看节点连线，用上面这个 canvas 地址。

## 4. 数据口径：这是演示种子，别和 8080 对账

**这套栈里的数据是演示种子数据。**

- 只有一份东西：FSLDM 三册合并本体（2675 个三元组 / 159 个类 / 129 个属性），起栈时灌进本机的 Oxigraph 和 PostgreSQL。
- 没有业务实例数据：没有文档、没有导入批次、没有事实库、没有指标观测值。所以「13个月继续率是多少」这类业务问题，这套栈本身也答不了。
- **8080 那套是另一份冻结归档**（只读）。两套的命名空间、版本、指标数字**本来就不同**，不要互相核对，也不要用这套栈的数去校验 8080 的数。
- 演示时能讲的只有：本体结构长什么样、类怎么分层、版本怎么管。不能讲业务数字。

## 6. 出问题怎么一键重来

### 先收掉

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1 -Stop
```

只停这套脚本自己起的进程和容器，**不动 8080 那套**，数据卷也保留。

### 再起一遍（最常见）

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1
```

### 还不对，就换一套端口起全新的

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1 -Stop
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1 -BasePort 9500
```

新端口块 = 新容器 = 新数据卷，等于全新环境，不会和旧的互相干扰。

### 彻底清掉演示数据（可选）

```powershell
docker rm -f coa-devup-pg-9400 coa-devup-oxi-9400
docker volume rm coa-devup-pg-data-9400 coa-devup-oxi-data-9400
```

### 起不来时先看日志

```
%TEMP%\coa-dev-up\logs-9400\ontology.err.log
%TEMP%\coa-dev-up\logs-9400\bridge.err.log
%TEMP%\coa-dev-up\logs-9400\web.log
```

自检哪一项红，就对应看哪个日志。脚本会直接写出是哪一环失败。
