## 1. 起（约 1 分钟）

在仓库根目录 `D:\agentABC\coa` 打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1
```

看到最后一行 `结论：OK` 就是起来了。会同时打印地址、每一步耗时和收栈命令。

固定在 9400 这套端口就加 `-BasePort 9400`；不传则自动从 9300 往后找一块连续空闲端口。
不会碰 8080/7878/8131/8210/8321/5331/5944/5432/8799。

起栈时会自动做三件和数据有关的事（不需要你动手）：

1. 灌入演示本体（FSLDM 三册）
2. 注册一个 `1.0.0` 的 draft 版本
3. 建好演示命名空间「FSLDM 演示」，让它在列表里可见、可点

### 第一次打开前，如果前端白屏

现象：一片空白，控制台报下面两种之一——

- `Failed to resolve entry for package "@coa/control-plane-client"`
- `does not provide an export named 'ListIngestionRunsCommand'`

含义：前端依赖或它依赖的 SDK 是旧的。在仓库根目录执行，然后重起前端或重起栈：

```powershell
pnpm install --frozen-lockfile
pnpm --filter @coa/control-plane-client build
```

本次实测就是先修好这一处才能打开页面；修完首页、命名空间、画布、版本、问答都正常。
若仍白屏，找维护人（前端还有一个 data-layer SDK 需要一并重建）。

## 3. 按这个顺序看（10 分钟内够用）

### 3.1 首页：http://127.0.0.1:9404/

显示「环境概览」，用来看整套栈活没活。命名空间列表不在这里。

### 3.2 命名空间：http://127.0.0.1:9404/namespaces

列表里应该有一条「FSLDM 演示」（语言 zh、状态 Active）。**点它进入。**

进去后左侧会出现这批入口：`Ontology`、`Induction`、`Explorer`、`画布`、`术语与别名`。

> 想再建一个自己的命名空间：点 `Create namespace` → 名称用英文（中文会被过滤成空名，校验不过）
> → 描述可留空 → 语言只能选 `en` / `ja`，建完不能改 → 确认弹窗点 `Confirm and create`。
> 注意：新建的命名空间里是空的，演示本体只在「FSLDM 演示」下。

### 3.3 画布（看节点和边）：点左侧 `画布`

首屏会看到：

- 统计文字：`Loaded 17 nodes / 11 edges · last page 17/11 · truncated — more pages exist`
- 节点标签示例：事件、机构、投资目标、特性取值
- 连线示例：`InvestmentObjective → subClassOf → Classification`、`Coverage → subClassOf → Feature`

想看类清单就去左侧 `Ontology`，那里是表格（能搜到 Basel I 风险权重等类名），不是画布。

### 3.4 版本：`Ontology` 页里的「版本」区块

1 条记录：`1.0.0` / `draft` / 2675 三元组 / versionId 以 `ont-` 开头。
「当前发布版本」是空的——种子里只注册了 draft，这是对的（见 §5）。

### 3.5 问答：http://127.0.0.1:9404/playground

1. 顶部 `Namespace switcher` 选「FSLDM 演示」（只有这一个时会自动选中）
2. 输入「13个月继续率是多少」，按回车或点 `Run query`
3. 约 10–30 秒出答案：

> 「13 个月继续率（有效保单件数）」（FIN-INS-021@v3.0）口径：numerator / denominator * 100；
> 观察期 period；证据 regulatory。事实层 degraded，不给出数值。

下面是 `4 sources cited`，展开是 4 条可读引用（本体版本 / 指标口径 / 指标公式 / 事实表）。

4. 再问一个域外问题，比如「今天北京天气怎么样」，会明确拒答：

> 证据不足，拒绝作答。缺口：本体未声明「今天北京天气」

不是报错，也不是编一个答案。

### 3.6 文档 / 导入批次

命名空间里左侧 `Documents`：页面正常，`Documents (0)`、`导入批次` 区块在，表格为空。
本栈没有导入过任何文档，0 条不是坏了。

## 4. 数据口径：这是演示种子，别和 8080 对账

**这套栈里的数据是演示种子数据。**

- 只有一份东西：FSLDM 三册合并本体（2675 个三元组 / 159 个类 / 129 个属性），起栈时灌进本机的 Oxigraph 和 PostgreSQL。
- 没有业务实例数据：没有文档、没有导入批次、没有事实行。所以问答只能给到「口径 + 引用」，不会给具体数值（页面会写明「事实层 degraded，不给出数值」）。
- **8080 那套是另一份冻结归档**（只读）。两套的命名空间、版本、指标数字本来就不同，不要互相核对，也不要用这套栈的数去校验 8080 的数。

## 5. 目前还不通的地方（照实记录）

| 现象 | 实测到的样子 | 影响 |
| --- | --- | --- |
| 首页没有命名空间列表 | 首页是「环境概览」 | 只是入口不同，列表在 `Namespaces` 页 |
| 版本不能发布 | 发布按钮会跑 SHACL/推理门禁，本机没有 shapes 目录、也没有推理服务，报 `E_SHACL_SHAPES_MISSING` / `E_REASONER_UNAVAILABLE` | 演示只到 draft；问答已按最新 draft 版本作答，不受影响 |
| 问答不给具体数值 | 答案写「事实层 degraded，不给出数值」 | 种子没有事实行；要数值得先导入业务数据 |
| 导入批次是空的 | `Import batches (0)` | 没有导入过文档 |
| 新建命名空间是空的 | 画布空、版本空 | 演示本体只挂在「FSLDM 演示」下 |

以上都不是操作错误，照手册做也一样。

## 6. 出问题怎么一键重来

### 先收掉

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1 -Stop
```

只停这套脚本自己起的进程和容器，**不动 8080 那套**，数据卷也保留。

### 再起一遍（最常见）

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1
```

### 还不对，就换一套端口起全新的

```powershell
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1 -Stop
powershell -ExecutionPolicy Bypass -File doc\coa-x\tools\dev-up.ps1 -BasePort 9500
```

新端口块 = 新容器 = 新数据卷，等于全新环境，不会和旧的互相干扰。

### 彻底清掉演示数据（可选）

```powershell
docker rm -f coa-devup-pg-9400 coa-devup-oxi-9400
docker volume rm coa-devup-pg-data-9400 coa-devup-oxi-data-9400
```

### 起不来时先看日志

```
%TEMP%\coa-dev-up\logs-9400\ontology.err.log
%TEMP%\coa-dev-up\logs-9400\bridge.err.log
%TEMP%\coa-dev-up\logs-9400\web.log
```

脚本自检哪一项红，就对应看哪个日志。
