## 1. 分类口径

- **壳（ACL）**：`platform_core` 已有可用实现，但方法名、同步/异步、参数形态、返回结构或错误类型与 COA 端口不一致。壳只做这四类转换。
- **新建实现**：`platform_core` 没有对应能力。即使形状全同也不算壳。

判据：能否在不写业务逻辑的前提下，用 60–320 行把平台对象变成端口对象。能 → 壳；不能 → 实现。

## 4. 不是壳（`platform_core` 无对应物）

按计划分阶段做，**不计入壳层工作量**：

| 端口 | 为什么不是壳 | 阶段 |
|---|---|---|
| `ContextManagerPort`、`SchemaProvider` | 平台有 FastAPI runtime，但语义是平台自己的契约，不是 COA 的 5 条操作；壳会把业务搬进来 | 2 |
| `ControlPlaneStore` | DynamoDB DAO 是具体实现，没有本地等价物；要新写 PG 实现并对齐分页/条件写/乐观锁 | 7 |
| `TaskQueuePort`、`WorkflowPort`、`EventBusPort`、`SchedulerPort`、`ComputePort`、`ServiceRegistryPort` | 平台完全没有 | 3–7 |
| `IdentityPort`、`ChangeFeedPort` | 平台完全没有 | 5–7 |
| `OcrPort` | 平台没有 OCR | 3 |
| `ConfigProvider(ssm)` | 平台只有 env；SSM 实现未接 | 7 |

## 5. 样板壳：`EnvSecretShell`

选它作为第一个真实可跑的样板，理由：签名完全一致，差异只落在错误类上，能把「壳到底在做什么」压到最小、最容易审。

### 5.1 转换内容

| 维度 | 平台 | COA 端口 | 壳的处理 |
|---|---|---|---|
| 方法名 | `get` | `get` | 直接转发 |
| 参数 | `name: str` | `name: str` | 直接转发 |
| 返回 | `str` | `str` | 直接转发 |
| 错误类型 | `platform_core.ports.PortError` | `coa_ports.PortError` | 按 `code` 映射到 7 个封闭码 |
| 错误码 | `"NotFound"` 等 PascalCase | `not_found` 等小写 | 查表转换；未知码 → `internal`，不猜 |
| 诊断信息 | 无约束 | `provider_code` 只用于日志 | 保留，且剔除 `details["value"]` |

### 5.2 真实调用单测

`packages/local-providers/tests/test_shell_secret_env.py`，7 例，不使用 mock 替身读配置：

1. 壳对象 `isinstance(..., coa_ports.SecretProvider)`；
2. `monkeypatch.setenv` 写真实进程环境变量 → 壳读到同一值；
3. 缺失密钥 → `not_found` + `provider_code=E_SECRET_NOT_FOUND` + `details.name`；
4. 平台错误里带 `value` → 壳的异常消息与 `details` 都不含该值；
5. 非预期异常（`RuntimeError`）→ `internal`，不伪装成 `not_found`；
6. 未登记的 `code`（`AccessDenied`）→ `internal`，不按字面猜；
7. 构造时传入无 `get` 的对象 → `TypeError`。

第 2 条是真实调用：走的是 `os.environ`，不是替身。
