## 0. 目标、范围、假设与事实核验

### 0.1 目标复述

把 COA 变成平台唯一入口：契约先行（页面每个动作有 operation 背书）、数据接管（8080 的文档/切片/图/本体/指标/PROV 迁入后退役）、本地一条命令可复现、功能对等可验收。当前阶段目标是 **P1 出口：后台自动解析与批量导入可重复、失败可恢复、有日志与结果校验，并把数据线迁到可对账**。

- 包含：契约与生成物、桥与路由、control-plane、ontology-engine、platform-core 数据层、web-app、数据接管、8080/8082 退役、质量门禁、并行治理。

## A. 复盘摘要（10 条）

1. **P0 出口已是事实，不是计划**：tag 可解析、五段基线全部祖先、quota 与导入线都在 tag 直系上；`merge-base --is-ancestor` 五条全真。P0 活跃任务清零。
2. **契约面第一次稳定**：154 op、4642 shapes、0 DANGER、`tsc`/`vite` 绿（登记），生成物与模型同 commit 定版，B0 的「29 个未提交文件」问题不再存在。
3. **导入线「后端可重复，前端读不出」**：3 次运行 3 条 `runId`、业务表新增 0、`import_run` 每次 +1；失败后 `--retry-failed` 可恢复且 `attempts` 递增。但真实桥端到端实测显示：接口 200、3 行全 indexed，页面表仍显示 0 行——契约把三个时间字段声明成 `Timestamp`，内核给的是 ISO 字符串，生成客户端抛 NaN 把整表吞掉；单条 run 详情四层全缺（契约/内核/桥/前端），请求 404。「接口通」不等于「页面可用」，这一条推翻「P1-01 只缺验收」的判断。
4. **数据线仍是最大缺口**：T1–T8 仍只有 T8 对上；1,908 版本 / 1,313 提案 / 10,134 事件未迁；V52 未发号；8080 仍是唯一完整实例。
5. **提案与事件仍在错位**：`install_ontology_jobs()` 有调用点但扫 `coa_local_items`，`#PROPOSAL#` 0 行，提案不会自动解析——「有调用点 ≠ 接线正确」。
6. **PROV 只有写入没有读出口**：三条 PROV 路由 404，T7 结构性不可执行，导致 T1–T8 永远不可能 8/8。
7. **查询可用性残余仍在**：`/graph/statements` 加 `ORDER BY` 后 100k 下 p95 4.8–10 秒、500k 422；≥3 个未绑定 `GRAPH` 的交叉积不响应取消，只靠看门狗；非图路由取消返回 500。
8. **鉴权从「全裸」到「有闸门」，但只在本地成立**：37 条生产映射已合、本地兜底 +5；tag 说明明确「未做外网暴露下的鉴权验证」，AR-01/02/03/05 仍阻塞上线。
9. **质量防线仍带既有红**：71 failed 合并前后不变（含模板体积 1.32MB、5 个 Windows 环境 suite），canvas 5 条在 tag 上就红；「全绿」目前靠豁免口径而不是事实。
10. **并行治理仍是隐性成本**：45 个 worktree、多条历史线未归档；两个运维动作（8082 停栈、8080 冻结）代码与清单就绪但等放行，放行前数据基线每天都在漂。

## 结论

**P1 出口的判据是「同一目录可重复、失败可恢复、结果可查、数据可对账」四件事同时有机器证据**：3 次运行 3 条 `runId` 且第 2/3 次新增 0、`--retry-failed` 后 `attempts` 递增且 `failure_code` 清零；**页面能看见这些 run（列表 ≥1 行且 total/indexed 与库内一致，单条可点入看 counters/items/attempts）**；1,908/1,313/10,134 在克隆库逐行哈希零差异、T1–T8 每行有数；8080 冻结上线并连续 14 天差异 0。当前差 **15.0 人日的 P1 工作 + 14 天日历**，其中 S1（迁移）5.5、S2（冻结到停用）3.0、前置 4.0、导入可用 2.5（契约时间格式 0.5 + 详情全链 1.0 + 页面验收 0.5 + CI 固化 0.5）。

**与 30 号相比的翻转**：F17/F18 由「不可用」翻为「路由已合」，但真实桥端到端又把页面判回**不通过**（契约时间字段 `Timestamp` vs ISO 字符串 → NaN 吞表；详情四层全缺），因此新增 P1-13/P1-14，P1-01 的判据从「接口 200」改为「页面有行且数与库一致」；导入线由「4 个缺陷 + 1 个缺失路由」翻为「后端已闭环、前端读不出，证据待 CI 固化」；P1 工时由 18.0 降到 15.0（先降后因两笔新任务回升）；迁移号由「V51 待发」翻为「51 已落地、两库实测 51，下一个是 V52」；P0 由「形式出口但非全绿」翻为「活跃清零，尾巴 3 项 2.5 人日」。
