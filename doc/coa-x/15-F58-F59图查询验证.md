# 15 F58 / F59 图查询验证

> 范围：只读验证 Oxigraph 能否直接算出 F58（术语锚点类计数）与 F59（术语别名表 7 列）。
> 不改契约、不改 schema、不碰 8080/8082、不碰主目录。
> 数据：命名空间 `ed70a15c-2d42-4dc9-8c61-33b2584f05fd` 下真实 FSDM codes T-Box，未新增、未修改任何三元组。

## 0. 结论（先看这个）

1. **F58 能只靠图查询实现。** 生产口径（`term:TermEntry` 锚点）当前返回 0；把「锚点」定义为类挂 `skos:altLabel`，图查询直接得到 **146 个锚点类**，耗时 **2.998 ms**。不需要落表。
2. **F59 不能只靠图查询交 7 列。** 图里只能拿到 7 列中的 **2 列**（`classLabel`、`label`）；`status`、`confidence`、`guardRegex`、`canonicalFor`、`suppressedSurface` 这 5 列在真实 T-Box 里没有任何对应三元组。生产口径查询可跑通，结果 **0 行**。
3. **不是「没数据」。** T-Box 有 SKOS 概念（95 个）和别名（146 条），只是没有 `term:` 层。所以 F58/F59 生产口径属于「查询可跑通、结果为空」，不是「图里没东西」。
4. **F59 若要 7 列非空，只有两条路：** 补 T-Box 的 `term:` 三元组，或把术语治理字段落表。这是**数据形态问题，不是图查询能力问题**——查询本身毫秒级。
5. **不要造数据凑数。** 本验证没有写入任何示例三元组；下面第 5 节给的是「需要什么形态」的说明，不是数据集。

## 3. F58 术语锚点类计数

### 3.1 生产口径（`term:TermEntry` 锚点）

```sparql
SELECT (COUNT(DISTINCT ?c) AS ?anchorClasses)
       (COUNT(DISTINCT ?e) AS ?altLabels)
       (COUNT(DISTINCT ?ev) AS ?evidenced)
       (COUNT(DISTINCT ?inf) AS ?inferred)
FROM <https://coa.local/graph/ed70a15c-2d42-4dc9-8c61-33b2584f05fd/https%3A%2F%2Fw3id.org%2Ffsldm%2Fcodes>
WHERE {
  ?e a <https://w3id.org/fsldm/terms#TermEntry> ;
     <https://w3id.org/fsldm/terms#forClass> ?c ;
     <https://w3id.org/fsldm/terms#label> ?label .
  OPTIONAL { ?e <https://w3id.org/fsldm/terms#status> ?ev . FILTER(STRENDS(STR(?ev), 'evidenced')) }
  OPTIONAL { ?e <https://w3id.org/fsldm/terms#status> ?inf . FILTER(STRENDS(STR(?inf), 'inferred')) }
}
```

真实结果：

| anchorClasses | altLabels | evidenced | inferred | 耗时 |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 0.002480 s |

### 3.2 图原生口径（类挂 `skos:altLabel`）

### 3.3 判断

## 4. F59 术语别名表 7 列

### 4.1 生产口径 7 列

```sparql
SELECT ?e ?c ?classLabel ?label ?status ?confidence ?guard ?canonical ?suppressed
FROM <https://coa.local/graph/ed70a15c-2d42-4dc9-8c61-33b2584f05fd/https%3A%2F%2Fw3id.org%2Ffsldm%2Fcodes>
WHERE {
  ?e a <https://w3id.org/fsldm/terms#TermEntry> ;
     <https://w3id.org/fsldm/terms#forClass> ?c ;
     <https://w3id.org/fsldm/terms#label> ?label .
  OPTIONAL { ?c <http://www.w3.org/2004/02/skos/core#prefLabel> ?classLabel }
  OPTIONAL { ?e <https://w3id.org/fsldm/terms#status> ?status }
  OPTIONAL { ?e <https://w3id.org/fsldm/terms#confidence> ?confidence }
  OPTIONAL { ?e <https://w3id.org/fsldm/terms#guardRegex> ?guard }
  OPTIONAL { ?c <https://w3id.org/fsldm/terms#canonicalFor> ?canonical }
  OPTIONAL { ?c <https://w3id.org/fsldm/terms#suppressedSurface> ?suppressed }
}
LIMIT 10
```

真实结果：**0 行**，耗时 **0.003060 s**。

### 4.2 图里能取到的列（2 列）

```sparql
SELECT ?classIRI ?classLabel (COUNT(?alias) AS ?n)
       (GROUP_CONCAT(DISTINCT ?alias; separator=' | ') AS ?aliases)
FROM <https://coa.local/graph/ed70a15c-2d42-4dc9-8c61-33b2584f05fd/https%3A%2F%2Fw3id.org%2Ffsldm%2Fcodes>
WHERE {
  ?classIRI <http://www.w3.org/2004/02/skos/core#altLabel> ?alias .
  OPTIONAL { ?classIRI <http://www.w3.org/2000/01/rdf-schema#label> ?classLabel }
}
GROUP BY ?classIRI ?classLabel
ORDER BY ?classIRI
LIMIT 10
```

真实结果（耗时 0.006053 s）：

| classLabel | label（别名） | 类 IRI |
|---|---|---|
| 账户 | ACCOUNT | `agreement#Account` |
| 账户特性 | ACCOUNT FEATURE | `agreement#AccountFeature` |
| 协议资产角色 | AGREEMENT ASSET | `agreement#AgreementAssetRole` |
| 协议分类 | AGREEMENT CLASS VALUE | `agreement#AgreementClassification` |
| 协议组 | ACCOUNT GROUP | `agreement#AgreementGroup` |
| 协议标识 | AGREEMENT IDENTIFICATION | `agreement#AgreementIdentification` |
| 协议当事人角色 | AGREEMENT PARTY | `agreement#AgreementPartyRole` |
| 协议产品适用关系 | ACCOUNT PRODUCT HISTORY | `agreement#AgreementProductAssignment` |
| 协议之间的关系 | AGREEMENT RELATED | `agreement#AgreementRelation` |
| 协议对账单 | AGREEMENT STATEMENT | `agreement#AgreementStatement` |

7 列的覆盖情况：

| 列 | 图里有没有 | 来源 |
|---|---|---|
| classLabel | 有 | `rdfs:label@zh`（类），或概念 `skos:prefLabel` |
| label | 有 | `skos:altLabel` |
| status | 无 | 需要 `term:status` |
| confidence | 无 | 需要 `term:confidence` |
| guardRegex | 无 | 需要 `term:guardRegex` |
| canonicalFor | 无 | 需要类侧 `term:canonicalFor` |
| suppressedSurface | 无 | 需要类侧 `term:suppressedSurface` |

### 4.3 判断

**不能只靠图查询交 7 列。** 2/7 有数据，5/7 没有对应三元组。

这不是性能问题：同规模查询 3–6 ms。这是**语义缺失**——`status`、`confidence` 是术语治理档位，`guardRegex` 是行级正则闸门，`canonicalFor`、`suppressedSurface` 是类级配置，标准 SKOS 词表里没有这些概念，必须由 `term:` 词表或关系表承载。

补法二选一（不属于本验证的施工范围）：

- **A. 补 T-Box**：让术语批次导入时写入 `term:` 三元组，图查询即可直接交 7 列，不需要新表。
- **B. 落表**：把术语治理字段放进 PG，`ListTerms` 做图 + 表拼接。需要新表、新写路径、幂等键。

## 5. 要验「非空 7 列」需要什么数据形态

下面只是**形态说明**，不是数据集，未写入任何图。

```turtle
# 行级：一条术语条目
<https://w3id.org/fsldm/terms#entry-account-01>
    a term:TermEntry ;
    term:forClass <https://w3id.org/fsldm/agreement#Account> ;
    term:label "ACCOUNT" ;
    term:status term:evidenced ;
    term:confidence term:high ;
    term:guardRegex "^ACCOUNT$" .

# 类级：锚点类的治理配置
<https://w3id.org/fsldm/agreement#Account>
    term:canonicalFor <https://w3id.org/fsldm/terms#entry-account-01> ;
    term:suppressedSurface "ACC" .
```

最小验收集：

- 至少 1 个 `term:TermEntry`，带 `forClass` + `label`（F58 计数、F59 行）。
- 至少 1 条 `term:status`（`evidenced` / `inferred`），用于档位列与计数。
- 至少 1 条 `term:confidence`、`term:guardRegex`，用于 4、5 列。
- 至少 1 条类侧 `term:canonicalFor`、`term:suppressedSurface`，用于 6、7 列。
- 带一条非法 `guardRegex` 的负样本，验证导入闸门会拒绝（`E_TERM_GUARD_INVALID`）。

## 6. 操作注意事项（实测踩到）

1. **Oxigraph 流式序列化会被非法端口 IRI 打断。** 投影宽泛 `?class` 时出现过空响应（curl exit 52），服务日志：
   `Internal server error while streaming results: The port 9 is not allowed for HTTP(S) because it is dedicated to an other use`
   规避：先只投影字面量或 `COUNT`，确认结果形态后再逐步加列。本次所有计数证据均不受影响。
2. **PowerShell `Invoke-RestMethod` 会把 JSON 按 latin1 解码。** 中文标签显示成 `è´¦æ·`，数据本身没坏。
   规避：改用 `curl.exe` 或按 UTF-8 读原始字节。文档里的中文样本均经 `curl.exe` 复核。
