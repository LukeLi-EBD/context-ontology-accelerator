## 1. 目标与边界

### 1.1 coa-x 是什么

- 在 COA 现有代码上二开，不新起并列系统。
- 把依赖 AWS 的组件换成本地实现：Oxigraph/Fuseki、pgvector、PostgreSQL、BGE-M3、本地 OpenAI 兼容 LLM。
- 整合 platform-core 已有能力，用端口 + 组合根收口，而不是在各服务里散落 `if provider == ...`。
- coa-gateway 只作载体/实验台，不是交付物；网关不聚合、不持有领域状态。

### 1.2 明确不做什么

| 不做 | 原因 |
|---|---|
| 不重写 COA 业务逻辑 | 只换依赖实现，保留既有行为 |
| 不重造 platform-core 已有组件 | 能复用就复用，端口只做薄壳 |
| 不做生产切换、IaC、多租户鉴权 | 本阶段是本机可运行，不是上线 |
| 不承诺未验证组合 | 没真跑过的 provider 不写成「可用」 |
| 不在网关里做聚合/编排 | 避免长出新单体 |
| 不做性能优化 | 当前只记录延迟，不调参 |

### 1.3 硬规则：禁止静默兜底

这条是硬规则，不是风格建议。`or "sum"`（D14）与 `except Exception` 吞异常是同一类错误：**缺东西时给一个看起来合理的值，把问题埋掉**。

- **缺字段、缺配置、缺依赖时，必须显式失败，并说明缺什么。** 错误信息要能直接回答「缺哪个键、在哪个文件、去哪补」。
- **禁止默认值兜底**（`x or "sum"`、`x or {}`、`x if x else 默认`）；**禁止空实现顶替**（返回空列表/空对象当作成功）；**禁止把异常降级成 warning 后继续跑**。
- **唯一例外**：降级必须同时满足三条——打日志、可观测、在响应里体现。参照 `lexical_retriever_unavailable`：调用方看得到「这条路径降级了」，而不是拿到一个看起来正常的空结果。悄悄降级一律算缺陷。
- 反向的正例也照此判：本轮 `fact_ledger_unavailable`（审批时账本未安装直接 503，不写单边）、`E_BUNDLE_METRIC_DEF_INCOMPLETE`（bundle 缺列直接拒收，不默认 `sum`）都是这条规则要求的形状。

### 7.1 M3b 前置条件：旧指标归到哪个命名空间，必须先定

这不是数据缺口，是**模型差异**。旧平台 `platform.metric_definition`（85 行，`domain` / `evidence_basis` / `publishable` 三列 `NOT NULL`、空值 0）**没有命名空间列**：旧平台按单租户建模，指标挂在一张全局注册表里；COA 是多命名空间，指标 URI、命名图、`GetMetric` 路由都按 `namespaceId` 隔离。差的不止是一列，是归属模型。

后果：把旧表 85 行直接搬进 COA，每一行都没有目标命名空间——接管结果要么是 85 条悬空指标，要么被迫全塞进某一个命名空间（等于替业务做了一次没人授权的归属裁决）。两种情况都不能算接管完成。

因此升成 **M3b 前置条件（先于 T3/T4 数据接管）**：接管前必须先定「旧指标归到哪个命名空间」的映射规则，并回答三件事：

1. **归属键用什么**：旧指标的业务域（`domain`：bank 38 / customer 13 / insurance 34）、来源库表，还是人工清单？现有证据只有 `domain`，而 `domain` 不等于命名空间。
2. **能否一对多**：同一个旧指标是否可以挂到多个命名空间？COA 里同名指标在不同命名空间是不同实体，必须明确是复制还是只取其一。
3. **与 COA 已有指标冲突怎么办**：例如 `ed70a15c…` 的 `loan_account_count` 与旧表同名指标，算冲突、合并，还是各留一份。

未定之前，T3/T4 的数据接管不动指标行。另有一个判据空档：`09-platform整合评估.md` §8.3 的 T3/T4 比的是文档字节与命名图 statement 计数，**指标行不在其覆盖范围**——也就是说现有接管判据发现不了「指标全悬空」。所以这条前置条件的交付物必须是一张可检查的映射表（每行旧 `metric_id` → 目标命名空间 + 批准人），而不是一句约定。

本条与 D 组进度无关，不并入 D 组剩余条目。

机器判据已补进 `09-platform整合评估.md` §8.3 **T8**：接管后三项——旧表每行 `metric_id` 在映射表命中（未命中 = 0）、每条映射的目标 namespace 在 `ListNamespaces` 存在（悬空 = 0）、抽查 20 条映射可用 `GetMetric` 读到（抽样，非全量）——全为 0 才算过。映射表靠人执行，T8 靠机器兜底；没有 T8，接管全做完也可能「假绿」。
